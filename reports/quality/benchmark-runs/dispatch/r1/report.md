Правила расходятся в исходе отправки черновика, допуске ведомости с 25 строками груза и сроке хранения при значении 7. Для показа «Передано» отсутствует измеримый предел задержки. S-7 задаёт текст и состояние при отказе. Остаётся уточнить, какое правило вывода текста имеет в виду S-6.

Каждый ID утверждения учитывается один раз. В число нарушений входят подтверждённые дефекты и неоднозначности, для которых показаны две опирающиеся на текст трактовки с разными последствиями. Один и тот же конфликт имеет один ID при любом числе затронутых требований. Критичный дефект блокирует приёмку существенного обязательного сценария. ### Z-003 · Отправка ведомости с 25 строками груза

**Дефект · Противоречивость · Критичная.** Файл с 25 строками груза выходит за предел S-3 и одновременно подпадает под S-4. Даже если приём файла считать отдельным шагом, S-4 прямо разрешает отправку. Для этого входа невозможно принять проверку допуска.

Затронутые утверждения — [R-M0010-01](#r-m0010-01), [R-M0011-01](#r-m0011-01), [R-M0011-02](#r-m0011-02).

[R-M0011-01](#r-m0011-01) · Отправка грузовых ведомостей / Параметры · [строка 11](../../../../../benchmark/dispatch/requirements.md#L11)

> При загрузке ведомости из 25 строк терминал принимает файл и разрешает отправку.  

[R-M0011-02](#r-m0011-02) · Отправка грузовых ведомостей / Параметры · [строка 11](../../../../../benchmark/dispatch/requirements.md#L11)

> При загрузке ведомости из 25 строк терминал принимает файл и разрешает отправку.  

**Сценарий.** Оператор загружает файл, все 25 строк которого являются строками груза. При проверке доступности отправки ведомость удовлетворяет остальным условиям отправки.

**Последствие.** По S-3 содержимое файла выходит за допустимый диапазон ведомости. По S-4 терминал принимает этот файл и разрешает отправку. Сам по себе приём файла конфликтует с пределом, только если приём означает признание ведомости допустимой.

**Общее условие.** Оператор загружает ведомость из 25 строк, каждая из которых является строкой груза. При проверке допуска выполнено условие состояния «Готова». Основания — [R-M0010-01](#r-m0010-01) «Одна ведомость содержит от 1 до 24 строк груза включительно.», [R-M0011-01](#r-m0011-01) «При загрузке ведомости из 25 строк терминал принимает файл и разрешает отправку.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Разрешить или запретить отправку ведомости с 25 строками груза? Если отправка запрещена, допустим ли отдельный приём такого файла без признания ведомости допустимой?

1. **Вариант 1.** Ведомость допускается к отправке при числе строк груза от 1 до 24 включительно.

   **Основание.** [R-M0010-01](#r-m0010-01) «Одна ведомость содержит от 1 до 24 строк груза включительно.».

   **Ожидаемый результат.** Ведомость с 25 строками груза к отправке не допускается.

   При выборе этого варианта привести в соответствие [R-M0011-01](#r-m0011-01).

2. **Вариант 2.** При загрузке ведомости из 25 строк груза терминал принимает файл и разрешает отправку при выполнении остальных условий отправки.

   **Основание.** [R-M0011-01](#r-m0011-01) «При загрузке ведомости из 25 строк терминал принимает файл и разрешает отправку.».

   **Ожидаемый результат.** Терминал принимает файл и разрешает отправку.

   При выборе этого варианта привести в соответствие [R-M0010-01](#r-m0010-01).

**Черновик приёмочного теста.** Загрузить файл с 25 строками груза и отдельно проверить приём файла и допуск к отправке при выполнении остальных условий. Если приём подтверждает допустимость, при сохранении предела файл должен быть отклонён. Если приём является отдельным шагом, его исход определяется ответом автора.

> Если перевозчик отклонил отправку, терминал выводит текст по правилу S-97.  

**Сценарий.** Вызвать отказ перевозчика при отправке ведомости в состоянии «Готова». Проверить вывод «Передача отклонена» и сохранение состояния «Готова». Если S-6 подразумевает S-7, использовать проверку текста для приёмки S-6. Если подразумевается отдельное правило, дополнительно сверить вывод с этим правилом.

**Последствие.** S-7 определяет текст и состояние при отказе. Ссылка на отсутствующее S-97 оставляет открытым вопрос, достаточно ли проверки вывода по S-7 для приёмки S-6.

**Уже установлено.** При отказе терминал показывает «Передача отклонена» и сохраняет состояние «Готова». Основания — [R-M0013-01](#r-m0013-01), [R-M0014-02](#r-m0014-02).

**Открытое решение.** Какое правило вывода текста обозначает ссылка на S-97 в S-6?

**Что различит проверка.** При выводе «Передача отклонена» и сохранении состояния «Готова» проверка по S-7 также подтверждает выполнение S-6. / Тот же вывод и состояние подтверждают S-7. Для приёмки S-6 требуется сверить вывод с отдельным правилом.

## Готовность и порядок исправлений

ТЗ не готово к разработке и приёмке отправки в двух обязательных сценариях. Для приёмки хранения и скорости показа подтверждения нужны однозначный срок и измеримый предел. Проверку текста и состояния при отказе можно провести по S-7. Объём проверки по S-6 зависит от уточнения ссылки.

1. Согласовать исход попытки отправки черновика и допуск ведомости с 25 строками груза. ([Z-001](#z-001), [Z-003](#z-003))
2. Согласовать единицу срока хранения и расшифровку значения 7. ([Z-006](#z-006))
3. Задать предельную задержку показа «Передано» после получения подтверждения. ([Z-004](#z-004))
4. Уточнить, какое правило вывода текста при отказе имеет в виду S-6. ([Z-005](#z-005))
