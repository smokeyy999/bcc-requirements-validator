## Проверка набора в целом

Правило длины однозначно запрещает включать реплику из 81 кодовой точки, но допускает два исхода экспорта смешанной дорожки. Для объявления миллисекунд нужен критерий проверки каждого поля.

Открытых предполагаемых пробелов — 1. Неоднозначностей — 1. Рекомендаций — 0.

Каждый ID утверждения учитывается один раз. В число нарушений входят подтверждённые дефекты и неоднозначности, для которых показаны две опирающиеся на текст трактовки с разными последствиями. Один и тот же конфликт имеет один ID при любом числе затронутых требований. Критичный дефект блокирует приёмку существенного обязательного сценария. Предполагаемый пробел оставляет открытым ожидаемое поведение или источник данных. Рекомендация предлагает улучшение. Вопросы и рекомендации имеют отдельные счётчики.

## Критичные дефекты

- [Z-001](#z-001) · T-7 требует отклонить реплику из 81 кодовой точки, а T-8 подтверждает этот порог. Слова «Reject a cue» допускают отклонение отдельной реплики или отказ команды экспорта из-за этой реплики. ### Z-001 · Область отклонения длинной реплики

**Неоднозначность · Однозначность · Критичная.** T-7 требует отклонить реплику из 81 кодовой точки, а T-8 подтверждает этот порог. Слова «Reject a cue» допускают отклонение отдельной реплики или отказ команды экспорта из-за этой реплики. В первом случае общее правило экспорта даёт файл с допустимой репликой, во втором файл не создаётся. Без выбора между этими исходами приёмка смешанной дорожки невозможна.

Затронутые утверждения — [R-M0003-02](#r-m0003-02), [R-M0014-01](#r-m0014-01), [R-M0015-01](#r-m0015-01).

[R-M0003-02](#r-m0003-02) · Subtitle track export · [строка 3](../../../../../benchmark/subtitles/baseline.md#L3)

> A desktop subtitle editor exports one open track to a local file.  

[R-M0014-01](#r-m0014-01) · Subtitle track export / Export limits · [строка 14](../../../../../benchmark/subtitles/baseline.md#L14)

> Reject a cue when its text exceeds 80 Unicode code points.  

[R-M0015-01](#r-m0015-01) · Subtitle track export / Export limits · [строка 15](../../../../../benchmark/subtitles/baseline.md#L15)

> In the acceptance sample, a cue of 81 Unicode code points is rejected.  

**Сценарий.** Экспортировать в новое место дорожку с двумя репликами длиной 80 и 81 кодовую точку Unicode. Остальные данные допустимы.

**Последствие.** Приёмка одного и того же входа может требовать либо файл с одной репликой, либо отклонение экспорта.

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой исход принимать для смешанной дорожки: файл с допустимой репликой или отказ всего экспорта?

1. **Вариант 1.** Если текст реплики превышает 80 кодовых точек Unicode, исключить эту реплику и экспортировать остальные.

   **Основание.** [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.».

   **Ожидаемый результат.** Создан файл с репликой длиной 80 кодовых точек. Реплика длиной 81 кодовую точку отсутствует.

2. **Вариант 2.** Если текст хотя бы одной реплики превышает 80 кодовых точек Unicode, отклонить экспорт дорожки целиком.

   **Основание.** [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.».

   **Ожидаемый результат.** Экспорт отклонён. Итоговый файл не создан.

**Черновик приёмочного теста.** Выполнить один экспорт смешанной дорожки, проверить наличие итогового файла и, если он создан, его содержимое. В T-8 проверить наблюдаемый признак отклонения, соответствующий выбранному правилу.

### Z-002 · Какое представление в экспортированном файле следует считать объявлением миллисекунд для каждого поля временной метки?

**Предполагаемый пробел · Проверяемость · Существенная.** T-3 задаёт миллисекунды для каждого поля и однозначно связывает одну секунду со значением 1000. Для проверки объявления единицы остаётся определить, какое представление подтверждает его наличие у каждого поля.

Затронутые утверждения — [R-M0008-01](#r-m0008-01).

[R-M0008-01](#r-m0008-01) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/baseline.md#L8)

> Each timestamp field declares milliseconds  

**Сценарий.** Экспортировать допустимую дорожку с временной меткой в одну секунду. Проверить значение 1000 в соответствующем поле и сверить объявление миллисекунд для каждого поля временной метки по согласованному критерию.

**Последствие.** T-3 задаёт миллисекунды для каждого поля и однозначно связывает одну секунду со значением 1000. Для проверки объявления единицы остаётся определить, какое представление подтверждает его наличие у каждого поля.

**Уже установлено.** Каждое поле временной метки объявляет миллисекунды. Одна секунда представлена числом 1000. Основания — [R-M0008-01](#r-m0008-01), [R-M0008-02](#r-m0008-02).

**Открытое решение.** Какое представление приёмка засчитывает как объявление миллисекунд для каждого поля.

**Что различит проверка.** Файл со значением 1000 для одной секунды и единицей, указанной только в именах всех полей времени, проходит проверку, если имена считаются объявлением. / Тот же файл проходит числовую проверку, но не проходит проверку объявления, если для каждого поля требуется отдельное указание единицы.

## Готовность и порядок исправлений

Для приёмки экспорта требуется определить результат для смешанной дорожки. Числовую шкалу временных меток можно проверить по T-3.

1. Зафиксировать исход экспорта смешанной дорожки и согласовать с ним проверку в T-8. ([Z-001](#z-001))
2. Уточнить, какое представление подтверждает объявление миллисекунд для каждого поля временной метки. ([Z-002](#z-002))
