## Проверка набора в целом

Правила формата и приёмки задают несовместимые исходы для BOM, временной метки одной минуты и субтитра из 81 кодовой точки. Для лёгкости экспорта отсутствует критерий проверки. Ссылка на сообщение для пустой дорожки ошибочна, хотя сама строка задана.

Открытых предполагаемых пробелов — 0. Неоднозначностей — 0. Рекомендаций — 0.

Каждый ID утверждения учитывается один раз. В число нарушений входят подтверждённые дефекты и неоднозначности, для которых показаны две опирающиеся на текст трактовки с разными последствиями. Один и тот же конфликт имеет один ID при любом числе затронутых требований. Критичный дефект блокирует приёмку существенного обязательного сценария. Предполагаемый пробел оставляет открытым ожидаемое поведение или источник данных. Рекомендация предлагает улучшение. Вопросы и рекомендации имеют отдельные счётчики.

### Z-001 · BOM в начале файла

**Дефект · Противоречивость · Критичная.** T-1 запрещает BOM в экспортированном файле, а T-2 требует BOM в том же файле. Базовый экспорт невозможно принять по обоим правилам.

Затронутые утверждения — [R-M0006-02](#r-m0006-02), [R-M0007-01](#r-m0007-01).

[R-M0006-02](#r-m0006-02) · Subtitle track export / Format · [строка 6](../../../../../benchmark/subtitles/requirements.md#L6)

> Write the exported track in UTF-8 without a byte-order mark.  

[R-M0007-01](#r-m0007-01) · Subtitle track export / Format · [строка 7](../../../../../benchmark/subtitles/requirements.md#L7)

> The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.  

**Сценарий.** Экспортировать непустую дорожку с коротким допустимым субтитром в локальный файл.

**Последствие.** Экспорт по T-1 провалит проверку T-2, а файл, проходящий T-2, нарушит T-1.

**Общее условие.** Приёмочный тест проверяет первые три байта файла, записанного при экспорте дорожки. Основания — [R-M0006-02](#r-m0006-02) «Write the exported track in UTF-8 without a byte-order mark.», [R-M0007-01](#r-m0007-01) «The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Должны ли первые три байта экспортированного файла образовывать UTF-8 BOM или файл должен начинаться без BOM?

1. **Вариант 1.** Записывать экспорт в UTF-8 без BOM.

   **Основание.** [R-M0006-02](#r-m0006-02) «Write the exported track in UTF-8 without a byte-order mark.».

   **Ожидаемый результат.** В начале файла нет UTF-8 BOM.

   При выборе этого варианта привести в соответствие [R-M0007-01](#r-m0007-01).

2. **Вариант 2.** Принимать файл UTF-8, если его первые три байта образуют BOM.

   **Основание.** [R-M0007-01](#r-m0007-01) «The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

   **Ожидаемый результат.** Первые три байта файла — EF BB BF.

   При выборе этого варианта привести в соответствие [R-M0006-02](#r-m0006-02).

**Черновик приёмочного теста.** Выполнить экспорт и сравнить первые три байта файла с EF BB BF. Ожидаемый результат сравнения зависит от выбранного правила.

### Z-002 · Масштаб временных меток

**Дефект · Противоречивость · Критичная.** T-3 объявляет миллисекунды для каждого поля, поэтому одной минуте соответствует 60000. Для той же длительности T-3 задаёт 1000. Единого ожидаемого значения для приёмки экспорта временных меток нет.

Затронутые утверждения — [R-M0008-01](#r-m0008-01), [R-M0008-02](#r-m0008-02).

[R-M0008-01](#r-m0008-01) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> Each timestamp field declares milliseconds  

[R-M0008-02](#r-m0008-02) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> the numeric value 1000 represents one minute.  

**Сценарий.** Экспортировать субтитр с началом через одну минуту от нуля.

**Последствие.** Число, соответствующее одной минуте по одному правилу, будет обозначать другой момент по второму.

**Общее условие.** В экспортируемом поле временной метки представлена одна минута от нуля. T-3 объявляет миллисекунды для каждого поля и прямо задаёт число для одной минуты. Основания — [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds», [R-M0008-02](#r-m0008-02) «the numeric value 1000 represents one minute.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какое число должно быть в поле для момента через одну минуту от нуля — 60000 или 1000?

1. **Вариант 1.** Выражать числовые значения всех временных меток в миллисекундах.

   **Основание.** [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds».

   **Ожидаемый результат.** Числовое значение метки начала равно 60000.

   При выборе этого варианта привести в соответствие [R-M0008-02](#r-m0008-02).

2. **Вариант 2.** Использовать шкалу, в которой числовое значение 1000 обозначает одну минуту.

   **Основание.** [R-M0008-02](#r-m0008-02) «the numeric value 1000 represents one minute.».

   **Ожидаемый результат.** Числовое значение метки начала равно 1000.

   При выборе этого варианта привести в соответствие [R-M0008-01](#r-m0008-01).

**Черновик приёмочного теста.** Экспортировать субтитр с началом ровно через одну минуту от нуля и сверить числовое значение поля с выбранным результатом.

### Z-003 · Критерий лёгкости экспорта

**Дефект · Проверяемость · Существенная.** T-4 требует, чтобы каждый пользователь воспринимал экспорт как лёгкий, но не задаёт наблюдаемой меры или порога. Выполненный экспорт сам по себе не позволяет оценить это свойство.

Затронутые утверждения — [R-M0009-01](#r-m0009-01).

[R-M0009-01](#r-m0009-01) · Subtitle track export / Format · [строка 9](../../../../../benchmark/subtitles/requirements.md#L9)

> The export experience must feel effortless to every user.  

**Сценарий.** Пользователи выполняют успешный экспорт, но по-разному оценивают требуемые усилия.

**Последствие.** Одинаковые наблюдения могут привести проверяющих к разным решениям о выполнении T-4.

**Уже установлено.** Требование относится к восприятию экспорта каждым пользователем. Основания — [R-M0009-01](#r-m0009-01).

**Открытое решение.** Какой наблюдаемый критерий определяет, что экспорт воспринимается как лёгкий?

**Что различит проверка.** При условной шкале от 1 до 5 все участники ставят 4 или 5. При пороге 4 для каждого испытание пройдено. / При тех же оценках порог 5 для каждого приводит к провалу испытания, поскольку есть оценка 4.

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** По какому наблюдаемому показателю, порогу и правилам учёта результатов пользователей принимать T-4?

Внести ответ на этот вопрос в [R-M0009-01](#r-m0009-01) для сценария «Пользователи выполняют успешный экспорт, но по-разному оценивают требуемые усилия.».

**Черновик приёмочного теста.** Провести экспорт по условиям согласованного критерия и оценить полученные результаты по утверждённому порогу и правилам учёта.

### Z-004 · Субтитр из 81 кодовой точки

**Дефект · Противоречивость · Существенная.** Текст субтитра из T-8 содержит 81 кодовую точку и подпадает под правило отклонения T-7. T-8 требует принять тот же субтитр. Ожидаемый результат обязательного граничного теста противоречив.

Затронутые утверждения — [R-M0014-01](#r-m0014-01), [R-M0015-01](#r-m0015-01).

[R-M0014-01](#r-m0014-01) · Subtitle track export / Export limits · [строка 14](../../../../../benchmark/subtitles/requirements.md#L14)

> Reject a cue when its text exceeds 80 Unicode code points.  

[R-M0015-01](#r-m0015-01) · Subtitle track export / Export limits · [строка 15](../../../../../benchmark/subtitles/requirements.md#L15)

> In the acceptance sample, a cue of 81 Unicode code points is accepted.  

**Сценарий.** Выполнить приёмочный пример T-8 с текстом ровно из 81 кодовой точки Unicode.

**Последствие.** Реализация общего правила отклонит субтитр, которого требует принять пример. Исключение для примера не задано.

**Общее условие.** На экспорт подаётся субтитр из приёмочного примера T-8 с текстом ровно из 81 кодовой точки Unicode, что превышает предел T-7. Основания — [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.», [R-M0015-01](#r-m0015-01) «In the acceptance sample, a cue of 81 Unicode code points is accepted.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой результат ожидается в примере T-8 — принятие или отклонение субтитра из 81 кодовой точки?

1. **Вариант 1.** Отклонять субтитр, если его текст превышает 80 кодовых точек Unicode.

   **Основание.** [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.».

   **Ожидаемый результат.** Субтитр из приёмочного примера отклонён.

   При выборе этого варианта привести в соответствие [R-M0015-01](#r-m0015-01).

2. **Вариант 2.** В приёмочном примере принимать субтитр из 81 кодовой точки Unicode.

   **Основание.** [R-M0015-01](#r-m0015-01) «In the acceptance sample, a cue of 81 Unicode code points is accepted.».

   **Ожидаемый результат.** Субтитр из приёмочного примера принят.

   При выборе этого варианта привести в соответствие [R-M0014-01](#r-m0014-01).

**Черновик приёмочного теста.** Подать субтитр из T-8 на экспорт и проверить, принят ли этот субтитр.

## Готовность и порядок исправлений

ТЗ не готово к разработке и приёмке затронутых сценариев. Сначала нужно согласовать формат файла, шкалу временных меток и исход граничного примера.

1. Согласовать наличие BOM и числовую шкалу временных меток в требованиях к файлу и его приёмке. ([Z-001](#z-001), [Z-002](#z-002))
2. Согласовать правило ограничения длины с ожидаемым исходом примера из 81 кодовой точки. ([Z-004](#z-004))
3. Задать наблюдаемую меру лёгкости экспорта, порог и правило оценки результатов пользователей. ([Z-003](#z-003))
4. В T-5 заменить ссылку на T-40 ссылкой на T-6. ([Z-005](#z-005))
