## Проверка набора в целом

Требования расходятся по наличию BOM в файле экспорта и по исходу проверки реплики из 81 кодовой точки. В T-3 нужно уточнить смысл объявления миллисекунд при заданном кодировании минутной отметки. Для лёгкости экспорта нужен измеримый критерий, а для текста сообщения о пустой дорожке — корректная ссылка.

Открытых предполагаемых пробелов — 2. Неоднозначностей — 0. Рекомендаций — 0.

Каждый ID утверждения учитывается один раз. В число нарушений входят подтверждённые дефекты и неоднозначности, для которых показаны две опирающиеся на текст трактовки с разными последствиями. Один и тот же конфликт имеет один ID при любом числе затронутых требований. Критичный дефект блокирует приёмку существенного обязательного сценария. Предполагаемый пробел оставляет открытым ожидаемое поведение или источник данных. Рекомендация предлагает улучшение. Вопросы и рекомендации имеют отдельные счётчики.

### Z-001 · BOM в начале файла

**Дефект · Противоречивость · Критичная.** T-1 исключает BOM из файла экспорта, а T-2 требует BOM в первых трёх байтах того же файла. Успешный экспорт нельзя принять одновременно по обоим правилам.

Затронутые утверждения — [R-M0006-01](#r-m0006-01), [R-M0007-01](#r-m0007-01).

[R-M0006-01](#r-m0006-01) · Subtitle track export / Format · [строка 6](../../../../../benchmark/subtitles/requirements.md#L6)

> Write the exported track in UTF-8 without a byte-order mark.  

[R-M0007-01](#r-m0007-01) · Subtitle track export / Format · [строка 7](../../../../../benchmark/subtitles/requirements.md#L7)

> The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.  

**Сценарий.** Экспортировать открытую дорожку с одной допустимой репликой и прочитать первые три байта файла.

**Последствие.** Файл, созданный по T-1, провалит проверку T-2.

**Общее условие.** Дорожка экспортирована в локальный файл, к которому применяется проверка первых трёх байтов. Основания — [R-M0006-01](#r-m0006-01) «Write the exported track in UTF-8 without a byte-order mark.», [R-M0007-01](#r-m0007-01) «The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой исход должен пройти приёмку — файл с BOM или файл без BOM?

1. **Вариант 1.** Записывать дорожку в UTF-8 без BOM.

   **Основание.** [R-M0006-01](#r-m0006-01) «Write the exported track in UTF-8 without a byte-order mark.».

   **Ожидаемый результат.** В начале файла нет UTF-8 BOM.

   При выборе этого варианта привести в соответствие [R-M0007-01](#r-m0007-01).

2. **Вариант 2.** Требовать UTF-8 BOM в первых трёх байтах файла экспорта.

   **Основание.** [R-M0007-01](#r-m0007-01) «The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

   **Ожидаемый результат.** Первые три байта файла образуют UTF-8 BOM.

   При выборе этого варианта привести в соответствие [R-M0006-01](#r-m0006-01).

**Черновик приёмочного теста.** Экспортировать одну допустимую реплику и проверить первые три байта по выбранному правилу.

### Z-004 · Реплика из 81 кодовой точки

**Дефект · Противоречивость · Существенная.** В примере T-8 текст реплики содержит 81 кодовую точку Unicode. Это превышает порог T-7, а слова «In the acceptance sample» задают сценарий проверки и не устанавливают исключения из порога. Результат приёмки на этой границе противоречив.

Затронутые утверждения — [R-M0014-01](#r-m0014-01), [R-M0015-01](#r-m0015-01).

[R-M0014-01](#r-m0014-01) · Subtitle track export / Export limits · [строка 14](../../../../../benchmark/subtitles/requirements.md#L14)

> Reject a cue when its text exceeds 80 Unicode code points.  

[R-M0015-01](#r-m0015-01) · Subtitle track export / Export limits · [строка 15](../../../../../benchmark/subtitles/requirements.md#L15)

> In the acceptance sample, a cue of 81 Unicode code points is accepted.  

**Сценарий.** Проверить реплику из приёмочного примера T-8, текст которой содержит 81 кодовую точку Unicode.

**Последствие.** По T-7 реплика отклоняется, а по T-8 принимается. В тексте нет исключения из T-7 для примера.

**Общее условие.** Проверяется реплика из приёмочного примера T-8 с текстом из 81 кодовой точки Unicode. Основания — [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.», [R-M0015-01](#r-m0015-01) «In the acceptance sample, a cue of 81 Unicode code points is accepted.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой исход закрепить для реплики из примера T-8 — отклонение или принятие?

1. **Вариант 1.** Отклонять реплику, если её текст превышает 80 кодовых точек Unicode, включая приёмочный пример.

   **Основание.** [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.».

   **Ожидаемый результат.** Реплика из приёмочного примера отклонена.

   При выборе этого варианта привести в соответствие [R-M0015-01](#r-m0015-01).

2. **Вариант 2.** Принимать реплику из 81 кодовой точки Unicode в указанном приёмочном примере.

   **Основание.** [R-M0015-01](#r-m0015-01) «In the acceptance sample, a cue of 81 Unicode code points is accepted.».

   **Ожидаемый результат.** Реплика из приёмочного примера принята.

   При выборе этого варианта привести в соответствие [R-M0014-01](#r-m0014-01).

**Черновик приёмочного теста.** Подать на экспорт реплику из приёмочного примера и проверить выбранный исход для этой реплики.

### Z-002 · Что означает объявление миллисекунд в T-3 при заданном соответствии 1000 одной минуте — единицу записанного числа или обозначение шкалы поля с отдельным правилом кодирования?

**Предполагаемый пробел · Полнота · Существенная.** T-3 прямо связывает минутную отметку со значением 1000. Значение 60 000 следует только при чтении объявленных миллисекунд как единицы самого записанного числа. Замена объявления единицы была бы правкой T-3.

Затронутые утверждения — [R-M0008-01](#r-m0008-01), [R-M0008-02](#r-m0008-02).

[R-M0008-01](#r-m0008-01) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> Each timestamp field declares milliseconds  

[R-M0008-02](#r-m0008-02) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> Each timestamp field declares milliseconds; the numeric value 1000 represents one minute.  

**Сценарий.** Экспортировать реплику с отметкой ровно в одну минуту от начала отсчёта поля. Проверить объявление миллисекунд и записанное значение 1000. По ответу оценить согласованность этой пары.

**Что нужно уточнить.** Неясно, задаёт ли объявление миллисекунд единицу записанного числа при явно указанном соответствии 1000 одной минуте.

**Как ответ изменит приёмку.** Если число выражено в миллисекундах, 1000 означает одну секунду и пара не проходит проверку согласованности. Если для числа действует отдельное кодирование по T-3, значение 1000 означает минуту.

**Уже установлено.** Поле объявляет миллисекунды, числовое значение 1000 соответствует одной минуте. Основания — [R-M0008-02](#r-m0008-02), [R-M0008-01](#r-m0008-01).

**Открытое решение.** Определить, задаёт ли объявление миллисекунд единицу записанного числа.

**Что различит проверка.** Пара «миллисекунды» и 1000 для минутной отметки не проходит проверку согласованности: в этой единице 1000 соответствует одной секунде. / Та же пара проходит проверку согласованности: заданное в T-3 кодирование определяет 1000 как одну минуту.

### Z-003 · Критерий лёгкости экспорта

**Предполагаемый пробел · Проверяемость · Существенная.** T-4 требует, чтобы экспорт воспринимался как лёгкий каждым пользователем. Успешное создание файла само по себе не даёт меры воспринимаемых усилий.

Затронутые утверждения — [R-M0009-01](#r-m0009-01).

[R-M0009-01](#r-m0009-01) · Subtitle track export / Format · [строка 9](../../../../../benchmark/subtitles/requirements.md#L9)

> The export experience must feel effortless to every user.  

**Сценарий.** Дать участникам задачу экспортировать одну открытую дорожку в локальный файл. После успешного экспорта применить согласованный критерий к результату каждого участника.

**Последствие.** По ТЗ нельзя определить, подтверждает ли наблюдение выполнение T-4.

**Уже установлено.** Задача состоит в локальном экспорте одной открытой дорожки. Требование лёгкости относится к каждому пользователю. Основания — [R-M0009-01](#r-m0009-01), [R-M0003-01](#r-m0003-01).

**Открытое решение.** Выбрать измеримый критерий лёгкости для каждого участника.

**Что различит проверка.** Если при шкале усилий от 1 до 5 проходит только оценка 1, успешный экспорт с оценкой 2 не проходит проверку лёгкости. / Если на той же шкале проходят оценки 1 и 2, тот же экспорт с оценкой 2 проходит проверку лёгкости.

Subtitle track export / Format · [строка 7](../../../../../benchmark/subtitles/requirements.md#L7)

> The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.  

**Связано с нарушением в спецификации.** T-1 исключает BOM из файла экспорта, а T-2 требует BOM в первых трёх байтах того же файла. Успешный экспорт нельзя принять одновременно по обоим правилам.

Связанные замечания — [Z-001](#z-001).

**Связано с вопросом к автору.** T-3 прямо связывает минутную отметку со значением 1000. Значение 60 000 следует только при чтении объявленных миллисекунд как единицы самого записанного числа. Замена объявления единицы была бы правкой T-3.

### R-M0010-01 · При экспорте пустой дорожки показывается точное сообщение из T-40.

Subtitle track export / Format · [строка 10](../../../../../benchmark/subtitles/requirements.md#L10)

> For an empty track, display the exact message listed in T-40  

**Связано с нарушением в спецификации.** T-5 ссылается на отсутствующее T-40. Точную строку «Add at least one cue» задаёт T-6, поэтому ссылка на T-6 исправляет трассировку, а сценарий пустой дорожки уже проверяем. Фразы «For an empty track» и «The message for an empty track» относятся к одной попытке экспорта. T-6 прямо задаёт ожидаемый текст «Add at least one cue». Ошибка ссылки остаётся замечанием по трассируемости.

Связанные замечания — [Z-005](#z-005).

Основания для снятия замечания — [R-M0011-01](#r-m0011-01).

## Готовность и порядок исправлений

ТЗ не готово к согласованию приёмки. Нужно определить единый ожидаемый результат для файла экспорта и для реплики из приёмочного примера.

1. Согласовать наличие BOM в файле и проверку его первых трёх байтов. ([Z-001](#z-001))
2. Согласовать исход для реплики из 81 кодовой точки в правиле и приёмочном примере. ([Z-004](#z-004))
3. Уточнить смысл объявления единицы и проверить согласованность минутной отметки. ([Z-002](#z-002))
4. Задать наблюдаемый критерий лёгкости экспорта для каждого участника проверки. ([Z-003](#z-003))
5. Исправить ссылку из T-5 на T-6. ([Z-005](#z-005))
