## Проверка набора в целом

Требования расходятся по BOM, шкале временных меток и исходу приёмочного примера для реплики из 81 кодовой точки. Для смешанной дорожки нужно определить итог экспорта, для лёгкости экспорта — критерий проверки. Ссылку на сообщение о пустой дорожке нужно направить на T-6.

Открытых предполагаемых пробелов — 1. Неоднозначностей — 0. Рекомендаций — 0.

Каждый ID утверждения учитывается один раз. В число нарушений входят подтверждённые дефекты и неоднозначности, для которых показаны две опирающиеся на текст трактовки с разными последствиями. Один и тот же конфликт имеет один ID при любом числе затронутых требований. Критичный дефект блокирует приёмку существенного обязательного сценария. Предполагаемый пробел оставляет открытым ожидаемое поведение или источник данных. Рекомендация предлагает улучшение. Вопросы и рекомендации имеют отдельные счётчики.

### Z-002 · BOM в файле экспорта

**Дефект · Противоречивость · Критичная.** T-1 требует записать файл без UTF-8 BOM, а T-2 требует BOM при приёмке того же файла. Формат результата экспорта нельзя принять до согласования этих правил.

Затронутые утверждения — [R-M0006-01](#r-m0006-01), [R-M0007-01](#r-m0007-01).

[R-M0006-01](#r-m0006-01) · Subtitle track export / Format · [строка 6](../../../../../benchmark/subtitles/requirements.md#L6)

> Write the exported track in UTF-8 without a byte-order mark.  

[R-M0007-01](#r-m0007-01) · Subtitle track export / Format · [строка 7](../../../../../benchmark/subtitles/requirements.md#L7)

> The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.  

**Сценарий.** Успешно экспортировать непустую дорожку в локальный файл.

**Последствие.** Для одного файла одновременно требуется наличие и отсутствие UTF-8 BOM.

**Общее условие.** Проверяются начальные байты файла, записанного при экспорте дорожки. Основания — [R-M0006-01](#r-m0006-01) «Write the exported track in UTF-8 without a byte-order mark.», [R-M0007-01](#r-m0007-01) «The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой результат принять для одного и того же экспортированного файла — наличие или отсутствие UTF-8 BOM?

1. **Вариант 1.** Записывать файл в UTF-8 без BOM.

   **Основание.** [R-M0006-01](#r-m0006-01) «Write the exported track in UTF-8 without a byte-order mark.».

   **Ожидаемый результат.** Файл начинается без UTF-8 BOM.

   При выборе этого варианта привести в соответствие [R-M0007-01](#r-m0007-01).

2. **Вариант 2.** Записывать UTF-8 BOM в первые три байта файла.

   **Основание.** [R-M0007-01](#r-m0007-01) «The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

   **Ожидаемый результат.** Первые три байта файла образуют UTF-8 BOM.

   При выборе этого варианта привести в соответствие [R-M0006-01](#r-m0006-01).

**Черновик приёмочного теста.** Проверить, образуют ли первые три байта файла UTF-8 BOM, и сравнить с выбранным ожиданием.

### Z-003 · Шкала временных меток

**Дефект · Противоречивость · Критичная.** T-3 объявляет миллисекунды единицей каждого поля и задаёт для минуты число 1000. В объявленной единице минута равна 60 000, поэтому корректность временных меток нельзя принять до согласования шкалы.

Затронутые утверждения — [R-M0008-01](#r-m0008-01), [R-M0008-02](#r-m0008-02).

[R-M0008-01](#r-m0008-01) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> Each timestamp field declares milliseconds  

[R-M0008-02](#r-m0008-02) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> Each timestamp field declares milliseconds; the numeric value 1000 represents one minute.  

**Сценарий.** Экспортировать реплику с началом через одну минуту от начала дорожки и прочитать поле начала.

**Последствие.** Для начала той же реплики получаются значения 60 000 и 1000.

**Общее условие.** Проверяется числовое значение экспортируемой временной метки в одну минуту. T-3 объявляет миллисекунды для каждого поля временной метки. Основания — [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds», [R-M0008-02](#r-m0008-02) «the numeric value 1000 represents one minute.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой исход выбрать для отметки в одну минуту — значение в миллисекундах или значение 1000 по заданному соответствию?

1. **Вариант 1.** Записывать числовое значение поля в миллисекундах.

   **Основание.** [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds».

   **Ожидаемый результат.** Поле начала содержит 60 000.

   При выборе этого варианта привести в соответствие [R-M0008-02](#r-m0008-02).

2. **Вариант 2.** Использовать шкалу, на которой значение 1000 соответствует одной минуте.

   **Основание.** [R-M0008-02](#r-m0008-02) «Each timestamp field declares milliseconds; the numeric value 1000 represents one minute.».

   **Ожидаемый результат.** Поле начала содержит 1000.

   При выборе этого варианта привести в соответствие [R-M0008-01](#r-m0008-01).

**Черновик приёмочного теста.** Прочитать поле начала в экспортированном файле и сверить число и объявленную единицу с выбранной шкалой.

### Z-004 · Реплика из 81 кодовой точки

**Дефект · Противоречивость · Существенная.** T-7 охватывает длину 81 кодовая точка, а T-8 задаёт для этой длины приёмку реплики в примере. Противоречие затрагивает проверку предела длины.

Затронутые утверждения — [R-M0014-01](#r-m0014-01), [R-M0015-01](#r-m0015-01).

[R-M0014-01](#r-m0014-01) · Subtitle track export / Export limits · [строка 14](../../../../../benchmark/subtitles/requirements.md#L14)

> Reject a cue when its text exceeds 80 Unicode code points.  

[R-M0015-01](#r-m0015-01) · Subtitle track export / Export limits · [строка 15](../../../../../benchmark/subtitles/requirements.md#L15)

> In the acceptance sample, a cue of 81 Unicode code points is accepted.  

**Сценарий.** Экспортировать реплику из приёмочного примера T-8 с текстом длиной 81 кодовая точка Unicode.

**Последствие.** Общее правило требует отклонить ту же реплику, которую пример требует принять.

**Общее условие.** Реплика из приёмочного примера содержит 81 кодовую точку Unicode и тем самым превышает предел в 80. Основания — [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.», [R-M0015-01](#r-m0015-01) «In the acceptance sample, a cue of 81 Unicode code points is accepted.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой исход выбрать в примере T-8 — принять реплику или отклонить её по T-7?

1. **Вариант 1.** Отклонять реплику, если её текст длиннее 80 кодовых точек Unicode, в том числе в приёмочном примере.

   **Основание.** [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.».

   **Ожидаемый результат.** Реплика отклонена.

   При выборе этого варианта привести в соответствие [R-M0015-01](#r-m0015-01).

2. **Вариант 2.** Принимать реплику из 81 кодовой точки Unicode в приёмочном примере как исключение из предела.

   **Основание.** [R-M0015-01](#r-m0015-01) «In the acceptance sample, a cue of 81 Unicode code points is accepted.».

   **Ожидаемый результат.** Реплика принята.

   При выборе этого варианта привести в соответствие [R-M0014-01](#r-m0014-01).

**Черновик приёмочного теста.** Запустить экспорт на данных T-8 и сверить исход для реплики с выбранным правилом.

<a id="decision"></a>

## Готовность и порядок исправлений

ТЗ не готово к разработке экспорта по проверяемым требованиям. Сначала нужно согласовать BOM и шкалу временных меток, затем определить ожидаемый исход проверки длины.

1. Согласовать наличие BOM и соответствие объявленной единицы числовой шкале. Зафиксировать оба решения в приёмочных проверках. (Z-002, Z-003)
2. Согласовать правило длины с ожидаемым исходом примера для 81 кодовой точки. (Z-004)
3. Определить итог экспорта смешанной дорожки и проверить наличие и содержимое файла назначения. (Z-001)
4. Задать наблюдаемый критерий лёгкости экспорта и способ проверки его выполнения. (Z-005)
5. Исправить в T-5 ссылку на требование с точным сообщением. (Z-006)
