## Проверка набора в целом

Требования расходятся по BOM, значению временной метки 1000 и допуску реплики из приёмочного образца. Для лёгкости экспорта отсутствует мера. Ссылка T-40 требует редакторского исправления. Точный текст сообщения для пустой дорожки уже задан в T-6, а T-5 требует оставить место назначения без изменений.

Открытых предполагаемых пробелов — 0. Неоднозначностей — 0. Рекомендаций — 0.

Каждый ID утверждения учитывается один раз. В число нарушений входят подтверждённые дефекты и неоднозначности, для которых показаны две опирающиеся на текст трактовки с разными последствиями. Один и тот же конфликт имеет один ID при любом числе затронутых требований. Критичный дефект блокирует приёмку существенного обязательного сценария. Предполагаемый пробел оставляет открытым ожидаемое поведение или источник данных. Рекомендация предлагает улучшение. Вопросы и рекомендации имеют отдельные счётчики.

## Критичные дефекты

- [Z-001](#z-001) · T-1 требует записать файл без BOM, а T-2 требует BOM в первых трёх байтах этого же файла. Оба условия одновременно выполнить невозможно.

- [Z-004](#z-004) · Длина реплики из T-8 превышает порог T-7. Общее правило требует отклонить эту реплику, а приёмочный образец требует принять её.

### Z-001 · Наличие BOM в файле

**Дефект · Противоречивость · Критичная.** T-1 требует записать файл без BOM, а T-2 требует BOM в первых трёх байтах этого же файла. Оба условия одновременно выполнить невозможно.

Затронутые утверждения — [R-M0006-01](#r-m0006-01), [R-M0007-01](#r-m0007-01).

[R-M0006-01](#r-m0006-01) · Subtitle track export / Format · [строка 6](../../../../../benchmark/subtitles/requirements.md#L6)

> Write the exported track in UTF-8 without a byte-order mark.  

[R-M0007-01](#r-m0007-01) · Subtitle track export / Format · [строка 7](../../../../../benchmark/subtitles/requirements.md#L7)

> The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.  

**Сценарий.** Экспортировать непустую дорожку с допустимой репликой и проверить первые три байта файла.

**Последствие.** Один файл не может одновременно удовлетворять требованиям к записи и приёмке.

**Общее условие.** Локальный файл успешно экспортированной дорожки проверяется по T-2. Основания — [R-M0006-01](#r-m0006-01) «Write the exported track in UTF-8 without a byte-order mark.», [R-M0007-01](#r-m0007-01) «The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой файл принимать: с UTF-8 BOM или без него?

1. **Вариант 1.** Записывать экспорт в UTF-8 без BOM.

   **Основание.** [R-M0006-01](#r-m0006-01) «Write the exported track in UTF-8 without a byte-order mark.».

   **Ожидаемый результат.** В начале файла нет UTF-8 BOM.

   При выборе этого варианта привести в соответствие [R-M0007-01](#r-m0007-01).

2. **Вариант 2.** Записывать UTF-8 BOM в первых трёх байтах экспорта.

   **Основание.** [R-M0007-01](#r-m0007-01) «The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

   **Ожидаемый результат.** Первые три байта файла — EF BB BF.

   При выборе этого варианта привести в соответствие [R-M0006-01](#r-m0006-01).

**Черновик приёмочного теста.** Выполнить один экспорт и проверить первые три байта на наличие EF BB BF согласно выбранному правилу.

### Z-002 · Масштаб временной метки

**Дефект · Противоречивость · Критичная.** T-3 задаёт миллисекунды для каждого поля. Для значения 1000 эта единица даёт одну секунду, а явное соответствие в том же пункте даёт одну минуту. Корректность времени в экспортированном файле проверить по обоим условиям невозможно.

Затронутые утверждения — [R-M0008-01](#r-m0008-01), [R-M0008-02](#r-m0008-02).

[R-M0008-01](#r-m0008-01) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> Each timestamp field declares milliseconds  

[R-M0008-02](#r-m0008-02) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> Each timestamp field declares milliseconds; the numeric value 1000 represents one minute.  

**Сценарий.** Прочитать поле временной метки со значением 1000.

**Последствие.** Одна и та же метка соответствует одной секунде по заявленной единице и одной минуте по явному соответствию.

**Общее условие.** В экспортированном поле временной метки записано число 1000. Поле подпадает под общую единицу T-3 и под явное соответствие для числа 1000. Основания — [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds», [R-M0008-02](#r-m0008-02) «the numeric value 1000 represents one minute.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какое время должна обозначать метка 1000 при приёмке: одну секунду или одну минуту?

1. **Вариант 1.** Интерпретировать числовые значения полей временных меток в миллисекундах.

   **Основание.** [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds».

   **Ожидаемый результат.** Метка 1000 соответствует одной секунде.

   При выборе этого варианта привести в соответствие [R-M0008-02](#r-m0008-02).

2. **Вариант 2.** Считать значение 1000 во временной метке одной минутой.

   **Основание.** [R-M0008-02](#r-m0008-02) «Each timestamp field declares milliseconds; the numeric value 1000 represents one minute.».

   **Ожидаемый результат.** Метка 1000 соответствует одной минуте.

   При выборе этого варианта привести в соответствие [R-M0008-01](#r-m0008-01).

**Черновик приёмочного теста.** Прочитать значение 1000 из поля экспортированной метки и сравнить обозначаемое время с выбранным исходом.

### Z-004 · Допуск реплики из образца

**Дефект · Противоречивость · Критичная.** Длина реплики из T-8 превышает порог T-7. Общее правило требует отклонить эту реплику, а приёмочный образец требует принять её.

Затронутые утверждения — [R-M0014-01](#r-m0014-01), [R-M0015-01](#r-m0015-01).

[R-M0014-01](#r-m0014-01) · Subtitle track export / Export limits · [строка 14](../../../../../benchmark/subtitles/requirements.md#L14)

> Reject a cue when its text exceeds 80 Unicode code points.  

[R-M0015-01](#r-m0015-01) · Subtitle track export / Export limits · [строка 15](../../../../../benchmark/subtitles/requirements.md#L15)

> In the acceptance sample, a cue of 81 Unicode code points is accepted.  

**Сценарий.** Проверить реплику длиной 81 кодовая точка Unicode из образца T-8.

**Последствие.** При соблюдении порога из T-7 образец T-8 не пройдёт приёмку.

**Общее условие.** Проверяется реплика из приёмочного образца T-8 с текстом длиной 81 кодовая точка Unicode. Основания — [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.», [R-M0015-01](#r-m0015-01) «In the acceptance sample, a cue of 81 Unicode code points is accepted.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** При проверке образца T-8 реплику нужно отклонить по T-7 или принять?

1. **Вариант 1.** Отклонять реплики длиннее 80 кодовых точек Unicode, включая реплику из образца.

   **Основание.** [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.».

   **Ожидаемый результат.** Реплика из образца отклоняется.

   При выборе этого варианта привести в соответствие [R-M0015-01](#r-m0015-01).

2. **Вариант 2.** Принимать реплику длиной 81 кодовая точка Unicode из приёмочного образца.

   **Основание.** [R-M0015-01](#r-m0015-01) «In the acceptance sample, a cue of 81 Unicode code points is accepted.».

   **Ожидаемый результат.** Реплика из образца принимается.

   При выборе этого варианта привести в соответствие [R-M0014-01](#r-m0014-01).

**Черновик приёмочного теста.** Запустить экспорт с репликой из образца T-8 и сравнить результат проверки реплики с выбранным исходом.

### Z-003 · Критерий лёгкости экспорта

**Дефект · Проверяемость · Существенная.** T-4 требует, чтобы каждый пользователь воспринимал экспорт как лёгкий. Критерий оценки этого свойства отсутствует. Запись файла можно проверить отдельно.

Затронутые утверждения — [R-M0009-01](#r-m0009-01).

[R-M0009-01](#r-m0009-01) · Subtitle track export / Format · [строка 9](../../../../../benchmark/subtitles/requirements.md#L9)

> The export experience must feel effortless to every user.  

**Сценарий.** Два пользователя успешно экспортируют дорожку и по-разному оценивают затраченные усилия.

**Последствие.** По T-4 невозможно однозначно решить, выполнено ли требование.

**Уже установлено.** Оценивается воспринимаемая лёгкость экспорта для каждого пользователя. Основания — [R-M0009-01](#r-m0009-01).

**Открытое решение.** Какой измеримый критерий восприятия усилий применять к оценке каждого участника приёмочного испытания.

**Что различит проверка.** При согласованном пороге обе полученные оценки усилий допустимы, и T-4 проходит проверку. / При более строгом пороге одна из тех же оценок выходит за допустимую границу, и T-4 не проходит проверку.

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** По какому наблюдаемому критерию и на какой группе пользователей принимать лёгкость экспорта по T-4?

Внести ответ на этот вопрос в [R-M0009-01](#r-m0009-01) для сценария «Два пользователя успешно экспортируют дорожку и по-разному оценивают затраченные усилия.».

**Черновик приёмочного теста.** Дать согласованной группе задание экспортировать дорожку и сравнить результаты с согласованным критерием.

## Готовность и порядок исправлений

ТЗ не готово к разработке и приёмке экспорта. Сначала нужно согласовать ожидаемые результаты проверки файла, временной метки и реплики из образца.

1. Согласовать наличие BOM, согласовать единицу временной метки со значением 1000 и установить единый исход для реплики из образца. ([Z-001](#z-001), [Z-002](#z-002), [Z-004](#z-004))
2. Задать измеримый критерий воспринимаемой лёгкости экспорта и способ его проверки. ([Z-003](#z-003))
3. Исправить ссылку T-40 редакторски, сохранив установленное поведение для пустой дорожки. ([Z-005](#z-005))
