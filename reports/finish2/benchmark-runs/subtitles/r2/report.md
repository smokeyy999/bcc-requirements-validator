## Проверка набора в целом

Требования расходятся по BOM, шкале временных меток и исходу примера с репликой из 81 кодовой точки. Для лёгкости экспорта отсутствует измеримый критерий. Ссылка T-40 требует редакторского исправления. Строка сообщения уже задана в T-6, а сохранение состояния места назначения предписано в T-5.

Открытых предполагаемых пробелов — 0. Неоднозначностей — 0. Рекомендаций — 0.

Каждый ID утверждения учитывается один раз. В число нарушений входят подтверждённые дефекты и неоднозначности, для которых показаны две опирающиеся на текст трактовки с разными последствиями. Один и тот же конфликт имеет один ID при любом числе затронутых требований. Критичный дефект блокирует приёмку существенного обязательного сценария. Предполагаемый пробел оставляет открытым ожидаемое поведение или источник данных. Рекомендация предлагает улучшение. Вопросы и рекомендации имеют отдельные счётчики.

### Z-001 · BOM в файле экспорта

**Дефект · Противоречивость · Критичная.** T-1 запрещает BOM, а T-2 требует его в первых трёх байтах того же файла. Экспорт нельзя принять по обоим требованиям одновременно.

Затронутые утверждения — [R-M0006-02](#r-m0006-02), [R-M0007-01](#r-m0007-01).

[R-M0006-02](#r-m0006-02) · Subtitle track export / Format · [строка 6](../../../../../benchmark/subtitles/requirements.md#L6)

> Write the exported track in UTF-8 without a byte-order mark.  

[R-M0007-01](#r-m0007-01) · Subtitle track export / Format · [строка 7](../../../../../benchmark/subtitles/requirements.md#L7)

> The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.  

**Сценарий.** Экспортировать непустую дорожку с допустимой репликой и прочитать первые три байта файла.

**Последствие.** Один файл не может одновременно удовлетворить обоим требованиям.

**Общее условие.** Приёмка проверяет первые три байта экспортированного файла UTF-8. Основания — [R-M0006-02](#r-m0006-02) «Write the exported track in UTF-8 without a byte-order mark.», [R-M0007-01](#r-m0007-01) «The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой результат считать правильным при приёмке: файл с UTF-8 BOM или без него?

1. **Вариант 1.** Записывать файл в UTF-8 без BOM.

   **Основание.** [R-M0006-02](#r-m0006-02) «Write the exported track in UTF-8 without a byte-order mark.».

   **Ожидаемый результат.** В начале файла нет UTF-8 BOM.

   При выборе этого варианта привести в соответствие [R-M0007-01](#r-m0007-01).

2. **Вариант 2.** Записывать UTF-8 BOM в первых трёх байтах файла.

   **Основание.** [R-M0007-01](#r-m0007-01) «The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

   **Ожидаемый результат.** Первые три байта файла равны EF BB BF.

   При выборе этого варианта привести в соответствие [R-M0006-02](#r-m0006-02).

**Черновик приёмочного теста.** Экспортировать одну и ту же дорожку и проверить наличие EF BB BF в начале файла по выбранному правилу.

### Z-002 · Шкала временных меток

**Дефект · Противоречивость · Критичная.** T-3 объявляет миллисекунды для каждого поля и приписывает значению 1000 одну минуту. Единую шкалу временных меток принять невозможно.

Затронутые утверждения — [R-M0008-01](#r-m0008-01), [R-M0008-02](#r-m0008-02).

[R-M0008-01](#r-m0008-01) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> Each timestamp field declares milliseconds  

[R-M0008-02](#r-m0008-02) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> the numeric value 1000 represents one minute.  

**Сценарий.** Прочитать значение 1000 в поле временной метки из файла экспорта.

**Последствие.** По объявленной единице это одна секунда, по явному соответствию в T-3 это одна минута.

**Общее условие.** Поле временной метки объявляет миллисекунды и содержит значение 1000. Основания — [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds», [R-M0008-02](#r-m0008-02) «the numeric value 1000 represents one minute.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какое время должно представлять значение 1000 при приёмке: одну секунду или одну минуту?

1. **Вариант 1.** Читать числовое значение каждого поля временной метки в объявленных миллисекундах.

   **Основание.** [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds».

   **Ожидаемый результат.** Значение 1000 соответствует одной секунде.

   При выборе этого варианта привести в соответствие [R-M0008-02](#r-m0008-02).

2. **Вариант 2.** Использовать шкалу, в которой значение 1000 соответствует одной минуте, и согласовать с ней объявленную единицу.

   **Основание.** [R-M0008-02](#r-m0008-02) «the numeric value 1000 represents one minute.».

   **Ожидаемый результат.** Значение 1000 соответствует одной минуте.

   При выборе этого варианта привести в соответствие [R-M0008-01](#r-m0008-01).

**Черновик приёмочного теста.** Прочитать поле со значением 1000 и сверить объявленную единицу и представленное время с выбранной шкалой.

### Z-003 · Критерий лёгкости экспорта

**Дефект · Проверяемость · Существенная.** T-4 требует, чтобы экспорт воспринимался как лёгкий каждым пользователем, но не задаёт меры для воспроизводимой проверки этого свойства. Сам экспорт можно проверить отдельно.

Затронутые утверждения — [R-M0009-01](#r-m0009-01).

[R-M0009-01](#r-m0009-01) · Subtitle track export / Format · [строка 9](../../../../../benchmark/subtitles/requirements.md#L9)

> The export experience must feel effortless to every user.  

**Сценарий.** Два пользователя успешно выполняют один и тот же экспорт и по-разному оценивают его лёгкость.

**Последствие.** По тексту ТЗ проверяющий не может вынести воспроизводимый вердикт по T-4.

**Уже установлено.** Редактор экспортирует одну открытую дорожку в локальный файл. T-4 требует, чтобы экспорт воспринимался как лёгкий каждым пользователем. Основания — [R-M0009-01](#r-m0009-01), [R-M0003-01](#r-m0003-01).

**Открытое решение.** Какой измеримый критерий определяет выполнение T-4 в приёмочном испытании?

**Что различит проверка.** При тех же наблюдениях в испытании результат каждого участника удовлетворяет утверждённому критерию, и T-4 проходит проверку. / При тех же наблюдениях результат хотя бы одного участника не удовлетворяет утверждённому критерию, и T-4 не проходит проверку.

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой измеримый результат, в каком сценарии и для каких участников будет означать выполнение T-4?

Внести ответ на этот вопрос в [R-M0009-01](#r-m0009-01) для сценария «Два пользователя успешно выполняют один и тот же экспорт и по-разному оценивают его лёгкость.».

**Черновик приёмочного теста.** Провести согласованный сценарий с указанными участниками и сравнить результат с утверждённым критерием.

### Z-004 · Реплика из 81 кодовой точки

**Дефект · Противоречивость · Существенная.** Общий лимит T-7 распространяется на реплику из примера T-8. Для её текста из 81 кодовой точки правило требует отклонения, а пример требует принятия.

Затронутые утверждения — [R-M0014-01](#r-m0014-01), [R-M0015-01](#r-m0015-01).

[R-M0014-01](#r-m0014-01) · Subtitle track export / Export limits · [строка 14](../../../../../benchmark/subtitles/requirements.md#L14)

> Reject a cue when its text exceeds 80 Unicode code points.  

[R-M0015-01](#r-m0015-01) · Subtitle track export / Export limits · [строка 15](../../../../../benchmark/subtitles/requirements.md#L15)

> In the acceptance sample, a cue of 81 Unicode code points is accepted.  

**Сценарий.** Выполнить приёмочный пример T-8 с репликой, текст которой содержит 81 кодовую точку Unicode.

**Последствие.** Реализация лимита T-7 не проходит пример T-8.

**Общее условие.** В приёмочном примере T-8 текст реплики содержит 81 кодовую точку Unicode. Основания — [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.», [R-M0015-01](#r-m0015-01) «In the acceptance sample, a cue of 81 Unicode code points is accepted.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** В примере T-8 реплику из 81 кодовой точки нужно принять или отклонить?

1. **Вариант 1.** Отклонять реплику, если её текст содержит более 80 кодовых точек Unicode.

   **Основание.** [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.».

   **Ожидаемый результат.** Реплика из 81 кодовой точки в приёмочном примере отклоняется.

   При выборе этого варианта привести в соответствие [R-M0015-01](#r-m0015-01).

2. **Вариант 2.** Принимать реплику из 81 кодовой точки Unicode в приёмочном примере.

   **Основание.** [R-M0015-01](#r-m0015-01) «In the acceptance sample, a cue of 81 Unicode code points is accepted.».

   **Ожидаемый результат.** Реплика из 81 кодовой точки в приёмочном примере принимается.

   При выборе этого варианта привести в соответствие [R-M0014-01](#r-m0014-01).

**Черновик приёмочного теста.** Выполнить пример T-8 и сверить результат обработки реплики с выбранным исходом.

## Готовность и порядок исправлений

ТЗ не готово к передаче в разработку. Для формата файла и обязательного примера нужны согласованные исходы, а для T-4 нужен критерий приёмки.

1. Согласовать наличие BOM и единую шкалу временных меток в требованиях и приёмке. ([Z-001](#z-001), [Z-002](#z-002))
2. Согласовать лимит длины с исходом приёмочного примера. ([Z-004](#z-004))
3. Задать измеримый критерий лёгкости экспорта и условия его проверки. ([Z-003](#z-003))
4. Исправить внутреннюю ссылку T-40 в T-5. ([Z-005](#z-005))
