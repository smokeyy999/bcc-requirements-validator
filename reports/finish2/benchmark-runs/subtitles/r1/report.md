## Проверка набора в целом

Формат файла и смысл временных меток заданы противоречиво. Правило ограничения длины расходится с приёмочным примером. Для лёгкости экспорта отсутствует мера, а внутренняя ссылка T-40 требует редакторской правки. Сообщение для пустой дорожки уже задано в T-6.

Открытых предполагаемых пробелов — 0. Неоднозначностей — 0. Рекомендаций — 0.

Каждый ID утверждения учитывается один раз. В число нарушений входят подтверждённые дефекты и неоднозначности, для которых показаны две опирающиеся на текст трактовки с разными последствиями. Один и тот же конфликт имеет один ID при любом числе затронутых требований. Критичный дефект блокирует приёмку существенного обязательного сценария. Предполагаемый пробел оставляет открытым ожидаемое поведение или источник данных. Рекомендация предлагает улучшение. Вопросы и рекомендации имеют отдельные счётчики.

### Z-001 · BOM в экспортируемом файле

**Дефект · Противоречивость · Критичная.** T-1 требует записать файл без BOM, а T-2 требует BOM в начале этого же файла. Успешный экспорт нельзя принять по обоим правилам.

Затронутые утверждения — [R-M0006-01](#r-m0006-01), [R-M0007-01](#r-m0007-01).

[R-M0006-01](#r-m0006-01) · Subtitle track export / Format · [строка 6](../../../../../benchmark/subtitles/requirements.md#L6)

> Write the exported track in UTF-8 without a byte-order mark.  

[R-M0007-01](#r-m0007-01) · Subtitle track export / Format · [строка 7](../../../../../benchmark/subtitles/requirements.md#L7)

> The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.  

**Сценарий.** Экспортировать непустую дорожку с допустимой репликой и проверить начало одного и того же файла.

**Последствие.** Нельзя одновременно выполнить требование к формату и пройти приёмочный тест.

**Общее условие.** Проверяются первые три байта файла, записанного при успешном экспорте дорожки. Основания — [R-M0006-01](#r-m0006-01) «Write the exported track in UTF-8 without a byte-order mark.», [R-M0007-01](#r-m0007-01) «The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой файл считать корректным при приёмке, с BOM или без него?

1. **Вариант 1.** Записывать дорожку в UTF-8 без BOM.

   **Основание.** [R-M0006-01](#r-m0006-01) «Write the exported track in UTF-8 without a byte-order mark.».

   **Ожидаемый результат.** В начале файла нет BOM.

   При выборе этого варианта привести в соответствие [R-M0007-01](#r-m0007-01).

2. **Вариант 2.** Записывать дорожку в UTF-8 с BOM в первых трёх байтах.

   **Основание.** [R-M0007-01](#r-m0007-01) «The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

   **Ожидаемый результат.** Первые три байта файла — EF BB BF.

   При выборе этого варианта привести в соответствие [R-M0006-01](#r-m0006-01).

**Черновик приёмочного теста.** Экспортировать дорожку и проверить первые три байта на наличие UTF-8 BOM по выбранному правилу.

### Z-002 · Шкала временных меток

**Дефект · Противоречивость · Критичная.** T-3 объявляет миллисекунды для каждого поля и одновременно приписывает числу 1000 значение одной минуты. Для приёмки формата нужны однозначные временные метки.

Затронутые утверждения — [R-M0008-01](#r-m0008-01), [R-M0008-02](#r-m0008-02).

[R-M0008-01](#r-m0008-01) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> Each timestamp field declares milliseconds  

[R-M0008-02](#r-m0008-02) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> Each timestamp field declares milliseconds; the numeric value 1000 represents one minute.  

**Сценарий.** Прочитать экспортированное поле временной метки со значением 1000.

**Последствие.** По заявленной единице метка означает одну секунду, а по заданному соответствию — одну минуту. Ожидаемое значение для приёмки различается в 60 раз.

**Общее условие.** В экспортированном поле временной метки, объявляющем миллисекунды, записано число 1000. Основания — [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds», [R-M0008-02](#r-m0008-02) «the numeric value 1000 represents one minute.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какое время должна обозначать экспортированная метка 1000, одну секунду или одну минуту?

1. **Вариант 1.** Значение каждого поля временной метки выражается в миллисекундах.

   **Основание.** [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds».

   **Ожидаемый результат.** Метка 1000 означает одну секунду.

   При выборе этого варианта привести в соответствие [R-M0008-02](#r-m0008-02).

2. **Вариант 2.** Значение 1000 в поле временной метки означает одну минуту. Объявление единицы должно соответствовать этой шкале.

   **Основание.** [R-M0008-02](#r-m0008-02) «Each timestamp field declares milliseconds; the numeric value 1000 represents one minute.».

   **Ожидаемый результат.** Метка 1000 означает одну минуту.

   При выборе этого варианта привести в соответствие [R-M0008-01](#r-m0008-01).

**Черновик приёмочного теста.** Прочитать метку 1000 по согласованному правилу формата и сверить полученное время с выбранным исходом.

### Z-003 · Критерий лёгкости экспорта

**Дефект · Проверяемость · Существенная.** T-4 требует, чтобы экспорт ощущался лёгким для каждого пользователя, но не задаёт наблюдаемой меры этого свойства. Успешная запись файла сама по себе его не подтверждает.

Затронутые утверждения — [R-M0009-01](#r-m0009-01).

[R-M0009-01](#r-m0009-01) · Subtitle track export / Format · [строка 9](../../../../../benchmark/subtitles/requirements.md#L9)

> The export experience must feel effortless to every user.  

**Сценарий.** Пользователь успешно экспортирует дорожку. Проверяющий оценивает выполнение T-4.

**Последствие.** Проверяющие могут дать разные оценки одному выполнению, и ТЗ не позволяет выбрать между ними.

**Уже установлено.** Оценивается опыт экспорта одной открытой дорожки в локальный файл. T-4 распространяет свойство на каждого пользователя. Основания — [R-M0009-01](#r-m0009-01), [R-M0003-02](#r-m0003-02).

**Открытое решение.** Какой наблюдаемый критерий лёгкости применять к каждому пользователю в согласованном сценарии экспорта?

**Что различит проверка.** При успешном экспорте и сообщении пользователя о небольшом усилии T-4 пройден, если критерий допускает такое усилие. / При том же результате T-4 не пройден, если критерий требует, чтобы каждый пользователь сообщал об отсутствии усилий.

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** По какому наблюдаемому критерию, в каком сценарии и с каким охватом пользователей принимать T-4?

Внести ответ на этот вопрос в [R-M0009-01](#r-m0009-01) для сценария «Пользователь успешно экспортирует дорожку. Проверяющий оценивает выполнение T-4.».

**Черновик приёмочного теста.** Провести согласованный сценарий с заданным охватом пользователей и сравнить наблюдаемый результат с критерием успеха.

### Z-004 · Реплика из 81 кодовой точки

**Дефект · Противоречивость · Существенная.** Текст реплики из T-8 превышает предел T-7. Слова «In the acceptance sample» задают сценарий проверки, а приоритет над общим правилом в тексте не установлен.

Затронутые утверждения — [R-M0014-01](#r-m0014-01), [R-M0015-01](#r-m0015-01).

[R-M0014-01](#r-m0014-01) · Subtitle track export / Export limits · [строка 14](../../../../../benchmark/subtitles/requirements.md#L14)

> Reject a cue when its text exceeds 80 Unicode code points.  

[R-M0015-01](#r-m0015-01) · Subtitle track export / Export limits · [строка 15](../../../../../benchmark/subtitles/requirements.md#L15)

> In the acceptance sample, a cue of 81 Unicode code points is accepted.  

**Сценарий.** Выполнить приёмочный пример T-8 с репликой из 81 кодовой точки Unicode и сверить её принятие или отклонение с согласованным правилом.

**Последствие.** По T-7 реплика подлежит отклонению, а T-8 требует её принятия.

**Общее условие.** Проверяется реплика приёмочного примера T-8, текст которой содержит 81 кодовую точку Unicode. Основания — [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.», [R-M0015-01](#r-m0015-01) «In the acceptance sample, a cue of 81 Unicode code points is accepted.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Как согласовать T-7 и T-8: пример должен ожидать отклонения реплики из 81 кодовой точки Unicode или правило должно допускать её принятие в этом случае?

1. **Вариант 1.** Отклонять реплику, если её текст превышает 80 кодовых точек Unicode, включая приёмочный пример.

   **Основание.** [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.».

   **Ожидаемый результат.** Реплика из примера отклонена.

   При выборе этого варианта привести в соответствие [R-M0015-01](#r-m0015-01).

2. **Вариант 2.** В указанном приёмочном примере принимать реплику из 81 кодовой точки Unicode как явное исключение из общего предела.

   **Основание.** [R-M0015-01](#r-m0015-01) «In the acceptance sample, a cue of 81 Unicode code points is accepted.».

   **Ожидаемый результат.** Реплика из примера принята.

   При выборе этого варианта привести в соответствие [R-M0014-01](#r-m0014-01).

**Черновик приёмочного теста.** Выполнить приёмочный пример T-8 с репликой из 81 кодовой точки Unicode и сверить её принятие или отклонение с согласованным правилом.

<a id="decision"></a>

## Готовность и порядок исправлений

ТЗ не готово к разработке с однозначной приёмкой. Сначала нужно согласовать формат и временную шкалу, затем исправить пример на границе ограничения и определить критерий лёгкости экспорта.

1. Согласовать наличие BOM и соответствие числовых значений временной шкале. ([Z-001](#z-001), [Z-002](#z-002))
2. Согласовать предел длины реплики с исходом примера T-8. ([Z-004](#z-004))
3. Задать наблюдаемый критерий лёгкости экспорта и условия его проверки. ([Z-003](#z-003))
4. Исправить неработающую ссылку T-40. ([Z-005](#z-005))
