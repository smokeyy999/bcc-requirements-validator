## Проверка набора в целом

Правила расходятся по отправке черновика, допустимому числу строк и сроку хранения подтверждения. Для скорости показа «Передано» нужен измеримый предел. В S-6 требуется исправить ссылку S-97. Текст и состояние при отказе заданы в S-7.

Открытых предполагаемых пробелов — 0. Неоднозначностей — 0. Рекомендаций — 0.

Каждый ID утверждения учитывается один раз. В число нарушений входят подтверждённые дефекты и неоднозначности, для которых показаны две опирающиеся на текст трактовки с разными последствиями. Один и тот же конфликт имеет один ID при любом числе затронутых требований. Критичный дефект блокирует приёмку существенного обязательного сценария. Предполагаемый пробел оставляет открытым ожидаемое поведение или источник данных. Рекомендация предлагает улучшение. Вопросы и рекомендации имеют отдельные счётчики.

**Дефект · Противоречивость · Критичная.** S-1 разрешает отправку только из состояния «Готова», а S-2 обязывает передать ту же ведомость при попытке отправки из «Черновика». Без согласования правил этот сценарий отправки нельзя принять.

> S-2. При попытке отправить ведомость в состоянии «Черновик» терминал сразу передаёт её перевозчику.  

**Сценарий.** При исправных сети и авторизации оператор пытается отправить сохранённую ведомость в состоянии «Черновик».

**Последствие.** Нельзя определить, должна ли ведомость поступить перевозчику.

**Общее условие.** При исправных сети и авторизации оператор пытается отправить сохранённую ведомость в состоянии «Черновик». Основания — [R-M0006-01](#r-m0006-01) «S-1. **Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой исход требуется при попытке отправить черновик: передать его перевозчику или не передавать?

   **Ожидаемый результат.** Терминал не передаёт черновик перевозчику.

   При выборе этого варианта привести в соответствие [R-M0007-01](#r-m0007-01).

2. **Вариант 2.** При попытке отправить ведомость в состоянии «Черновик» терминал сразу передаёт её перевозчику.

   **Основание.** [R-M0007-01](#r-m0007-01) «S-2. При попытке отправить ведомость в состоянии «Черновик» терминал сразу передаёт её перевозчику.».

   **Ожидаемый результат.** Терминал сразу передаёт черновик перевозчику.

**Общее условие.** Загружена одна ведомость из 25 строк груза. Остальные условия отправки выполнены. Основания — [R-M0010-01](#r-m0010-01) «S-3. **Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

   **Основание.** [R-M0010-01](#r-m0010-01) «S-3. Одна ведомость содержит от 1 до 24 строк груза включительно.».

   **Ожидаемый результат.** Отправка ведомости из 25 строк не разрешена.

   При выборе этого варианта привести в соответствие [R-M0011-02](#r-m0011-02).

2. **Вариант 2.** При загрузке ведомости из 25 строк терминал принимает файл и разрешает отправку.

   **Основание.** [R-M0011-02](#r-m0011-02) «S-4. При загрузке ведомости из 25 строк терминал принимает файл и разрешает отправку.».

   **Ожидаемый результат.** Отправка ведомости из 25 строк разрешена.

**Общее условие.** Для одного и того же срока локального хранения подтверждения задано значение 7. ## Готовность и порядок исправлений

ТЗ не готово к разработке. Для отправки черновика и ведомости из 25 строк, а также для хранения подтверждения при значении 7 требуется согласовать ожидаемые результаты приёмки.

1. Согласовать исход попытки отправить черновик и допустимость отправки ведомости из 25 строк. ([Z-001](#z-001), [Z-002](#z-002))
2. Согласовать единицу срока хранения и длительность для значения 7. ([Z-003](#z-003))
3. Задать максимальное время от подтверждения перевозчика до показа «Передано». ([Z-005](#z-005))
4. Исправить внутреннюю ссылку S-97 в S-6. ([Z-006](#z-006))
