## Проверка набора в целом

Правила дают взаимоисключающие исходы для отправки черновика и готовой ведомости из 25 строк. Для локального хранения подтверждения расходятся две длительности при значении 7. У показа «Передано» отсутствует предел задержки. Ссылку S-97 нужно исправить редакторски, а текст отказа и состояние ведомости уже заданы в S-7.

Открытых предполагаемых пробелов — 0. Неоднозначностей — 0. Рекомендаций — 0.

Каждый ID утверждения учитывается один раз. В число нарушений входят подтверждённые дефекты и неоднозначности, для которых показаны две опирающиеся на текст трактовки с разными последствиями. Один и тот же конфликт имеет один ID при любом числе затронутых требований. Критичный дефект блокирует приёмку существенного обязательного сценария. Предполагаемый пробел оставляет открытым ожидаемое поведение или источник данных. Рекомендация предлагает улучшение. Вопросы и рекомендации имеют отдельные счётчики.

## Критичные дефекты

- [Z-001](#z-001) · S-1 допускает отправку только из состояния «Готова». S-2 требует передать ту же ведомость при попытке отправки из состояния «Черновик». Приёмка отправки не может определить, должен ли перевозчик получить черновик.
- [Z-002](#z-002) · S-3 ограничивает одну ведомость 24 строками. S-4 принимает ведомость из 25 строк и разрешает отправку. Даже в состоянии «Готова» для этой ведомости нельзя определить ожидаемое разрешение на отправку.

**Дефект · Противоречивость · Критичная.** S-1 допускает отправку только из состояния «Готова». S-2 требует передать ту же ведомость при попытке отправки из состояния «Черновик». Приёмка отправки не может определить, должен ли перевозчик получить черновик.

> При попытке отправить ведомость в состоянии «Черновик» терминал сразу передаёт её перевозчику.  

[R-M0007-02](#r-m0007-02) · Отправка грузовых ведомостей / Отправка · [строка 7](../../../../../benchmark/dispatch/requirements.md#L7)

> При попытке отправить ведомость в состоянии «Черновик» терминал сразу передаёт её перевозчику.  

**Сценарий.** Оператор пытается отправить ведомость из одной строки в состоянии «Черновик». Сеть и авторизация исправны.

**Последствие.** Приёмка не может определить, должен ли перевозчик получить ведомость.

**Общее условие.** Оператор пытается отправить сохранённую ведомость из одной строки в состоянии «Черновик» при исправных сети и авторизации. Основания — [R-M0006-01](#r-m0006-01) «Оператор может отправить ведомость только в состоянии «Готова».», [R-M0007-02](#r-m0007-02) «При попытке отправить ведомость в состоянии «Черновик» терминал сразу передаёт её перевозчику.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** При попытке отправки черновика запретить передачу или передать ведомость перевозчику?

1. **Вариант 1.** Разрешать отправку только в состоянии «Готова».

   **Основание.** [R-M0006-01](#r-m0006-01) «Оператор может отправить ведомость только в состоянии «Готова».».

   **Ожидаемый результат.** Терминал не передаёт черновик перевозчику.

   При выборе этого варианта привести в соответствие [R-M0007-02](#r-m0007-02).

2. **Вариант 2.** При попытке отправки в состоянии «Черновик» терминал сразу передаёт ведомость перевозчику.

   **Основание.** [R-M0007-02](#r-m0007-02) «При попытке отправить ведомость в состоянии «Черновик» терминал сразу передаёт её перевозчику.».

   **Ожидаемый результат.** Перевозчик получает черновик.

   При выборе этого варианта привести в соответствие [R-M0006-01](#r-m0006-01).

**Черновик приёмочного теста.** Попытаться отправить черновик и проверить на стороне перевозчика, поступила ли ведомость.

   **Ожидаемый результат.** Отправка ведомости из 25 строк разрешена.

### R-M0006-01 · Отправка допустима только из состояния «Готова».

> Оператор может отправить ведомость только в состоянии «Готова».  

**Связано с нарушением в спецификации.** S-1 допускает отправку только из состояния «Готова». S-2 требует передать ту же ведомость при попытке отправки из состояния «Черновик». Даже в состоянии «Готова» для этой ведомости нельзя определить ожидаемое разрешение на отправку.

## Готовность и порядок исправлений

ТЗ не готово к разработке и приёмке отправки до согласования правил для черновика и ведомости из 25 строк. Для полной приёмки также нужно согласовать срок хранения и предел задержки показа «Передано».

1. Согласовать исход попытки отправить черновик и допустимость отправки готовой ведомости из 25 строк. Привести соответствующие правила к этим решениям. ([Z-001](#z-001), [Z-002](#z-002))
2. Согласовать единицу срока локального хранения и значение длительности для настройки 7. ([Z-003](#z-003))
3. Задать предельный интервал от подтверждения перевозчика до появления «Передано». ([Z-005](#z-005))
4. Исправить ссылку S-97 в S-6. ([Z-006](#z-006))
