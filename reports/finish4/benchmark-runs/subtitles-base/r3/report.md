<a id="z-003"></a>

### Z-003 · Место объявления миллисекунд

**Неоднозначность · Однозначность · Существенная.** «Each timestamp field declares milliseconds» допускает объявление единицы в описании поля или в самом файле. Значение 1000 в обоих прочтениях обозначает одну секунду, но файл с одними числами проходит проверку объявления только при первом прочтении.

Затронутые утверждения — [R-M0008-01](#r-m0008-01), [R-M0008-02](#r-m0008-02).

[R-M0008-01](#r-m0008-01) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/baseline.md#L8)

> Each timestamp field declares milliseconds  

[R-M0008-02](#r-m0008-02) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/baseline.md#L8)

> Each timestamp field declares milliseconds; the numeric value 1000 represents one second.  

**Сценарий.** В файле записано число 1000 без обозначения единицы. Описание формата объявляет миллисекунды для каждого поля временной метки.

**Последствие.** Один проверяющий примет файл, другой потребует объявить единицу в самом файле.

**Уже установлено.** Миллисекунды объявляются для каждого поля временной метки. Число 1000 обозначает одну секунду. Основания — [R-M0008-01](#r-m0008-01), [R-M0008-02](#r-m0008-02), [R-M0006-01](#r-m0006-01), [R-M0007-02](#r-m0007-02).

**Открытое решение.** Достаточно ли объявления единицы в описании формата или оно обязательно в файле.

**Что различит проверка.** Файл с числовой меткой 1000 не проходит проверку объявления, если единица указана только в описании формата. / Тот же файл проходит проверку объявления единицы.

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Принять файл с числовыми метками, если миллисекунды объявлены для каждого поля только в описании формата, или требовать объявления в самом файле?

1. **Вариант 1.** Для каждого поля временной метки единица «миллисекунды» объявляется в экспортированном файле.

   **Основание.** [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds».

   **Ожидаемый результат.** Файл не проходит проверку объявления единицы.

2. **Вариант 2.** Для каждого поля временной метки единица «миллисекунды» объявляется в описании формата, а в файле достаточно числового значения.

   **Основание.** [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds».

   **Ожидаемый результат.** Файл проходит проверку объявления единицы.

**Черновик приёмочного теста.** Экспортировать метку в одну секунду, сверить значение 1000 и проверить объявление единицы в согласованном месте.

### Z-001 · По какому правилу в экспортированном файле связываются текст и временные метки каждой реплики?

**Предполагаемый пробел · Полнота · Существенная.** Экспорт одной дорожки в локальный файл задан. Кодировка и шкала времени определены, но по ним нельзя установить, как сопоставить текст и метки каждой реплики с исходной дорожкой.

Затронутые утверждения — [R-M0003-01](#r-m0003-01), [R-M0008-02](#r-m0008-02).

[R-M0003-01](#r-m0003-01) · Subtitle track export · [строка 3](../../../../../benchmark/subtitles/baseline.md#L3)

> A desktop subtitle editor exports one open track to a local file.  

[R-M0008-02](#r-m0008-02) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/baseline.md#L8)

> Each timestamp field declares milliseconds; the numeric value 1000 represents one second.  

**Сценарий.** Экспортировать две допустимые реплики с разными текстами и метками. Декодировать файл как UTF-8 и по согласованному правилу сверить текст и метки каждой реплики с исходной дорожкой.

**Последствие.** Экспорт одной дорожки в локальный файл задан. Кодировка и шкала времени определены, но по ним нельзя установить, как сопоставить текст и метки каждой реплики с исходной дорожкой.

**Уже установлено.** Результат экспорта — локальный файл в UTF-8 без BOM. Временные метки выражены в миллисекундах. Основания — [R-M0003-01](#r-m0003-01), [R-M0006-01](#r-m0006-01), [R-M0007-02](#r-m0007-02), [R-M0008-02](#r-m0008-02).

**Открытое решение.** Как в файле определить принадлежность текста и меток одной реплике.

**Что различит проверка.** Текст и метки каждой реплики находятся в одной записи. / Тексты и метки находятся в отдельных списках и сопоставляются по позиции.

<a id="z-002"></a>

### Z-002 · Каков ожидаемый результат команды экспорта дорожки с одной допустимой репликой после отклонения второй реплики длиной 81 кодовая точка Unicode?

**Предполагаемый пробел · Полнота · Существенная.** Правило и пример требуют отклонить реплику из 81 кодовой точки. Они не определяют, создаётся ли файл с допустимой репликой из той же дорожки.

Затронутые утверждения — [R-M0003-01](#r-m0003-01), [R-M0014-01](#r-m0014-01), [R-M0015-01](#r-m0015-01).

[R-M0003-01](#r-m0003-01) · Subtitle track export · [строка 3](../../../../../benchmark/subtitles/baseline.md#L3)

> A desktop subtitle editor exports one open track to a local file.  

[R-M0014-01](#r-m0014-01) · Subtitle track export / Export limits · [строка 14](../../../../../benchmark/subtitles/baseline.md#L14)

> Reject a cue when its text exceeds 80 Unicode code points.  

[R-M0015-01](#r-m0015-01) · Subtitle track export / Export limits · [строка 15](../../../../../benchmark/subtitles/baseline.md#L15)

> In the acceptance sample, a cue of 81 Unicode code points is rejected.  

**Сценарий.** Экспортировать дорожку с одной допустимой репликой и одной репликой длиной 81 кодовая точка Unicode в изначально отсутствующий файл. Проверить, создан ли файл. Если создан, проверить, что он содержит только допустимую реплику.

**Что нужно уточнить.** Должен ли экспорт в локальный файл завершиться, если одна реплика допустима, а вторая подлежит отклонению?

**Как ответ изменит приёмку.** Если экспорт продолжается, файл содержит допустимую реплику. Если экспорт отменяется, файл отсутствует. Реплика из 81 кодовой точки отклоняется в обоих случаях.

**Уже установлено.** Реплика из 81 кодовой точки подлежит отклонению. Правило сохранения назначения относится к пустой дорожке. Основания — [R-M0014-01](#r-m0014-01), [R-M0015-01](#r-m0015-01), [R-M0003-01](#r-m0003-01), [R-M0010-02](#r-m0010-02).

**Открытое решение.** Создавать ли файл с допустимой репликой после отклонения второй.

**Что различит проверка.** Создан файл, содержащий только допустимую реплику. / Файл отсутствует.

## Готовность и порядок исправлений

Проверки кодировки, отсутствия BOM, срока появления диалога и поведения на пустой дорожке можно подготовить. Приёмка содержимого файла и результата экспорта смешанной дорожки требует уточнений.

1. Описать, как сопоставить текст и временные метки каждой реплики в экспортированном файле. ([Z-001](#z-001))
2. Определить состояние файла после экспорта смешанной дорожки с отклонённой репликой. ([Z-002](#z-002))
3. Указать, где объявляются миллисекунды для каждого поля временной метки. ([Z-003](#z-003))
