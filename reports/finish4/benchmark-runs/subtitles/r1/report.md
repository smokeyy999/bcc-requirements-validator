## Проверка набора в целом

Формат экспортируемого файла, масштаб временных меток и исход примера с 81 кодовой точкой заданы противоречиво. Для лёгкости экспорта отсутствует критерий приёмки. Ссылка T-40 требует редакторской правки. Сообщение для пустой дорожки уже задано в T-6, а сохранение назначения без изменений — в T-5.

Открытых предполагаемых пробелов — 0. Неоднозначностей — 0. Рекомендаций — 0.

Каждый ID утверждения учитывается один раз. В число нарушений входят подтверждённые дефекты и неоднозначности, для которых показаны две опирающиеся на текст трактовки с разными последствиями. Один и тот же конфликт имеет один ID при любом числе затронутых требований. Критичный дефект блокирует приёмку существенного обязательного сценария. Предполагаемый пробел оставляет открытым ожидаемое поведение или источник данных. Рекомендация предлагает улучшение. Вопросы и рекомендации имеют отдельные счётчики.

### Z-001 · BOM в файле экспорта

**Дефект · Противоречивость · Критичная.** Для одного экспортированного файла T-1 запрещает BOM, а T-2 требует его в первых трёх байтах. Ни один файл не удовлетворит обоим условиям приёмки формата.

Затронутые утверждения — [R-M0006-01](#r-m0006-01), [R-M0007-01](#r-m0007-01).

[R-M0006-01](#r-m0006-01) · Subtitle track export / Format · [строка 6](../../../../../benchmark/subtitles/requirements.md#L6)

> Write the exported track in UTF-8 without a byte-order mark.  

[R-M0007-01](#r-m0007-01) · Subtitle track export / Format · [строка 7](../../../../../benchmark/subtitles/requirements.md#L7)

> The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.  

**Сценарий.** Экспортировать непустую дорожку с допустимой репликой и проверить начало файла.

**Последствие.** Файл без BOM провалит приёмочный тест, а файл с BOM нарушит требование к формату.

**Общее условие.** Проверяются первые три байта файла, записанного при экспорте дорожки. Основания — [R-M0006-01](#r-m0006-01) «Write the exported track in UTF-8 without a byte-order mark.», [R-M0007-01](#r-m0007-01) «The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой результат считать правильным при приёмке: BOM присутствует или отсутствует?

1. **Вариант 1.** Записывать файл в UTF-8 без BOM.

   **Основание.** [R-M0006-01](#r-m0006-01) «Write the exported track in UTF-8 without a byte-order mark.».

   **Ожидаемый результат.** В начале файла отсутствует BOM.

   При выборе этого варианта привести в соответствие [R-M0007-01](#r-m0007-01).

2. **Вариант 2.** Первые три байта файла должны быть UTF-8 BOM.

   **Основание.** [R-M0007-01](#r-m0007-01) «The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

   **Ожидаемый результат.** Первые три байта файла образуют UTF-8 BOM.

   При выборе этого варианта привести в соответствие [R-M0006-01](#r-m0006-01).

**Черновик приёмочного теста.** Экспортировать одну и ту же допустимую дорожку и проверить наличие BOM по первым трём байтам.

### Z-002 · Масштаб временной метки

**Дефект · Противоречивость · Критичная.** T-3 задаёт миллисекунды для каждого поля временной метки и одновременно сопоставляет 1000 одной минуте. Для одной минутной метки эти условия требуют разных чисел, поэтому представление времени нельзя принять.

Затронутые утверждения — [R-M0008-01](#r-m0008-01), [R-M0008-02](#r-m0008-02).

[R-M0008-01](#r-m0008-01) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> Each timestamp field declares milliseconds  

[R-M0008-02](#r-m0008-02) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> Each timestamp field declares milliseconds; the numeric value 1000 represents one minute.  

**Сценарий.** Экспортировать допустимую реплику со стартовой меткой ровно через одну минуту от начала дорожки.

**Последствие.** Приёмка не может одновременно подтвердить миллисекунды в поле и соответствие числа 1000 одной минуте.

**Общее условие.** В экспортируемом поле записывается временная метка в одну минуту. Объявленная единица распространяется на каждое поле. Основания — [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds», [R-M0008-02](#r-m0008-02) «the numeric value 1000 represents one minute.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какое число ожидается для отметки в одну минуту: 60000 или 1000?

1. **Вариант 1.** Числовое значение временной метки выражается в миллисекундах.

   **Основание.** [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds».

   **Ожидаемый результат.** В поле стартовой метки записано 60000.

   При выборе этого варианта привести в соответствие [R-M0008-02](#r-m0008-02).

2. **Вариант 2.** Числовое значение 1000 представляет одну минуту.

   **Основание.** [R-M0008-02](#r-m0008-02) «Each timestamp field declares milliseconds; the numeric value 1000 represents one minute.».

   **Ожидаемый результат.** В поле стартовой метки записано 1000.

   При выборе этого варианта привести в соответствие [R-M0008-01](#r-m0008-01).

**Черновик приёмочного теста.** Экспортировать реплику с отметкой в одну минуту и сверить число в поле и объявленную единицу с выбранным масштабом.

### Z-003 · Критерий простоты экспорта

**Дефект · Проверяемость · Существенная.** T-4 требует, чтобы экспорт ощущался лёгким для каждого пользователя, но не задаёт наблюдаемую меру и порог. Даже при успешном экспорте оценки пользователей не дают воспроизводимого результата проверки T-4.

Затронутые утверждения — [R-M0009-01](#r-m0009-01).

[R-M0009-01](#r-m0009-01) · Subtitle track export / Format · [строка 9](../../../../../benchmark/subtitles/requirements.md#L9)

> The export experience must feel effortless to every user.  

**Сценарий.** Пользователи успешно экспортируют одну и ту же дорожку и дают разные оценки затраченных усилий.

**Последствие.** Проверяющий не может вынести воспроизводимое решение о выполнении требования.

**Уже установлено.** Проверяемая операция — экспорт одной открытой дорожки в локальный файл. T-4 распространяет требование к воспринимаемой лёгкости на каждого пользователя. Основания — [R-M0009-01](#r-m0009-01), [R-M0003-01](#r-m0003-01).

**Открытое решение.** По какому наблюдаемому критерию считать экспорт лёгким для каждого пользователя?

**Что различит проверка.** Если все участники оценили лёгкость экспорта на 4 из 5, при пороге 4 для каждого T-4 выполнено. / При тех же оценках и пороге 5 для каждого T-4 не выполнено.

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой наблюдаемый результат и порядок проверки подтвердят, что экспорт дался пользователям без усилий?

Внести ответ на этот вопрос в [R-M0009-01](#r-m0009-01) для сценария «Пользователи успешно экспортируют одну и ту же дорожку и дают разные оценки затраченных усилий.».

**Черновик приёмочного теста.** Провести экспорт по согласованному сценарию и оценить наблюдаемый результат по заданному критерию.

### Z-004 · Приёмка реплики из 81 кодовой точки

**Дефект · Противоречивость · Существенная.** 81 кодовая точка превышает предел T-7, поэтому реплика из T-8 подлежит отклонению. T-8 ожидает её принятия, а T-7 не предусматривает исключения для приёмочного примера.

Затронутые утверждения — [R-M0014-01](#r-m0014-01), [R-M0015-01](#r-m0015-01).

[R-M0014-01](#r-m0014-01) · Subtitle track export / Export limits · [строка 14](../../../../../benchmark/subtitles/requirements.md#L14)

> Reject a cue when its text exceeds 80 Unicode code points.  

[R-M0015-01](#r-m0015-01) · Subtitle track export / Export limits · [строка 15](../../../../../benchmark/subtitles/requirements.md#L15)

> In the acceptance sample, a cue of 81 Unicode code points is accepted.  

**Сценарий.** Запустить приёмочный пример с указанной в нём репликой из 81 кодовой точки Unicode.

**Последствие.** Отклонение реплики провалит приёмочный пример, а принятие нарушит общее правило.

**Общее условие.** Проверяется реплика из приёмочного примера, текст которой содержит 81 кодовую точку Unicode. Основания — [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.», [R-M0015-01](#r-m0015-01) «In the acceptance sample, a cue of 81 Unicode code points is accepted.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой исход должен подтвердить приёмочный пример: отклонение или принятие реплики?

1. **Вариант 1.** Отклонять реплики длиннее 80 кодовых точек Unicode, включая реплику из приёмочного примера.

   **Основание.** [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.».

   **Ожидаемый результат.** Реплика из 81 кодовой точки отклонена.

   При выборе этого варианта привести в соответствие [R-M0015-01](#r-m0015-01).

2. **Вариант 2.** Принять реплику из 81 кодовой точки в указанном приёмочном примере.

   **Основание.** [R-M0015-01](#r-m0015-01) «In the acceptance sample, a cue of 81 Unicode code points is accepted.».

   **Ожидаемый результат.** Реплика из 81 кодовой точки принята.

   При выборе этого варианта привести в соответствие [R-M0014-01](#r-m0014-01).

**Черновик приёмочного теста.** Выполнить указанный приёмочный пример и проверить исход для реплики из 81 кодовой точки.

<a id="decision"></a>

## Готовность и порядок исправлений

ТЗ не готово к разработке и приёмке экспорта. Сначала нужно согласовать формат файла, масштаб временных меток и исход приёмочного примера с длинной репликой.

1. Согласовать наличие BOM в файле и привести объявленную единицу временных меток в соответствие с числом для одной минуты. ([Z-001](#z-001), [Z-002](#z-002))
2. Согласовать правило длины и ожидаемый исход приёмочного примера для реплики из 81 кодовой точки Unicode. ([Z-004](#z-004))
3. Задать наблюдаемую меру и порог лёгкости экспорта для каждого пользователя. ([Z-003](#z-003))
4. Исправить внутреннюю ссылку на отсутствующий пункт T-40. ([Z-005](#z-005))
