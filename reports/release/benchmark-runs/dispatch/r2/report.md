## Проверка набора в целом

Правила отправки дают разные исходы для черновика и для готовой ведомости из 25 строк. Для хранения подтверждения при значении 7 заданы два срока. Отображение слова «Передано» проверяемо, для его задержки нужен предел. Ссылка S-97 требует редакторской правки, текст при отказе уже задан в S-7.

Открытых предполагаемых пробелов — 1. Неоднозначностей — 0. Рекомендаций — 0.

Каждый ID утверждения учитывается один раз. В число нарушений входят подтверждённые дефекты и неоднозначности, для которых показаны две опирающиеся на текст трактовки с разными последствиями. Один и тот же конфликт имеет один ID при любом числе затронутых требований. Критичный дефект блокирует приёмку существенного обязательного сценария. Предполагаемый пробел оставляет открытым ожидаемое поведение или источник данных. Рекомендация предлагает улучшение. Вопросы и рекомендации имеют отдельные счётчики.

> S-2. При попытке отправить ведомость в состоянии «Черновик» терминал сразу передаёт её перевозчику.

**Последствие.** Одна реализация передаст черновик перевозчику, другая заблокирует передачу.

**Общее условие.** Оператор пытается отправить сохранённую ведомость в состоянии «Черновик». Сеть и авторизация исправны. **Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

   **Ожидаемый результат.** По этой попытке терминал не передаёт ведомость перевозчику.

   При выборе этого варианта привести в соответствие [R-M0007-02](#r-m0007-02).

2. **Вариант 2.** При попытке отправить ведомость в состоянии «Черновик» терминал сразу передаёт её перевозчику.

   **Основание.** [R-M0007-02](#r-m0007-02) «S-2. При попытке отправить ведомость в состоянии «Черновик» терминал сразу передаёт её перевозчику.».

**Последствие.** Для одной и той же готовой ведомости приёмка получит противоположные результаты проверки допуска.

**Общее условие.** Оператор загружает ведомость с 25 строками груза и проверяет допуск к отправке при выполненном условии «Готова». Основания — [R-M0010-01](#r-m0010-01) «Одна ведомость содержит от 1 до 24 строк груза включительно.», [R-M0011-01](#r-m0011-01) «При загрузке ведомости из 25 строк терминал принимает файл и разрешает отправку.», [R-M0006-01](#r-m0006-01) «Оператор может отправить ведомость только в состоянии «Готова».».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

   **Основание.** [R-M0010-01](#r-m0010-01) «S-3. Одна ведомость содержит от 1 до 24 строк груза включительно.».

   При выборе этого варианта привести в соответствие [R-M0011-01](#r-m0011-01).

2. **Вариант 2.** При загрузке ведомости из 25 строк терминал принимает файл и допускает ведомость к отправке при соблюдении условия «Готова».

   **Основание.** [R-M0011-01](#r-m0011-01) «S-4. При загрузке ведомости из 25 строк терминал принимает файл и разрешает отправку.».

   **Ожидаемый результат.** Ведомость из 25 строк допускается к отправке.

   При выборе этого варианта привести в соответствие [R-M0010-01](#r-m0010-01).

## Готовность и порядок исправлений

ТЗ не готово к разработке и приёмке сценариев отправки черновика, допуска ведомости из 25 строк и хранения подтверждения при значении 7. Для проверки своевременности отображения нужен измеримый предел.

1. Согласовать исход попытки отправки черновика и допуск готовой ведомости из 25 строк. ([Z-001](#z-001), [Z-002](#z-002))
2. Согласовать единицу срока хранения и расшифровку значения 7. ([Z-005](#z-005))
3. Задать максимальную задержку между подтверждением перевозчика и появлением слова «Передано». ([Z-004](#z-004))
4. Исправить внутреннюю ссылку S-97. ([Z-006](#z-006))
