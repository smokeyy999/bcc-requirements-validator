## Проверка набора в целом

Требования расходятся по BOM, масштабу временных меток и исходу примера с 81 кодовой точкой. Лёгкость экспорта не имеет критерия приёмки. Текст сообщения для пустой дорожки определён в T-6, ссылка из T-5 ошибочна.

Открытых предполагаемых пробелов — 0. Неоднозначностей — 0. Рекомендаций — 0.

Каждый ID утверждения учитывается один раз. В число нарушений входят подтверждённые дефекты и неоднозначности, для которых показаны две опирающиеся на текст трактовки с разными последствиями. Один и тот же конфликт имеет один ID при любом числе затронутых требований. Критичный дефект блокирует приёмку существенного обязательного сценария. Предполагаемый пробел оставляет открытым ожидаемое поведение или источник данных. Рекомендация предлагает улучшение. Вопросы и рекомендации имеют отдельные счётчики.

### Z-001 · BOM при экспорте

**Дефект · Противоречивость · Критичная.** T-1 запрещает BOM в экспортированном файле, а T-2 требует его в первых трёх байтах того же файла. Приёмка результата экспорта по обоим правилам невозможна.

Затронутые утверждения — [R-M0006-02](#r-m0006-02), [R-M0007-01](#r-m0007-01).

[R-M0006-02](#r-m0006-02) · Subtitle track export / Format · [строка 6](../../../../../benchmark/subtitles/requirements.md#L6)

> Write the exported track in UTF-8 without a byte-order mark.  

[R-M0007-01](#r-m0007-01) · Subtitle track export / Format · [строка 7](../../../../../benchmark/subtitles/requirements.md#L7)

> The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.  

**Сценарий.** Экспортировать непустую дорожку с допустимой репликой в локальный файл.

**Последствие.** Проверка начала файла даёт противоположные результаты приёмки.

**Общее условие.** Проверяются первые три байта UTF-8-файла, полученного при экспорте дорожки. Основания — [R-M0006-02](#r-m0006-02) «Write the exported track in UTF-8 without a byte-order mark.», [R-M0007-01](#r-m0007-01) «The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой результат ожидается при приёмке — отсутствие или наличие UTF-8 BOM?

1. **Вариант 1.** Записывать дорожку в UTF-8 без BOM.

   **Основание.** [R-M0006-02](#r-m0006-02) «Write the exported track in UTF-8 without a byte-order mark.».

   **Ожидаемый результат.** В начале файла нет UTF-8 BOM.

   При выборе этого варианта привести в соответствие [R-M0007-01](#r-m0007-01).

2. **Вариант 2.** Записывать UTF-8 BOM в первых трёх байтах файла.

   **Основание.** [R-M0007-01](#r-m0007-01) «The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

   **Ожидаемый результат.** Первые три байта файла — EF BB BF.

   При выборе этого варианта привести в соответствие [R-M0006-02](#r-m0006-02).

**Черновик приёмочного теста.** Выполнить экспорт и проверить первые три байта файла по выбранному правилу.

### Z-002 · Масштаб временных меток

**Дефект · Противоречивость · Критичная.** T-3 объявляет миллисекунды для каждого поля временной метки и задаёт минуту для значения 1000. Масштаб временных меток нельзя принять по обеим частям T-3.

Затронутые утверждения — [R-M0008-01](#r-m0008-01), [R-M0008-02](#r-m0008-02).

[R-M0008-01](#r-m0008-01) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> Each timestamp field declares milliseconds  

[R-M0008-02](#r-m0008-02) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> the numeric value 1000 represents one minute.  

**Сценарий.** Проверить значение 1000 в экспортированном поле временной метки.

**Последствие.** Одна и та же метка соответствует либо одной секунде, либо одной минуте.

**Общее условие.** В экспортированном поле временной метки со шкалой в миллисекундах записано число 1000. Основания — [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds», [R-M0008-02](#r-m0008-02) «the numeric value 1000 represents one minute.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какое время должно обозначать значение 1000 — одну секунду или одну минуту?

1. **Вариант 1.** Числовые значения временных меток выражаются в миллисекундах.

   **Основание.** [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds».

   **Ожидаемый результат.** Значение 1000 соответствует одной секунде.

   При выборе этого варианта привести в соответствие [R-M0008-02](#r-m0008-02).

2. **Вариант 2.** Значение 1000 в поле временной метки обозначает одну минуту. Объявленная единица должна соответствовать этому масштабу.

   **Основание.** [R-M0008-02](#r-m0008-02) «the numeric value 1000 represents one minute.».

   **Ожидаемый результат.** Значение 1000 соответствует одной минуте.

   При выборе этого варианта привести в соответствие [R-M0008-01](#r-m0008-01).

**Черновик приёмочного теста.** Сверить объявленную единицу и время, соответствующее значению 1000 в экспортированном поле.

### Z-003 · Критерий лёгкости экспорта

**Дефект · Проверяемость · Существенная.** T-4 требует, чтобы экспорт воспринимался как лёгкий каждым пользователем. Критерий успешного выполнения этого свойства отсутствует. Запись файла можно проверить отдельно.

Затронутые утверждения — [R-M0009-01](#r-m0009-01).

[R-M0009-01](#r-m0009-01) · Subtitle track export / Format · [строка 9](../../../../../benchmark/subtitles/requirements.md#L9)

> The export experience must feel effortless to every user.  

**Сценарий.** Пользователи экспортируют дорожку и по-разному оценивают лёгкость операции.

**Последствие.** По результатам испытания невозможно вынести однозначное решение о выполнении T-4.

**Уже установлено.** T-4 задаёт оценку лёгкости экспорта для каждого пользователя. Операция экспортирует одну открытую дорожку в локальный файл. Основания — [R-M0009-01](#r-m0009-01), [R-M0003-02](#r-m0003-02).

**Открытое решение.** Какой наблюдаемый критерий применить к каждому участнику приёмочной проверки T-4?

**Что различит проверка.** Если каждый участник оценил лёгкость экспорта на 4 из 5 и достаточно оценки 4, T-4 проходит проверку. / При тех же оценках и обязательной оценке 5 от каждого участника T-4 проваливает проверку.

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** По какому наблюдаемому критерию и на какой группе пользователей принимать T-4?

Внести ответ на этот вопрос в [R-M0009-01](#r-m0009-01) для сценария «Пользователи экспортируют дорожку и по-разному оценивают лёгкость операции.».

**Черновик приёмочного теста.** Провести экспорт с согласованной группой и оценить результат по заданному критерию.

<a id="z-004"></a>

### Z-004 · Реплика из 81 кодовой точки

**Дефект · Противоречивость · Существенная.** T-7 требует отклонить реплику длиной 81 кодовая точка Unicode, а T-8 принимает такую реплику. Исключение для примера не задано. Конфликт блокирует приёмку данного примера.

Затронутые утверждения — [R-M0014-01](#r-m0014-01), [R-M0015-01](#r-m0015-01).

[R-M0014-01](#r-m0014-01) · Subtitle track export / Export limits · [строка 14](../../../../../benchmark/subtitles/requirements.md#L14)

> Reject a cue when its text exceeds 80 Unicode code points.  

[R-M0015-01](#r-m0015-01) · Subtitle track export / Export limits · [строка 15](../../../../../benchmark/subtitles/requirements.md#L15)

> In the acceptance sample, a cue of 81 Unicode code points is accepted.  

**Сценарий.** Проверить реплику из примера T-8 с текстом длиной 81 кодовая точка Unicode.

**Последствие.** Приёмочный пример требует принять реплику, которую общее правило требует отклонить.

**Общее условие.** Проверяется реплика из приёмочного примера T-8, текст которой содержит 81 кодовую точку Unicode. Основания — [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.», [R-M0015-01](#r-m0015-01) «In the acceptance sample, a cue of 81 Unicode code points is accepted.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой результат должен ожидать тест T-8 — принятие или отклонение реплики?

1. **Вариант 1.** Отклонять любую реплику с текстом длиннее 80 кодовых точек Unicode.

   **Основание.** [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.».

   **Ожидаемый результат.** Реплика из примера отклонена.

   При выборе этого варианта привести в соответствие [R-M0015-01](#r-m0015-01).

2. **Вариант 2.** Принимать реплику из приёмочного примера с текстом длиной 81 кодовая точка Unicode.

   **Основание.** [R-M0015-01](#r-m0015-01) «In the acceptance sample, a cue of 81 Unicode code points is accepted.».

   **Ожидаемый результат.** Реплика из примера принята.

   При выборе этого варианта привести в соответствие [R-M0014-01](#r-m0014-01).

**Черновик приёмочного теста.** Передать на экспорт реплику из T-8 длиной 81 кодовая точка Unicode и проверить выбранный исход.

**Сценарий.** Попытаться экспортировать пустую дорожку и сверить сообщение со строкой «Add at least one cue».

**Последствие.** По ссылке из требования об экспорте пустой дорожки нельзя найти ожидаемое сообщение.

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

## Готовность и порядок исправлений

ТЗ не готово к передаче в разработку. Сначала нужно согласовать формат файла, масштаб временных меток и исход приёмочного примера.

1. Согласовать правило о BOM с приёмочным тестом и привести объявленную единицу временных меток в соответствие со значением 1000. ([Z-001](#z-001), [Z-002](#z-002))
2. Согласовать ограничение длины реплики с ожидаемым исходом примера T-8. ([Z-004](#z-004))
3. Задать наблюдаемый критерий лёгкости экспорта для каждого участника приёмочной проверки. ([Z-003](#z-003))
4. Исправить ссылку в T-5 на T-6. ([Z-005](#z-005))
