## Проверка набора в целом

ТЗ задаёт несовместимые условия для BOM, метки со значением 1000 и реплики из 81 кодовой точки в приёмочном примере. Для удобства экспорта отсутствует измеримый критерий. Ссылка на сообщение для пустой дорожки ведёт на отсутствующее требование.

Открытых предполагаемых пробелов — 0. Неоднозначностей — 0. Рекомендаций — 0.

Каждый ID утверждения учитывается один раз. В число нарушений входят подтверждённые дефекты и неоднозначности, для которых показаны две опирающиеся на текст трактовки с разными последствиями. Один и тот же конфликт имеет один ID при любом числе затронутых требований. Критичный дефект блокирует приёмку существенного обязательного сценария. Предполагаемый пробел оставляет открытым ожидаемое поведение или источник данных. Рекомендация предлагает улучшение. Вопросы и рекомендации имеют отдельные счётчики.

### Z-001 · BOM в начале файла

**Дефект · Противоречивость · Критичная.** Для одного экспортированного файла T-1 запрещает BOM, а T-2 требует его в первых трёх байтах. По этим правилам принять формат файла невозможно.

Затронутые утверждения — [R-M0006-02](#r-m0006-02), [R-M0007-01](#r-m0007-01).

[R-M0006-02](#r-m0006-02) · Subtitle track export / Format · [строка 6](../../../../../benchmark/subtitles/requirements.md#L6)

> Write the exported track in UTF-8 without a byte-order mark.  

[R-M0007-01](#r-m0007-01) · Subtitle track export / Format · [строка 7](../../../../../benchmark/subtitles/requirements.md#L7)

> The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.  

**Сценарий.** Экспортировать непустую дорожку с одной репликой «Привет» в локальный файл.

**Последствие.** Для одного файла одновременно требуются отсутствие и наличие BOM в начале.

**Общее условие.** Приёмка проверяет первые три байта файла, полученного экспортом дорожки в UTF-8. Основания — [R-M0006-02](#r-m0006-02) «Write the exported track in UTF-8 without a byte-order mark.», [R-M0007-01](#r-m0007-01) «The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой файл должен пройти приёмку, с BOM или без BOM?

1. **Вариант 1.** Записывать файл в UTF-8 без BOM.

   **Основание.** [R-M0006-02](#r-m0006-02) «Write the exported track in UTF-8 without a byte-order mark.».

   **Ожидаемый результат.** Первые три байта не равны EF BB BF.

   При выборе этого варианта привести в соответствие [R-M0007-01](#r-m0007-01).

2. **Вариант 2.** Для приёмки файл UTF-8 должен начинаться с BOM.

   **Основание.** [R-M0007-01](#r-m0007-01) «The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

   **Ожидаемый результат.** Первые три байта равны EF BB BF.

   При выборе этого варианта привести в соответствие [R-M0006-02](#r-m0006-02).

**Черновик приёмочного теста.** Выполнить экспорт и сравнить первые три байта с EF BB BF по выбранному правилу.

### Z-002 · Шкала временных меток

**Дефект · Противоречивость · Критичная.** T-3 объявляет для временной метки миллисекунды и одновременно приравнивает 1000 к минуте. Для этого значения невозможно принять корректность экспортированного времени.

Затронутые утверждения — [R-M0008-01](#r-m0008-01), [R-M0008-02](#r-m0008-02).

[R-M0008-01](#r-m0008-01) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> Each timestamp field declares milliseconds  

[R-M0008-02](#r-m0008-02) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> the numeric value 1000 represents one minute.  

**Сценарий.** Прочитать поле временной метки со значением 1000 в экспортированном файле.

**Последствие.** Одна и та же метка означает одну секунду по объявленной единице или одну минуту по явному соответствию.

**Общее условие.** Одно поле экспортированной временной метки объявляет миллисекунды и содержит значение 1000. Основания — [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds», [R-M0008-02](#r-m0008-02) «the numeric value 1000 represents one minute.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какое время должно обозначать значение 1000, одну секунду или одну минуту?

1. **Вариант 1.** Числовое значение каждого поля временной метки выражено в миллисекундах.

   **Основание.** [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds».

   **Ожидаемый результат.** Значение 1000 соответствует одной секунде.

   При выборе этого варианта привести в соответствие [R-M0008-02](#r-m0008-02).

2. **Вариант 2.** Числовое значение 1000 в поле временной метки соответствует одной минуте.

   **Основание.** [R-M0008-02](#r-m0008-02) «the numeric value 1000 represents one minute.».

   **Ожидаемый результат.** Значение 1000 соответствует одной минуте.

   При выборе этого варианта привести в соответствие [R-M0008-01](#r-m0008-01).

**Черновик приёмочного теста.** Проверить, какому времени соответствует значение 1000 в экспортированной метке, по согласованной шкале.

### Z-003 · Критерий удобства экспорта

**Дефект · Проверяемость · Существенная.** T-4 обещает каждому пользователю экспорт без ощутимых усилий. ТЗ не задаёт способ измерения и критерий успеха для этого свойства.

Затронутые утверждения — [R-M0009-01](#r-m0009-01).

[R-M0009-01](#r-m0009-01) · Subtitle track export / Format · [строка 9](../../../../../benchmark/subtitles/requirements.md#L9)

> The export experience must feel effortless to every user.  

**Сценарий.** Пользователь успешно экспортирует дорожку и сообщает, что экспорт потребовал усилий.

**Последствие.** По ТЗ нельзя вынести воспроизводимый вердикт о выполнении T-4.

**Уже установлено.** Свойство относится к опыту экспорта каждого пользователя. Основания — [R-M0009-01](#r-m0009-01).

**Открытое решение.** Какой наблюдаемый критерий определяет выполнение T-4?

**Что различит проверка.** В проверке успешного экспорта наблюдаемый результат удовлетворяет критерию T-4. / В той же проверке наблюдаемый результат не удовлетворяет критерию T-4.

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** По какому наблюдаемому критерию и каким способом проверять выполнение T-4?

Внести ответ на этот вопрос в [R-M0009-01](#r-m0009-01) для сценария «Пользователь успешно экспортирует дорожку и сообщает, что экспорт потребовал усилий.».

**Черновик приёмочного теста.** Провести экспорт в условиях согласованной проверки и сравнить наблюдаемый результат с критерием.

### Z-004 · Реплика из 81 кодовой точки

**Дефект · Противоречивость · Существенная.** Текст реплики из приёмочного примера превышает порог T-7. Для этой реплики T-7 требует отклонения, а T-8 фиксирует принятие. Ожидаемый исход примера требует согласования.

Затронутые утверждения — [R-M0014-01](#r-m0014-01), [R-M0015-01](#r-m0015-01).

[R-M0014-01](#r-m0014-01) · Subtitle track export / Export limits · [строка 14](../../../../../benchmark/subtitles/requirements.md#L14)

> Reject a cue when its text exceeds 80 Unicode code points.  

[R-M0015-01](#r-m0015-01) · Subtitle track export / Export limits · [строка 15](../../../../../benchmark/subtitles/requirements.md#L15)

> In the acceptance sample, a cue of 81 Unicode code points is accepted.  

**Сценарий.** Выполнить приёмочный пример с репликой, текст которой содержит 81 кодовую точку Unicode.

**Последствие.** Один и тот же пример требует принять и отклонить реплику.

**Общее условие.** В приёмочном примере текст реплики содержит 81 кодовую точку Unicode. Основания — [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.», [R-M0015-01](#r-m0015-01) «In the acceptance sample, a cue of 81 Unicode code points is accepted.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой исход требуется в приёмочном примере, принять реплику из 81 кодовой точки или отклонить её?

1. **Вариант 1.** Отклонять реплику, если её текст содержит более 80 кодовых точек Unicode.

   **Основание.** [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.».

   **Ожидаемый результат.** Реплика из приёмочного примера отклонена.

   При выборе этого варианта привести в соответствие [R-M0015-01](#r-m0015-01).

2. **Вариант 2.** В приёмочном примере принимать реплику из 81 кодовой точки Unicode.

   **Основание.** [R-M0015-01](#r-m0015-01) «In the acceptance sample, a cue of 81 Unicode code points is accepted.».

   **Ожидаемый результат.** Реплика из приёмочного примера принята.

   При выборе этого варианта привести в соответствие [R-M0014-01](#r-m0014-01).

**Черновик приёмочного теста.** Выполнить приёмочный пример и сверить исход для реплики с выбранным правилом.

## Готовность и порядок исправлений

ТЗ не готово к разработке и однозначной приёмке. Сначала нужно согласовать формат файла, шкалу меток и исход приёмочного примера.

1. Согласовать наличие BOM и шкалу временных меток. ([Z-001](#z-001), [Z-002](#z-002))
2. Согласовать порог длины с ожидаемым исходом приёмочного примера. ([Z-004](#z-004))
3. Установить измеримый критерий удобства экспорта и способ проверки. ([Z-003](#z-003))
4. Заменить в T-5 ссылку на T-40 ссылкой на T-6. ([Z-005](#z-005))
