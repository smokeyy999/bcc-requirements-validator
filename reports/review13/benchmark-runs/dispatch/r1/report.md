Один и тот же конфликт имеет один ID при любом числе затронутых требований. Критичный дефект блокирует приёмку существенного обязательного сценария. ### Z-001 · Отправка черновика

**Дефект · Противоречивость · Критичная.** S-1 исключает отправку черновика, а S-2 требует передать его перевозчику при той же попытке. Пока правила расходятся, нельзя принять проверку отправки по состоянию ведомости.

Затронутые утверждения — [R-M0006-01](#r-m0006-01), [R-M0007-01](#r-m0007-01).

> Оператор может отправить ведомость только в состоянии «Готова».  

[R-M0007-01](#r-m0007-01) · Отправка грузовых ведомостей / Отправка · [строка 7](../../../../../benchmark/dispatch/requirements.md#L7)

> При попытке отправить ведомость в состоянии «Черновик» терминал сразу передаёт её перевозчику.  

**Сценарий.** При исправных сети и авторизации оператор пытается отправить сохранённую ведомость из одной строки груза в состоянии «Черновик».

**Последствие.** Нельзя согласовать, должен ли перевозчик получить ведомость после этой попытки.

**Общее условие.** При исправных сети и авторизации оператор пытается отправить сохранённую ведомость в состоянии «Черновик». Основания — [R-M0006-01](#r-m0006-01) «Оператор может отправить ведомость только в состоянии «Готова».», [R-M0007-01](#r-m0007-01) «При попытке отправить ведомость в состоянии «Черновик» терминал сразу передаёт её перевозчику.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** При попытке отправить черновик терминал блокирует передачу или передаёт ведомость перевозчику?

1. **Вариант 1.** Отправка разрешена только в состоянии «Готова».

   **Основание.** [R-M0006-01](#r-m0006-01) «Оператор может отправить ведомость только в состоянии «Готова».».

   **Ожидаемый результат.** Перевозчик не получает ведомость после попытки отправить черновик.

   При выборе этого варианта привести в соответствие [R-M0007-01](#r-m0007-01).

2. **Вариант 2.** При попытке отправить ведомость в состоянии «Черновик» терминал сразу передаёт её перевозчику.

   **Основание.** [R-M0007-01](#r-m0007-01) «При попытке отправить ведомость в состоянии «Черновик» терминал сразу передаёт её перевозчику.».

   **Ожидаемый результат.** Перевозчик получает черновик после попытки отправки.

   При выборе этого варианта привести в соответствие [R-M0006-01](#r-m0006-01).

**Черновик приёмочного теста.** Попытаться отправить черновик и проверить факт передачи перевозчику по выбранному правилу.

## Готовность и порядок исправлений

ТЗ пока не готово к разработке и приёмке. Сначала нужно согласовать отправку черновика и верхнюю границу числа строк, затем определить срок хранения для значения 7 и критерий задержки показа «Передано».

1. Согласовать факт передачи при попытке отправить черновик и доступность отправки готовой ведомости из 25 строк груза. ([Z-001](#z-001), [Z-003](#z-003))
2. Согласовать единицу настройки и длительность локального хранения при значении 7. ([Z-005](#z-005))
3. Задать наблюдаемое событие начала замера и предельное время до показа «Передано». ([Z-004](#z-004))
4. Исправить ссылку S-97 в S-6 по действительному адресу правила. ([Z-006](#z-006))
