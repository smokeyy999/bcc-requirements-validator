## Проверка набора в целом

Формат файла, шкала временных меток и исход приёмочного примера с репликой из 81 кодовой точки требуют согласования. Для лёгкости экспорта нужен воспроизводимый критерий. В T-5 требуется редакторская правка ссылки T-40. Сообщение для пустой дорожки уже задано в T-6.

Открытых предполагаемых пробелов — 0. Неоднозначностей — 0. Рекомендаций — 0.

Каждый ID утверждения учитывается один раз. В число нарушений входят подтверждённые дефекты и неоднозначности, для которых показаны две опирающиеся на текст трактовки с разными последствиями. Один и тот же конфликт имеет один ID при любом числе затронутых требований. Критичный дефект блокирует приёмку существенного обязательного сценария. Предполагаемый пробел оставляет открытым ожидаемое поведение или источник данных. Рекомендация предлагает улучшение. Вопросы и рекомендации имеют отдельные счётчики.

### Z-001 · BOM в файле экспорта

**Дефект · Противоречивость · Критичная.** T-1 требует записать экспортированный файл без BOM, а T-2 требует BOM в начале того же файла. Формат файла невозможно принять по обоим правилам.

Затронутые утверждения — [R-M0006-01](#r-m0006-01), [R-M0007-01](#r-m0007-01).

[R-M0006-01](#r-m0006-01) · Subtitle track export / Format · [строка 6](../../../../../benchmark/subtitles/requirements.md#L6)

> Write the exported track in UTF-8 without a byte-order mark.  

[R-M0007-01](#r-m0007-01) · Subtitle track export / Format · [строка 7](../../../../../benchmark/subtitles/requirements.md#L7)

> The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.  

**Сценарий.** Экспортировать непустую дорожку с допустимой репликой и проверить начало созданного файла.

**Последствие.** Ни один результат этого экспорта не удовлетворит одновременно формату и приёмочному тесту.

**Общее условие.** Проверяются первые три байта файла, созданного при экспорте дорожки. Основания — [R-M0006-01](#r-m0006-01) «Write the exported track in UTF-8 without a byte-order mark.», [R-M0007-01](#r-m0007-01) «The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой результат должна требовать приёмка для одного и того же файла экспорта: отсутствие BOM или BOM в первых трёх байтах?

1. **Вариант 1.** Записывать файл в UTF-8 без BOM и проверять его отсутствие.

   **Основание.** [R-M0006-01](#r-m0006-01) «Write the exported track in UTF-8 without a byte-order mark.».

   **Ожидаемый результат.** В начале файла нет BOM.

   При выборе этого варианта привести в соответствие [R-M0007-01](#r-m0007-01).

2. **Вариант 2.** Записывать файл в UTF-8 с BOM в первых трёх байтах и проверять его наличие.

   **Основание.** [R-M0007-01](#r-m0007-01) «The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

   **Ожидаемый результат.** Первые три байта файла равны EF BB BF.

   При выборе этого варианта привести в соответствие [R-M0006-01](#r-m0006-01).

**Черновик приёмочного теста.** Прочитать первые три байта файла после экспорта и сравнить их с EF BB BF по выбранному правилу.

### Z-002 · Шкала временной метки

**Дефект · Противоречивость · Критичная.** T-3 объявляет миллисекунды для каждого поля временной метки и приписывает значению 1000 одну минуту. В объявленной единице 1000 означает одну секунду. Приёмка временной разметки требует единой шкалы.

Затронутые утверждения — [R-M0008-01](#r-m0008-01), [R-M0008-02](#r-m0008-02).

[R-M0008-01](#r-m0008-01) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> Each timestamp field declares milliseconds; the numeric value 1000 represents one minute.  

[R-M0008-02](#r-m0008-02) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> Each timestamp field declares milliseconds; the numeric value 1000 represents one minute.  

**Сценарий.** В экспортированном поле временной метки указаны миллисекунды и записано значение 1000.

**Последствие.** Одна и та же метка читается как одна секунда или одна минута от начала отсчёта.

**Общее условие.** В одном поле временной метки с объявленной единицей «миллисекунды» записано числовое значение 1000. Основания — [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds», [R-M0008-02](#r-m0008-02) «the numeric value 1000 represents one minute.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой момент должна обозначать метка 1000 при приёмке: одну секунду или одну минуту от начала отсчёта?

1. **Вариант 1.** Читать числовое значение поля в объявленных миллисекундах.

   **Основание.** [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds; the numeric value 1000 represents one minute.».

   **Ожидаемый результат.** Значение 1000 обозначает одну секунду.

   При выборе этого варианта привести в соответствие [R-M0008-02](#r-m0008-02).

2. **Вариант 2.** Применять явно заданное соответствие значения 1000 одной минуте.

   **Основание.** [R-M0008-02](#r-m0008-02) «Each timestamp field declares milliseconds; the numeric value 1000 represents one minute.».

   **Ожидаемый результат.** Значение 1000 обозначает одну минуту.

   При выборе этого варианта привести в соответствие [R-M0008-01](#r-m0008-01).

**Черновик приёмочного теста.** Сверить метку со значением 1000 с выбранным моментом дорожки.

### Z-003 · Приёмка реплики из 81 кодовой точки

**Дефект · Противоречивость · Существенная.** T-7 требует отклонить реплику с текстом длиннее 80 кодовых точек Unicode. T-8 требует принять реплику с текстом из 81 кодовой точки. Расхождение блокирует конкретный граничный пример.

Затронутые утверждения — [R-M0014-01](#r-m0014-01), [R-M0015-01](#r-m0015-01).

[R-M0014-01](#r-m0014-01) · Subtitle track export / Export limits · [строка 14](../../../../../benchmark/subtitles/requirements.md#L14)

> Reject a cue when its text exceeds 80 Unicode code points.  

[R-M0015-01](#r-m0015-01) · Subtitle track export / Export limits · [строка 15](../../../../../benchmark/subtitles/requirements.md#L15)

> In the acceptance sample, a cue of 81 Unicode code points is accepted.  

**Сценарий.** Проверить указанную в T-8 реплику с текстом длиной 81 кодовая точка Unicode. T-7 применяет порог 80 к длине текста реплики.

**Последствие.** Отклонение выполняет T-7, а принятие выполняет T-8. Для этого примера исключение не задано.

**Общее условие.** Проверяется реплика из приёмочного примера T-8 с текстом длиной 81 кодовая точка Unicode. Основания — [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.», [R-M0015-01](#r-m0015-01) «In the acceptance sample, a cue of 81 Unicode code points is accepted.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой исход выбрать для реплики из 81 кодовой точки в T-8: принятие или отклонение?

1. **Вариант 1.** Отклонять реплику, если её текст превышает 80 кодовых точек Unicode, в том числе в приёмочном примере.

   **Основание.** [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.».

   **Ожидаемый результат.** Реплика из 81 кодовой точки отклонена.

   При выборе этого варианта привести в соответствие [R-M0015-01](#r-m0015-01).

2. **Вариант 2.** Принимать реплику из 81 кодовой точки Unicode в указанном приёмочном примере.

   **Основание.** [R-M0015-01](#r-m0015-01) «In the acceptance sample, a cue of 81 Unicode code points is accepted.».

   **Ожидаемый результат.** Реплика из 81 кодовой точки принята.

   При выборе этого варианта привести в соответствие [R-M0014-01](#r-m0014-01).

**Черновик приёмочного теста.** Выполнить приёмочный пример с репликой из 81 кодовой точки и проверить, принята ли она.

### Z-004 · Критерий лёгкости экспорта

**Дефект · Проверяемость · Существенная.** T-4 требует, чтобы экспорт воспринимался как лёгкий каждым пользователем. Документ не задаёт наблюдаемой меры, по которой можно воспроизводимо оценить это свойство.

Затронутые утверждения — [R-M0009-01](#r-m0009-01).

[R-M0009-01](#r-m0009-01) · Subtitle track export / Format · [строка 9](../../../../../benchmark/subtitles/requirements.md#L9)

> The export experience must feel effortless to every user.  

**Сценарий.** Несколько пользователей выполняют один и тот же экспорт и по-разному оценивают затраченные усилия.

**Последствие.** По тексту нельзя вынести воспроизводимый вердикт о выполнении T-4.

**Уже установлено.** Проверяемое свойство касается восприятия экспорта одной открытой дорожки в локальный файл каждым пользователем. Основания — [R-M0009-01](#r-m0009-01), [R-M0003-01](#r-m0003-01).

**Открытое решение.** Определить воспроизводимый критерий, по которому оценивается лёгкость экспорта.

**Что различит проверка.** В одной и той же пробе каждый участник оценил лёгкость экспорта на 4 из 5. При согласованном минимуме 4 из 5 проба проходит. / При тех же оценках и согласованном минимуме 5 из 5 проба не проходит.

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** В каком сценарии, для каких пользователей и по какому наблюдаемому критерию принимать требование T-4?

Внести ответ на этот вопрос в [R-M0009-01](#r-m0009-01) для сценария «Несколько пользователей выполняют один и тот же экспорт и по-разному оценивают затраченные усилия.».

**Черновик приёмочного теста.** Выполнить согласованный сценарий с заданной группой и сверить наблюдаемый результат с критерием успеха.

## Готовность и порядок исправлений

ТЗ не готово к разработке. Противоречия в формате файла и шкале меток блокируют приёмку экспорта, а расхождение по длине реплики блокирует граничный тест.

1. Согласовать наличие BOM и шкалу числовых значений временных меток. Привести требования и проверки к выбранным исходам. ([Z-001](#z-001), [Z-002](#z-002))
2. Согласовать предел длины текста реплики с исходом приёмочного примера из 81 кодовой точки. ([Z-003](#z-003))
3. Задать воспроизводимый критерий лёгкости экспорта и условия его проверки. ([Z-004](#z-004))
4. Исправить ссылку T-40 в T-5 и проверить наличие её адресата. ([Z-005](#z-005))
