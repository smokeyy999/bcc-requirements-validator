Каждый ID утверждения учитывается один раз. В число нарушений входят подтверждённые дефекты и неоднозначности, для которых показаны две опирающиеся на текст трактовки с разными последствиями. ### Z-002 · BOM в начале файла

**Дефект · Противоречивость · Критичная.** T-1 исключает BOM, а T-2 требует BOM в начале того же файла. Приёмка формата успешного экспорта невозможна.

Затронутые утверждения — [R-M0006-02](#r-m0006-02), [R-M0007-01](#r-m0007-01).

[R-M0006-02](#r-m0006-02) · Subtitle track export / Format · [строка 6](../../../../../benchmark/subtitles/requirements.md#L6)

> Write the exported track in UTF-8 without a byte-order mark.  

[R-M0007-01](#r-m0007-01) · Subtitle track export / Format · [строка 7](../../../../../benchmark/subtitles/requirements.md#L7)

> The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.  

**Сценарий.** Экспортировать непустую дорожку с короткой допустимой репликой в новый локальный файл.

**Последствие.** Файл, соответствующий одному правилу, провалит проверку по другому.

**Общее условие.** Проверяются первые три байта файла, полученного при успешном экспорте дорожки. Основания — [R-M0006-02](#r-m0006-02) «Write the exported track in UTF-8 without a byte-order mark.», [R-M0007-01](#r-m0007-01) «The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой результат принять для начала файла: отсутствие BOM или EF BB BF?

1. **Вариант 1.** Экспортировать в UTF-8 без BOM.

   **Основание.** [R-M0006-02](#r-m0006-02) «Write the exported track in UTF-8 without a byte-order mark.».

   **Ожидаемый результат.** В начале файла нет EF BB BF.

   При выборе этого варианта привести в соответствие [R-M0007-01](#r-m0007-01).

2. **Вариант 2.** Первые три байта экспортированного файла должны быть BOM UTF-8.

   **Основание.** [R-M0007-01](#r-m0007-01) «The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

   **Ожидаемый результат.** Первые три байта файла равны EF BB BF.

   При выборе этого варианта привести в соответствие [R-M0006-02](#r-m0006-02).

**Черновик приёмочного теста.** Экспортировать дорожку из сценария и сравнить первые три байта файла с EF BB BF.

### Z-003 · Шкала временных меток

**Дефект · Противоречивость · Критичная.** T-3 объявляет миллисекунды для каждого поля и приписывает значению 1000 одну минуту. Из-за несовместимых значений нельзя принять временные метки экспортированных субтитров.

Затронутые утверждения — [R-M0008-01](#r-m0008-01), [R-M0008-02](#r-m0008-02).

[R-M0008-01](#r-m0008-01) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> Each timestamp field declares milliseconds;  

[R-M0008-02](#r-m0008-02) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> Each timestamp field declares milliseconds; the numeric value 1000 represents one minute.  

**Сценарий.** Проверить экспортированное поле временной метки со значением 1000.

**Последствие.** Проверка по заявленной единице даёт одну секунду, а проверка по расшифровке T-3 даёт одну минуту.

**Общее условие.** Проверяется значение 1000 в экспортированном поле временной метки, для которого объявлены миллисекунды. Основания — [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds;», [R-M0008-02](#r-m0008-02) «the numeric value 1000 represents one minute.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Что должно обозначать значение 1000 в экспортированном поле: одну секунду или одну минуту?

1. **Вариант 1.** Читать числовое значение каждого поля временной метки в миллисекундах.

   **Основание.** [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds;».

   **Ожидаемый результат.** 1000 обозначает одну секунду.

   При выборе этого варианта привести в соответствие [R-M0008-02](#r-m0008-02).

2. **Вариант 2.** Считать значение 1000 обозначением одной минуты и согласовать с этим объявление шкалы поля.

   **Основание.** [R-M0008-02](#r-m0008-02) «Each timestamp field declares milliseconds; the numeric value 1000 represents one minute.».

   **Ожидаемый результат.** 1000 обозначает одну минуту.

   При выборе этого варианта привести в соответствие [R-M0008-01](#r-m0008-01).

**Черновик приёмочного теста.** Сопоставить значение 1000 в поле с известным временем исходной метки по согласованной шкале.

### Z-004 · Реплика длиной 81 кодовая точка

**Дефект · Противоречивость · Существенная.** T-7 требует отклонить реплику с текстом длиннее 80 кодовых точек Unicode. T-8 принимает реплику с текстом из 81 кодовой точки. Расхождение касается заданной проверки на границе лимита.

Затронутые утверждения — [R-M0014-01](#r-m0014-01), [R-M0015-01](#r-m0015-01).

[R-M0014-01](#r-m0014-01) · Subtitle track export / Export limits · [строка 14](../../../../../benchmark/subtitles/requirements.md#L14)

> Reject a cue when its text exceeds 80 Unicode code points.  

[R-M0015-01](#r-m0015-01) · Subtitle track export / Export limits · [строка 15](../../../../../benchmark/subtitles/requirements.md#L15)

> In the acceptance sample, a cue of 81 Unicode code points is accepted.  

**Сценарий.** Экспортировать реплику из приёмочного примера с текстом из 81 кодовой точки Unicode.

**Последствие.** Отклонение реплики выполняет T-7 и проваливает T-8. Приём реплики выполняет T-8 и нарушает T-7.

**Общее условие.** При экспорте проверяется реплика из приёмочного примера с текстом ровно из 81 кодовой точки Unicode. Основания — [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.», [R-M0015-01](#r-m0015-01) «In the acceptance sample, a cue of 81 Unicode code points is accepted.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой исход принять для реплики из 81 кодовой точки в примере: отклонение или приём?

1. **Вариант 1.** Отклонять реплику при длине текста свыше 80 кодовых точек Unicode, в том числе в приёмочном примере.

   **Основание.** [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.».

   **Ожидаемый результат.** Реплика из 81 кодовой точки отклонена.

   При выборе этого варианта привести в соответствие [R-M0015-01](#r-m0015-01).

2. **Вариант 2.** Принимать реплику из 81 кодовой точки Unicode в приёмочном примере и согласовать область действия ограничения с этим исходом.

   **Основание.** [R-M0015-01](#r-m0015-01) «In the acceptance sample, a cue of 81 Unicode code points is accepted.».

   **Ожидаемый результат.** Реплика из 81 кодовой точки принята.

   При выборе этого варианта привести в соответствие [R-M0014-01](#r-m0014-01).

**Черновик приёмочного теста.** Подать на экспорт реплику с текстом ровно из 81 кодовой точки и проверить исход для этой реплики.

<a id="z-005"></a>

### Z-005 · Критерий лёгкости экспорта

**Дефект · Проверяемость · Существенная.** T-4 требует, чтобы экспорт воспринимался как лёгкий каждым пользователем, но не задаёт измеримого критерия соответствия. Это мешает принять заявленное свойство.

Затронутые утверждения — [R-M0009-01](#r-m0009-01).

[R-M0009-01](#r-m0009-01) · Subtitle track export / Format · [строка 9](../../../../../benchmark/subtitles/requirements.md#L9)

> The export experience must feel effortless to every user.  

**Сценарий.** Два пользователя выполняют одинаковый экспорт и по-разному оценивают затраченные усилия.

**Последствие.** Проверяющие могут вынести разные решения о соответствии T-4 при одинаковом поведении редактора.

**Уже установлено.** Лёгкость требуется при экспорте одной открытой дорожки в локальный файл и относится к каждому пользователю. Основания — [R-M0009-01](#r-m0009-01), [R-M0003-02](#r-m0003-02).

**Открытое решение.** Определить измеримый критерий лёгкости экспорта для каждого участника приёмочного испытания.

**Что различит проверка.** В одном испытании оценки каждого участника достигают согласованного порога, и T-4 выполнено. / Те же оценки не достигают более строгого порога у одного из участников, и T-4 не выполнено.

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой наблюдаемый результат и на каких пользователях подтвердит выполнение T-4?

Внести ответ на этот вопрос в [R-M0009-01](#r-m0009-01) для сценария «Два пользователя выполняют одинаковый экспорт и по-разному оценивают затраченные усилия.».

**Черновик приёмочного теста.** Дать согласованной группе выполнить экспорт и сравнить измеренный результат с согласованным критерием.

### Z-001 · Если открытая дорожка содержит одну допустимую реплику и одну реплику, отклонённую по T-7, должен ли экспорт создать файл с допустимой репликой или завершиться без создания файла?

**Предполагаемый пробел · Полнота · Существенная.** T-7 требует отклонить реплику из 82 кодовых точек. T-5 регулирует пустую дорожку. Для дорожки с допустимой и отклонённой репликами исход экспорта не задан.

Затронутые утверждения — [R-M0003-02](#r-m0003-02), [R-M0014-01](#r-m0014-01).

[R-M0003-02](#r-m0003-02) · Subtitle track export · [строка 3](../../../../../benchmark/subtitles/requirements.md#L3)

> A desktop subtitle editor exports one open track to a local file.  

[R-M0014-01](#r-m0014-01) · Subtitle track export / Export limits · [строка 14](../../../../../benchmark/subtitles/requirements.md#L14)

> Reject a cue when its text exceeds 80 Unicode code points.  

**Сценарий.** Экспортировать в новый локальный файл дорожку с одной допустимой репликой и одной репликой с текстом из 82 кодовых точек Unicode. Проверить наличие файла и, если он создан, наличие в нём только допустимой реплики.

**Последствие.** T-7 требует отклонить реплику из 82 кодовых точек. T-5 регулирует пустую дорожку. Для дорожки с допустимой и отклонённой репликами исход экспорта не задан.

**Уже установлено.** Экспорт выполняется в локальный файл. Реплику с текстом длиннее 80 кодовых точек Unicode требуется отклонить. Правило о неизменности назначения задано для пустой дорожки. Основания — [R-M0014-01](#r-m0014-01), [R-M0003-02](#r-m0003-02), [R-M0010-02](#r-m0010-02).

**Открытое решение.** Определить, создаётся ли файл с допустимой репликой после отклонения другой реплики той же дорожки.

**Что различит проверка.** Создан файл, содержащий только допустимую реплику. / Файл не создан.

### R-M0014-01 · Реплика отклоняется, если её текст содержит больше 80 кодовых точек Unicode.

## Готовность и порядок исправлений

ТЗ не готово к разработке и приёмке формата экспорта. Сначала нужно согласовать наличие BOM и шкалу временных меток.

1. Согласовать наличие BOM и привести единицу временной метки и значение 1000 к единой шкале. ([Z-002](#z-002), [Z-003](#z-003))
2. Согласовать предел длины текста с исходом приёмочного примера для 81 кодовой точки Unicode. ([Z-004](#z-004))
3. Определить, создаётся ли файл после отклонения реплики в дорожке, где есть допустимая реплика. ([Z-001](#z-001))
4. Задать измеримый критерий лёгкости экспорта и условия его приёмочной проверки. ([Z-005](#z-005))
5. Исправить внутреннюю ссылку T-40 редакторской правкой. ([Z-006](#z-006))
