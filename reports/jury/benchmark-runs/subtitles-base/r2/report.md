## Реестр замечаний

<a id="z-002"></a>

### Z-002 · Обозначение единицы в поле временной метки

**Неоднозначность · Однозначность · Существенная.** В T-3 слово «declares» допускает явное обозначение единицы в поле, а заданное соответствие числа времени допускает прочтение миллисекунд как единицы, уже определённой спецификацией. Выбор влияет на приёмку поля с одним числом.

Затронутые утверждения — [R-M0008-01](#r-m0008-01), [R-M0008-02](#r-m0008-02).

[R-M0008-01](#r-m0008-01) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/baseline.md#L8)

> Each timestamp field declares milliseconds  

[R-M0008-02](#r-m0008-02) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/baseline.md#L8)

> Each timestamp field declares milliseconds; the numeric value 1000 represents one second.  

**Сценарий.** Экспортируется метка в одну секунду. В соответствующем поле файла записано только число 1000.

**Последствие.** Один тест примет поле, другой отклонит его из-за отсутствия явного обозначения единицы.

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Принять поле только с числом или требовать явное обозначение миллисекунд в поле? Если обозначение обязательно, по какому признаку его проверять?

1. **Вариант 1.** Каждое поле временной метки должно явно обозначать миллисекунды в файле.

   **Основание.** [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds».

   **Ожидаемый результат.** Поле, содержащее только 1000, отклоняется.

2. **Вариант 2.** Единица поля задана спецификацией. В файле достаточно числового значения в миллисекундах.

   **Основание.** [R-M0008-02](#r-m0008-02) «Each timestamp field declares milliseconds; the numeric value 1000 represents one second.».

   **Ожидаемый результат.** Поле, содержащее только 1000, проходит проверку представления метки.

**Черновик приёмочного теста.** Экспортировать метку в одну секунду, сверить число с 1000 и по ответу автора определить, проходит ли поле без обозначения единицы.

<a id="z-001"></a>

### Z-001 · Какой результат экспорта ожидается для непустой дорожки с одной допустимой репликой и одной репликой из 81 кодовой точки, если файла назначения ещё нет?

**Предполагаемый пробел · Полнота · Существенная.** T-7 и T-8 требуют отклонить реплику из 81 кодовой точки. Описание экспорта задаёт локальный файл как результат, но судьба файла при отклонении одной реплики в непустой дорожке остаётся открытой.

Затронутые утверждения — [R-M0003-02](#r-m0003-02), [R-M0014-01](#r-m0014-01).

[R-M0014-01](#r-m0014-01) · Subtitle track export / Export limits · [строка 14](../../../../../benchmark/subtitles/baseline.md#L14)

> Reject a cue when its text exceeds 80 Unicode code points.  

[R-M0003-02](#r-m0003-02) · Subtitle track export · [строка 3](../../../../../benchmark/subtitles/baseline.md#L3)

> exports one open track to a local file  

**Сценарий.** Экспортировать такую дорожку по свободному локальному пути и по ответу автора проверить наличие файла и, если он создан, его содержимое.

**Что нужно уточнить.** Продолжается ли экспорт непустой дорожки после отклонения одной из двух реплик?

**Как ответ изменит приёмку.** Если экспорт продолжается с допустимой репликой, проверяется файл с этой репликой. Если команда прерывается без записи, проверяется отсутствие файла.

## Готовность и порядок исправлений

Разработку и приёмочные тесты по однозначным требованиям можно начать. Для завершения приёмки нужны правило представления единицы метки и ожидаемый результат экспорта дорожки с допустимой и отклонённой репликами.

1. Установить, достаточно ли числового поля и как проверять обозначение миллисекунд, если оно обязательно. (Z-002)
2. Уточнить ожидаемый результат экспорта дорожки с допустимой и отклонённой репликами и закрепить проверку файла. (Z-001)
