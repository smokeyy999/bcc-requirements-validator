## Проверка набора в целом

Правила отправки расходятся для черновика и ведомости из 25 строк. Срок показа подтверждения не измерим по ТЗ, а срок передачи черновика требует критерия, если черновики разрешат отправлять. Состояние после подтверждения открыто, ссылка на правило вывода при отказе отсутствует в документе.

Открытых предполагаемых пробелов — 1. Неоднозначностей — 0. Рекомендаций — 0.

Каждый ID утверждения учитывается один раз. В число нарушений входят подтверждённые дефекты и неоднозначности, для которых показаны две опирающиеся на текст трактовки с разными последствиями. Один и тот же конфликт имеет один ID при любом числе затронутых требований. Критичный дефект блокирует приёмку существенного обязательного сценария. Предполагаемый пробел оставляет открытым ожидаемое поведение или источник данных. Рекомендация предлагает улучшение. Вопросы и рекомендации имеют отдельные счётчики.

**Дефект · Противоречивость · Критичная.** Для одной попытки отправки черновика S-1 запрещает передачу, а S-2 требует её. Приёмка отправки по состоянию ведомости заблокирована.

**Последствие.** Перевозчик либо получает черновик, либо не получает его.

**Общее условие.** Оператор пытается отправить ведомость в состоянии «Черновик». Основания — [R-M0006-01](#r-m0006-01) «Оператор может отправить ведомость только в состоянии «Готова».», [R-M0007-01](#r-m0007-01) «При попытке отправить ведомость в состоянии «Черновик» терминал сразу передаёт её перевозчику.».

   **Ожидаемый результат.** Черновик не передан перевозчику.

   При выборе этого варианта привести в соответствие [R-M0007-01](#r-m0007-01).

2. **Вариант 2.** При попытке отправить ведомость в состоянии «Черновик» терминал сразу передаёт её перевозчику.

   **Основание.** [R-M0007-01](#r-m0007-01) «При попытке отправить ведомость в состоянии «Черновик» терминал сразу передаёт её перевозчику.».

   **Ожидаемый результат.** Терминал передаёт черновик перевозчику.

   При выборе этого варианта привести в соответствие [R-M0006-01](#r-m0006-01).

<a id="decision"></a>

## Готовность и порядок исправлений

ТЗ требует согласования до разработки правил отправки. Для полной приёмки нужно определить критерии времени и уточнить состояние после подтверждения.

1. Согласовать результат попытки отправки черновика. (Z-001)
2. Согласовать допуск к отправке ведомости из 25 строк. (Z-004)
3. Задать измеримый срок показа «Передано» и, если передача черновика сохранится, измеримый срок такой передачи. (Z-005, Z-003)
4. Уточнить состояние после подтверждения для проверки допуска при повторной попытке. (Z-002)
5. Исправить ссылку на правило вывода сообщения при отказе. (Z-007)
