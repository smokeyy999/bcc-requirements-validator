## Проверка набора в целом

Правила допуска дают взаимоисключающие исходы для отправки черновика. Для значения 7 задано два срока хранения. Критерий скорости показа подтверждения отсутствует, а критерий скорости передачи черновика понадобится при сохранении этого сценария. Состав 25 строк и состояние после подтверждения требуют уточнения. Надпись при отказе определена в S-7, ссылка в S-6 не разрешается.

Открытых предполагаемых пробелов — 2. Неоднозначностей — 0. Рекомендаций — 0.

Каждый ID утверждения учитывается один раз. В число нарушений входят подтверждённые дефекты и неоднозначности, для которых показаны две опирающиеся на текст трактовки с разными последствиями. Один и тот же конфликт имеет один ID при любом числе затронутых требований. Критичный дефект блокирует приёмку существенного обязательного сценария. Предполагаемый пробел оставляет открытым ожидаемое поведение или источник данных. Рекомендация предлагает улучшение. Вопросы и рекомендации имеют отдельные счётчики.

## Проверка каждого требования

<a id="r-m0006-01"></a>

### R-M0006-01 · Отправка ведомости допускается только в состоянии «Готова».

Отправка грузовых ведомостей / Отправка · [строка 6](../../../../../benchmark/dispatch/requirements.md#L6)

> Оператор может отправить ведомость только в состоянии «Готова».  

**Связано с нарушением в спецификации.** S-1 допускает отправку только из состояния «Готова», а S-2 требует передачи перевозчику при той же попытке отправки из «Черновика». Для основной операции нельзя принять оба исхода. S-5 задаёт надпись после подтверждения. Состояние ведомости после подтверждения остаётся открытым, а от него зависит допуск по S-1. S-7 устанавливает состояние только при отказе.

Связанные замечания — [Z-001](#z-001), [Z-002](#z-002).

<a id="r-m0007-01"></a>

### R-M0007-01 · Передача черновика должна происходить сразу после попытки отправки.

Отправка грузовых ведомостей / Отправка · [строка 7](../../../../../benchmark/dispatch/requirements.md#L7)

> При попытке отправить ведомость в состоянии «Черновик» терминал сразу передаёт её перевозчику.  

**Связано с нарушением в спецификации.** S-2 обещает передать черновик «сразу». Факт передачи наблюдаем, а для оценки задержки нужен критерий. Временной тест нужен, если по Z-001 сохраняется передача черновика.

Связанные замечания — [Z-003](#z-003).

<a id="r-m0010-01"></a>

### R-M0010-01 · Максимум для одной ведомости составляет 24 строки груза.

Отправка грузовых ведомостей / Параметры · [строка 10](../../../../../benchmark/dispatch/requirements.md#L10)

> Одна ведомость содержит от 1 до 24 строк груза включительно.  

**Связано с вопросом к автору.** S-3 ограничивает число строк груза. S-4 разрешает отправку при загрузке ведомости из 25 строк, состав которых не указан. Противоречие зависит от того, охватывает ли S-4 случай с 25 строками груза.

Связанные замечания — [Z-004](#z-004).

> Одна ведомость содержит от 1 до 24 строк груза включительно.

<a id="r-m0011-01"></a>

### R-M0011-01 · При загрузке ведомости из 25 строк терминал принимает файл.

Отправка грузовых ведомостей / Параметры · [строка 11](../../../../../benchmark/dispatch/requirements.md#L11)

> При загрузке ведомости из 25 строк терминал принимает файл и разрешает отправку.  

**Нарушений не выявлено.** S-4 прямо требует принять файл. S-3 ограничивает состав ведомости. Сам приём файла совместим с проверкой состава, а конфликт возникает на разрешении отправки. При сквозной проверке это утверждение исключено из оснований замечания.

## Готовность и порядок исправлений

ТЗ не готово к разработке и приёмке правил допуска к отправке до согласования исхода для черновика.

1. Согласовать единый исход попытки отправки черновика. (Z-001)
2. Уточнить подсчёт строк и допуск на границе, затем определить состояние и доступность повторной отправки после подтверждения. (Z-004, Z-002)
3. Согласовать длительность хранения при значении 7. (Z-006)
4. Задать измеримый предел задержки показа подтверждения и, если передача черновика сохранится, предел задержки этой передачи. (Z-005, Z-003)
5. Направить ссылку на S-7. (Z-007)
