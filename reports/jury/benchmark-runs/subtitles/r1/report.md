## Проверка набора в целом

Требования расходятся по BOM, шкале временных меток и исходу приёмочного примера с 81 кодовой точкой. Для лёгкости экспорта отсутствует критерий проверки. Ссылка на текст сообщения для пустой дорожки ведёт к отсутствующему требованию.

Открытых предполагаемых пробелов — 1. Неоднозначностей — 0. Рекомендаций — 0.

Каждый ID утверждения учитывается один раз. В число нарушений входят подтверждённые дефекты и неоднозначности, для которых показаны две опирающиеся на текст трактовки с разными последствиями. Один и тот же конфликт имеет один ID при любом числе затронутых требований. Критичный дефект блокирует приёмку существенного обязательного сценария. Предполагаемый пробел оставляет открытым ожидаемое поведение или источник данных. Рекомендация предлагает улучшение. Вопросы и рекомендации имеют отдельные счётчики.

### Z-002 · BOM при экспорте

**Дефект · Противоречивость · Критичная.** T-1 требует записать файл без BOM, а T-2 требует обнаружить BOM в начале того же файла. Ни один файл не удовлетворит обоим требованиям.

Затронутые утверждения — [R-M0006-02](#r-m0006-02), [R-M0007-01](#r-m0007-01).

[R-M0006-02](#r-m0006-02) · Subtitle track export / Format · [строка 6](../../../../../benchmark/subtitles/requirements.md#L6)

> Write the exported track in UTF-8 without a byte-order mark.  

[R-M0007-01](#r-m0007-01) · Subtitle track export / Format · [строка 7](../../../../../benchmark/subtitles/requirements.md#L7)

> The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.  

**Сценарий.** Экспортировать непустую дорожку с репликой допустимой длины и проверить начало файла.

**Последствие.** Файл, записанный по T-1, провалит проверку T-2.

**Общее условие.** Проверяются первые три байта записанного файла экспорта. Основания — [R-M0006-02](#r-m0006-02) «Write the exported track in UTF-8 without a byte-order mark.», [R-M0007-01](#r-m0007-01) «The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой результат должен принимать тест — файл без BOM или с BOM в первых трёх байтах?

1. **Вариант 1.** Записывать файл в UTF-8 без BOM.

   **Основание.** [R-M0006-02](#r-m0006-02) «Write the exported track in UTF-8 without a byte-order mark.».

   **Ожидаемый результат.** В начале файла нет UTF-8 BOM.

   При выборе этого варианта привести в соответствие [R-M0007-01](#r-m0007-01).

2. **Вариант 2.** Записывать UTF-8 BOM в первые три байта файла.

   **Основание.** [R-M0007-01](#r-m0007-01) «The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

   **Ожидаемый результат.** Первые три байта файла образуют UTF-8 BOM.

   При выборе этого варианта привести в соответствие [R-M0006-02](#r-m0006-02).

**Черновик приёмочного теста.** Прочитать первые три байта экспортированного файла и проверить наличие или отсутствие BOM по выбранному правилу.

### Z-003 · Шкала временных меток

**Дефект · Противоречивость · Критичная.** T-3 задаёт единицу и соответствие для одного поля. В объявленных миллисекундах значение 1000 означает одну секунду, а явное соответствие задаёт одну минуту. Приёмка времени реплик требует согласованной шкалы.

Затронутые утверждения — [R-M0008-01](#r-m0008-01), [R-M0008-02](#r-m0008-02).

[R-M0008-01](#r-m0008-01) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> Each timestamp field declares milliseconds  

[R-M0008-02](#r-m0008-02) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> Each timestamp field declares milliseconds; the numeric value 1000 represents one minute.  

**Сценарий.** Проверить поле временной метки со значением 1000.

**Последствие.** Одна и та же метка обозначает либо одну секунду, либо одну минуту.

**Общее условие.** Проверяется поле временной метки со значением 1000 и объявленной единицей «миллисекунды». Основания — [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds», [R-M0008-02](#r-m0008-02) «Each timestamp field declares milliseconds; the numeric value 1000 represents one minute.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какое время должно обозначать значение 1000 и какую единицу следует объявлять в поле?

1. **Вариант 1.** Читать числовое значение каждого поля временной метки в миллисекундах.

   **Основание.** [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds».

   **Ожидаемый результат.** Значение 1000 обозначает одну секунду.

   При выборе этого варианта привести в соответствие [R-M0008-02](#r-m0008-02).

2. **Вариант 2.** Использовать шкалу, в которой значение 1000 обозначает одну минуту, и согласовать с ней объявление единицы.

   **Основание.** [R-M0008-02](#r-m0008-02) «Each timestamp field declares milliseconds; the numeric value 1000 represents one minute.».

   **Ожидаемый результат.** Значение 1000 обозначает одну минуту.

   При выборе этого варианта привести в соответствие [R-M0008-01](#r-m0008-01).

**Черновик приёмочного теста.** Проверить в экспортированном поле со значением 1000 объявленную единицу и соответствие числа ожидаемому времени.

### Z-004 · Реплика из 81 кодовой точки

**Дефект · Противоречивость · Существенная.** Текст реплики из T-8 превышает порог T-7 на одну кодовую точку. Общее правило требует отклонения, а приёмочный пример требует принятия. Противоречие блокирует проверку этого примера.

Затронутые утверждения — [R-M0014-01](#r-m0014-01), [R-M0015-01](#r-m0015-01).

[R-M0014-01](#r-m0014-01) · Subtitle track export / Export limits · [строка 14](../../../../../benchmark/subtitles/requirements.md#L14)

> Reject a cue when its text exceeds 80 Unicode code points.  

[R-M0015-01](#r-m0015-01) · Subtitle track export / Export limits · [строка 15](../../../../../benchmark/subtitles/requirements.md#L15)

> In the acceptance sample, a cue of 81 Unicode code points is accepted.  

**Сценарий.** Экспортировать дорожку с репликой из приёмочного примера, текст которой содержит 81 кодовую точку Unicode.

**Последствие.** Реализация порога из T-7 провалит пример T-8.

**Общее условие.** Проверяется реплика из приёмочного примера с текстом из 81 кодовой точки Unicode. Основания — [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.», [R-M0015-01](#r-m0015-01) «In the acceptance sample, a cue of 81 Unicode code points is accepted.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Реплика из приёмочного примера должна быть отклонена или принята?

1. **Вариант 1.** Отклонять реплику с текстом длиннее 80 кодовых точек Unicode, в том числе в приёмочном примере.

   **Основание.** [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.».

   **Ожидаемый результат.** Реплика отклонена.

   При выборе этого варианта привести в соответствие [R-M0015-01](#r-m0015-01).

2. **Вариант 2.** Принимать реплику из 81 кодовой точки Unicode в указанном приёмочном примере.

   **Основание.** [R-M0015-01](#r-m0015-01) «In the acceptance sample, a cue of 81 Unicode code points is accepted.».

   **Ожидаемый результат.** Реплика принята.

   При выборе этого варианта привести в соответствие [R-M0014-01](#r-m0014-01).

**Черновик приёмочного теста.** Повторить приёмочный пример и сверить результат проверки реплики с выбранным исходом.

### Z-005 · Ссылка на сообщение пустой дорожки

**Дефект · Трассируемость · Низкая.** T-5 ссылается на отсутствующее T-40. Точный текст для пустой дорожки задан в T-6, поэтому можно исправить ссылку и провести проверку сообщения.

Затронутые утверждения — [R-M0010-01](#r-m0010-01), [R-M0011-01](#r-m0011-01).

[R-M0010-01](#r-m0010-01) · Subtitle track export / Format · [строка 10](../../../../../benchmark/subtitles/requirements.md#L10)

> For an empty track, display the exact message listed in T-40  

[R-M0011-01](#r-m0011-01) · Subtitle track export / Format · [строка 11](../../../../../benchmark/subtitles/requirements.md#L11)

> The message for an empty track is “Add at least one cue”.  

**Сценарий.** При подготовке проверки экспорта пустой дорожки перейти по ссылке из T-5.

**Последствие.** По ссылке нельзя найти ожидаемую строку. Её приходится искать по условию в T-6.

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

Проект правки по [R-M0010-01](#r-m0010-01), [R-M0011-01](#r-m0011-01) — Сослаться на требование, которое задаёт точный текст сообщения для пустой дорожки.

**Черновик приёмочного теста.** Открыть исправленные пункты [R-M0010-01](#r-m0010-01), [R-M0011-01](#r-m0011-01) и проверить выполнение предложенной правки «Сослаться на требование, которое задаёт точный текст сообщения для пустой дорожки.».

## Готовность и порядок исправлений

ТЗ не готово к разработке и приёмке экспорта. Сначала нужно согласовать формат файла, шкалу времени и ожидаемый исход проверки реплики из приёмочного примера.

1. Согласовать наличие BOM, объявленную единицу времени и соответствие числовых значений времени. Синхронизировать требования и приёмочные проверки. (Z-002, Z-003)
2. Согласовать порог длины текста с ожидаемым исходом для реплики из 81 кодовой точки. (Z-004)
3. Определить наблюдаемый критерий лёгкости экспорта и условия его проверки. (Z-001)
4. В T-5 заменить ссылку на T-40 ссылкой на T-6. (Z-005)
