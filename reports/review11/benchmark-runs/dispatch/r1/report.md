Каждый ID утверждения учитывается один раз. В число нарушений входят подтверждённые дефекты и неоднозначности, для которых показаны две опирающиеся на текст трактовки с разными последствиями. Один и тот же конфликт имеет один ID при любом числе затронутых требований. Критичный дефект блокирует приёмку существенного обязательного сценария. Предполагаемый пробел оставляет открытым ожидаемое поведение или источник данных. Рекомендация предлагает улучшение. Вопросы и рекомендации имеют отдельные счётчики.

**Общее условие.** Терминал загрузил одну ведомость из 25 строк груза. Разрешение на отправку проверяется в состоянии «Готова». 1. **Вариант 1.** Одна отправляемая ведомость содержит от 1 до 24 строк груза включительно.

   **Основание.** [R-M0010-01](#r-m0010-01) «Одна ведомость содержит от 1 до 24 строк груза включительно.».

   **Ожидаемый результат.** Терминал не разрешает отправку одной ведомости из 25 строк груза.

   При выборе этого варианта привести в соответствие [R-M0011-02](#r-m0011-02).

2. **Вариант 2.** При загрузке одной ведомости из 25 строк терминал принимает файл и разрешает отправку этой ведомости из состояния «Готова».

   **Ожидаемый результат.** Терминал принимает файл и разрешает отправку ведомости из 25 строк груза.

### Z-003 · Срок хранения при значении 7

**Дефект · Противоречивость · Существенная.** Значение 7 относится к одной настройке срока хранения. Объявленная единица даёт семь суток, а расшифровка значения даёт семь часов. Отдельное правило, меняющее единицу для 7, не задано.

Затронутые утверждения — [R-M0015-01](#r-m0015-01), [R-M0015-02](#r-m0015-02).

> Срок локального хранения подтверждения задаётся в сутках  

[R-M0015-02](#r-m0015-02) · Отправка грузовых ведомостей / Параметры · [строка 15](../../../../../benchmark/dispatch/requirements.md#L15)

> Срок локального хранения подтверждения задаётся в сутках; значение 7 означает семь часов.  

**Сценарий.** Срок локального хранения подтверждения установлен в 7. С момента начала локального хранения прошло восемь часов.

**Последствие.** К моменту проверки срок либо ещё действует, либо уже истёк.

**Общее условие.** Для срока локального хранения подтверждения установлено значение 7. Основания — [R-M0015-01](#r-m0015-01) «Срок локального хранения подтверждения задаётся в сутках», [R-M0015-02](#r-m0015-02) «Срок локального хранения подтверждения задаётся в сутках; значение 7 означает семь часов.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой срок действует при значении 7, семь суток или семь часов?

1. **Вариант 1.** Срок локального хранения подтверждения задаётся в сутках, включая значение 7.

   **Основание.** [R-M0015-01](#r-m0015-01) «Срок локального хранения подтверждения задаётся в сутках».

   **Ожидаемый результат.** Срок составляет 604800000 мс и через восемь часов ещё действует.

2. **Вариант 2.** Значение 7 означает семь часов локального хранения подтверждения.

   **Основание.** [R-M0015-02](#r-m0015-02) «Срок локального хранения подтверждения задаётся в сутках; значение 7 означает семь часов.».

   **Ожидаемый результат.** Срок составляет 25200000 мс и через восемь часов уже истёк.

   При выборе этого варианта привести в соответствие [R-M0015-01](#r-m0015-01).

## Проверка каждого требования

<a id="r-m0006-01"></a>

### R-M0006-01 · Отправка разрешена только из состояния «Готова».

Отправка грузовых ведомостей / Отправка · [строка 6](../../../../../benchmark/dispatch/requirements.md#L6)

> Оператор может отправить ведомость только в состоянии «Готова».  

**Связано с нарушением в спецификации.** S-1 разрешает отправку только из состояния «Готова», а S-2 требует передать перевозчику ведомость при попытке отправки из состояния «Черновик». Приёмка отправки невозможна без единого ожидаемого исхода. Приём файла совместим с пределом в 24 строки. Расхождение возникает при разрешении отправки той же ведомости из 25 строк. ТЗ не предусматривает изменения её состава.

Связанные замечания — [Z-001](#z-001), [Z-002](#z-002).

## Готовность и порядок исправлений

ТЗ не готово к разработке и приёмке спорных сценариев. В первую очередь требуется согласовать исход попытки отправки черновика.

1. Согласовать исход попытки отправки черновика и привести S-1 и S-2 в соответствие. ([Z-001](#z-001))
2. Согласовать предел числа строк с разрешением отправки после загрузки. ([Z-002](#z-002))
3. Установить единый срок локального хранения при значении 7. ([Z-003](#z-003))
4. Задать допустимую задержку показа «Передано» от подтверждения перевозчика. ([Z-005](#z-005))
5. Исправить внутреннюю ссылку на S-97. ([Z-006](#z-006))
