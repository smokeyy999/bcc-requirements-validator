## Проверка набора в целом

Формат файла и шкала временных меток противоречат требованиям к результату экспорта. Нужно согласовать исход для реплики из 81 кодовой точки и определить критерий лёгкости экспорта. Ссылка T-40 требует редакторского исправления. Сообщение для пустой дорожки задано в T-6, а сохранение состояния места назначения задано в T-5.

Открытых предполагаемых пробелов — 0. Неоднозначностей — 0. Рекомендаций — 0.

Каждый ID утверждения учитывается один раз. В число нарушений входят подтверждённые дефекты и неоднозначности, для которых показаны две опирающиеся на текст трактовки с разными последствиями. Один и тот же конфликт имеет один ID при любом числе затронутых требований. Критичный дефект блокирует приёмку существенного обязательного сценария. Предполагаемый пробел оставляет открытым ожидаемое поведение или источник данных. Рекомендация предлагает улучшение. Вопросы и рекомендации имеют отдельные счётчики.

## Критичные дефекты

- [Z-001](#z-001) · T-1 требует записать файл без BOM, а T-2 требует BOM в первых трёх байтах того же файла. Успешный экспорт не может пройти обе проверки.
- [Z-002](#z-002) · T-3 объявляет миллисекунды для каждого поля и сопоставляет одной минуте число 1000. Одна минута равна 60000 миллисекунд, поэтому у экспортируемых временных меток нет согласованной шкалы для приёмки.

### Z-001 · BOM в экспортированном файле

**Дефект · Противоречивость · Критичная.** T-1 требует записать файл без BOM, а T-2 требует BOM в первых трёх байтах того же файла. Успешный экспорт не может пройти обе проверки.

Затронутые утверждения — [R-M0006-02](#r-m0006-02), [R-M0007-01](#r-m0007-01).

[R-M0006-02](#r-m0006-02) · Subtitle track export / Format · [строка 6](../../../../../benchmark/subtitles/requirements.md#L6)

> Write the exported track in UTF-8 without a byte-order mark.  

[R-M0007-01](#r-m0007-01) · Subtitle track export / Format · [строка 7](../../../../../benchmark/subtitles/requirements.md#L7)

> The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.  

**Сценарий.** Успешно экспортировать откры​тую дорожку с одной обычной репликой.

**Последствие.** Один файл не может одновременно удовлетворить обоим требованиям.

**Общее условие.** Оба требования применяются к одному файлу успешного экспорта открытой дорожки. Основания — [R-M0006-02](#r-m0006-02) «Write the exported track in UTF-8 without a byte-order mark.», [R-M0007-01](#r-m0007-01) «The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой результат принимать для начала файла: отсутствие BOM или наличие BOM UTF-8?

1. **Вариант 1.** Записывать дорожку в UTF-8 без BOM.

   **Основание.** [R-M0006-02](#r-m0006-02) «Write the exported track in UTF-8 without a byte-order mark.».

   **Ожидаемый результат.** В начале файла нет BOM UTF-8.

   При выборе этого варианта привести в соответствие [R-M0007-01](#r-m0007-01).

2. **Вариант 2.** Требовать BOM UTF-8 в первых трёх байтах файла.

   **Основание.** [R-M0007-01](#r-m0007-01) «The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

   **Ожидаемый результат.** Первые три байта файла — EF BB BF.

   При выборе этого варианта привести в соответствие [R-M0006-02](#r-m0006-02).

**Черновик приёмочного теста.** Экспортировать дорожку с репликой, начинающейся обычной буквой, и проверить первые три байта файла.

### Z-002 · Шкала временных меток

**Дефект · Противоречивость · Критичная.** T-3 объявляет миллисекунды для каждого поля и сопоставляет одной минуте число 1000. Одна минута равна 60000 миллисекунд, поэтому у экспортируемых временных меток нет согласованной шкалы для приёмки.

Затронутые утверждения — [R-M0008-01](#r-m0008-01), [R-M0008-02](#r-m0008-02).

[R-M0008-01](#r-m0008-01) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> Each timestamp field declares milliseconds  

[R-M0008-02](#r-m0008-02) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> the numeric value 1000 represents one minute.  

**Сценарий.** Экспортировать реплику с временной меткой, равной одной минуте.

**Последствие.** Реализация и приёмочный тест могут ожидать разные числа в одном поле.

**Общее условие.** Экспортируемое поле временной метки представляет одну минуту и объявляет миллисекунды. Основания — [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds», [R-M0008-02](#r-m0008-02) «the numeric value 1000 represents one minute.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какое число должен содержать экспорт для метки в одну минуту: 60000 или 1000?

1. **Вариант 1.** Объявлять миллисекунды и выражать значения полей в миллисекундах.

   **Основание.** [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds».

   **Ожидаемый результат.** Метка в одну минуту записывается числом 60000.

   При выборе этого варианта привести в соответствие [R-M0008-02](#r-m0008-02).

2. **Вариант 2.** Использовать шкалу, на которой 1000 представляет одну минуту, и объявлять соответствующую ей единицу.

   **Основание.** [R-M0008-02](#r-m0008-02) «the numeric value 1000 represents one minute.».

   **Ожидаемый результат.** Метка в одну минуту записывается числом 1000.

   При выборе этого варианта привести в соответствие [R-M0008-01](#r-m0008-01).

**Черновик приёмочного теста.** Экспортировать метку в одну минуту и сверить объявленную единицу и число с выбранной шкалой.

### Z-003 · Критерий лёгкости экспорта

**Дефект · Проверяемость · Существенная.** T-4 требует лёгкости экспорта для каждого пользователя, но не задаёт наблюдаемого критерия успеха. Это мешает воспроизводимо оценить удобство экспорта.

Затронутые утверждения — [R-M0009-01](#r-m0009-01).

[R-M0009-01](#r-m0009-01) · Subtitle track export / Format · [строка 9](../../../../../benchmark/subtitles/requirements.md#L9)

> The export experience must feel effortless to every user.  

**Сценарий.** Пользователи выполняют один и тот же экспорт и дают разные оценки его лёгкости.

**Последствие.** По ТЗ нельзя вынести воспроизводимый вердикт о соответствии.

**Уже установлено.** Критерий лёгкости должен выполняться для каждого пользователя. Основания — [R-M0009-01](#r-m0009-01).

**Открытое решение.** Какой наблюдаемый критерий определяет, что экспорт дался пользователю легко?

**Что различит проверка.** При пороге 4 из 5 для каждого пользователя оценки 4 и 5 проходят проверку. / При пороге 5 из 5 для каждого пользователя те же оценки не проходят проверку.

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой наблюдаемый результат подтвердит лёгкость экспорта и как при приёмке проверять условие для каждого пользователя?

Внести ответ на этот вопрос в [R-M0009-01](#r-m0009-01) для сценария «Пользователи выполняют один и тот же экспорт и дают разные оценки его лёгкости.».

**Черновик приёмочного теста.** Провести экспорт по согласованному сценарию, зафиксировать выбранный показатель и применить согласованный критерий успеха.

<a id="z-004"></a>

### Z-004 · Приёмка реплики из 81 кодовой точки

**Дефект · Противоречивость · Существенная.** T-7 требует отклонить реплику с текстом длиннее 80 кодовых точек Unicode, а T-8 принимает реплику из 81 кодовой точки в приёмочном примере. Расхождение затрагивает проверку предела длины.

Затронутые утверждения — [R-M0014-01](#r-m0014-01), [R-M0015-01](#r-m0015-01).

[R-M0014-01](#r-m0014-01) · Subtitle track export / Export limits · [строка 14](../../../../../benchmark/subtitles/requirements.md#L14)

> Reject a cue when its text exceeds 80 Unicode code points.  

[R-M0015-01](#r-m0015-01) · Subtitle track export / Export limits · [строка 15](../../../../../benchmark/subtitles/requirements.md#L15)

> In the acceptance sample, a cue of 81 Unicode code points is accepted.  

**Сценарий.** Экспортировать реплику из приёмочного примера, текст которой содержит 81 кодовую точку Unicode.

**Последствие.** Отклонение выполняет предел длины, а принятие выполняет ожидание примера. Приоритет или исключение для примера не заданы.

**Общее условие.** На экспорт подана реплика из приёмочного примера с текстом длиной 81 кодовую точку Unicode. Основания — [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.», [R-M0015-01](#r-m0015-01) «In the acceptance sample, a cue of 81 Unicode code points is accepted.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Реплика из приёмочного примера должна быть отклонена или принята?

1. **Вариант 1.** Отклонять реплику, если её текст превышает 80 кодовых точек Unicode.

   **Основание.** [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.».

   **Ожидаемый результат.** Реплика из примера отклонена.

   При выборе этого варианта привести в соответствие [R-M0015-01](#r-m0015-01).

2. **Вариант 2.** Принимать в приёмочном примере реплику из 81 кодовой точки Unicode.

   **Основание.** [R-M0015-01](#r-m0015-01) «In the acceptance sample, a cue of 81 Unicode code points is accepted.».

   **Ожидаемый результат.** Реплика из примера принята.

   При выборе этого варианта привести в соответствие [R-M0014-01](#r-m0014-01).

**Черновик приёмочного теста.** Передать на экспорт указанную в примере реплику из 81 кодовой точки и проверить, принята ли она.

## Готовность и порядок исправлений

ТЗ не готово к разработке и приёмке формата экспорта до согласования BOM и шкалы временных меток.

1. Согласовать наличие BOM, единицу и числовую шкалу временных меток. Привести требования и приёмочные проверки к выбранным результатам. ([Z-001](#z-001), [Z-002](#z-002))
2. Согласовать предел длины с ожидаемым исходом для реплики из 81 кодовой точки Unicode. ([Z-004](#z-004))
3. Задать наблюдаемый критерий лёгкости экспорта для каждого пользователя. ([Z-003](#z-003))
