## Проверка набора в целом

Требования расходятся по BOM, значению временной метки 1000 и исходу проверки реплики из 81 кодовой точки. Для простоты экспорта не задан измеримый критерий. Ссылка T-40 требует редакторского исправления. Сообщение для пустой дорожки уже задано в T-6, сохранение назначения предписано в T-5.

Открытых предполагаемых пробелов — 0. Неоднозначностей — 0. Рекомендаций — 0.

Каждый ID утверждения учитывается один раз. В число нарушений входят подтверждённые дефекты и неоднозначности, для которых показаны две опирающиеся на текст трактовки с разными последствиями. Один и тот же конфликт имеет один ID при любом числе затронутых требований. Критичный дефект блокирует приёмку существенного обязательного сценария. Предполагаемый пробел оставляет открытым ожидаемое поведение или источник данных. Рекомендация предлагает улучшение. Вопросы и рекомендации имеют отдельные счётчики.

## Критичные дефекты

- [Z-001](#z-001) · T-1 требует записать файл без BOM, а T-2 требует BOM в первых трёх байтах того же файла. Для дорожки с обычной начальной буквой ни один результат не удовлетворяет обоим требованиям, поэтому приёмка формата экспорта заблокирована.
- [Z-002](#z-002) · В T-3 значение 1000 в поле с объявленными миллисекундами соответствует одной секунде, а пояснение задаёт одну минуту. Приёмка временных меток требует единой шкалы.

### Z-001 · UTF-8 BOM при экспорте

**Дефект · Противоречивость · Критичная.** T-1 требует записать файл без BOM, а T-2 требует BOM в первых трёх байтах того же файла. Для дорожки с обычной начальной буквой ни один результат не удовлетворяет обоим требованиям, поэтому приёмка формата экспорта заблокирована.

Затронутые утверждения — [R-M0006-02](#r-m0006-02), [R-M0007-01](#r-m0007-01).

[R-M0006-02](#r-m0006-02) · Subtitle track export / Format · [строка 6](../../../../../benchmark/subtitles/requirements.md#L6)

> Write the exported track in UTF-8 without a byte-order mark.  

[R-M0007-01](#r-m0007-01) · Subtitle track export / Format · [строка 7](../../../../../benchmark/subtitles/requirements.md#L7)

> The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.  

**Сценарий.** Экспортировать непустую открытую дорожку с допустимой репликой, текст которой начинается с обычной буквы.

**Последствие.** Файл, записанный по T-1, не проходит проверку T-2.

**Общее условие.** Проверяются первые три байта экспортированного файла UTF-8. Основания — [R-M0006-02](#r-m0006-02) «Write the exported track in UTF-8 without a byte-order mark.», [R-M0007-01](#r-m0007-01) «The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Файл в этом сценарии должен начинаться с UTF-8 BOM или записываться без него?

1. **Вариант 1.** Записывать дорожку в UTF-8 без BOM.

   **Основание.** [R-M0006-02](#r-m0006-02) «Write the exported track in UTF-8 without a byte-order mark.».

   **Ожидаемый результат.** В начале файла отсутствует UTF-8 BOM.

   При выборе этого варианта привести в соответствие [R-M0007-01](#r-m0007-01).

2. **Вариант 2.** Записывать UTF-8 BOM в первых трёх байтах экспортированного файла.

   **Основание.** [R-M0007-01](#r-m0007-01) «The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

   **Ожидаемый результат.** Первые три байта файла образуют UTF-8 BOM.

   При выборе этого варианта привести в соответствие [R-M0006-02](#r-m0006-02).

**Черновик приёмочного теста.** Проверить первые три байта файла и сравнить наличие BOM с выбранным условием.

### Z-002 · Шкала временной метки

**Дефект · Противоречивость · Критичная.** В T-3 значение 1000 в поле с объявленными миллисекундами соответствует одной секунде, а пояснение задаёт одну минуту. Приёмка временных меток требует единой шкалы.

Затронутые утверждения — [R-M0008-01](#r-m0008-01), [R-M0008-02](#r-m0008-02).

[R-M0008-01](#r-m0008-01) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> Each timestamp field declares milliseconds  

[R-M0008-02](#r-m0008-02) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> the numeric value 1000 represents one minute.  

**Сценарий.** Прочитать значение 1000 в экспортированном поле временной метки.

**Последствие.** Для одной и той же метки получаются одна секунда по объявленной единице и одна минута по пояснению.

**Общее условие.** Читается значение 1000 в поле временной метки с объявленной единицей «миллисекунды». Основания — [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds», [R-M0008-02](#r-m0008-02) «the numeric value 1000 represents one minute.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какую длительность должно обозначать значение 1000 в этом поле — одну секунду или одну минуту?

1. **Вариант 1.** Интерпретировать числовые значения полей временных меток в миллисекундах.

   **Основание.** [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds».

   **Ожидаемый результат.** Значение 1000 означает одну секунду.

   При выборе этого варианта привести в соответствие [R-M0008-02](#r-m0008-02).

2. **Вариант 2.** Установить шкалу поля так, чтобы значение 1000 означало одну минуту.

   **Основание.** [R-M0008-02](#r-m0008-02) «the numeric value 1000 represents one minute.».

   **Ожидаемый результат.** Значение 1000 означает одну минуту.

   При выборе этого варианта привести в соответствие [R-M0008-01](#r-m0008-01).

**Черновик приёмочного теста.** Прочитать значение 1000 по согласованному формату и сверить длительность с выбранным исходом.

### Z-003 · Критерий простоты экспорта

**Дефект · Проверяемость · Существенная.** T-4 требует, чтобы экспорт ощущался лёгким для каждого пользователя, но не задаёт меру, по которой приёмщик может воспроизводимо оценить это свойство.

Затронутые утверждения — [R-M0009-01](#r-m0009-01).

[R-M0009-01](#r-m0009-01) · Subtitle track export / Format · [строка 9](../../../../../benchmark/subtitles/requirements.md#L9)

> The export experience must feel effortless to every user.  

**Сценарий.** Дать каждому участнику приёмки экспортировать дорожку, зафиксировать его оценку усилий по согласованной шкале и применить согласованный критерий к каждому результату.

**Последствие.** Приёмщик не может вынести воспроизводимый вердикт по T-4.

**Уже установлено.** Экспорт должен ощущаться лёгким для каждого пользователя. Основания — [R-M0009-01](#r-m0009-01).

**Открытое решение.** Какой результат индивидуальной оценки считается достаточным для выполнения T-4.

**Что различит проверка.** При оценке 4 из 5 одним участником и 5 из 5 остальными порог 4 из 5 даёт зачёт по T-4. / При тех же оценках порог 5 из 5 даёт незачёт по T-4.

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** По какому наблюдаемому критерию определить, что экспорт ощущается лёгким для каждого пользователя по T-4?

Внести ответ на этот вопрос в [R-M0009-01](#r-m0009-01) для сценария «Дать каждому участнику приёмки экспортировать дорожку, зафиксировать его оценку усилий по согласованной шкале и применить согласованный критерий к каждому результату.».

**Черновик приёмочного теста.** Дать каждому участнику приёмки экспортировать дорожку, зафиксировать его оценку усилий по согласованной шкале и применить согласованный критерий к каждому результату.

### Z-004 · Реплика из 81 кодовой точки

**Дефект · Противоречивость · Существенная.** T-7 требует отклонить реплику с текстом длиннее 80 кодовых точек Unicode, а T-8 принимает реплику длиной 81 в той же единице. Противоречие блокирует приёмку этого примера.

Затронутые утверждения — [R-M0014-01](#r-m0014-01), [R-M0015-01](#r-m0015-01).

[R-M0014-01](#r-m0014-01) · Subtitle track export / Export limits · [строка 14](../../../../../benchmark/subtitles/requirements.md#L14)

> Reject a cue when its text exceeds 80 Unicode code points.  

[R-M0015-01](#r-m0015-01) · Subtitle track export / Export limits · [строка 15](../../../../../benchmark/subtitles/requirements.md#L15)

> In the acceptance sample, a cue of 81 Unicode code points is accepted.  

**Сценарий.** Проверить реплику из приёмочного примера с текстом длиной 81 кодовая точка Unicode.

**Последствие.** Отклонение по T-7 проваливает приёмочный пример T-8, а принятие нарушает предел T-7.

**Общее условие.** Проверяется реплика из приёмочного примера с текстом длиной 81 кодовая точка Unicode. Основания — [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.», [R-M0015-01](#r-m0015-01) «In the acceptance sample, a cue of 81 Unicode code points is accepted.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Реплику из приёмочного примера с длиной 81 кодовая точка следует отклонить или принять?

1. **Вариант 1.** Отклонять реплику при длине текста свыше 80 кодовых точек Unicode, включая приёмочный пример.

   **Основание.** [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.».

   **Ожидаемый результат.** Реплика из примера отклонена.

   При выборе этого варианта привести в соответствие [R-M0015-01](#r-m0015-01).

2. **Вариант 2.** В приёмочном примере принимать реплику с текстом длиной 81 кодовая точка Unicode.

   **Основание.** [R-M0015-01](#r-m0015-01) «In the acceptance sample, a cue of 81 Unicode code points is accepted.».

   **Ожидаемый результат.** Реплика из примера принята.

   При выборе этого варианта привести в соответствие [R-M0014-01](#r-m0014-01).

**Черновик приёмочного теста.** Предъявить реплику из примера, подтвердить длину её текста в кодовых точках Unicode и сверить исход проверки реплики с выбранным правилом.

## Готовность и порядок исправлений

ТЗ не готово к разработке и приёмке. Нужно согласовать формат файла, шкалу временных меток и ожидаемый исход приёмочного примера с 81 кодовой точкой.

1. Согласовать наличие BOM и шкалу временных меток, затем привести требования и приёмку в соответствие. ([Z-001](#z-001), [Z-002](#z-002))
2. Согласовать предел длины с ожидаемым исходом для реплики из 81 кодовой точки. ([Z-004](#z-004))
3. Задать измеримый критерий индивидуальной оценки простоты экспорта. ([Z-003](#z-003))
4. Исправить внутреннюю ссылку T-40. ([Z-005](#z-005))
