## Проверка набора в целом

Требования к формату файла и шкале меток расходятся с обязательными исходами. Приёмочный образец противоречит лимиту длины реплики. Для лёгкости экспорта нужен измеримый критерий. Ссылка T-40 требует редакторского исправления, а точное сообщение для пустой дорожки уже задано в T-6.

Открытых предполагаемых пробелов — 0. Неоднозначностей — 0. Рекомендаций — 0.

Каждый ID утверждения учитывается один раз. В число нарушений входят подтверждённые дефекты и неоднозначности, для которых показаны две опирающиеся на текст трактовки с разными последствиями. Один и тот же конфликт имеет один ID при любом числе затронутых требований. Критичный дефект блокирует приёмку существенного обязательного сценария. Предполагаемый пробел оставляет открытым ожидаемое поведение или источник данных. Рекомендация предлагает улучшение. Вопросы и рекомендации имеют отдельные счётчики.

## Критичные дефекты

- [Z-001](#z-001) · T-1 требует записать файл без BOM, а T-2 требует BOM в первых трёх байтах того же файла. Успешный экспорт нельзя принять по обоим пунктам.
- [Z-002](#z-002) · T-3 объявляет миллисекунды для каждого поля и в том же пункте приравнивает 1000 к минуте. Для минутной метки миллисекунды дают 60000, поэтому шкалу экспортируемых меток нельзя принять по T-3.

### Z-001 · Наличие UTF-8 BOM

**Дефект · Противоречивость · Критичная.** T-1 требует записать файл без BOM, а T-2 требует BOM в первых трёх байтах того же файла. Успешный экспорт нельзя принять по обоим пунктам.

Затронутые утверждения — [R-M0006-02](#r-m0006-02), [R-M0007-01](#r-m0007-01).

[R-M0006-02](#r-m0006-02) · Subtitle track export / Format · [строка 6](../../../../../benchmark/subtitles/requirements.md#L6)

> Write the exported track in UTF-8 without a byte-order mark.  

[R-M0007-01](#r-m0007-01) · Subtitle track export / Format · [строка 7](../../../../../benchmark/subtitles/requirements.md#L7)

> The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.  

**Сценарий.** Успешно экспортировать открытую непустую дорожку с допустимой репликой.

**Последствие.** Для одного файла приёмка одновременно требует отсутствия и наличия BOM.

**Общее условие.** Запись и приёмочная проверка одного успешно экспортированного файла дорожки. Основания — [R-M0006-02](#r-m0006-02) «Write the exported track in UTF-8 without a byte-order mark.», [R-M0007-01](#r-m0007-01) «The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой файл должен пройти приёмку, с UTF-8 BOM или без него?

1. **Вариант 1.** Записывать экспорт в UTF-8 без BOM.

   **Основание.** [R-M0006-02](#r-m0006-02) «Write the exported track in UTF-8 without a byte-order mark.».

   **Ожидаемый результат.** Файл начинается без UTF-8 BOM.

   При выборе этого варианта привести в соответствие [R-M0007-01](#r-m0007-01).

2. **Вариант 2.** Записывать UTF-8 BOM в первые три байта файла.

   **Основание.** [R-M0007-01](#r-m0007-01) «The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

   **Ожидаемый результат.** Первые три байта файла — EF BB BF.

   При выборе этого варианта привести в соответствие [R-M0006-02](#r-m0006-02).

**Черновик приёмочного теста.** Экспортировать одну и ту же допустимую дорожку и проверить первые три байта файла.

### Z-002 · Шкала временных меток

**Дефект · Противоречивость · Критичная.** T-3 объявляет миллисекунды для каждого поля и в том же пункте приравнивает 1000 к минуте. Для минутной метки миллисекунды дают 60000, поэтому шкалу экспортируемых меток нельзя принять по T-3.

Затронутые утверждения — [R-M0008-01](#r-m0008-01), [R-M0008-02](#r-m0008-02).

[R-M0008-01](#r-m0008-01) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> Each timestamp field declares milliseconds  

[R-M0008-02](#r-m0008-02) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> Each timestamp field declares milliseconds; the numeric value 1000 represents one minute.  

**Сценарий.** Экспортировать реплику с временной меткой в одну минуту.

**Последствие.** Один файл может получить разные оценки приёмки в зависимости от применённой части T-3.

**Общее условие.** Экспорт поля временной метки со значением в одну минуту по T-3. Основания — [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds», [R-M0008-02](#r-m0008-02) «the numeric value 1000 represents one minute.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какое значение должно пройти приёмку для метки в одну минуту, 60000 или 1000?

1. **Вариант 1.** Записывать числовые значения временных меток в объявленных миллисекундах.

   **Основание.** [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds».

   **Ожидаемый результат.** В поле записано 60000.

   При выборе этого варианта привести в соответствие [R-M0008-02](#r-m0008-02).

2. **Вариант 2.** Использовать шкалу, в которой 1000 означает одну минуту, и согласовать с ней объявление единицы.

   **Основание.** [R-M0008-02](#r-m0008-02) «Each timestamp field declares milliseconds; the numeric value 1000 represents one minute.».

   **Ожидаемый результат.** В поле записано 1000.

   При выборе этого варианта привести в соответствие [R-M0008-01](#r-m0008-01).

**Черновик приёмочного теста.** Экспортировать дорожку с известной минутной меткой и сверить число в соответствующем поле.

### Z-003 · Критерий лёгкости экспорта

**Дефект · Проверяемость · Существенная.** T-4 требует, чтобы экспорт воспринимался как лёгкий каждым пользователем. Порог успешной оценки и способ проверить охват пользователей не заданы.

Затронутые утверждения — [R-M0009-01](#r-m0009-01).

[R-M0009-01](#r-m0009-01) · Subtitle track export / Format · [строка 9](../../../../../benchmark/subtitles/requirements.md#L9)

> The export experience must feel effortless to every user.  

**Сценарий.** Дать пользователю задание экспортировать открытую дорожку и оценить выполнение T-4.

**Последствие.** Одинаковое наблюдение допускает разные оценки удобства экспорта.

**Уже установлено.** Оценивается восприятие экспорта открытой дорожки каждым пользователем. Основания — [R-M0009-01](#r-m0009-01), [R-M0003-01](#r-m0003-01).

**Открытое решение.** Какой измеримый критерий, включая охват пользователей, подтверждает выполнение T-4?

**Что различит проверка.** Если достаточно оценки лёгкости 4 из 5 от каждого участника согласованного испытания, результат, где каждый поставил 4, проходит. / Если требуется оценка 5 из 5 от каждого участника того же испытания, тот же результат не проходит.

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какое наблюдение в сценарии экспорта считать достаточным для выполнения T-4 и как проверить условие «для каждого пользователя»?

Внести ответ на этот вопрос в [R-M0009-01](#r-m0009-01) для сценария «Дать пользователю задание экспортировать открытую дорожку и оценить выполнение T-4.».

**Черновик приёмочного теста.** Провести согласованное испытание экспорта и оценить результат по заданному автором критерию.

### Z-004 · Приёмка реплики из 81 кодовой точки

**Дефект · Противоречивость · Существенная.** Текст реплики из образца содержит 81 кодовую точку Unicode. T-7 требует её отклонить, а T-8 фиксирует принятие. Противоречие блокирует проверку образца на границе лимита.

Затронутые утверждения — [R-M0014-01](#r-m0014-01), [R-M0015-01](#r-m0015-01).

[R-M0014-01](#r-m0014-01) · Subtitle track export / Export limits · [строка 14](../../../../../benchmark/subtitles/requirements.md#L14)

> Reject a cue when its text exceeds 80 Unicode code points.  

[R-M0015-01](#r-m0015-01) · Subtitle track export / Export limits · [строка 15](../../../../../benchmark/subtitles/requirements.md#L15)

> In the acceptance sample, a cue of 81 Unicode code points is accepted.  

**Сценарий.** Экспортировать открытую дорожку с репликой из T-8, длина текста которой в сопоставленной паре составляет 81 кодовую точку Unicode.

**Последствие.** Один и тот же результат обработки реплики нельзя принять по обоим требованиям.

**Общее условие.** При экспорте обрабатывается реплика из приёмочного образца с текстом длиной 81 кодовая точка Unicode. Основания — [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.», [R-M0015-01](#r-m0015-01) «In the acceptance sample, a cue of 81 Unicode code points is accepted.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой исход должен пройти приёмку для реплики из T-8, отклонение или принятие?

1. **Вариант 1.** Отклонять реплику при длине текста свыше 80 кодовых точек Unicode, включая реплику из образца.

   **Основание.** [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.».

   **Ожидаемый результат.** Реплика из образца отклонена.

   При выборе этого варианта привести в соответствие [R-M0015-01](#r-m0015-01).

2. **Вариант 2.** Принимать указанную в образце реплику из 81 кодовой точки Unicode.

   **Основание.** [R-M0015-01](#r-m0015-01) «In the acceptance sample, a cue of 81 Unicode code points is accepted.».

   **Ожидаемый результат.** Реплика из образца принята.

   При выборе этого варианта привести в соответствие [R-M0014-01](#r-m0014-01).

**Черновик приёмочного теста.** Выполнить экспорт с репликой из образца и проверить исход обработки этой реплики.

## Готовность и порядок исправлений

ТЗ не готово к разработке и приёмке. Сначала согласовать формат файла, шкалу временных меток и исход для приёмочного образца. Ссылку T-40 можно исправить параллельно.

1. Согласовать наличие BOM и привести единицу временных меток в соответствие с числом для одной минуты. ([Z-001](#z-001), [Z-002](#z-002))
2. Согласовать лимит и приёмочный исход для реплики из 81 кодовой точки Unicode. ([Z-004](#z-004))
3. Задать измеримый критерий лёгкости экспорта и способ проверки охвата пользователей. ([Z-003](#z-003))
