### Z-001 · Где проверяющий должен найти объявление миллисекунд для каждого поля временной метки?

**Предполагаемый пробел · Трассируемость · Существенная.** T-3 требует объявить миллисекунды для каждого поля. Значение 1000 проверяет числовую шкалу, а источник объявления единицы для поля не указан.

Затронутые утверждения — [R-M0008-01](#r-m0008-01), [R-M0008-02](#r-m0008-02).

[R-M0008-01](#r-m0008-01) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/baseline.md#L8)

> Each timestamp field declares milliseconds  

[R-M0008-02](#r-m0008-02) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/baseline.md#L8)

> Each timestamp field declares milliseconds; the numeric value 1000 represents one second.  

**Сценарий.** Экспортировать дорожку с меткой в одну секунду. Проверить значение 1000 в соответствующем поле и объявление миллисекунд для каждого поля в указанном источнике.

**Последствие.** T-3 требует объявить миллисекунды для каждого поля. Значение 1000 проверяет числовую шкалу, а источник объявления единицы для поля не указан.

**Уже установлено.** Единица каждого поля — миллисекунды. Одна секунда записывается числом 1000. Основания — [R-M0008-01](#r-m0008-01), [R-M0008-02](#r-m0008-02), [R-M0006-01](#r-m0006-01).

**Открытое решение.** Указать, где для каждого экспортированного поля читать объявление его единицы.

**Что различит проверка.** Объявление миллисекунд проверяется в записи каждого поля. / Объявление миллисекунд проверяется в общем описании, которое явно распространяется на каждое поле.

### Z-002 · Если в дорожке есть реплики из 80 и 81 кодовой точки Unicode, должна ли реплика из 80 кодовых точек попасть в файл после отклонения длинной реплики?

**Предполагаемый пробел · Полнота · Существенная.** T-7 и T-8 требуют отклонить реплику из 81 кодовой точки. В смешанной дорожке остаётся открытым результат экспорта реплики из 80 кодовых точек.

Затронутые утверждения — [R-M0014-01](#r-m0014-01), [R-M0015-01](#r-m0015-01).

[R-M0014-01](#r-m0014-01) · Subtitle track export / Export limits · [строка 14](../../../../../benchmark/subtitles/baseline.md#L14)

> Reject a cue when its text exceeds 80 Unicode code points.  

[R-M0015-01](#r-m0015-01) · Subtitle track export / Export limits · [строка 15](../../../../../benchmark/subtitles/baseline.md#L15)

> In the acceptance sample, a cue of 81 Unicode code points is rejected.  

**Сценарий.** В приёмочном примере проверить, что реплика из 81 кодовой точки не экспортирована. Затем экспортировать дорожку с репликами из 80 и 81 кодовой точки Unicode. Проверить отклонение длинной реплики и сверить с ответом автора, записана ли допустимая реплика в файл.

**Последствие.** T-7 и T-8 требуют отклонить реплику из 81 кодовой точки. В смешанной дорожке остаётся открытым результат экспорта реплики из 80 кодовых точек.

**Уже установлено.** Реплика из 81 кодовой точки подлежит отклонению. Реплика из 80 кодовых точек укладывается в лимит. Правило о состоянии файла в T-5 относится к пустой дорожке. Основания — [R-M0014-01](#r-m0014-01), [R-M0015-01](#r-m0015-01), [R-M0003-01](#r-m0003-01), [R-M0010-02](#r-m0010-02).

**Открытое решение.** Определить, записывается ли допустимая реплика при экспорте смешанной дорожки.

**Что различит проверка.** В файл записана реплика из 80 кодовых точек. Реплика из 81 кодовой точки отклонена. / Ни одна из двух реплик не записана. Реплика из 81 кодовой точки отклонена.
