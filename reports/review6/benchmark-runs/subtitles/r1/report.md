## Проверка набора в целом

Формат файла, шкала временных меток и проверка предельной длины реплики содержат противоречия. Лёгкость экспорта не имеет наблюдаемого критерия. Ссылка на T-40 требует редакторского исправления. T-6 уже задаёт сообщение для пустой дорожки.

Открытых предполагаемых пробелов — 0. Неоднозначностей — 0. Рекомендаций — 0.

Каждый ID утверждения учитывается один раз. В число нарушений входят подтверждённые дефекты и неоднозначности, для которых показаны две опирающиеся на текст трактовки с разными последствиями. Один и тот же конфликт имеет один ID при любом числе затронутых требований. Критичный дефект блокирует приёмку существенного обязательного сценария. Предполагаемый пробел оставляет открытым ожидаемое поведение или источник данных. Рекомендация предлагает улучшение. Вопросы и рекомендации имеют отдельные счётчики.

### Z-001 · Наличие BOM в файле экспорта

**Дефект · Противоречивость · Критичная.** T-1 запрещает BOM в экспортированном файле, а T-2 требует его в первых трёх байтах того же файла. Приёмка формата невозможна.

Затронутые утверждения — [R-M0006-01](#r-m0006-01), [R-M0007-01](#r-m0007-01).

[R-M0006-01](#r-m0006-01) · Subtitle track export / Format · [строка 6](../../../../../benchmark/subtitles/requirements.md#L6)

> Write the exported track in UTF-8 without a byte-order mark.  

[R-M0007-01](#r-m0007-01) · Subtitle track export / Format · [строка 7](../../../../../benchmark/subtitles/requirements.md#L7)

> The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.  

**Сценарий.** Успешно экспортировать непустую дорожку с репликой допустимой длины и проверить начало локального файла.

**Последствие.** Один файл не может одновременно удовлетворить требованиям к записи и приёмке.

**Общее условие.** Приёмочный тест проверяет первые три байта файла экспорта в UTF-8. Основания — [R-M0006-01](#r-m0006-01) «Write the exported track in UTF-8 without a byte-order mark.», [R-M0007-01](#r-m0007-01) «The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой файл должен пройти приёмку, с UTF-8 BOM или без него?

1. **Вариант 1.** Записывать и принимать файл в UTF-8 без BOM.

   **Основание.** [R-M0006-01](#r-m0006-01) «Write the exported track in UTF-8 without a byte-order mark.».

   **Ожидаемый результат.** В начале файла нет UTF-8 BOM.

   При выборе этого варианта привести в соответствие [R-M0007-01](#r-m0007-01).

2. **Вариант 2.** Записывать и принимать файл с UTF-8 BOM в первых трёх байтах.

   **Основание.** [R-M0007-01](#r-m0007-01) «The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

   **Ожидаемый результат.** Первые три байта файла образуют UTF-8 BOM.

   При выборе этого варианта привести в соответствие [R-M0006-01](#r-m0006-01).

**Черновик приёмочного теста.** Экспортировать одну и ту же дорожку и проверить первые три байта на наличие UTF-8 BOM.

### Z-002 · Масштаб временных меток

**Дефект · Противоречивость · Критичная.** Обе части T-3 относятся к значению одного поля. В объявленных миллисекундах 1000 означает секунду, а заданное соответствие даёт минуту. Приёмка точности временных меток невозможна.

Затронутые утверждения — [R-M0008-01](#r-m0008-01), [R-M0008-02](#r-m0008-02).

[R-M0008-01](#r-m0008-01) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> Each timestamp field declares milliseconds  

[R-M0008-02](#r-m0008-02) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> the numeric value 1000 represents one minute.  

**Сценарий.** Прочитать значение 1000 в экспортированном поле временной метки, объявленном в миллисекундах.

**Последствие.** Одна и та же метка даёт разницу во времени в 59 секунд.

**Общее условие.** Экспортированное поле временной метки объявлено в миллисекундах и содержит число 1000. Основания — [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds», [R-M0008-02](#r-m0008-02) «the numeric value 1000 represents one minute.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какому времени должно соответствовать значение 1000 в экспортированной метке, одной секунде или одной минуте?

1. **Вариант 1.** Трактовать числовые значения полей временных меток в миллисекундах.

   **Основание.** [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds».

   **Ожидаемый результат.** Значение 1000 соответствует одной секунде.

   При выборе этого варианта привести в соответствие [R-M0008-02](#r-m0008-02).

2. **Вариант 2.** Использовать шкалу, в которой числовое значение 1000 означает одну минуту, и согласовать с ней объявленную единицу.

   **Основание.** [R-M0008-02](#r-m0008-02) «the numeric value 1000 represents one minute.».

   **Ожидаемый результат.** Значение 1000 соответствует одной минуте.

   При выборе этого варианта привести в соответствие [R-M0008-01](#r-m0008-01).

**Черновик приёмочного теста.** Для одного и того же экспортированного значения 1000 сверить объявленную единицу и ожидаемое время.

### Z-003 · Критерий простоты экспорта

**Дефект · Проверяемость · Существенная.** T-4 требует лёгкости экспорта для каждого пользователя. По успешному завершению экспорта нельзя определить, выполнено ли это свойство, пока не задан наблюдаемый критерий.

Затронутые утверждения — [R-M0009-01](#r-m0009-01).

[R-M0009-01](#r-m0009-01) · Subtitle track export / Format · [строка 9](../../../../../benchmark/subtitles/requirements.md#L9)

> The export experience must feel effortless to every user.  

**Сценарий.** Пользователь успешно экспортирует дорожку после одной подсказки и оценивает процесс как лёгкий. Применить согласованный критерий T-4 к этому наблюдению, сохраняя требование для каждого пользователя.

**Последствие.** Проверяющие могут вынести разные решения о выполнении T-4 по одному наблюдению.

**Уже установлено.** Редактор экспортирует открытую дорожку в локальный файл. Экспорт должен восприниматься как лёгкий каждым пользователем. Основания — [R-M0009-01](#r-m0009-01), [R-M0003-02](#r-m0003-02).

**Открытое решение.** Определить наблюдаемый критерий лёгкости экспорта для отдельного пользователя.

**Что различит проверка.** При критерии по оценке пользователя это наблюдение проходит проверку T-4. / При критерии самостоятельного завершения необходимость подсказки приводит к провалу проверки T-4.

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой наблюдаемый критерий определяет, что экспорт дался пользователю без усилий по T-4?

Внести ответ на этот вопрос в [R-M0009-01](#r-m0009-01) для сценария «Пользователь успешно экспортирует дорожку после одной подсказки и оценивает процесс как лёгкий. Применить согласованный критерий T-4 к этому наблюдению, сохраняя требование для каждого пользователя.».

**Черновик приёмочного теста.** Пользователь успешно экспортирует дорожку после одной подсказки и оценивает процесс как лёгкий. Применить согласованный критерий T-4 к этому наблюдению, сохраняя требование для каждого пользователя.

### Z-004 · Реплика длиной 81 кодовую точку

**Дефект · Противоречивость · Существенная.** Общий порог T-7 охватывает реплику из T-8. Для неё T-7 требует отклонения, а приёмочный пример требует принятия. Приёмка этого граничного случая заблокирована.

Затронутые утверждения — [R-M0014-01](#r-m0014-01), [R-M0015-01](#r-m0015-01).

[R-M0014-01](#r-m0014-01) · Subtitle track export / Export limits · [строка 14](../../../../../benchmark/subtitles/requirements.md#L14)

> Reject a cue when its text exceeds 80 Unicode code points.  

[R-M0015-01](#r-m0015-01) · Subtitle track export / Export limits · [строка 15](../../../../../benchmark/subtitles/requirements.md#L15)

> In the acceptance sample, a cue of 81 Unicode code points is accepted.  

**Сценарий.** Выполнить приёмочный пример T-8 с репликой, текст которой содержит 81 кодовую точку Unicode.

**Последствие.** Соблюдение порога T-7 приводит к провалу примера T-8.

**Общее условие.** Текст реплики в приёмочном примере T-8 содержит 81 кодовую точку Unicode и превышает порог T-7. Основания — [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.», [R-M0015-01](#r-m0015-01) «In the acceptance sample, a cue of 81 Unicode code points is accepted.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой исход должен проверять пример T-8, отклонение или принятие реплики?

1. **Вариант 1.** Отклонять реплику при длине текста свыше 80 кодовых точек Unicode, включая приёмочный пример.

   **Основание.** [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.».

   **Ожидаемый результат.** Реплика в примере отклонена.

   При выборе этого варианта привести в соответствие [R-M0015-01](#r-m0015-01).

2. **Вариант 2.** Принимать реплику длиной 81 кодовую точку Unicode в приёмочном примере и согласовать с этим применимость общего порога.

   **Основание.** [R-M0015-01](#r-m0015-01) «In the acceptance sample, a cue of 81 Unicode code points is accepted.».

   **Ожидаемый результат.** Реплика в примере принята.

   При выборе этого варианта привести в соответствие [R-M0014-01](#r-m0014-01).

**Черновик приёмочного теста.** Запустить пример T-8 и проверить, принята ли реплика из 81 кодовой точки Unicode.

## Готовность и порядок исправлений

ТЗ не готово к разработке и приёмке экспорта. Сначала нужно согласовать BOM и шкалу временных меток, затем определить исход приёмочного примера с 81 кодовой точкой.

1. Согласовать наличие BOM, единицу временных меток и соответствие значения 1000. ([Z-001](#z-001), [Z-002](#z-002))
2. Согласовать общий порог длины с исходом приёмочного примера. ([Z-004](#z-004))
3. Задать наблюдаемый критерий лёгкости экспорта по T-4. ([Z-003](#z-003))
4. Исправить внутреннюю ссылку на T-40. ([Z-005](#z-005))
