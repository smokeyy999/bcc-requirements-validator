## Проверка набора в целом

Формат файла, шкала временных меток и приёмочный пример ограничения длины содержат противоречия. Для смешанной дорожки требуется определить результат записи, для удобства экспорта — критерий приёмки. Ссылка на T-40 требует редакторской правки. Сообщение для пустой дорожки уже задано в T-6.

Открытых предполагаемых пробелов — 1. Неоднозначностей — 0. Рекомендаций — 0.

Каждый ID утверждения учитывается один раз. В число нарушений входят подтверждённые дефекты и неоднозначности, для которых показаны две опирающиеся на текст трактовки с разными последствиями. Один и тот же конфликт имеет один ID при любом числе затронутых требований. Критичный дефект блокирует приёмку существенного обязательного сценария. Предполагаемый пробел оставляет открытым ожидаемое поведение или источник данных. Рекомендация предлагает улучшение. Вопросы и рекомендации имеют отдельные счётчики.

**При экспорте дорожки с допустимым субтитром и субтитром длиной 82 кодовые точки Unicode должен ли после отклонения длинного субтитра появиться новый файл с допустимым субтитром?**

Требует уточнения · [Z-002](#z-002). Зависимый сценарий — Экспортировать такую дорожку в отсутствующий локальный файл. Проверить отклонение длинного субтитра и, по ответу, наличие файла с допустимым субтитром либо отсутствие файла.

### Z-001 · BOM в экспортируемом файле

**Дефект · Противоречивость · Критичная.** T-1 запрещает BOM, а T-2 требует его в первых трёх байтах того же файла. Экспортированный файл не может одновременно соответствовать формату и пройти приёмку.

Затронутые утверждения — [R-M0006-02](#r-m0006-02), [R-M0007-01](#r-m0007-01).

[R-M0006-02](#r-m0006-02) · Subtitle track export / Format · [строка 6](../../../../../benchmark/subtitles/requirements.md#L6)

> Write the exported track in UTF-8 without a byte-order mark.  

[R-M0007-01](#r-m0007-01) · Subtitle track export / Format · [строка 7](../../../../../benchmark/subtitles/requirements.md#L7)

> The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.  

**Сценарий.** Экспортировать непустую дорожку с допустимым субтитром и проверить первые три байта файла.

**Последствие.** Файл, записанный по T-1, не проходит тест T-2.

**Общее условие.** Первые три байта файла, полученного при экспорте дорожки. Основания — [R-M0006-02](#r-m0006-02) «Write the exported track in UTF-8 without a byte-order mark.», [R-M0007-01](#r-m0007-01) «The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой файл должен пройти приёмку: с UTF-8 BOM или без него?

1. **Вариант 1.** Записывать файл в UTF-8 без BOM.

   **Основание.** [R-M0006-02](#r-m0006-02) «Write the exported track in UTF-8 without a byte-order mark.».

   **Ожидаемый результат.** В начале файла нет UTF-8 BOM.

   При выборе этого варианта привести в соответствие [R-M0007-01](#r-m0007-01).

2. **Вариант 2.** Записывать UTF-8 BOM в первые три байта файла, как требует приёмочный тест.

   **Основание.** [R-M0007-01](#r-m0007-01) «The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

   **Ожидаемый результат.** Первые три байта файла равны EF BB BF.

   При выборе этого варианта привести в соответствие [R-M0006-02](#r-m0006-02).

**Черновик приёмочного теста.** Выполнить один и тот же экспорт и сравнить первые три байта с EF BB BF. Равенство означает наличие BOM.

### Z-003 · Шкала временных меток

**Дефект · Противоречивость · Критичная.** T-3 задаёт для каждого поля миллисекунды, в которых 1000 соответствует одной секунде. Тот же пункт назначает числу 1000 одну минуту. Получатель файла не может однозначно восстановить время.

Затронутые утверждения — [R-M0008-01](#r-m0008-01), [R-M0008-02](#r-m0008-02).

[R-M0008-01](#r-m0008-01) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> Each timestamp field declares milliseconds  

[R-M0008-02](#r-m0008-02) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> Each timestamp field declares milliseconds; the numeric value 1000 represents one minute.  

**Сценарий.** Прочитать экспортированное поле временной метки со значением 1000 и определить соответствующий момент на шкале.

**Последствие.** Одна и та же метка интерпретируется как одна секунда или одна минута.

**Общее условие.** Экспортированное поле временной метки имеет объявленную единицу «миллисекунды» и числовое значение 1000. Основания — [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds», [R-M0008-02](#r-m0008-02) «Each timestamp field declares milliseconds; the numeric value 1000 represents one minute.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой момент должен соответствовать значению 1000 при приёмке: одна секунда или одна минута?

1. **Вариант 1.** Интерпретировать числовые значения каждого поля временной метки в миллисекундах.

   **Основание.** [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds».

   **Ожидаемый результат.** Значение 1000 соответствует одной секунде.

   При выборе этого варианта привести в соответствие [R-M0008-02](#r-m0008-02).

2. **Вариант 2.** Считать, что в поле, объявленном в миллисекундах, значение 1000 представляет одну минуту.

   **Основание.** [R-M0008-02](#r-m0008-02) «Each timestamp field declares milliseconds; the numeric value 1000 represents one minute.».

   **Ожидаемый результат.** Значение 1000 соответствует одной минуте.

   При выборе этого варианта привести в соответствие [R-M0008-01](#r-m0008-01).

**Черновик приёмочного теста.** Для одного экспортированного поля со значением 1000 сверить представленный момент с согласованной шкалой.

### Z-004 · Критерий удобства экспорта

**Дефект · Проверяемость · Существенная.** T-4 обещает лёгкость экспорта для каждого пользователя. Без наблюдаемой меры одинаковые результаты испытания могут получить разные оценки.

Затронутые утверждения — [R-M0009-01](#r-m0009-01).

[R-M0009-01](#r-m0009-01) · Subtitle track export / Format · [строка 9](../../../../../benchmark/subtitles/requirements.md#L9)

> The export experience must feel effortless to every user.  

**Сценарий.** Пользователи выполняют один и тот же сценарий экспорта и оценивают затраченное усилие по-разному.

**Последствие.** Приёмщики могут вынести разные решения по одним и тем же наблюдениям.

**Уже установлено.** Требование распространяется на каждого пользователя локального экспорта открытой дорожки. Основания — [R-M0009-01](#r-m0009-01), [R-M0003-01](#r-m0003-01).

**Открытое решение.** Какой измеримый критерий определяет выполнение T-4 в приёмочном сценарии?

**Что различит проверка.** Наблюдения в сценарии удовлетворяют критерию, T-4 принято. / Те же наблюдения выходят за пределы критерия, T-4 не принято.

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** По какому наблюдаемому критерию, в каких условиях и для какого охвата пользователей принимать T-4?

Внести ответ на этот вопрос в [R-M0009-01](#r-m0009-01) для сценария «Пользователи выполняют один и тот же сценарий экспорта и оценивают затраченное усилие по-разному.».

**Черновик приёмочного теста.** Провести согласованный сценарий экспорта для установленного охвата пользователей и сопоставить наблюдения с выбранным критерием.

### Z-005 · Приёмка субтитра длиной 81 кодовая точка

**Дефект · Противоречивость · Существенная.** Длина текста в примере T-8 превышает порог T-7. Для одного и того же субтитра T-7 требует отклонения, а T-8 фиксирует принятие. Конфликт блокирует приёмку на границе ограничения.

Затронутые утверждения — [R-M0014-01](#r-m0014-01), [R-M0015-01](#r-m0015-01).

[R-M0014-01](#r-m0014-01) · Subtitle track export / Export limits · [строка 14](../../../../../benchmark/subtitles/requirements.md#L14)

> Reject a cue when its text exceeds 80 Unicode code points.  

[R-M0015-01](#r-m0015-01) · Subtitle track export / Export limits · [строка 15](../../../../../benchmark/subtitles/requirements.md#L15)

> In the acceptance sample, a cue of 81 Unicode code points is accepted.  

**Сценарий.** Экспортировать дорожку с субтитром из приёмочного примера длиной 81 кодовая точка Unicode.

**Последствие.** Соблюдение порога T-7 приводит к провалу примера T-8.

**Общее условие.** Проверяется субтитр из приёмочного примера, текст которого содержит 81 кодовую точку Unicode. Основания — [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.», [R-M0015-01](#r-m0015-01) «In the acceptance sample, a cue of 81 Unicode code points is accepted.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Следует принять или отклонить субтитр длиной 81 кодовая точка в приёмочном примере?

1. **Вариант 1.** Отклонять субтитр из примера по общему правилу для текста длиннее 80 кодовых точек Unicode.

   **Основание.** [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.».

   **Ожидаемый результат.** Субтитр длиной 81 кодовая точка отклоняется.

   При выборе этого варианта привести в соответствие [R-M0015-01](#r-m0015-01).

2. **Вариант 2.** Принимать субтитр длиной 81 кодовая точка Unicode в приёмочном примере.

   **Основание.** [R-M0015-01](#r-m0015-01) «In the acceptance sample, a cue of 81 Unicode code points is accepted.».

   **Ожидаемый результат.** Субтитр длиной 81 кодовая точка принимается.

   При выборе этого варианта привести в соответствие [R-M0014-01](#r-m0014-01).

**Черновик приёмочного теста.** Повторить приёмочный пример и проверить, принят ли указанный субтитр.

### Z-002 · При экспорте дорожки с допустимым субтитром и субтитром длиной 82 кодовые точки Unicode должен ли после отклонения длинного субтитра появиться новый файл с допустимым субтитром?

**Предполагаемый пробел · Полнота · Существенная.** T-7 требует отклонить субтитр длиной 82 кодовые точки, а описание экспорта обещает локальный файл. Результат для остальной дорожки при таком отклонении не задан. T-5 описывает пустую дорожку, а T-8 использует длину 81.

Затронутые утверждения — [R-M0003-01](#r-m0003-01), [R-M0014-01](#r-m0014-01).

[R-M0003-01](#r-m0003-01) · Subtitle track export · [строка 3](../../../../../benchmark/subtitles/requirements.md#L3)

> A desktop subtitle editor exports one open track to a local file.  

[R-M0014-01](#r-m0014-01) · Subtitle track export / Export limits · [строка 14](../../../../../benchmark/subtitles/requirements.md#L14)

> Reject a cue when its text exceeds 80 Unicode code points.  

**Сценарий.** Экспортировать такую дорожку в отсутствующий локальный файл. Проверить отклонение длинного субтитра и, по ответу, наличие файла с допустимым субтитром либо отсутствие файла.

**Последствие.** T-7 требует отклонить субтитр длиной 82 кодовые точки, а описание экспорта обещает локальный файл. Результат для остальной дорожки при таком отклонении не задан. T-5 описывает пустую дорожку, а T-8 использует длину 81.

**Уже установлено.** Экспорт направлен в локальный файл. Субтитр длиной 82 кодовые точки подлежит отклонению. Основания — [R-M0014-01](#r-m0014-01), [R-M0003-01](#r-m0003-01), [R-M0010-02](#r-m0010-02), [R-M0015-01](#r-m0015-01).

**Открытое решение.** Создаётся ли файл с допустимым субтитром после отклонения длинного субтитра?

**Что различит проверка.** Появляется файл с допустимым субтитром без длинного. / Длинный субтитр отклонён, файл отсутствует.

## Готовность и порядок исправлений

ТЗ не готово к разработке и приёмке экспорта. Сначала нужно согласовать BOM, значение временной метки 1000 и исход приёмочного примера с 81 кодовой точкой.

1. Согласовать требования и ожидаемые результаты для BOM, временной метки 1000 и субтитра из приёмочного примера. ([Z-001](#z-001), [Z-003](#z-003), [Z-005](#z-005))
2. Определить результат записи файла при отклонении субтитра длиной 82 кодовые точки в смешанной дорожке. ([Z-002](#z-002))
3. Задать измеримый критерий приёмки удобства экспорта. ([Z-004](#z-004))
4. Исправить ссылку на отсутствующий пункт T-40. ([Z-006](#z-006))
