## Проверка набора в целом

ТЗ задаёт основной сценарий достижения порога, но даёт несовместимые результаты для месяца покупки на границе периода, повторного push после смены порога и ответа при отклонении суммы. Запись через GET нарушает семантику HTTP. Для интеграционной приёмки остаются вопросы о чтении настроек и источниках данных.

Открытых предполагаемых пробелов — 7. Неоднозначностей — 0. Рекомендаций — 0.

Каждый ID утверждения учитывается один раз. В число нарушений входят подтверждённые дефекты и неоднозначности, для которых показаны две опирающиеся на текст трактовки с разными последствиями. Один и тот же конфликт имеет один ID при любом числе затронутых требований. Критичный дефект блокирует приёмку существенного обязательного сценария. Предполагаемый пробел оставляет открытым ожидаемое поведение или источник данных. Рекомендация предлагает улучшение. Вопросы и рекомендации имеют отдельные счётчики.

**Откуда сервис расходов получает дату совершения и сумму покупки, а при возврате — сумму уменьшения и связь с исходной покупкой?**

Требует уточнения · [Z-003](#z-003). Зависимый сценарий — По указанным источникам сверить дату и сумму январской покупки на 4 000 ₸, сумму февральского возврата 1 250 ₸ и его связь с покупкой. Проверить учёт покупки в январе, уменьшение январской суммы на 1 250 ₸ и неизменность февральской.

**Как приложение читает порог и состояние переключателя и какое значение порога получает до первого сохранения?**

Требует уточнения · [Z-004](#z-004). Зависимый сценарий — Открыть экран с сохранённым порогом 50 000 ₸ и включённым уведомлением, затем открыть экран карты без настройки. Сверить оба поля и проверить отсутствие записи при открытии.

**Какую сумму и в какой единице сервис расходов передаёт сервису push при достижении порога?**

Требует уточнения · [Z-009](#z-009). Зависимый сценарий — При расходах 48 500 ₸ и пороге 50 000 ₸ провести покупку на 2 000 ₸ и сверить значение и единицу суммы в вызове push.

**Из какого источника сервис расходов получает последние четыре цифры карты для push?**

Требует уточнения · [Z-011](#z-011). Зависимый сценарий — Для тестовой карты с известными последними цифрами сверить их в указанном источнике и в вызове push при достижении порога.

**Предусмотрен ли для этого метода отдельный случай ответа 403 и при каком условии он возникает?**

Требует уточнения · [Z-015](#z-015). Зависимый сценарий — Если отдельный случай предусмотрен, проверить 403 при указанном условии. Для чужой и отсутствующей карты проверить одинаковый ответ 404.

**Предполагаемый пробел · Полнота · Низкая.** M0175 явно перечисляет 403 для запрета доступа. M0189 отдельно задаёт 404 для чужой и отсутствующей карты. Условия для самостоятельной проверки 403 не приведены.

Затронутые утверждения — [R-M0175-01](#r-m0175-01).

[R-M0175-01](#r-m0175-01) · Уведомление о расходах по карте / Часть B. REST API / Статусы / 200. Successful — Created · [строка 175](../docs/requirements.md#L175)

> \*\*403.\*\* Ответ в случае, если на указанный ресурс доступ запрещен.  

**Сценарий.** Если отдельный случай предусмотрен, проверить 403 при указанном условии. Для чужой и отсутствующей карты проверить одинаковый ответ 404.

**Последствие.** M0175 явно перечисляет 403 для запрета доступа. M0189 отдельно задаёт 404 для чужой и отсутствующей карты. Условия для самостоятельной проверки 403 не приведены.

<a id="decision"></a>

## Готовность и порядок исправлений

ТЗ пока не готово к согласованию приёмки. Нужно определить ожидаемые результаты спорных сценариев и согласовать контракт сохранения с HTTP.

1. Согласовать месяц учёта покупки на границе периода и число push после смены порога. Привести правила и критерии приёмки к единым исходам. (Z-006, Z-010)
2. Согласовать HTTP-метод сохранения и единый ответ на порог 999 ₸. Зафиксировать код, поля ошибки, наличие прежнего порога и переключателя в теле и проверить неизменность сохранённой настройки. (Z-005, Z-012)
3. Описать чтение настроек, подтвердить источники месячной суммы и входов учёта, определить сумму и источник четырёх цифр для push. (Z-004, Z-002, Z-003, Z-009, Z-011)
4. Уточнить критерий времени получения push и применимость 403. Согласовать заголовки разделов с кодами ответов. (Z-001, Z-015, Z-018)
