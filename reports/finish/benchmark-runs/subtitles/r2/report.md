### Z-002 · BOM в экспортированном файле

**Дефект · Противоречивость · Критичная.** T-1 исключает BOM, а T-2 требует его в начале того же файла. Результат обычного экспорта нельзя принять по обоим требованиям.

Затронутые утверждения — [R-M0006-02](#r-m0006-02), [R-M0007-01](#r-m0007-01).

[R-M0006-02](#r-m0006-02) · Subtitle track export / Format · [строка 6](../../../../../benchmark/subtitles/requirements.md#L6)

> Write the exported track in UTF-8 without a byte-order mark.  

[R-M0007-01](#r-m0007-01) · Subtitle track export / Format · [строка 7](../../../../../benchmark/subtitles/requirements.md#L7)

> The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.  

**Сценарий.** Экспортировать непустую дорожку с допустимой репликой, которая начинается с обычной буквы.

**Последствие.** Приёмка одного и того же файла зависит от выбора требования.

**Общее условие.** Проверяются первые три байта файла, записанного при экспорте дорожки. Основания — [R-M0006-02](#r-m0006-02) «Write the exported track in UTF-8 without a byte-order mark.», [R-M0007-01](#r-m0007-01) «The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой результат должна считать успешным приёмка, наличие или отсутствие UTF-8 BOM?

1. **Вариант 1.** Записывать файл в UTF-8 без BOM.

   **Основание.** [R-M0006-02](#r-m0006-02) «Write the exported track in UTF-8 without a byte-order mark.».

   **Ожидаемый результат.** Первые три байта файла не образуют UTF-8 BOM.

   При выборе этого варианта привести в соответствие [R-M0007-01](#r-m0007-01).

2. **Вариант 2.** Записывать UTF-8 BOM в первых трёх байтах файла.

   **Основание.** [R-M0007-01](#r-m0007-01) «The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

   **Ожидаемый результат.** Первые три байта файла образуют UTF-8 BOM.

   При выборе этого варианта привести в соответствие [R-M0006-02](#r-m0006-02).

**Черновик приёмочного теста.** После экспорта сравнить первые три байта файла с UTF-8 BOM.

### Z-003 · Шкала временных меток

**Дефект · Противоречивость · Критичная.** T-3 объявляет миллисекунды для каждого поля временной метки и сопоставляет значению 1000 одну минуту. По объявленной единице это одна секунда. Однозначно проверить соответствие экспортированной метки исходному времени нельзя.

Затронутые утверждения — [R-M0008-01](#r-m0008-01), [R-M0008-02](#r-m0008-02).

[R-M0008-01](#r-m0008-01) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> Each timestamp field declares milliseconds  

[R-M0008-02](#r-m0008-02) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> Each timestamp field declares milliseconds; the numeric value 1000 represents one minute.  

**Сценарий.** Прочитать числовое значение 1000 в поле временной метки с объявленной единицей «миллисекунды».

**Последствие.** Одна и та же метка соответствует либо одной секунде, либо одной минуте.

**Общее условие.** В поле временной метки со шкалой в миллисекундах записано число 1000. Основания — [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds», [R-M0008-02](#r-m0008-02) «the numeric value 1000 represents one minute.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой результат выбрать для метки 1000, одну секунду или одну минуту?

1. **Вариант 1.** Числа в полях временных меток выражаются в миллисекундах.

   **Основание.** [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds».

   **Ожидаемый результат.** Метка 1000 означает одну секунду.

   При выборе этого варианта привести в соответствие [R-M0008-02](#r-m0008-02).

2. **Вариант 2.** Числовое значение 1000 в поле временной метки означает одну минуту.

   **Основание.** [R-M0008-02](#r-m0008-02) «Each timestamp field declares milliseconds; the numeric value 1000 represents one minute.».

   **Ожидаемый результат.** Метка 1000 означает одну минуту.

   При выборе этого варианта привести в соответствие [R-M0008-01](#r-m0008-01).

**Черновик приёмочного теста.** Проверить, какому исходному времени должна соответствовать метка 1000 в экспортированном файле.

<a id="z-004"></a>

### Z-004 · Критерий лёгкости экспорта

**Дефект · Проверяемость · Существенная.** T-4 требует, чтобы экспорт ощущался лёгким для каждого пользователя. Показатель и порог лёгкости не заданы. Успешная запись файла сама по себе не подтверждает это свойство.

Затронутые утверждения — [R-M0009-01](#r-m0009-01).

[R-M0009-01](#r-m0009-01) · Subtitle track export / Format · [строка 9](../../../../../benchmark/subtitles/requirements.md#L9)

> The export experience must feel effortless to every user.  

**Сценарий.** Пользователи успешно экспортируют дорожку, но по-разному оценивают удобство операции.

**Последствие.** По T-4 невозможно воспроизводимо принять результат.

**Уже установлено.** Экспорт записывает открытую дорожку в локальный файл. Условие лёгкости относится к каждому пользователю. Основания — [R-M0009-01](#r-m0009-01), [R-M0003-02](#r-m0003-02).

**Открытое решение.** Какой измеримый критерий подтверждает лёгкость экспорта для каждого пользователя.

**Что различит проверка.** Результаты каждого участника удовлетворяют согласованному критерию, T-4 проходит проверку. / Результат хотя бы одного участника не удовлетворяет согласованному критерию, T-4 не проходит проверку.

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой наблюдаемый критерий и какой охват пользователей подтверждают выполнение T-4?

Внести ответ на этот вопрос в [R-M0009-01](#r-m0009-01) для сценария «Пользователи успешно экспортируют дорожку, но по-разному оценивают удобство операции.».

**Черновик приёмочного теста.** Провести заданный сценарий экспорта с согласованным охватом и сравнить результаты с критерием успеха.

### Z-005 · Приёмка реплики из 81 кодовой точки

**Дефект · Противоречивость · Существенная.** Порог T-7 применяется к реплике из T-8. Слова «In the acceptance sample» задают область примера, а правило T-7 охватывает любую реплику длиннее 80 кодовых точек. Приёмка этого граничного случая заблокирована.

Затронутые утверждения — [R-M0014-01](#r-m0014-01), [R-M0015-01](#r-m0015-01).

[R-M0014-01](#r-m0014-01) · Subtitle track export / Export limits · [строка 14](../../../../../benchmark/subtitles/requirements.md#L14)

> Reject a cue when its text exceeds 80 Unicode code points.  

[R-M0015-01](#r-m0015-01) · Subtitle track export / Export limits · [строка 15](../../../../../benchmark/subtitles/requirements.md#L15)

> In the acceptance sample, a cue of 81 Unicode code points is accepted.  

**Сценарий.** Проверить реплику из T-8, текст которой содержит 81 кодовую точку Unicode.

**Последствие.** Реализация порога T-7 даст исход, противоположный ожидаемому в примере.

**Общее условие.** Проверяется реплика из приёмочного примера T-8 с длиной текста 81 кодовая точка Unicode. Основания — [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.», [R-M0015-01](#r-m0015-01) «In the acceptance sample, a cue of 81 Unicode code points is accepted.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой исход выбрать для реплики из T-8, отклонение или принятие?

1. **Вариант 1.** Отклонять реплику, если её текст превышает 80 кодовых точек Unicode.

   **Основание.** [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.».

   **Ожидаемый результат.** Реплика из примера отклоняется.

   При выборе этого варианта привести в соответствие [R-M0015-01](#r-m0015-01).

2. **Вариант 2.** В приёмочном примере принимать реплику из 81 кодовой точки Unicode.

   **Основание.** [R-M0015-01](#r-m0015-01) «In the acceptance sample, a cue of 81 Unicode code points is accepted.».

   **Ожидаемый результат.** Реплика из примера принимается.

   При выборе этого варианта привести в соответствие [R-M0014-01](#r-m0014-01).

**Черновик приёмочного теста.** Передать на экспорт реплику из приёмочного примера и проверить исход проверки длины.

### Z-001 · Каким должен стать файл назначения после попытки экспорта дорожки с одной допустимой репликой и одной репликой, отклонённой по длине?

**Предполагаемый пробел · Полнота · Существенная.** T-7 требует отклонить длинную реплику. Для непустой дорожки с допустимой и отклонённой репликами состояние файла назначения не задано. Правило T-5 относится к пустой дорожке.

Затронутые утверждения — [R-M0003-02](#r-m0003-02), [R-M0014-01](#r-m0014-01).

[R-M0003-02](#r-m0003-02) · Subtitle track export · [строка 3](../../../../../benchmark/subtitles/requirements.md#L3)

> exports one open track to a local file  

[R-M0014-01](#r-m0014-01) · Subtitle track export / Export limits · [строка 14](../../../../../benchmark/subtitles/requirements.md#L14)

> Reject a cue when its text exceeds 80 Unicode code points.  

**Сценарий.** Подготовить существующий файл назначения с отличимым содержимым. Экспортировать дорожку с одной допустимой репликой и одной репликой из 82 кодовых точек Unicode. Убедиться, что длинная реплика отклонена, и сверить состояние и содержимое файла с согласованным результатом.

**Последствие.** T-7 требует отклонить длинную реплику. Для непустой дорожки с допустимой и отклонённой репликами состояние файла назначения не задано. Правило T-5 относится к пустой дорожке.

**Уже установлено.** Экспорт направлен в локальный файл. T-7 предписывает отклонение реплики из 82 кодовых точек. T-5 сохраняет файл назначения для пустой дорожки. Основания — [R-M0014-01](#r-m0014-01), [R-M0003-02](#r-m0003-02), [R-M0010-02](#r-m0010-02), [R-M0015-01](#r-m0015-01).

**Открытое решение.** Состояние файла назначения после отклонения одной реплики при наличии допустимой.

**Что различит проверка.** Файл назначения содержит экспорт только допустимой реплики. / Файл назначения сохраняет прежнее содержимое.

## Готовность и порядок исправлений

ТЗ не готово к разработке и приёмке в текущем виде. Сначала нужны согласованные исходы для обычного экспорта, временных меток и граничного примера.

1. Согласовать требования к BOM и соответствие числовой метки исходному времени. ([Z-002](#z-002), [Z-003](#z-003))
2. Согласовать порог длины с исходом приёмочного примера. ([Z-005](#z-005))
3. Определить состояние файла назначения при отклонении реплики в смешанной дорожке. ([Z-001](#z-001))
4. Задать измеримый критерий лёгкости экспорта и процедуру его проверки. ([Z-004](#z-004))
5. Исправить ссылку в T-5 на T-6. ([Z-006](#z-006))
