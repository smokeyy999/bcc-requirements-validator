### Z-002 · BOM в экспортном файле

**Дефект · Противоречивость · Критичная.** T-1 исключает BOM, а T-2 требует его в первых трёх байтах того же файла. Экспортный файл невозможно принять по обоим требованиям.

Затронутые утверждения — [R-M0006-01](#r-m0006-01), [R-M0007-01](#r-m0007-01).

[R-M0006-01](#r-m0006-01) · Subtitle track export / Format · [строка 6](../../../../../benchmark/subtitles/requirements.md#L6)

> Write the exported track in UTF-8 without a byte-order mark.  

[R-M0007-01](#r-m0007-01) · Subtitle track export / Format · [строка 7](../../../../../benchmark/subtitles/requirements.md#L7)

> The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.  

**Сценарий.** Экспортировать непустую дорожку с допустимой репликой в локальный файл.

**Последствие.** Реализация и приёмка требуют разных первых байтов одного файла.

**Общее условие.** Один и тот же файл, записанный при экспорте и проверяемый на приёмке. Основания — [R-M0006-01](#r-m0006-01) «Write the exported track in UTF-8 without a byte-order mark.», [R-M0007-01](#r-m0007-01) «The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой файл должен пройти приёмку — с начальным BOM или без него?

1. **Вариант 1.** Записывать файл в UTF-8 без BOM.

   **Основание.** [R-M0006-01](#r-m0006-01) «Write the exported track in UTF-8 without a byte-order mark.».

   **Ожидаемый результат.** Начальный BOM отсутствует.

   При выборе этого варианта привести в соответствие [R-M0007-01](#r-m0007-01).

2. **Вариант 2.** Первые три байта экспортного файла должны быть BOM UTF-8.

   **Основание.** [R-M0007-01](#r-m0007-01) «The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

   **Ожидаемый результат.** Файл начинается с EF BB BF.

   При выборе этого варианта привести в соответствие [R-M0006-01](#r-m0006-01).

**Черновик приёмочного теста.** Экспортировать одну и ту же допустимую дорожку и проверить первые три байта файла.

### Z-003 · Масштаб временных меток

**Дефект · Противоречивость · Критичная.** T-3 объявляет миллисекунды для каждого поля временной метки и приписывает числу 1000 в таком поле одну минуту. Для приёмки времени реплики получаются две несовместимые длительности.

Затронутые утверждения — [R-M0008-01](#r-m0008-01), [R-M0008-02](#r-m0008-02).

[R-M0008-01](#r-m0008-01) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> Each timestamp field declares milliseconds  

[R-M0008-02](#r-m0008-02) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> Each timestamp field declares milliseconds; the numeric value 1000 represents one minute.  

**Сценарий.** Проверить поле экспортированной временной метки со значением 1000.

**Последствие.** Одна и та же метка означает одну секунду по заявленной единице и одну минуту по числовому правилу.

**Общее условие.** Поле экспортированной временной метки содержит число 1000. Объявление миллисекунд распространяется на каждое такое поле. Основания — [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds», [R-M0008-02](#r-m0008-02) «the numeric value 1000 represents one minute.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой отсчёт должен подтвердить тест для значения 1000 — одну секунду или одну минуту?

1. **Вариант 1.** Число в каждом поле временной метки выражено в миллисекундах.

   **Основание.** [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds».

   **Ожидаемый результат.** 1000 соответствует одной секунде.

   При выборе этого варианта привести в соответствие [R-M0008-02](#r-m0008-02).

2. **Вариант 2.** Числовое значение 1000 в поле временной метки означает одну минуту.

   **Основание.** [R-M0008-02](#r-m0008-02) «Each timestamp field declares milliseconds; the numeric value 1000 represents one minute.».

   **Ожидаемый результат.** 1000 соответствует одной минуте.

   При выборе этого варианта привести в соответствие [R-M0008-01](#r-m0008-01).

**Черновик приёмочного теста.** Проверить соответствие значения 1000 исходному времени метки и выбранной единице.

### Z-006 · Реплика из 81 кодовой точки

**Дефект · Противоречивость · Критичная.** Длина реплики в образце T-8 превышает порог T-7. Общее правило требует отклонить её, а образец требует принять. Проверку лимита по этому образцу невозможно принять.

Затронутые утверждения — [R-M0014-01](#r-m0014-01), [R-M0015-01](#r-m0015-01).

[R-M0014-01](#r-m0014-01) · Subtitle track export / Export limits · [строка 14](../../../../../benchmark/subtitles/requirements.md#L14)

> Reject a cue when its text exceeds 80 Unicode code points.  

[R-M0015-01](#r-m0015-01) · Subtitle track export / Export limits · [строка 15](../../../../../benchmark/subtitles/requirements.md#L15)

> In the acceptance sample, a cue of 81 Unicode code points is accepted.  

**Сценарий.** Выполнить приёмочный образец T-8 с указанной в нём репликой из 81 кодовой точки Unicode.

**Последствие.** Для одной реплики приёмка одновременно требует отклонения и принятия.

**Общее условие.** Проверяется реплика из приёмочного образца T-8 длиной 81 кодовая точка Unicode. Основания — [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.», [R-M0015-01](#r-m0015-01) «In the acceptance sample, a cue of 81 Unicode code points is accepted.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой исход должен подтвердить приёмочный образец — отклонение реплики или принятие?

1. **Вариант 1.** Отклонять реплику, если её текст превышает 80 кодовых точек Unicode, в том числе в приёмочном образце.

   **Основание.** [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.».

   **Ожидаемый результат.** Реплика образца отклонена.

   При выборе этого варианта привести в соответствие [R-M0015-01](#r-m0015-01).

2. **Вариант 2.** В приёмочном образце принимать реплику из 81 кодовой точки Unicode.

   **Основание.** [R-M0015-01](#r-m0015-01) «In the acceptance sample, a cue of 81 Unicode code points is accepted.».

   **Ожидаемый результат.** Реплика образца принята.

   При выборе этого варианта привести в соответствие [R-M0014-01](#r-m0014-01).

**Черновик приёмочного теста.** Выполнить экспорт для образца T-8 и проверить решение по его реплике.

### Z-005 · Критерий лёгкости экспорта

**Дефект · Проверяемость · Существенная.** T-4 требует, чтобы экспорт воспринимался лёгким каждым пользователем. Успешная запись файла сама по себе этого свойства не измеряет, а критерий оценки в ТЗ отсутствует.

Затронутые утверждения — [R-M0009-01](#r-m0009-01).

[R-M0009-01](#r-m0009-01) · Subtitle track export / Format · [строка 9](../../../../../benchmark/subtitles/requirements.md#L9)

> The export experience must feel effortless to every user.  

**Сценарий.** Пользователь выполняет экспорт открытой дорожки, и файл успешно записывается.

**Последствие.** Успешная запись подтверждает результат экспорта, а вывод о лёгкости остаётся на усмотрение проверяющего.

**Уже установлено.** Редактор экспортирует открытую дорожку в локальный файл. T-4 требует ощущения лёгкости у каждого пользователя. Основания — [R-M0009-01](#r-m0009-01), [R-M0003-02](#r-m0003-02).

**Открытое решение.** Определить измеримый критерий, по которому экспорт считается лёгким для каждого пользователя.

**Что различит проверка.** При оценке усилия по шкале от 0 до 4 результат проходит, если каждый участник поставил 0 или 1. / Те же оценки не проходят при требовании 0 у каждого участника, если хотя бы один поставил 1.

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой наблюдаемый критерий и способ проверки должны подтверждать требование о лёгкости экспорта для пользователей?

Внести ответ на этот вопрос в [R-M0009-01](#r-m0009-01) для сценария «Пользователь выполняет экспорт открытой дорожки, и файл успешно записывается.».

**Черновик приёмочного теста.** Дать пользователям выполнить экспорт и оценить результат по согласованному критерию и способу проверки.

### Z-001 · Каким должен быть результат записи в существующий файл, если на экспортируемой дорожке есть допустимая реплика и реплика, которую требуется отклонить по согласованному лимиту?

**Предполагаемый пробел · Полнота · Существенная.** T-7 задаёт отклонение реплики. T-5 определяет состояние назначения только для пустой дорожки. Результат записи непустой дорожки с допустимой и отклонённой репликами остаётся открытым.

Затронутые утверждения — [R-M0003-02](#r-m0003-02), [R-M0014-01](#r-m0014-01).

**Сценарий.** Экспортировать такую дорожку в заранее подготовленный локальный файл. Подтвердить отклонение реплики по лимиту и сверить итоговое содержимое файла с согласованным результатом.

**Что различит проверка.** Файл содержит допустимую реплику без отклонённой. / Файл сохраняет исходное содержимое.

### R-M0008-01 · В каждом поле временной метки указывается единица «миллисекунды».

## Готовность и порядок исправлений

ТЗ не готово к разработке с однозначной приёмкой. Сначала нужно согласовать начало файла, смысл временных меток и ожидаемое решение по реплике из приёмочного образца.

1. Согласовать правила и ожидаемые результаты приёмки для BOM, значения 1000 и реплики из 81 кодовой точки. ([Z-002](#z-002), [Z-003](#z-003), [Z-006](#z-006))
2. По согласованным правилам определить итоговое содержимое файла после отклонения реплики и проверяемое представление единицы в каждом поле. ([Z-001](#z-001), [Z-004](#z-004))
3. Задать измеримый критерий лёгкости экспорта и способ его проверки для пользователей. ([Z-005](#z-005))
