## Проверка набора в целом

Формат файла и шкала временных меток задают несовместимые результаты. Ограничение длины реплики расходится с приёмочным примером. Для лёгкости экспорта нужен измеримый критерий, а для сообщения о пустой дорожке — корректная ссылка.

Открытых предполагаемых пробелов — 0. Неоднозначностей — 0. Рекомендаций — 0.

Каждый ID утверждения учитывается один раз. В число нарушений входят подтверждённые дефекты и неоднозначности, для которых показаны две опирающиеся на текст трактовки с разными последствиями. Один и тот же конфликт имеет один ID при любом числе затронутых требований. Критичный дефект блокирует приёмку существенного обязательного сценария. Предполагаемый пробел оставляет открытым ожидаемое поведение или источник данных. Рекомендация предлагает улучшение. Вопросы и рекомендации имеют отдельные счётчики.

### Z-001 · BOM в экспортированном файле

**Дефект · Противоречивость · Критичная.** T-1 исключает BOM в экспортированном файле, а T-2 требует BOM в первых трёх байтах того же файла. Обычный экспорт нельзя принять по обоим требованиям.

Затронутые утверждения — [R-M0006-02](#r-m0006-02), [R-M0007-01](#r-m0007-01).

[R-M0006-02](#r-m0006-02) · Subtitle track export / Format · [строка 6](../../../../../benchmark/subtitles/requirements.md#L6)

> Write the exported track in UTF-8 without a byte-order mark.  

[R-M0007-01](#r-m0007-01) · Subtitle track export / Format · [строка 7](../../../../../benchmark/subtitles/requirements.md#L7)

> The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.  

**Сценарий.** Экспортировать непустую дорожку с допустимой репликой.

**Последствие.** Наличие BOM удовлетворяет только одному из двух требований.

**Общее условие.** Приёмка проверяет начало файла, записанного при экспорте допустимой непустой дорожки. Основания — [R-M0006-02](#r-m0006-02) «Write the exported track in UTF-8 without a byte-order mark.», [R-M0007-01](#r-m0007-01) «The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Должен ли файл начинаться с BOM UTF-8?

1. **Вариант 1.** Записывать файл в UTF-8 без BOM и ожидать его отсутствия при приёмке.

   **Основание.** [R-M0006-02](#r-m0006-02) «Write the exported track in UTF-8 without a byte-order mark.».

   **Ожидаемый результат.** Начальный BOM отсутствует.

   При выборе этого варианта привести в соответствие [R-M0007-01](#r-m0007-01).

2. **Вариант 2.** Записывать файл в UTF-8 с BOM в первых трёх байтах и проверять его наличие.

   **Основание.** [R-M0007-01](#r-m0007-01) «The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

   **Ожидаемый результат.** Первые три байта файла — EF BB BF.

   При выборе этого варианта привести в соответствие [R-M0006-02](#r-m0006-02).

**Черновик приёмочного теста.** После экспорта прочитать первые три байта и проверить выбранное условие на BOM.

### Z-002 · Шкала временных меток

**Дефект · Противоречивость · Критичная.** T-3 объявляет миллисекунды для каждого поля временной метки и в том же правиле сопоставляет одной минуте значение 1000. В объявленной единице минута равна 60000, поэтому приёмка временных меток требует согласованной шкалы.

Затронутые утверждения — [R-M0008-01](#r-m0008-01), [R-M0008-02](#r-m0008-02).

[R-M0008-01](#r-m0008-01) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> Each timestamp field declares milliseconds  

[R-M0008-02](#r-m0008-02) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> the numeric value 1000 represents one minute.  

**Сценарий.** Экспортировать реплику с временной меткой ровно в одну минуту.

**Последствие.** Экспорт одной и той же метки даёт разные числовые значения.

**Общее условие.** Экспортируемое поле временной метки представляет одну минуту. Объявленная единица и числовое соответствие заданы для этого поля. Основания — [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds», [R-M0008-02](#r-m0008-02) «the numeric value 1000 represents one minute.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какое значение должна содержать минутная метка при экспорте?

1. **Вариант 1.** Выражать числовые значения временных меток в миллисекундах.

   **Основание.** [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds».

   **Ожидаемый результат.** В поле записано 60000.

   При выборе этого варианта привести в соответствие [R-M0008-02](#r-m0008-02).

2. **Вариант 2.** Использовать шкалу, в которой значение 1000 соответствует одной минуте, и объявить соответствующую единицу.

   **Основание.** [R-M0008-02](#r-m0008-02) «the numeric value 1000 represents one minute.».

   **Ожидаемый результат.** В поле записано 1000.

   При выборе этого варианта привести в соответствие [R-M0008-01](#r-m0008-01).

**Черновик приёмочного теста.** Экспортировать минутную метку и сверить числовое значение и объявленную единицу с выбранной шкалой.

### Z-003 · Критерий лёгкости экспорта

**Дефект · Проверяемость · Существенная.** T-4 требует, чтобы каждый пользователь воспринимал экспорт как лёгкий. Для этого свойства отсутствует измеримый критерий приёмки. Успешность самого экспорта проверяется отдельно.

Затронутые утверждения — [R-M0009-01](#r-m0009-01).

[R-M0009-01](#r-m0009-01) · Subtitle track export / Format · [строка 9](../../../../../benchmark/subtitles/requirements.md#L9)

> The export experience must feel effortless to every user.  

**Сценарий.** Пользователь успешно экспортирует допустимую дорожку и оценивает, насколько легко ему было это сделать.

**Последствие.** По результатам экспорта и оценке пользователя нельзя вынести воспроизводимый вердикт о выполнении T-4.

**Уже установлено.** Пользователь экспортирует открытую дорожку в локальный файл. Требование лёгкости относится к каждому пользователю. Основания — [R-M0009-01](#r-m0009-01), [R-M0003-01](#r-m0003-01).

**Открытое решение.** Задать измеримый критерий лёгкости экспорта для каждого пользователя в условиях испытания.

**Что различит проверка.** При оценке 4 из 5 у каждого участника результат проходит приёмку, если критерий допускает такую оценку. / Тот же результат не проходит приёмку, если критерий требует 5 из 5 у каждого участника.

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** По какому наблюдаемому критерию и в каких условиях следует принимать требование лёгкости экспорта для каждого пользователя?

Внести ответ на этот вопрос в [R-M0009-01](#r-m0009-01) для сценария «Пользователь успешно экспортирует допустимую дорожку и оценивает, насколько легко ему было это сделать.».

**Черновик приёмочного теста.** Провести экспорт в согласованных условиях и оценить наблюдаемый результат по заданному критерию.

### Z-004 · Приёмка реплики из 81 кодовой точки

**Дефект · Противоречивость · Существенная.** T-7 распространяет предел на любую реплику длиннее 80 кодовых точек Unicode. T-8 требует принять реплику из 81 кодовой точки. Конфликт блокирует приёмку этого примера.

Затронутые утверждения — [R-M0014-01](#r-m0014-01), [R-M0015-01](#r-m0015-01).

[R-M0014-01](#r-m0014-01) · Subtitle track export / Export limits · [строка 14](../../../../../benchmark/subtitles/requirements.md#L14)

> Reject a cue when its text exceeds 80 Unicode code points.  

[R-M0015-01](#r-m0015-01) · Subtitle track export / Export limits · [строка 15](../../../../../benchmark/subtitles/requirements.md#L15)

> In the acceptance sample, a cue of 81 Unicode code points is accepted.  

**Сценарий.** Выполнить приёмочный пример с репликой, текст которой содержит 81 кодовую точку Unicode.

**Последствие.** Для одной реплики реализация и приёмочный пример требуют противоположных исходов.

**Общее условие.** Выполняется приёмочный пример с репликой из 81 кодовой точки Unicode. Её длина превышает предел T-7. Основания — [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.», [R-M0015-01](#r-m0015-01) «In the acceptance sample, a cue of 81 Unicode code points is accepted.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Должна ли реплика из приёмочного примера быть отклонена или принята?

1. **Вариант 1.** Отклонять реплики длиннее 80 кодовых точек Unicode, включая реплику из приёмочного примера.

   **Основание.** [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.».

   **Ожидаемый результат.** Реплика с 81 кодовой точкой отклонена.

   При выборе этого варианта привести в соответствие [R-M0015-01](#r-m0015-01).

2. **Вариант 2.** Принимать реплику из приёмочного примера с 81 кодовой точкой Unicode и согласовать с этим область общего ограничения.

   **Основание.** [R-M0015-01](#r-m0015-01) «In the acceptance sample, a cue of 81 Unicode code points is accepted.».

   **Ожидаемый результат.** Реплика с 81 кодовой точкой принята.

   При выборе этого варианта привести в соответствие [R-M0014-01](#r-m0014-01).

**Черновик приёмочного теста.** Выполнить экспорт с репликой из примера и проверить выбранный исход для этой реплики.

[R-M0011-01](#r-m0011-01) · Subtitle track export / Format · [строка 11](../../../../../benchmark/subtitles/requirements.md#L11)

**Сценарий.** При подготовке проверки экспорта пустой дорожки перейти по ссылке на сообщение из T-5.

**Последствие.** По указанному адресу нельзя получить текст для посимвольного сравнения.

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Черновик приёмочного теста.** Открыть исправленные пункты [R-M0010-01](#r-m0010-01), [R-M0011-01](#r-m0011-01) и проверить выполнение предложенной правки «Заменить оборванную ссылку ссылкой на требование, которое задаёт текст «Add at least one cue» для пустой дорожки.».

## Готовность и порядок исправлений

ТЗ не готово к разработке экспорта по единому набору приёмочных требований. Сначала нужно согласовать BOM, шкалу временных меток и исход примера с 81 кодовой точкой Unicode.

1. Согласовать наличие BOM с приёмкой, а единицу временной метки — с числовым значением одной минуты. ([Z-001](#z-001), [Z-002](#z-002))
2. Согласовать исход примера с 81 кодовой точкой Unicode с правилом длины реплики. ([Z-004](#z-004))
3. Задать измеримый критерий лёгкости экспорта и условия его проверки. ([Z-003](#z-003))
4. Заменить в T-5 ссылку на T-40 ссылкой на T-6. ([Z-005](#z-005))
