## Проверка набора в целом

Правило о BOM, шкала временных отметок и приёмка реплики из 81 кодовой точки задают несовместимые исходы. Для удобства экспорта отсутствует критерий проверки. Ссылка T-40 требует редакторского исправления. Сообщение при пустой дорожке уже задано в T-6, а состояние файла назначения определено в T-5.

Открытых предполагаемых пробелов — 0. Неоднозначностей — 0. Рекомендаций — 0.

Каждый ID утверждения учитывается один раз. В число нарушений входят подтверждённые дефекты и неоднозначности, для которых показаны две опирающиеся на текст трактовки с разными последствиями. Один и тот же конфликт имеет один ID при любом числе затронутых требований. Критичный дефект блокирует приёмку существенного обязательного сценария. Предполагаемый пробел оставляет открытым ожидаемое поведение или источник данных. Рекомендация предлагает улучшение. Вопросы и рекомендации имеют отдельные счётчики.

## Критичные дефекты

- [Z-001](#z-001) · T-1 требует записать файл без BOM, а T-2 требует BOM в первых трёх байтах этого же файла. Успешный экспорт нельзя принять по обоим требованиям.
- [Z-002](#z-002) · T-3 задаёт миллисекунды для каждого поля и одновременно приравнивает 1000 к минуте. Для такой отметки нельзя однозначно проверить время в экспортированном файле.

### Z-001 · BOM в файле экспорта

**Дефект · Противоречивость · Критичная.** T-1 требует записать файл без BOM, а T-2 требует BOM в первых трёх байтах этого же файла. Успешный экспорт нельзя принять по обоим требованиям.

Затронутые утверждения — [R-M0006-02](#r-m0006-02), [R-M0007-01](#r-m0007-01).

[R-M0006-02](#r-m0006-02) · Subtitle track export / Format · [строка 6](../../../../../benchmark/subtitles/requirements.md#L6)

> Write the exported track in UTF-8 without a byte-order mark.  

[R-M0007-01](#r-m0007-01) · Subtitle track export / Format · [строка 7](../../../../../benchmark/subtitles/requirements.md#L7)

> The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.  

**Сценарий.** Экспортировать непустую дорожку в локальный файл и прочитать первые три байта.

**Последствие.** Один файл не может пройти обе проверки.

**Общее условие.** Приёмочный тест проверяет первые три байта записанного файла экспорта. Основания — [R-M0006-02](#r-m0006-02) «Write the exported track in UTF-8 without a byte-order mark.», [R-M0007-01](#r-m0007-01) «The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой результат считать успешным при проверке начала файла?

1. **Вариант 1.** Записывать UTF-8 без BOM.

   **Основание.** [R-M0006-02](#r-m0006-02) «Write the exported track in UTF-8 without a byte-order mark.».

   **Ожидаемый результат.** Файл не начинается с EF BB BF.

   При выборе этого варианта привести в соответствие [R-M0007-01](#r-m0007-01).

2. **Вариант 2.** Требовать UTF-8 BOM в первых трёх байтах.

   **Основание.** [R-M0007-01](#r-m0007-01) «The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

   **Ожидаемый результат.** Файл начинается с EF BB BF.

   При выборе этого варианта привести в соответствие [R-M0006-02](#r-m0006-02).

**Черновик приёмочного теста.** На одном экспорте сравнить первые три байта с EF BB BF и проверить выбранное условие.

### Z-002 · Шкала временных отметок

**Дефект · Противоречивость · Критичная.** T-3 задаёт миллисекунды для каждого поля и одновременно приравнивает 1000 к минуте. Для такой отметки нельзя однозначно проверить время в экспортированном файле.

Затронутые утверждения — [R-M0008-01](#r-m0008-01), [R-M0008-02](#r-m0008-02).

[R-M0008-01](#r-m0008-01) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> Each timestamp field declares milliseconds  

[R-M0008-02](#r-m0008-02) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> the numeric value 1000 represents one minute.  

**Сценарий.** Прочитать поле временной отметки с числовым значением 1000.

**Последствие.** Одно и то же число соответствует разному времени.

**Общее условие.** В поле временной отметки, для которого объявлены миллисекунды, записано 1000. Основания — [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds», [R-M0008-02](#r-m0008-02) «the numeric value 1000 represents one minute.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какое время должна представлять отметка со значением 1000?

1. **Вариант 1.** Интерпретировать числовое значение поля в миллисекундах.

   **Основание.** [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds».

   **Ожидаемый результат.** 1000 означает одну секунду.

   При выборе этого варианта привести в соответствие [R-M0008-02](#r-m0008-02).

2. **Вариант 2.** Использовать шкалу, в которой 1000 означает одну минуту.

   **Основание.** [R-M0008-02](#r-m0008-02) «the numeric value 1000 represents one minute.».

   **Ожидаемый результат.** 1000 означает одну минуту.

   При выборе этого варианта привести в соответствие [R-M0008-01](#r-m0008-01).

**Черновик приёмочного теста.** Для поля со значением 1000 сверить представленное время с выбранным исходом.

<a id="z-004"></a>

### Z-004 · Приёмка реплики из 81 кодовой точки

**Дефект · Противоречивость · Критичная.** Текст реплики из T-8 содержит 81 кодовую точку Unicode и превышает предел T-7. Обязательный приёмочный пример требует принять реплику, которую то же правило экспорта требует отклонить.

Затронутые утверждения — [R-M0014-01](#r-m0014-01), [R-M0015-01](#r-m0015-01).

[R-M0014-01](#r-m0014-01) · Subtitle track export / Export limits · [строка 14](../../../../../benchmark/subtitles/requirements.md#L14)

> Reject a cue when its text exceeds 80 Unicode code points.  

[R-M0015-01](#r-m0015-01) · Subtitle track export / Export limits · [строка 15](../../../../../benchmark/subtitles/requirements.md#L15)

> In the acceptance sample, a cue of 81 Unicode code points is accepted.  

**Сценарий.** При экспорте проверить реплику из T-8 с текстом длиной 81 кодовая точка Unicode.

**Последствие.** В одном сценарии проверка длины требует одновременно отклонить и принять реплику.

**Общее условие.** При экспорте проверяется реплика из приёмочного примера, текст которой содержит 81 кодовую точку Unicode. Основания — [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.», [R-M0015-01](#r-m0015-01) «In the acceptance sample, a cue of 81 Unicode code points is accepted.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Приёмочный пример с 81 кодовой точкой должен завершиться принятием или отклонением реплики?

1. **Вариант 1.** Отклонять реплику, если её текст превышает 80 кодовых точек Unicode.

   **Основание.** [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.».

   **Ожидаемый результат.** Реплика из примера отклонена.

   При выборе этого варианта привести в соответствие [R-M0015-01](#r-m0015-01).

2. **Вариант 2.** Принимать реплику из приёмочного примера длиной 81 кодовая точка Unicode.

   **Основание.** [R-M0015-01](#r-m0015-01) «In the acceptance sample, a cue of 81 Unicode code points is accepted.».

   **Ожидаемый результат.** Реплика из примера принята.

   При выборе этого варианта привести в соответствие [R-M0014-01](#r-m0014-01).

**Черновик приёмочного теста.** Проверить решение по реплике из примера, сохранив длину её текста в 81 кодовую точку.

<a id="z-003"></a>

### Z-003 · Критерий удобства экспорта

**Дефект · Проверяемость · Существенная.** T-4 требует, чтобы экспорт воспринимался как лёгкий каждым пользователем. Без наблюдаемого критерия успешный экспорт сам по себе не позволяет проверить это свойство.

Затронутые утверждения — [R-M0009-01](#r-m0009-01).

[R-M0009-01](#r-m0009-01) · Subtitle track export / Format · [строка 9](../../../../../benchmark/subtitles/requirements.md#L9)

> The export experience must feel effortless to every user.  

**Сценарий.** Пользователь успешно экспортирует открытую дорожку, после чего проверяющий оценивает удобство экспорта.

**Последствие.** Проверяющие могут вынести разные решения о соответствии T-4 при одинаковом результате.

**Уже установлено.** Редактор экспортирует одну открытую дорожку в локальный файл. T-4 распространяет требование к удобству на каждого пользователя. Основания — [R-M0009-01](#r-m0009-01), [R-M0003-01](#r-m0003-01).

**Открытое решение.** По какому наблюдаемому критерию в согласованных условиях считать экспорт лёгким для каждого пользователя?

**Что различит проверка.** В одном и том же испытании наблюдаемые действия каждого пользователя укладываются в выбранный критерий, и T-4 проходит проверку. / В том же испытании действия хотя бы одного пользователя выходят за пределы выбранного критерия, и T-4 не проходит проверку.

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** По какому наблюдаемому критерию и в каких условиях оценивать выполнение T-4 для заявленных пользователей?

Внести ответ на этот вопрос в [R-M0009-01](#r-m0009-01) для сценария «Пользователь успешно экспортирует открытую дорожку, после чего проверяющий оценивает удобство экспорта.».

**Черновик приёмочного теста.** Выполнить экспорт в согласованных условиях и проверить результат по заданному критерию.

<a id="decision"></a>

## Готовность и порядок исправлений

ТЗ не готово к разработке и приёмке экспорта до согласования требований к формату файла, трактовке временных отметок и проверке длины текста реплики.

1. Согласовать наличие BOM и время, соответствующее значению 1000. Привести правила формата и приёмочные ожидания в соответствие. ([Z-001](#z-001), [Z-002](#z-002))
2. Согласовать правило предельной длины с ожидаемым исходом для реплики из примера с 81 кодовой точкой Unicode. ([Z-004](#z-004))
3. Задать наблюдаемый критерий и условия проверки удобства экспорта. ([Z-003](#z-003))
4. Исправить ссылку T-40 редакторской правкой. ([Z-005](#z-005))
