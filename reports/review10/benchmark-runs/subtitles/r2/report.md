## Проверка набора в целом

Требования расходятся по наличию BOM, шкале временных меток и приёмке реплики из 81 кодовой точки. Удобство экспорта не измеримо по T-4. В T-5 требуется редакторское исправление ссылки T-40. Текст сообщения уже задан в T-6.

Открытых предполагаемых пробелов — 0. Неоднозначностей — 0. Рекомендаций — 0.

Каждый ID утверждения учитывается один раз. В число нарушений входят подтверждённые дефекты и неоднозначности, для которых показаны две опирающиеся на текст трактовки с разными последствиями. Один и тот же конфликт имеет один ID при любом числе затронутых требований. Критичный дефект блокирует приёмку существенного обязательного сценария. Предполагаемый пробел оставляет открытым ожидаемое поведение или источник данных. Рекомендация предлагает улучшение. Вопросы и рекомендации имеют отдельные счётчики.

### Z-002 · BOM в экспортированном файле

**Дефект · Противоречивость · Критичная.** T-1 запрещает BOM в экспортированном файле, а T-2 требует BOM в первых трёх байтах этого же файла. Успешный экспорт нельзя принять по обоим пунктам.

Затронутые утверждения — [R-M0006-02](#r-m0006-02), [R-M0007-01](#r-m0007-01).

[R-M0006-02](#r-m0006-02) · Subtitle track export / Format · [строка 6](../../../../../benchmark/subtitles/requirements.md#L6)

> Write the exported track in UTF-8 without a byte-order mark.  

[R-M0007-01](#r-m0007-01) · Subtitle track export / Format · [строка 7](../../../../../benchmark/subtitles/requirements.md#L7)

> The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.  

**Сценарий.** Успешно экспортировать непустую дорожку с допустимой репликой в локальный файл.

**Последствие.** Один и тот же файл должен одновременно содержать и не содержать начальную метку UTF-8 BOM.

**Общее условие.** Проверяются первые три байта файла после успешного экспорта дорожки. Основания — [R-M0006-02](#r-m0006-02) «Write the exported track in UTF-8 without a byte-order mark.», [R-M0007-01](#r-m0007-01) «The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой результат должна требовать приёмка, наличие или отсутствие начальной метки UTF-8 BOM?

1. **Вариант 1.** Записывать файл в UTF-8 без начальной метки BOM.

   **Основание.** [R-M0006-02](#r-m0006-02) «Write the exported track in UTF-8 without a byte-order mark.».

   **Ожидаемый результат.** Первые три байта файла не образуют UTF-8 BOM.

   При выборе этого варианта привести в соответствие [R-M0007-01](#r-m0007-01).

2. **Вариант 2.** Записывать файл в UTF-8 с меткой BOM в первых трёх байтах.

   **Основание.** [R-M0007-01](#r-m0007-01) «The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

   **Ожидаемый результат.** Первые три байта файла — EF BB BF.

   При выборе этого варианта привести в соответствие [R-M0006-02](#r-m0006-02).

**Черновик приёмочного теста.** Экспортировать дорожку из сценария, прочитать первые три байта файла и сверить наличие BOM с выбранным правилом.

### Z-003 · Шкала временных меток

**Дефект · Противоречивость · Критичная.** T-3 объявляет миллисекунды для каждого поля временной метки и задаёт для 1000 одну минуту. Выходную шкалу нельзя принять по обоим правилам.

Затронутые утверждения — [R-M0008-01](#r-m0008-01), [R-M0008-02](#r-m0008-02).

[R-M0008-01](#r-m0008-01) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> Each timestamp field declares milliseconds  

[R-M0008-02](#r-m0008-02) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> Each timestamp field declares milliseconds; the numeric value 1000 represents one minute.  

**Сценарий.** Интерпретировать значение 1000 в экспортированном поле временной метки.

**Последствие.** Объявленная единица даёт одну секунду, а правило для значения 1000 даёт одну минуту.

**Общее условие.** В экспортированном поле временной метки указано значение 1000. Основания — [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds», [R-M0008-02](#r-m0008-02) «the numeric value 1000 represents one minute.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой момент должен обозначать 1000 при приёмке, одну секунду или одну минуту?

1. **Вариант 1.** Объявлять миллисекунды и интерпретировать числовое значение каждого поля в миллисекундах.

   **Основание.** [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds».

   **Ожидаемый результат.** Значение 1000 соответствует одной секунде.

   При выборе этого варианта привести в соответствие [R-M0008-02](#r-m0008-02).

2. **Вариант 2.** Сохранить соответствие значения 1000 одной минуте и согласовать с ним объявление единицы и шкалы поля.

   **Основание.** [R-M0008-02](#r-m0008-02) «Each timestamp field declares milliseconds; the numeric value 1000 represents one minute.».

   **Ожидаемый результат.** Значение 1000 соответствует одной минуте.

   При выборе этого варианта привести в соответствие [R-M0008-01](#r-m0008-01).

**Черновик приёмочного теста.** Прочитать объявленную единицу поля со значением 1000 и проверить, что она и числовая шкала дают выбранный момент.

### Z-001 · Критерий удобства экспорта

**Дефект · Проверяемость · Существенная.** T-4 требует, чтобы экспорт воспринимался как лёгкий каждым пользователем. Показатель, порог и способ проверки заявленного охвата не заданы.

Затронутые утверждения — [R-M0003-01](#r-m0003-01), [R-M0003-02](#r-m0003-02), [R-M0009-01](#r-m0009-01).

[R-M0003-01](#r-m0003-01) · Subtitle track export · [строка 3](../../../../../benchmark/subtitles/requirements.md#L3)

> exports one open track to a local file  

[R-M0003-02](#r-m0003-02) · Subtitle track export · [строка 3](../../../../../benchmark/subtitles/requirements.md#L3)

> exports one open track to a local file  

[R-M0009-01](#r-m0009-01) · Subtitle track export / Format · [строка 9](../../../../../benchmark/subtitles/requirements.md#L9)

> The export experience must feel effortless to every user.  

**Сценарий.** Пользователь экспортирует одну открытую дорожку в локальный файл. Проверяющий оценивает, выполнено ли T-4.

**Последствие.** По одному и тому же наблюдению проверяющие могут вынести разные вердикты.

**Уже установлено.** T-4 распространяется на каждого пользователя при экспорте одной открытой дорожки в локальный файл. Основания — [R-M0009-01](#r-m0009-01), [R-M0003-01](#r-m0003-01).

**Открытое решение.** Установить измеримый критерий лёгкости экспорта и способ проверки заявленного охвата.

**Что различит проверка.** При выбранном критерии результаты испытания подтверждают выполнение T-4. / При другом критерии те же результаты испытания не подтверждают выполнение T-4.

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой наблюдаемый показатель, порог и охват пользователей определяют выполнение T-4 при экспорте дорожки?

Внести ответ на этот вопрос в [R-M0003-01](#r-m0003-01), [R-M0003-02](#r-m0003-02), [R-M0009-01](#r-m0009-01) для сценария «Пользователь экспортирует одну открытую дорожку в локальный файл. Проверяющий оценивает, выполнено ли T-4.».

**Черновик приёмочного теста.** Проверить сценарий экспорта на согласованной группе пользователей и сравнить наблюдаемый показатель с согласованным порогом.

### Z-004 · Приёмка реплики из 81 кодовой точки

**Дефект · Противоречивость · Существенная.** Текст реплики из T-8 содержит 81 кодовую точку Unicode. Лимит T-7 требует её отклонить, а приёмочный пример требует принять. Расхождение касается проверки превышения лимита.

Затронутые утверждения — [R-M0014-01](#r-m0014-01), [R-M0015-01](#r-m0015-01).

[R-M0014-01](#r-m0014-01) · Subtitle track export / Export limits · [строка 14](../../../../../benchmark/subtitles/requirements.md#L14)

> Reject a cue when its text exceeds 80 Unicode code points.  

[R-M0015-01](#r-m0015-01) · Subtitle track export / Export limits · [строка 15](../../../../../benchmark/subtitles/requirements.md#L15)

> In the acceptance sample, a cue of 81 Unicode code points is accepted.  

**Сценарий.** Проверить реплику из приёмочного примера T-8, текст которой содержит 81 кодовую точку Unicode.

**Последствие.** 81 превышает предел 80, поэтому T-7 требует отклонения реплики, а T-8 требует её принятия.

**Общее условие.** Проверяется реплика из приёмочного примера с текстом длиной 81 кодовая точка Unicode. Основания — [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.», [R-M0015-01](#r-m0015-01) «In the acceptance sample, a cue of 81 Unicode code points is accepted.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Реплику из 81 кодовой точки в приёмочном примере нужно отклонить или принять?

1. **Вариант 1.** Отклонять реплики с текстом длиннее 80 кодовых точек Unicode, включая реплику из приёмочного примера.

   **Основание.** [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.».

   **Ожидаемый результат.** Реплика из 81 кодовой точки отклонена.

   При выборе этого варианта привести в соответствие [R-M0015-01](#r-m0015-01).

2. **Вариант 2.** Явно предусмотреть принятие реплики из 81 кодовой точки в приёмочном примере.

   **Основание.** [R-M0015-01](#r-m0015-01) «In the acceptance sample, a cue of 81 Unicode code points is accepted.».

   **Ожидаемый результат.** Реплика из 81 кодовой точки принята.

   При выборе этого варианта привести в соответствие [R-M0014-01](#r-m0014-01).

**Черновик приёмочного теста.** Подать реплику из примера T-8, подтвердить длину её текста в кодовых точках и проверить выбранный исход на уровне реплики.

<a id="decision"></a>

## Готовность и порядок исправлений

ТЗ не готово к разработке с однозначной приёмкой. Сначала нужно согласовать формат файла и шкалу времени, затем определить ожидаемый исход для реплики из примера и критерий удобства. Ссылку T-40 можно исправить параллельно.

1. Согласовать наличие BOM при записи и приёмке, а также объявленную единицу и смысл значения 1000. ([Z-002](#z-002), [Z-003](#z-003))
2. Согласовать лимит текста реплики с приёмочным исходом для 81 кодовой точки Unicode. ([Z-004](#z-004))
3. Задать измеримый критерий удобства экспорта и способ проверки заявленного охвата пользователей. ([Z-001](#z-001))
4. Исправить ссылку T-40 в T-5 редакторской правкой. ([Z-005](#z-005))
