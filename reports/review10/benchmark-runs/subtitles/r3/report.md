## Проверка набора в целом

Правила расходятся по наличию BOM, шкале значения временной метки 1000 и исходу для реплики из 81 кодовой точки. Для лёгкости экспорта отсутствует критерий проверки. Ссылка T-40 требует редакторского исправления. Сообщение для пустой дорожки уже задано в T-6, а сохранение места назначения предписано T-5.

Открытых предполагаемых пробелов — 0. Неоднозначностей — 0. Рекомендаций — 0.

Каждый ID утверждения учитывается один раз. В число нарушений входят подтверждённые дефекты и неоднозначности, для которых показаны две опирающиеся на текст трактовки с разными последствиями. Один и тот же конфликт имеет один ID при любом числе затронутых требований. Критичный дефект блокирует приёмку существенного обязательного сценария. Предполагаемый пробел оставляет открытым ожидаемое поведение или источник данных. Рекомендация предлагает улучшение. Вопросы и рекомендации имеют отдельные счётчики.

### Z-001 · Наличие BOM в экспортируемом файле

**Дефект · Противоречивость · Критичная.** T-1 запрещает BOM в экспортируемом файле, а T-2 требует BOM в первых трёх байтах этого же файла. Успешный экспорт невозможно принять по обоим правилам.

Затронутые утверждения — [R-M0006-02](#r-m0006-02), [R-M0007-01](#r-m0007-01).

[R-M0006-02](#r-m0006-02) · Subtitle track export / Format · [строка 6](../../../../../benchmark/subtitles/requirements.md#L6)

> Write the exported track in UTF-8 without a byte-order mark.  

[R-M0007-01](#r-m0007-01) · Subtitle track export / Format · [строка 7](../../../../../benchmark/subtitles/requirements.md#L7)

> The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.  

**Сценарий.** Экспортировать непустую дорожку и проверить начало полученного локального файла.

**Последствие.** Один и тот же файл должен одновременно начинаться с UTF-8 BOM и не иметь BOM.

**Общее условие.** Приёмка локального файла, полученного при успешном экспорте одной открытой непустой дорожки. Основания — [R-M0006-02](#r-m0006-02) «Write the exported track in UTF-8 without a byte-order mark.», [R-M0007-01](#r-m0007-01) «The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой результат считать правильным при приёмке файла — отсутствие UTF-8 BOM или его наличие в первых трёх байтах?

1. **Вариант 1.** Записывать дорожку в UTF-8 без BOM.

   **Основание.** [R-M0006-02](#r-m0006-02) «Write the exported track in UTF-8 without a byte-order mark.».

   **Ожидаемый результат.** В начале файла нет UTF-8 BOM.

   При выборе этого варианта привести в соответствие [R-M0007-01](#r-m0007-01).

2. **Вариант 2.** Записывать дорожку в UTF-8 с BOM в первых трёх байтах.

   **Основание.** [R-M0007-01](#r-m0007-01) «The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

   **Ожидаемый результат.** Первые три байта файла — EF BB BF.

   При выборе этого варианта привести в соответствие [R-M0006-02](#r-m0006-02).

**Черновик приёмочного теста.** Экспортировать одну непустую дорожку и проверить первые три байта файла по выбранному правилу.

### Z-002 · Шкала временных меток

**Дефект · Противоречивость · Критичная.** Для одного значения 1000 в поле T-3 объявляет миллисекунды и одновременно задаёт одну минуту. По объявленной единице это одна секунда. Числовую шкалу экспорта невозможно принять однозначно.

Затронутые утверждения — [R-M0008-01](#r-m0008-01), [R-M0008-02](#r-m0008-02).

[R-M0008-01](#r-m0008-01) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> Each timestamp field declares milliseconds  

[R-M0008-02](#r-m0008-02) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> Each timestamp field declares milliseconds; the numeric value 1000 represents one minute.  

**Сценарий.** Интерпретировать значение 1000 в экспортированном поле временной метки, которое объявляет миллисекунды.

**Последствие.** По заявленной единице значение соответствует одной секунде, а по явному соответствию T-3 — одной минуте.

**Общее условие.** Экспортированное поле временной метки объявляет миллисекунды и содержит числовое значение 1000. Основания — [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds», [R-M0008-02](#r-m0008-02) «Each timestamp field declares milliseconds; the numeric value 1000 represents one minute.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** При значении 1000 принимать временную метку как одну секунду или как одну минуту?

1. **Вариант 1.** Числовые значения всех полей временных меток выражаются в миллисекундах.

   **Основание.** [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds».

   **Ожидаемый результат.** Значение 1000 означает одну секунду.

   При выборе этого варианта привести в соответствие [R-M0008-02](#r-m0008-02).

2. **Вариант 2.** Временные метки используют шкалу, в которой значение 1000 означает одну минуту.

   **Основание.** [R-M0008-02](#r-m0008-02) «Each timestamp field declares milliseconds; the numeric value 1000 represents one minute.».

   **Ожидаемый результат.** Значение 1000 означает одну минуту.

   При выборе этого варианта привести в соответствие [R-M0008-01](#r-m0008-01).

**Черновик приёмочного теста.** Для поля со значением 1000 сверить полученную длительность с выбранным исходом и проверить соответствие объявленной единицы выбранной шкале.

### Z-003 · Критерий лёгкости экспорта

**Дефект · Проверяемость · Существенная.** T-4 требует, чтобы экспорт ощущался лёгким для каждого пользователя, но не задаёт наблюдаемой меры и порога прохождения. Успешность записи файла можно проверить отдельно.

Затронутые утверждения — [R-M0009-01](#r-m0009-01).

[R-M0009-01](#r-m0009-01) · Subtitle track export / Format · [строка 9](../../../../../benchmark/subtitles/requirements.md#L9)

> The export experience must feel effortless to every user.  

**Сценарий.** Дать пользователю выполнить экспорт открытой дорожки и оценить, выполнено ли T-4.

**Последствие.** Даже успешный экспорт и отзыв пользователя не дают однозначного решения о соответствии T-4.

**Уже установлено.** Сценарий включает экспорт одной открытой дорожки в локальный файл. Требование к лёгкости экспорта относится к каждому пользователю. Основания — [R-M0009-01](#r-m0009-01), [R-M0003-02](#r-m0003-02).

**Открытое решение.** Какой наблюдаемый критерий считать мерой лёгкости выполнения экспорта?

**Что различит проверка.** В испытании пользователь успешно экспортирует дорожку со второй попытки и проходит проверку, если критерий допускает одну повторную попытку. / Тот же результат не проходит проверку, если критерий требует успеха с первой попытки.

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой наблюдаемый результат, на каком сценарии и для каких пользователей считать прохождением T-4?

Внести ответ на этот вопрос в [R-M0009-01](#r-m0009-01) для сценария «Дать пользователю выполнить экспорт открытой дорожки и оценить, выполнено ли T-4.».

**Черновик приёмочного теста.** Провести согласованный сценарий экспорта с заданными участниками и сравнить результаты с утверждённым критерием.

### Z-004 · Приёмка реплики из 81 кодовой точки

**Дефект · Противоречивость · Существенная.** Текст реплики из примера содержит 81 кодовую точку Unicode. T-7 требует отклонить её, а T-8 фиксирует принятие. Расхождение блокирует приёмку проверки лимита на этом примере.

Затронутые утверждения — [R-M0014-01](#r-m0014-01), [R-M0015-01](#r-m0015-01).

[R-M0014-01](#r-m0014-01) · Subtitle track export / Export limits · [строка 14](../../../../../benchmark/subtitles/requirements.md#L14)

> Reject a cue when its text exceeds 80 Unicode code points.  

[R-M0015-01](#r-m0015-01) · Subtitle track export / Export limits · [строка 15](../../../../../benchmark/subtitles/requirements.md#L15)

> In the acceptance sample, a cue of 81 Unicode code points is accepted.  

**Сценарий.** Выполнить приёмочный пример T-8 с репликой, текст которой содержит ровно 81 кодовую точку Unicode.

**Последствие.** 81 превышает предел 80, поэтому T-7 требует отклонить реплику, а T-8 требует её принять. Исключение для примера не задано.

**Общее условие.** На экспорт подана реплика из приёмочного примера с текстом ровно в 81 кодовую точку Unicode. К её тексту применяется предел T-7 в 80 кодовых точек. Основания — [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.», [R-M0015-01](#r-m0015-01) «In the acceptance sample, a cue of 81 Unicode code points is accepted.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой исход должен проверять пример T-8 — отклонение или принятие реплики из 81 кодовой точки Unicode?

1. **Вариант 1.** Отклонять реплику, если её текст превышает 80 кодовых точек Unicode, включая приёмочный пример.

   **Основание.** [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.».

   **Ожидаемый результат.** Реплика из 81 кодовой точки отклонена.

   При выборе этого варианта привести в соответствие [R-M0015-01](#r-m0015-01).

2. **Вариант 2.** Принимать реплику из 81 кодовой точки Unicode в приёмочном примере.

   **Основание.** [R-M0015-01](#r-m0015-01) «In the acceptance sample, a cue of 81 Unicode code points is accepted.».

   **Ожидаемый результат.** Реплика из 81 кодовой точки принята.

   При выборе этого варианта привести в соответствие [R-M0014-01](#r-m0014-01).

**Черновик приёмочного теста.** Подать на экспорт реплику из примера с текстом ровно в 81 кодовую точку Unicode и проверить, принята ли она.

<a id="decision"></a>

## Готовность и порядок исправлений

ТЗ не готово к разработке и приёмке. Сначала нужно согласовать формат файла и ожидаемый исход проверки лимита, затем определить критерий лёгкости экспорта и исправить ссылку T-40.

1. Согласовать наличие BOM и соответствие числа 1000 объявленной единице временной метки. ([Z-001](#z-001), [Z-002](#z-002))
2. Согласовать правило длины с ожидаемым исходом приёмочного примера для 81 кодовой точки Unicode. ([Z-004](#z-004))
3. Установить наблюдаемый критерий лёгкости экспорта и способ его проверки. ([Z-003](#z-003))
4. Исправить ссылку T-40 в правиле для пустой дорожки. ([Z-005](#z-005))
