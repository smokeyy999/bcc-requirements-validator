### Z-002 · Какое наблюдаемое представление считается объявлением миллисекунд для каждого поля временной метки?

**Предполагаемый пробел · Проверяемость · Существенная.** T-3 требует объявления миллисекунд для каждого поля. Значение 1000 при метке в одну секунду подтверждает шкалу. Для проверки объявления нужен отдельный наблюдаемый признак.

Затронутые утверждения — [R-M0008-01](#r-m0008-01).

[R-M0008-01](#r-m0008-01) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/baseline.md#L8)

> Each timestamp field declares milliseconds  

**Сценарий.** Экспортировать дорожку с меткой в одну секунду. Проверить число 1000 в соответствующем поле и наличие объявления миллисекунд в согласованной форме для каждого поля временной метки.

**Последствие.** T-3 требует объявления миллисекунд для каждого поля. Значение 1000 при метке в одну секунду подтверждает шкалу. Для проверки объявления нужен отдельный наблюдаемый признак.

**Уже установлено.** Каждое поле объявляет миллисекунды. Одна секунда представлена числом 1000. Основания — [R-M0008-01](#r-m0008-01), [R-M0008-02](#r-m0008-02).

**Открытое решение.** Какой признак подтверждает, что конкретное поле объявляет миллисекунды.

**Что различит проверка.** Файл с числом 1000 для метки в одну секунду и обозначением миллисекунд в имени каждого поля проходит проверку, если обозначение в имени считается объявлением. / Тот же файл проходит проверку числа и проваливает проверку объявления, если для каждого поля требуется отдельный атрибут единицы.

### Z-003 · Каким должно быть состояние существующего файла назначения после экспорта дорожки с репликами из 80 и 81 кодовой точки при обязательном отклонении второй реплики?

**Предполагаемый пробел · Полнота · Существенная.** T-7 и T-8 устанавливают отклонение реплики из 81 кодовой точки. Исход для файла и реплики из 80 кодовых точек при смешанном экспорте открыт. T-5 задаёт сохранение назначения для пустой дорожки.

Затронутые утверждения — [R-M0014-01](#r-m0014-01).

[R-M0014-01](#r-m0014-01) · Subtitle track export / Export limits · [строка 14](../../../../../benchmark/subtitles/baseline.md#L14)

> Reject a cue when its text exceeds 80 Unicode code points.  

**Сценарий.** Подготовить существующий файл с отличимым содержимым и выполнить экспорт дорожки с репликами из 80 и 81 кодовой точки. Убедиться, что реплика из 81 кодовой точки не записана, и сверить состояние файла и наличие реплики из 80 кодовых точек с согласованным исходом.

**Последствие.** T-7 и T-8 устанавливают отклонение реплики из 81 кодовой точки. Исход для файла и реплики из 80 кодовых точек при смешанном экспорте открыт. T-5 задаёт сохранение назначения для пустой дорожки.

**Уже установлено.** Команда экспортирует одну открытую дорожку. Реплика из 81 кодовой точки отклоняется, а порог длины не требует отклонять реплику из 80 кодовых точек. Для пустой дорожки файл остаётся прежним. Основания — [R-M0014-01](#r-m0014-01), [R-M0003-01](#r-m0003-01), [R-M0015-01](#r-m0015-01), [R-M0010-02](#r-m0010-02).

**Открытое решение.** Какой результат команды экспорта ожидается в файле назначения после отклонения одной реплики в смешанной дорожке.

**Что различит проверка.** Файл обновлён и содержит реплику из 80 кодовых точек. Реплика из 81 кодовой точки не записана. / Экспорт отменён. Файл сохраняет исходное содержимое, обе реплики из дорожки не записаны.
