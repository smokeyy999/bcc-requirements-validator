## Проверка набора в целом

Правила записи и приёмки расходятся по BOM, смыслу временной метки 1000 и обработке реплики из 81 кодовой точки Unicode. Итог смешанного экспорта требует уточнения, а удобство экспорта требует измеримого критерия. Ссылка на отсутствующий T-40 требует редакторской правки. Сообщение для пустой дорожки задано в T-6.

Открытых предполагаемых пробелов — 1. Неоднозначностей — 0. Рекомендаций — 0.

Каждый ID утверждения учитывается один раз. В число нарушений входят подтверждённые дефекты и неоднозначности, для которых показаны две опирающиеся на текст трактовки с разными последствиями. Один и тот же конфликт имеет один ID при любом числе затронутых требований. Критичный дефект блокирует приёмку существенного обязательного сценария. Предполагаемый пробел оставляет открытым ожидаемое поведение или источник данных. Рекомендация предлагает улучшение. Вопросы и рекомендации имеют отдельные счётчики.

## Критичные дефекты

- [Z-001](#z-001) · T-1 запрещает BOM в экспортированном файле, а T-2 требует BOM в первых трёх байтах этого же файла. Ни один результат записи не удовлетворяет обоим требованиям.
- [Z-003](#z-003) · T-3 объявляет миллисекунды для каждого поля и сопоставляет числу 1000 одну минуту. Для того же числа объявленная единица даёт одну секунду, поэтому приёмка временных меток заблокирована.
- [Z-004](#z-004) · T-7 требует отклонить текст длиннее 80 кодовых точек Unicode. T-8 принимает реплику из 81 кодовой точки, поэтому для заданного приёмочного примера невозможно выполнить оба требования.

### Z-001 · BOM в файле экспорта

**Дефект · Противоречивость · Критичная.** T-1 запрещает BOM в экспортированном файле, а T-2 требует BOM в первых трёх байтах этого же файла. Ни один результат записи не удовлетворяет обоим требованиям.

Затронутые утверждения — [R-M0006-02](#r-m0006-02), [R-M0007-01](#r-m0007-01).

[R-M0006-02](#r-m0006-02) · Subtitle track export / Format · [строка 6](../../../../../benchmark/subtitles/requirements.md#L6)

> Write the exported track in UTF-8 without a byte-order mark.  

[R-M0007-01](#r-m0007-01) · Subtitle track export / Format · [строка 7](../../../../../benchmark/subtitles/requirements.md#L7)

> The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.  

**Сценарий.** Экспортировать непустую открытую дорожку с допустимой репликой.

**Последствие.** Файл без BOM нарушает T-2, файл с BOM нарушает T-1.

**Общее условие.** Приёмка проверяет первые три байта файла, созданного экспортом открытой дорожки с допустимой репликой. Основания — [R-M0006-02](#r-m0006-02) «Write the exported track in UTF-8 without a byte-order mark.», [R-M0007-01](#r-m0007-01) «The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой файл должен пройти приёмку — с BOM UTF-8 или без него?

1. **Вариант 1.** Записывать дорожку в UTF-8 без BOM.

   **Основание.** [R-M0006-02](#r-m0006-02) «Write the exported track in UTF-8 without a byte-order mark.».

   **Ожидаемый результат.** В начале файла нет BOM UTF-8.

   При выборе этого варианта привести в соответствие [R-M0007-01](#r-m0007-01).

2. **Вариант 2.** Первые три байта файла должны быть BOM UTF-8.

   **Основание.** [R-M0007-01](#r-m0007-01) «The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

   **Ожидаемый результат.** Первые три байта файла содержат BOM UTF-8.

   При выборе этого варианта привести в соответствие [R-M0006-02](#r-m0006-02).

**Черновик приёмочного теста.** Экспортировать дорожку и проверить первые байты файла на BOM UTF-8.

### Z-003 · Шкала временных меток

**Дефект · Противоречивость · Критичная.** T-3 объявляет миллисекунды для каждого поля и сопоставляет числу 1000 одну минуту. Для того же числа объявленная единица даёт одну секунду, поэтому приёмка временных меток заблокирована.

Затронутые утверждения — [R-M0008-01](#r-m0008-01), [R-M0008-02](#r-m0008-02).

[R-M0008-01](#r-m0008-01) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> Each timestamp field declares milliseconds  

[R-M0008-02](#r-m0008-02) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> Each timestamp field declares milliseconds; the numeric value 1000 represents one minute.  

**Сценарий.** В экспортированном поле временной метки записано значение 1000.

**Последствие.** По объявленным миллисекундам метка соответствует одной секунде, по явной расшифровке — одной минуте.

**Общее условие.** Число 1000 находится в экспортированном поле временной метки, для которого T-3 объявляет миллисекунды. Основания — [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds», [R-M0008-02](#r-m0008-02) «Each timestamp field declares milliseconds; the numeric value 1000 represents one minute.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какое время должно соответствовать значению 1000 при приёмке — одна секунда или одна минута?

1. **Вариант 1.** Интерпретировать числовые значения полей временных меток в миллисекундах.

   **Основание.** [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds».

   **Ожидаемый результат.** Метка 1000 соответствует одной секунде.

   При выборе этого варианта привести в соответствие [R-M0008-02](#r-m0008-02).

2. **Вариант 2.** Значение 1000 в поле временной метки означает одну минуту.

   **Основание.** [R-M0008-02](#r-m0008-02) «Each timestamp field declares milliseconds; the numeric value 1000 represents one minute.».

   **Ожидаемый результат.** Метка 1000 соответствует одной минуте.

   При выборе этого варианта привести в соответствие [R-M0008-01](#r-m0008-01).

**Черновик приёмочного теста.** Проверить, какому времени соответствует значение 1000 в экспортированном поле.

### Z-004 · Реплика из 81 кодовой точки

**Дефект · Противоречивость · Критичная.** T-7 требует отклонить текст длиннее 80 кодовых точек Unicode. T-8 принимает реплику из 81 кодовой точки, поэтому для заданного приёмочного примера невозможно выполнить оба требования.

Затронутые утверждения — [R-M0014-01](#r-m0014-01), [R-M0015-01](#r-m0015-01).

[R-M0014-01](#r-m0014-01) · Subtitle track export / Export limits · [строка 14](../../../../../benchmark/subtitles/requirements.md#L14)

> Reject a cue when its text exceeds 80 Unicode code points.  

[R-M0015-01](#r-m0015-01) · Subtitle track export / Export limits · [строка 15](../../../../../benchmark/subtitles/requirements.md#L15)

> In the acceptance sample, a cue of 81 Unicode code points is accepted.  

**Сценарий.** Экспортировать дорожку с репликой, текст которой содержит ровно 81 кодовую точку Unicode, как в приёмочном примере.

**Последствие.** T-7 требует отклонить реплику, поскольку 81 больше 80, а T-8 требует принять её.

**Общее условие.** В приёмочном примере обрабатывается реплика с текстом из 81 кодовой точки Unicode. К этому тексту применим предел в 80 кодовых точек. Основания — [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.», [R-M0015-01](#r-m0015-01) «In the acceptance sample, a cue of 81 Unicode code points is accepted.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Должна ли реплика из 81 кодовой точки в приёмочном примере быть принята или отклонена?

1. **Вариант 1.** Отклонять реплику, если длина её текста превышает 80 кодовых точек Unicode.

   **Основание.** [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.».

   **Ожидаемый результат.** Реплика отклонена.

   При выборе этого варианта привести в соответствие [R-M0015-01](#r-m0015-01).

2. **Вариант 2.** В приёмочном примере принимать реплику из 81 кодовой точки Unicode.

   **Основание.** [R-M0015-01](#r-m0015-01) «In the acceptance sample, a cue of 81 Unicode code points is accepted.».

   **Ожидаемый результат.** Реплика принята.

   При выборе этого варианта привести в соответствие [R-M0014-01](#r-m0014-01).

**Черновик приёмочного теста.** Запустить экспорт с репликой из примера и проверить результат её обработки.

### Z-005 · Критерий удобства экспорта

**Дефект · Проверяемость · Существенная.** T-4 требует, чтобы каждый пользователь воспринимал экспорт как лёгкий. Наблюдаемый критерий и порог успеха отсутствуют, поэтому одни и те же наблюдения допускают разные оценки.

Затронутые утверждения — [R-M0009-01](#r-m0009-01).

[R-M0009-01](#r-m0009-01) · Subtitle track export / Format · [строка 9](../../../../../benchmark/subtitles/requirements.md#L9)

> The export experience must feel effortless to every user.  

**Сценарий.** Разные пользователи выполняют один и тот же экспорт и по-разному оценивают усилие.

**Последствие.** Проверяющие могут вынести разные вердикты по T-4 на одинаковых наблюдениях.

**Уже установлено.** T-4 требует лёгкости экспорта по восприятию каждого пользователя. Основания — [R-M0009-01](#r-m0009-01).

**Открытое решение.** Выбрать наблюдаемый критерий с порогом, по которому оценивается выполнение T-4 для каждого пользователя.

**Что различит проверка.** Зафиксированные результаты каждого пользователя удовлетворяют выбранному критерию, T-4 проходит проверку. / Те же результаты хотя бы одного пользователя выходят за пределы выбранного критерия, T-4 проваливает проверку.

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** По какому наблюдаемому критерию и порогу принимать удобство экспорта?

Внести ответ на этот вопрос в [R-M0009-01](#r-m0009-01) для сценария «Разные пользователи выполняют один и тот же экспорт и по-разному оценивают усилие.».

**Черновик приёмочного теста.** Провести согласованную пользователем проверку экспорта и сравнить результат с установленным порогом.

### Z-002 · Каким должен быть итоговый файл при экспорте в существующий файл дорожки с допустимой репликой и репликой из 82 кодовых точек Unicode после обязательного отклонения длинной реплики?

**Предполагаемый пробел · Полнота · Существенная.** T-7 требует отклонить реплику из 82 кодовых точек. Состояние файла после этого отклонения не задано. Правило T-5 о сохранении назначения распространяется на пустую дорожку.

Затронутые утверждения — [R-M0003-01](#r-m0003-01), [R-M0014-01](#r-m0014-01).

[R-M0003-01](#r-m0003-01) · Subtitle track export · [строка 3](../../../../../benchmark/subtitles/requirements.md#L3)

> exports one open track to a local file  

[R-M0014-01](#r-m0014-01) · Subtitle track export / Export limits · [строка 14](../../../../../benchmark/subtitles/requirements.md#L14)

> Reject a cue when its text exceeds 80 Unicode code points.  

**Сценарий.** Сохранить исходное содержимое файла, запустить экспорт смешанной дорожки и проверить отклонение длинной реплики. Сверить итоговое содержимое файла с согласованным результатом, включая наличие допустимой реплики.

**Последствие.** T-7 требует отклонить реплику из 82 кодовых точек. Состояние файла после этого отклонения не задано. Правило T-5 о сохранении назначения распространяется на пустую дорожку.

**Уже установлено.** Экспорт предназначен для записи открытой дорожки в локальный файл. Реплику из 82 кодовых точек нужно отклонить. Сохранение назначения явно предписано для пустой дорожки, а пример относится к реплике из 81 кодовой точки. Основания — [R-M0014-01](#r-m0014-01), [R-M0003-01](#r-m0003-01), [R-M0010-02](#r-m0010-02), [R-M0015-01](#r-m0015-01).

**Открытое решение.** Определить итоговое содержимое существующего файла после обязательного отклонения длинной реплики в смешанной дорожке.

**Что различит проверка.** Длинная реплика отклонена, файл содержит экспортированную допустимую реплику. / Длинная реплика отклонена, файл сохраняет исходное содержимое.

## Готовность и порядок исправлений

ТЗ не готово к разработке и приёмке экспорта. Для файла, временных меток и приёмочного примера с длинной репликой необходимо согласовать обязательные результаты.

1. Согласовать наличие BOM и единицу временных меток с расшифровкой значения 1000. Привести требования и проверки файла к согласованным результатам. ([Z-001](#z-001), [Z-003](#z-003))
2. Согласовать правило предельной длины с приёмочным примером для 81 кодовой точки Unicode. ([Z-004](#z-004))
3. Определить итоговое содержимое существующего файла при обязательном отклонении длинной реплики из смешанной дорожки. ([Z-002](#z-002))
4. Установить наблюдаемый критерий и порог проверки удобства экспорта. ([Z-005](#z-005))
5. Исправить ссылку на отсутствующий T-40 в правиле о пустой дорожке. ([Z-006](#z-006))
