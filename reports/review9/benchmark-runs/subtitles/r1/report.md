## Проверка набора в целом

Требования расходятся по BOM, значению временной метки 1000 и исходу проверки реплики из 81 кодовой точки Unicode. Для лёгкости экспорта нужна наблюдаемая мера. Ссылка T-40 требует редакторской правки, а результат для пустой дорожки уже задан в T-5 и T-6.

Открытых предполагаемых пробелов — 0. Неоднозначностей — 0. Рекомендаций — 0.

Каждый ID утверждения учитывается один раз. В число нарушений входят подтверждённые дефекты и неоднозначности, для которых показаны две опирающиеся на текст трактовки с разными последствиями. Один и тот же конфликт имеет один ID при любом числе затронутых требований. Критичный дефект блокирует приёмку существенного обязательного сценария. Предполагаемый пробел оставляет открытым ожидаемое поведение или источник данных. Рекомендация предлагает улучшение. Вопросы и рекомендации имеют отдельные счётчики.

### Z-001 · BOM в начале файла

**Дефект · Противоречивость · Критичная.** T-1 исключает BOM, а T-2 требует BOM в первых трёх байтах того же файла. Успешный экспорт нельзя принять по обоим правилам.

Затронутые утверждения — [R-M0006-02](#r-m0006-02), [R-M0007-01](#r-m0007-01).

[R-M0006-02](#r-m0006-02) · Subtitle track export / Format · [строка 6](../../../../../benchmark/subtitles/requirements.md#L6)

> Write the exported track in UTF-8 without a byte-order mark.  

[R-M0007-01](#r-m0007-01) · Subtitle track export / Format · [строка 7](../../../../../benchmark/subtitles/requirements.md#L7)

> The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.  

**Сценарий.** Успешно экспортировать непустую дорожку в UTF-8 и проверить начало файла.

**Последствие.** Один файл не может одновременно удовлетворить обоим условиям.

**Общее условие.** Приёмка проверяет первые три байта записанного файла экспорта в UTF-8. Основания — [R-M0006-02](#r-m0006-02) «Write the exported track in UTF-8 without a byte-order mark.», [R-M0007-01](#r-m0007-01) «The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой результат считать правильным при приёмке — отсутствие или наличие BOM в начале файла?

1. **Вариант 1.** Записывать экспорт в UTF-8 без BOM.

   **Основание.** [R-M0006-02](#r-m0006-02) «Write the exported track in UTF-8 without a byte-order mark.».

   **Ожидаемый результат.** В начале файла отсутствует UTF-8 BOM.

   При выборе этого варианта привести в соответствие [R-M0007-01](#r-m0007-01).

2. **Вариант 2.** Первые три байта файла должны составлять UTF-8 BOM.

   **Основание.** [R-M0007-01](#r-m0007-01) «The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

   **Ожидаемый результат.** Первые три байта файла равны EF BB BF.

   При выборе этого варианта привести в соответствие [R-M0006-02](#r-m0006-02).

**Черновик приёмочного теста.** Экспортировать одну непустую дорожку и сравнить первые три байта файла с EF BB BF.

### Z-002 · Шкала временной метки

**Дефект · Противоречивость · Критичная.** T-3 задаёт миллисекунды для каждого поля метки и приравнивает 1000 к минуте. Для одной метки получаются два несовместимых ожидаемых времени.

Затронутые утверждения — [R-M0008-01](#r-m0008-01), [R-M0008-02](#r-m0008-02).

[R-M0008-01](#r-m0008-01) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> Each timestamp field declares milliseconds  

[R-M0008-02](#r-m0008-02) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> Each timestamp field declares milliseconds; the numeric value 1000 represents one minute.  

**Сценарий.** Прочитать поле временной метки со значением 1000 и объявленной единицей «миллисекунды».

**Последствие.** Для поля нельзя установить единое ожидаемое время при приёмке.

**Общее условие.** В поле временной метки с объявленной единицей «миллисекунды» записано значение 1000. Основания — [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds», [R-M0008-02](#r-m0008-02) «the numeric value 1000 represents one minute.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какое время должно обозначать значение 1000 при приёмке — одну секунду или одну минуту?

1. **Вариант 1.** Числовые значения полей временных меток выражаются в миллисекундах.

   **Основание.** [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds».

   **Ожидаемый результат.** Значение 1000 соответствует одной секунде.

   При выборе этого варианта привести в соответствие [R-M0008-02](#r-m0008-02).

2. **Вариант 2.** Числовое значение 1000 в поле временной метки соответствует одной минуте.

   **Основание.** [R-M0008-02](#r-m0008-02) «Each timestamp field declares milliseconds; the numeric value 1000 represents one minute.».

   **Ожидаемый результат.** Значение 1000 соответствует одной минуте.

   При выборе этого варианта привести в соответствие [R-M0008-01](#r-m0008-01).

**Черновик приёмочного теста.** Прочитать значение 1000 в поле экспортированной метки и сверить обозначаемое время с выбранным исходом.

### Z-003 · Критерий лёгкости экспорта

**Дефект · Проверяемость · Существенная.** T-4 требует лёгкости экспорта для каждого пользователя. У наблюдаемого выполнения нет заданной меры, по которой проверяющие могли бы одинаково оценить выполнение T-4.

Затронутые утверждения — [R-M0009-01](#r-m0009-01).

[R-M0009-01](#r-m0009-01) · Subtitle track export / Format · [строка 9](../../../../../benchmark/subtitles/requirements.md#L9)

> The export experience must feel effortless to every user.  

**Сценарий.** Наблюдать выполнение экспорта непустой дорожки пользователем и по согласованному критерию определить, выполнено ли для него T-4.

**Последствие.** Проверяющие могут присвоить разные итоги одному наблюдаемому выполнению.

**Уже установлено.** Требование касается экспорта одной открытой дорожки в локальный файл и распространяется на каждого пользователя. Основания — [R-M0009-01](#r-m0009-01), [R-M0003-01](#r-m0003-01).

**Открытое решение.** Определить наблюдаемый критерий лёгкости экспорта.

**Что различит проверка.** Наблюдаемое выполнение экспорта удовлетворяет выбранному критерию и проходит проверку T-4. / То же выполнение экспорта по другому критерию не проходит проверку T-4.

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** По какому наблюдаемому критерию считать экспорт лёгким для пользователя, как требует T-4?

Внести ответ на этот вопрос в [R-M0009-01](#r-m0009-01) для сценария «Наблюдать выполнение экспорта непустой дорожки пользователем и по согласованному критерию определить, выполнено ли для него T-4.».

**Черновик приёмочного теста.** Наблюдать выполнение экспорта непустой дорожки пользователем и по согласованному критерию определить, выполнено ли для него T-4.

### Z-004 · Реплика из 81 кодовой точки

**Дефект · Противоречивость · Существенная.** T-7 требует отклонить реплику приёмочного примера, поскольку её текст превышает предел в 80 кодовых точек Unicode. T-8 фиксирует принятие этой реплики.

Затронутые утверждения — [R-M0014-01](#r-m0014-01), [R-M0015-01](#r-m0015-01).

[R-M0014-01](#r-m0014-01) · Subtitle track export / Export limits · [строка 14](../../../../../benchmark/subtitles/requirements.md#L14)

> Reject a cue when its text exceeds 80 Unicode code points.  

[R-M0015-01](#r-m0015-01) · Subtitle track export / Export limits · [строка 15](../../../../../benchmark/subtitles/requirements.md#L15)

> In the acceptance sample, a cue of 81 Unicode code points is accepted.  

**Сценарий.** Экспортировать дорожку с репликой приёмочного примера длиной 81 кодовая точка Unicode.

**Последствие.** Один и тот же исход нельзя принять по общему правилу и по примеру.

**Общее условие.** При экспорте проверяется реплика приёмочного примера с текстом длиной 81 кодовая точка Unicode. Основания — [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.», [R-M0015-01](#r-m0015-01) «In the acceptance sample, a cue of 81 Unicode code points is accepted.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой исход приёмочного примера зафиксировать — отклонение или принятие реплики из 81 кодовой точки?

1. **Вариант 1.** Отклонять реплику, если её текст превышает 80 кодовых точек Unicode.

   **Основание.** [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.».

   **Ожидаемый результат.** Реплика из 81 кодовой точки отклоняется.

   При выборе этого варианта привести в соответствие [R-M0015-01](#r-m0015-01).

2. **Вариант 2.** Принимать в приёмочном примере реплику длиной 81 кодовая точка Unicode.

   **Основание.** [R-M0015-01](#r-m0015-01) «In the acceptance sample, a cue of 81 Unicode code points is accepted.».

   **Ожидаемый результат.** Реплика из 81 кодовой точки принимается.

   При выборе этого варианта привести в соответствие [R-M0014-01](#r-m0014-01).

**Черновик приёмочного теста.** Подать на экспорт реплику с текстом ровно из 81 кодовой точки Unicode и проверить, принята ли она.

Subtitle track export / Format · [строка 7](../../../../../benchmark/subtitles/requirements.md#L7)

> The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.  

**Связано с нарушением в спецификации.** T-1 исключает BOM, а T-2 требует BOM в первых трёх байтах того же файла. Успешный экспорт нельзя принять по обоим правилам.

Связанные замечания — [Z-001](#z-001).

<a id="decision"></a>

## Готовность и порядок исправлений

ТЗ не готово к разработке и приёмке экспорта до согласования формата файла, шкалы меток и исхода приёмочного примера. Для проверки T-4 нужно определить критерий лёгкости экспорта.

1. Согласовать наличие BOM и обозначаемое значением 1000 время с заявленной единицей. ([Z-001](#z-001), [Z-002](#z-002))
2. Согласовать предел длины текста с исходом приёмочного примера для 81 кодовой точки Unicode. ([Z-004](#z-004))
3. Задать наблюдаемый критерий лёгкости экспорта для проверки T-4. ([Z-003](#z-003))
4. Исправить внутреннюю ссылку T-40. ([Z-005](#z-005))
