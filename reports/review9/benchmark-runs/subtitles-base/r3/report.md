T-3 однозначно задаёт числовую шкалу меток, но допускает два прочтения записи единицы. Для смешанной дорожки задано отклонение длинной реплики, а итог записи файла требует уточнения.

Открытых предполагаемых пробелов — 1. Неоднозначностей — 1. Рекомендаций — 0.

Каждый ID утверждения учитывается один раз. В число нарушений входят подтверждённые дефекты и неоднозначности, для которых показаны две опирающиеся на текст трактовки с разными последствиями. Один и тот же конфликт имеет один ID при любом числе затронутых требований. Критичный дефект блокирует приёмку существенного обязательного сценария. Предполагаемый пробел оставляет открытым ожидаемое поведение или источник данных. Рекомендация предлагает улучшение. Вопросы и рекомендации имеют отдельные счётчики.

### Z-002 · Обозначение миллисекунд в поле

**Неоднозначность · Однозначность · Существенная.** T-3 фиксирует шкалу и значение 1000 для одной секунды. Оборот «Each timestamp field declares milliseconds» допускает указание единицы в каждом записанном поле или задание единицы в определении поля. От этого зависит приёмка поля с одним числом 1000.

Затронутые утверждения — [R-M0008-01](#r-m0008-01), [R-M0008-02](#r-m0008-02).

[R-M0008-01](#r-m0008-01) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/baseline.md#L8)

> Each timestamp field declares milliseconds  

[R-M0008-02](#r-m0008-02) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/baseline.md#L8)

> Each timestamp field declares milliseconds; the numeric value 1000 represents one second.  

**Сценарий.** Экспортировать дорожку с меткой в одну секунду и проверить поле, содержащее число 1000 без обозначения единицы в самом поле.

**Последствие.** Один и тот же файл проходит или проваливает проверку представления меток.

**Уже установлено.** Единица временной метки — миллисекунда. Число 1000 означает одну секунду. Основания — [R-M0008-01](#r-m0008-01), [R-M0008-02](#r-m0008-02).

**Открытое решение.** Достаточно ли записать в поле только число 1000?

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Число 1000 в любом случае означает одну секунду. Достаточно ли числа в поле или поле должно явно обозначать миллисекунды? Если обозначение обязательно, какое представление должен принять тест?

1. **Вариант 1.** Явно обозначать миллисекунды в каждом экспортируемом поле временной метки.

   **Основание.** [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds».

   **Ожидаемый результат.** Поле с одним числом 1000 не проходит проверку.

2. **Вариант 2.** Считать миллисекунды заданной единицей числового поля и допускать запись одного числа.

   **Основание.** [R-M0008-02](#r-m0008-02) «Each timestamp field declares milliseconds; the numeric value 1000 represents one second.».

   **Ожидаемый результат.** Поле с одним числом 1000 проходит проверку.

**Черновик приёмочного теста.** Проверить поле с числом 1000 на соответствие выбранному правилу представления единицы.

**Открытое решение.** Создаётся ли файл с допустимой репликой после отклонения второй реплики?

**Что различит проверка.** Создан файл с единственной репликой из 80 кодовых точек. / Файл по выбранному пути отсутствует.

## Готовность и порядок исправлений

Разработку можно начать по определённым требованиям. Для приёмки записи меток и экспорта смешанной дорожки нужны ожидаемые результаты двух отдельных проверок.

1. Уточнить в T-3, проходит ли проверку поле с одним числом 1000 для метки в одну секунду. ([Z-002](#z-002))
2. Задать ожидаемое состояние файла после экспорта смешанной дорожки с обязательным отклонением длинной реплики. ([Z-001](#z-001))
