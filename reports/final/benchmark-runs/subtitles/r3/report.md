## Проверка набора в целом

Правила для BOM и масштаба временных меток противоречат условиям приёмки экспортированного файла. Для реплики из приёмочного примера заданы противоположные исходы. Лёгкость экспорта остаётся непроверяемой, а ссылка на источник сообщения для пустой дорожки ведёт к отсутствующему пункту.

Открытых предполагаемых пробелов — 1. Неоднозначностей — 0. Рекомендаций — 0.

Каждый ID утверждения учитывается один раз. В число нарушений входят подтверждённые дефекты и неоднозначности, для которых показаны две опирающиеся на текст трактовки с разными последствиями. Один и тот же конфликт имеет один ID при любом числе затронутых требований. Критичный дефект блокирует приёмку существенного обязательного сценария. Предполагаемый пробел оставляет открытым ожидаемое поведение или источник данных. Рекомендация предлагает улучшение. Вопросы и рекомендации имеют отдельные счётчики.

## Критичные дефекты

- [Z-001](#z-001) · T-1 запрещает BOM, а T-2 требует его в начале того же файла. Ни один результат записи не удовлетворяет обоим условиям приёмки экспорта.
- [Z-002](#z-002) · T-3 объявляет миллисекунды для каждого поля и задаёт несовместимый с этой единицей масштаб. Для одной минуты нельзя согласовать числовое значение и объявленную единицу, поэтому корректность времени в экспортированном файле проверить невозможно.

### Z-001 · BOM в экспортируемом файле

**Дефект · Противоречивость · Критичная.** T-1 запрещает BOM, а T-2 требует его в начале того же файла. Ни один результат записи не удовлетворяет обоим условиям приёмки экспорта.

Затронутые утверждения — [R-M0006-01](#r-m0006-01), [R-M0007-01](#r-m0007-01).

[R-M0006-01](#r-m0006-01) · Subtitle track export / Format · [строка 6](../../../../../benchmark/subtitles/requirements.md#L6)

> Write the exported track in UTF-8 without a byte-order mark.  

[R-M0007-01](#r-m0007-01) · Subtitle track export / Format · [строка 7](../../../../../benchmark/subtitles/requirements.md#L7)

> The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.  

**Сценарий.** Успешно экспортировать непустую дорожку с текстом, начинающимся с обычных ASCII-символов.

**Последствие.** Для одного файла заданы взаимоисключающие требования к первым байтам.

**Общее условие.** Проверяются первые три байта успешно экспортированного файла. Основания — [R-M0006-01](#r-m0006-01) «Write the exported track in UTF-8 without a byte-order mark.», [R-M0007-01](#r-m0007-01) «The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой исход принимать для экспортированного файла — с BOM или без BOM?

1. **Вариант 1.** Записывать файл в UTF-8 без BOM.

   **Основание.** [R-M0006-01](#r-m0006-01) «Write the exported track in UTF-8 without a byte-order mark.».

   **Ожидаемый результат.** Первые три байта файла не образуют UTF-8 BOM.

   При выборе этого варианта привести в соответствие [R-M0007-01](#r-m0007-01).

2. **Вариант 2.** Записывать UTF-8 BOM в первых трёх байтах файла.

   **Основание.** [R-M0007-01](#r-m0007-01) «The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

   **Ожидаемый результат.** Первые три байта файла образуют UTF-8 BOM.

   При выборе этого варианта привести в соответствие [R-M0006-01](#r-m0006-01).

**Черновик приёмочного теста.** После экспорта проверить первые три байта на соответствие выбранному правилу.

### Z-002 · Масштаб временных меток

**Дефект · Противоречивость · Критичная.** T-3 объявляет миллисекунды для каждого поля и задаёт несовместимый с этой единицей масштаб. Для одной минуты нельзя согласовать числовое значение и объявленную единицу, поэтому корректность времени в экспортированном файле проверить невозможно.

Затронутые утверждения — [R-M0008-01](#r-m0008-01), [R-M0008-02](#r-m0008-02).

[R-M0008-01](#r-m0008-01) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> Each timestamp field declares milliseconds  

[R-M0008-02](#r-m0008-02) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> the numeric value 1000 represents one minute.  

**Сценарий.** Экспортировать реплику с временной меткой ровно в одну минуту от начала дорожки.

**Последствие.** Одна минута представляется как 60000 при объявленной единице измерения и как 1000 по прямому соответствию в T-3.

**Общее условие.** Числовое поле временной метки представляет одну минуту. Основания — [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds», [R-M0008-02](#r-m0008-02) «the numeric value 1000 represents one minute.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какое значение должна содержать экспортированная метка для одной минуты — 60000 или 1000?

1. **Вариант 1.** Во всех полях выражать время в миллисекундах.

   **Основание.** [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds».

   **Ожидаемый результат.** Числовое значение метки равно 60000.

   При выборе этого варианта привести в соответствие [R-M0008-02](#r-m0008-02).

2. **Вариант 2.** Для временной метки значение 1000 представляет одну минуту.

   **Основание.** [R-M0008-02](#r-m0008-02) «the numeric value 1000 represents one minute.».

   **Ожидаемый результат.** Числовое значение метки равно 1000.

   При выборе этого варианта привести в соответствие [R-M0008-01](#r-m0008-01).

**Черновик приёмочного теста.** Прочитать числовое значение экспортированной метки и сравнить с выбранным результатом.

### Z-005 · Приёмка реплики из 81 кодовой точки

**Дефект · Противоречивость · Существенная.** Общий порог T-7 распространяется на реплику из T-8. Указание на приёмочный пример задаёт исход, но не устанавливает исключение из порога. Расхождение блокирует проверку этого примера.

Затронутые утверждения — [R-M0014-01](#r-m0014-01), [R-M0015-01](#r-m0015-01).

[R-M0014-01](#r-m0014-01) · Subtitle track export / Export limits · [строка 14](../../../../../benchmark/subtitles/requirements.md#L14)

> Reject a cue when its text exceeds 80 Unicode code points.  

[R-M0015-01](#r-m0015-01) · Subtitle track export / Export limits · [строка 15](../../../../../benchmark/subtitles/requirements.md#L15)

> In the acceptance sample, a cue of 81 Unicode code points is accepted.  

**Сценарий.** Выполнить экспорт с репликой из приёмочного примера T-8, содержащей 81 кодовую точку Unicode.

**Последствие.** Одна и та же реплика по T-7 отклоняется, а по T-8 принимается.

**Общее условие.** Проверяется реплика из приёмочного примера с текстом длиной 81 кодовая точка Unicode. Основания — [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.», [R-M0015-01](#r-m0015-01) «In the acceptance sample, a cue of 81 Unicode code points is accepted.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Реплику из примера T-8 нужно отклонить или принять?

1. **Вариант 1.** Отклонять реплику, если её текст превышает 80 кодовых точек Unicode.

   **Основание.** [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.».

   **Ожидаемый результат.** Реплика из приёмочного примера отклонена.

   При выборе этого варианта привести в соответствие [R-M0015-01](#r-m0015-01).

2. **Вариант 2.** Принимать реплику из 81 кодовой точки Unicode в приёмочном примере.

   **Основание.** [R-M0015-01](#r-m0015-01) «In the acceptance sample, a cue of 81 Unicode code points is accepted.».

   **Ожидаемый результат.** Реплика из приёмочного примера принята.

   При выборе этого варианта привести в соответствие [R-M0014-01](#r-m0014-01).

**Черновик приёмочного теста.** Выполнить пример T-8 и проверить, принят или отклонён указанный в нём текст реплики.

<a id="z-003"></a>

### Z-003 · Критерий лёгкости экспорта

**Предполагаемый пробел · Проверяемость · Существенная.** T-4 обещает лёгкость экспорта для каждого пользователя. В ТЗ отсутствуют наблюдаемый критерий лёгкости и способ проверить заявленный охват. Корректность файла сама по себе этого свойства не подтверждает.

Затронутые утверждения — [R-M0009-01](#r-m0009-01).

[R-M0009-01](#r-m0009-01) · Subtitle track export / Format · [строка 9](../../../../../benchmark/subtitles/requirements.md#L9)

> The export experience must feel effortless to every user.  

**Сценарий.** Пользователи экспортируют открытые дорожки, после чего проверяющий оценивает выполнение T-4.

**Последствие.** Даже при корректно записанных файлах проверяющий не может вынести решение о выполнении T-4.

### Z-004 · Ссылка на сообщение для пустой дорожки

**Дефект · Трассируемость · Низкая.** T-5 ссылается на отсутствующий в ТЗ пункт T-40. Точную строку можно проверить по T-6, а сохранение назначения в исходном состоянии прямо задано T-5.

Затронутые утверждения — [R-M0010-01](#r-m0010-01), [R-M0011-01](#r-m0011-01).

[R-M0010-01](#r-m0010-01) · Subtitle track export / Format · [строка 10](../../../../../benchmark/subtitles/requirements.md#L10)

> For an empty track, display the exact message listed in T-40  

[R-M0011-01](#r-m0011-01) · Subtitle track export / Format · [строка 11](../../../../../benchmark/subtitles/requirements.md#L11)

> The message for an empty track is “Add at least one cue”.  

**Сценарий.** Попытаться экспортировать пустую дорожку в существующий локальный файл и сверить показанное сообщение с требованиями.

**Последствие.** T-6 задаёт строку «Add at least one cue», а соответствие этой строки ссылке в T-5 проверить невозможно. Сохранение файла проверяется отдельно.

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Должна ли ссылка T-5 вести на T-6? Если T-40 — отдельный пункт, где в нём задана та же обязательная строка?

Внести ответ на этот вопрос в [R-M0010-01](#r-m0010-01), [R-M0011-01](#r-m0011-01) для сценария «Попытаться экспортировать пустую дорожку в существующий локальный файл и сверить показанное сообщение с требованиями.».

**Черновик приёмочного теста.** При экспорте пустой дорожки проверить точную строку «Add at least one cue» и сверить её с подтверждённым источником T-5.

<a id="decision"></a>

## Готовность и порядок исправлений

ТЗ не готово к разработке и приёмке экспорта. Сначала нужно согласовать формат файла и исход для приёмочного примера.

1. Согласовать наличие BOM с проверкой первых байтов и объявленную единицу временных меток с числовым представлением одной минуты. ([Z-001](#z-001), [Z-002](#z-002))
2. Согласовать порог длины и ожидаемый результат для реплики из приёмочного примера. ([Z-005](#z-005))
3. Задать наблюдаемый критерий лёгкости экспорта и способ проверить заявленный охват пользователей. ([Z-003](#z-003))
4. Указать действующий источник точного сообщения в ссылке T-5. ([Z-004](#z-004))
