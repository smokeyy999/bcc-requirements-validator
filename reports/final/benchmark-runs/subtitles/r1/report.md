## Проверка набора в целом

Правила расходятся в требованиях к BOM, значению временной метки и приёмке реплики из примера. Для файла после отклонения реплики требуется уточнение. T-4 требует критерия проверки, а T-5 требует исправления ссылки.

Открытых предполагаемых пробелов — 1. Неоднозначностей — 0. Рекомендаций — 0.

Каждый ID утверждения учитывается один раз. В число нарушений входят подтверждённые дефекты и неоднозначности, для которых показаны две опирающиеся на текст трактовки с разными последствиями. Один и тот же конфликт имеет один ID при любом числе затронутых требований. Критичный дефект блокирует приёмку существенного обязательного сценария. Предполагаемый пробел оставляет открытым ожидаемое поведение или источник данных. Рекомендация предлагает улучшение. Вопросы и рекомендации имеют отдельные счётчики.

## Критичные дефекты

- [Z-002](#z-002) · T-1 запрещает BOM в выходном файле, а T-2 требует BOM в первых трёх байтах этого файла. Запись по T-1 не проходит обязательную проверку формата.
- [Z-003](#z-003) · T-3 объявляет миллисекунды единицей каждого поля временной метки и задаёт для значения 1000 в этом поле одну минуту. По объявленной единице это одна секунда. Корректность времени реплик при экспорте нельзя принять по обеим формулировкам.

### Z-002 · UTF-8 BOM в начале файла

**Дефект · Противоречивость · Критичная.** T-1 запрещает BOM в выходном файле, а T-2 требует BOM в первых трёх байтах этого файла. Запись по T-1 не проходит обязательную проверку формата.

Затронутые утверждения — [R-M0006-01](#r-m0006-01), [R-M0007-01](#r-m0007-01).

[R-M0006-01](#r-m0006-01) · Subtitle track export / Format · [строка 6](../../../../../benchmark/subtitles/requirements.md#L6)

> Write the exported track in UTF-8 without a byte-order mark.  

[R-M0007-01](#r-m0007-01) · Subtitle track export / Format · [строка 7](../../../../../benchmark/subtitles/requirements.md#L7)

> The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.  

**Сценарий.** Экспортировать непустую дорожку с короткой репликой, текст которой не начинается с U+FEFF.

**Последствие.** Файл, записанный по одному правилу, будет отклонён по другому.

**Общее условие.** Приёмочный тест проверяет начало файла, созданного при экспорте дорожки. Основания — [R-M0006-01](#r-m0006-01) «Write the exported track in UTF-8 without a byte-order mark.», [R-M0007-01](#r-m0007-01) «The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой исход считать правильным при приёмке: файл с UTF-8 BOM или без него?

1. **Вариант 1.** Записывать файл в UTF-8 без BOM.

   **Основание.** [R-M0006-01](#r-m0006-01) «Write the exported track in UTF-8 without a byte-order mark.».

   **Ожидаемый результат.** В начале файла нет UTF-8 BOM.

   При выборе этого варианта привести в соответствие [R-M0007-01](#r-m0007-01).

2. **Вариант 2.** Записывать UTF-8 BOM в первые три байта файла.

   **Основание.** [R-M0007-01](#r-m0007-01) «The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

   **Ожидаемый результат.** Первые три байта файла — EF BB BF.

   При выборе этого варианта привести в соответствие [R-M0006-01](#r-m0006-01).

**Черновик приёмочного теста.** Экспортировать дорожку и сравнить первые три байта файла с EF BB BF.

### Z-003 · Шкала временных меток

**Дефект · Противоречивость · Критичная.** T-3 объявляет миллисекунды единицей каждого поля временной метки и задаёт для значения 1000 в этом поле одну минуту. По объявленной единице это одна секунда. Корректность времени реплик при экспорте нельзя принять по обеим формулировкам.

Затронутые утверждения — [R-M0008-01](#r-m0008-01), [R-M0008-02](#r-m0008-02).

[R-M0008-01](#r-m0008-01) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> Each timestamp field declares milliseconds  

[R-M0008-02](#r-m0008-02) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> Each timestamp field declares milliseconds; the numeric value 1000 represents one minute.  

**Сценарий.** Прочитать значение 1000 в экспортированном поле временной метки.

**Последствие.** Одна и та же метка представляет одну секунду по объявленной единице и одну минуту по числовому правилу.

**Общее условие.** Экспортированное поле временной метки объявляет миллисекунды и содержит значение 1000. Основания — [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds», [R-M0008-02](#r-m0008-02) «the numeric value 1000 represents one minute.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какую длительность должна представлять метка 1000 при приёмке — одну секунду или одну минуту?

1. **Вариант 1.** Числовые значения временных меток выражаются в миллисекундах.

   **Основание.** [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds».

   **Ожидаемый результат.** Значение 1000 соответствует одной секунде.

   При выборе этого варианта привести в соответствие [R-M0008-02](#r-m0008-02).

2. **Вариант 2.** Числовая шкала временных меток задаётся соответствием 1000 одной минуте.

   **Основание.** [R-M0008-02](#r-m0008-02) «Each timestamp field declares milliseconds; the numeric value 1000 represents one minute.».

   **Ожидаемый результат.** Значение 1000 соответствует одной минуте.

   При выборе этого варианта привести в соответствие [R-M0008-01](#r-m0008-01).

**Черновик приёмочного теста.** Проверить, какой длительности по выбранной шкале соответствует значение 1000 в поле временной метки.

Затронутые утверждения — [R-M0009-01](#r-m0009-01).

**Сценарий.** Пользователь экспортирует открытую дорожку в локальный файл.

**Последствие.** Успешное создание файла не даёт проверяющему основания принять требование T-4.

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** По какому наблюдаемому критерию и как подтвердить лёгкость экспорта для заявленной аудитории?

Внести ответ на этот вопрос в [R-M0009-01](#r-m0009-01) для сценария «Пользователь экспортирует открытую дорожку в локальный файл.».

**Черновик приёмочного теста.** Провести экспорт по согласованной процедуре оценки и сверить наблюдаемый результат с заданным критерием.

### Z-005 · Приёмка реплики на границе длины

**Дефект · Противоречивость · Существенная.** Реплика из T-8 превышает порог T-7. Слова «In the acceptance sample» задают конкретный вход и его принятие. T-7 распространяется и на этот вход, поэтому ожидаемый результат примера не определён.

Затронутые утверждения — [R-M0014-01](#r-m0014-01), [R-M0015-01](#r-m0015-01).

[R-M0014-01](#r-m0014-01) · Subtitle track export / Export limits · [строка 14](../../../../../benchmark/subtitles/requirements.md#L14)

> Reject a cue when its text exceeds 80 Unicode code points.  

[R-M0015-01](#r-m0015-01) · Subtitle track export / Export limits · [строка 15](../../../../../benchmark/subtitles/requirements.md#L15)

> In the acceptance sample, a cue of 81 Unicode code points is accepted.  

**Сценарий.** Экспортировать дорожку из приёмочного примера с репликой длиной 81 кодовую точку Unicode.

**Последствие.** Для одной реплики заданы противоположные результаты проверки длины.

**Общее условие.** Проверяется реплика из приёмочного примера длиной 81 кодовую точку Unicode. Основания — [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.», [R-M0015-01](#r-m0015-01) «In the acceptance sample, a cue of 81 Unicode code points is accepted.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой результат должен ожидать приёмочный тест T-8 — отклонение или принятие реплики?

1. **Вариант 1.** Отклонять реплику, если её текст длиннее 80 кодовых точек Unicode, в том числе в приёмочном примере.

   **Основание.** [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.».

   **Ожидаемый результат.** Реплика из примера отклонена.

   При выборе этого варианта привести в соответствие [R-M0015-01](#r-m0015-01).

2. **Вариант 2.** Принимать реплику из приёмочного примера длиной 81 кодовую точку Unicode.

   **Основание.** [R-M0015-01](#r-m0015-01) «In the acceptance sample, a cue of 81 Unicode code points is accepted.».

   **Ожидаемый результат.** Реплика из примера принята.

   При выборе этого варианта привести в соответствие [R-M0014-01](#r-m0014-01).

**Черновик приёмочного теста.** Воспроизвести приёмочный пример и проверить результат валидации реплики.

### Z-001 · Что должно произойти с существующим файлом назначения и допустимой репликой, если другую реплику требуется отклонить по согласованному правилу длины?

**Предполагаемый пробел · Полнота · Существенная.** T-7 требует отклонить реплику. Для непустой дорожки с допустимой и отклонённой репликами состояние файла назначения не определено. Условие «For an empty track» ограничивает правило T-5 пустой дорожкой.

Затронутые утверждения — [R-M0003-03](#r-m0003-03), [R-M0014-01](#r-m0014-01).

[R-M0003-03](#r-m0003-03) · Subtitle track export · [строка 3](../../../../../benchmark/subtitles/requirements.md#L3)

[R-M0014-01](#r-m0014-01) · Subtitle track export / Export limits · [строка 14](../../../../../benchmark/subtitles/requirements.md#L14)

> Reject a cue when its text exceeds 80 Unicode code points.  

**Сценарий.** Экспортировать в существующий файл дорожку с допустимой репликой и репликой, подлежащей отклонению по согласованному правилу длины. Проверить отклонение второй реплики, состояние файла и запись допустимой реплики по согласованному исходу.

**Что нужно уточнить.** Какое состояние существующего файла требуется после отклонения одной реплики, если в дорожке есть допустимая реплика?

## Готовность и порядок исправлений

ТЗ не готово к разработке и приёмке экспорта. Сначала нужно согласовать байты начала файла, шкалу времени и результат проверки реплики из приёмочного примера.

1. Согласовать наличие BOM и привести объявленную единицу времени в соответствие с числовой шкалой. ([Z-002](#z-002), [Z-003](#z-003))
2. Согласовать правило длины с ожидаемым результатом приёмочного примера. ([Z-005](#z-005))
3. После согласования правила длины определить состояние существующего файла и судьбу допустимой реплики при отклонении другой. ([Z-001](#z-001))
4. Задать наблюдаемый критерий и процедуру проверки лёгкости экспорта. ([Z-004](#z-004))
5. Исправить ссылку в T-5 на T-6. ([Z-006](#z-006))
