Каждый ID утверждения учитывается один раз. В число нарушений входят подтверждённые дефекты и неоднозначности, для которых показаны две опирающиеся на текст трактовки с разными последствиями. Один и тот же конфликт имеет один ID при любом числе затронутых требований. Критичный дефект блокирует приёмку существенного обязательного сценария. Предполагаемый пробел оставляет открытым ожидаемое поведение или источник данных. Рекомендация предлагает улучшение. Вопросы и рекомендации имеют отдельные счётчики.

**Что нужно уточнить.** Если передачу из «Черновика» сохранят, неизвестно, в каком состоянии ведомость получит отказ перевозчика.

**Как ответ изменит приёмку.** При отказе в состоянии «Готова» проверяется его сохранение. При отказе в состоянии «Черновик» для результата по S-7 потребуется переход в «Готова».

## Готовность и порядок исправлений

ТЗ пока не готово к разработке сценариев отправки из «Черновика» и допуска ведомости из 25 строк. Если передачу из «Черновика» сохранят, нужно уточнить состояние при поступлении отказа и критерий немедленной передачи.

1. Установить единый исход попытки отправки из «Черновика». ([Z-001](#z-001))
2. Согласовать предел числа строк с допуском готовой ведомости из 25 строк. ([Z-002](#z-002))
3. Если передачу из «Черновика» сохранят, уточнить состояние при поступлении отказа и задать критерий немедленной передачи. ([Z-003](#z-003), [Z-006](#z-006))
4. Установить однозначный срок локального хранения подтверждения при значении 7. ([Z-005](#z-005))
5. Задать допустимую задержку показа «Передано» после подтверждения. ([Z-004](#z-004))
6. Исправить ссылку в S-6 и сверить правило с текстом отказа по S-7. ([Z-007](#z-007))
