## Проверка набора в целом

Правила экспорта и приёмки расходятся по BOM, шкале временных отметок и исходу для реплики из 81 кодовой точки. Для удобства экспорта требуется измеримый критерий. Ссылка T-40 требует редакторской правки. Сообщение для пустой дорожки уже задано в T-6.

Открытых предполагаемых пробелов — 0. Неоднозначностей — 0. Рекомендаций — 0.

Каждый ID утверждения учитывается один раз. В число нарушений входят подтверждённые дефекты и неоднозначности, для которых показаны две опирающиеся на текст трактовки с разными последствиями. Один и тот же конфликт имеет один ID при любом числе затронутых требований. Критичный дефект блокирует приёмку существенного обязательного сценария. Предполагаемый пробел оставляет открытым ожидаемое поведение или источник данных. Рекомендация предлагает улучшение. Вопросы и рекомендации имеют отдельные счётчики.

## Критичные дефекты

- [Z-001](#z-001) · T-1 исключает BOM, а T-2 требует его в первых трёх байтах того же файла. Ни один файл не удовлетворяет одновременно правилу записи и приёмочному тесту.

### Z-001 · BOM в экспортируемом файле

**Дефект · Противоречивость · Критичная.** T-1 исключает BOM, а T-2 требует его в первых трёх байтах того же файла. Ни один файл не удовлетворяет одновременно правилу записи и приёмочному тесту.

Затронутые утверждения — [R-M0006-02](#r-m0006-02), [R-M0007-01](#r-m0007-01).

[R-M0006-02](#r-m0006-02) · Subtitle track export / Format · [строка 6](../../../../../benchmark/subtitles/requirements.md#L6)

> T-1. Write the exported track in UTF-8 without a byte-order mark.  

[R-M0007-01](#r-m0007-01) · Subtitle track export / Format · [строка 7](../../../../../benchmark/subtitles/requirements.md#L7)

> T-2. The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.  

**Сценарий.** Экспортировать непустую дорожку с короткой репликой в локальный файл.

**Последствие.** Файл без BOM соответствует T-1 и проваливает T-2. Файл с BOM проходит T-2 и нарушает T-1.

**Общее условие.** Проверяются первые три байта файла, полученного при экспорте дорожки. Основания — [R-M0006-02](#r-m0006-02) «Write the exported track in UTF-8 without a byte-order mark.», [R-M0007-01](#r-m0007-01) «The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Должен ли файл начинаться с UTF-8 BOM?

1. **Вариант 1.** Записывать файл в UTF-8 без BOM.

   **Основание.** [R-M0006-02](#r-m0006-02) «T-1. Write the exported track in UTF-8 without a byte-order mark.».

   **Ожидаемый результат.** В начале файла нет UTF-8 BOM.

   При выборе этого варианта привести в соответствие [R-M0007-01](#r-m0007-01).

2. **Вариант 2.** Записывать UTF-8 BOM в первые три байта файла.

   **Основание.** [R-M0007-01](#r-m0007-01) «T-2. The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

   **Ожидаемый результат.** Первые три байта файла образуют UTF-8 BOM.

   При выборе этого варианта привести в соответствие [R-M0006-02](#r-m0006-02).

**Черновик приёмочного теста.** Экспортировать одну непустую дорожку и проверить первые три байта файла на наличие UTF-8 BOM.

### Z-002 · Числовое представление минуты

**Дефект · Противоречивость · Критичная.** Объявленная единица применяется к каждому полю временной отметки. Для одной минуты она даёт 60000, а соответствие в том же T-3 требует 1000. Приёмка шкалы экспортируемых отметок заблокирована.

Затронутые утверждения — [R-M0008-01](#r-m0008-01), [R-M0008-02](#r-m0008-02).

[R-M0008-01](#r-m0008-01) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> Each timestamp field declares milliseconds  

[R-M0008-02](#r-m0008-02) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> Each timestamp field declares milliseconds; the numeric value 1000 represents one minute.  

**Сценарий.** Экспортировать реплику с временной отметкой ровно в одну минуту.

**Последствие.** При шкале в миллисекундах минута записывается как 60000. По заданному в T-3 соответствию она записывается как 1000.

**Общее условие.** Экспортируется поле временной отметки ровно в одну минуту. Основания — [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds», [R-M0008-02](#r-m0008-02) «the numeric value 1000 represents one minute.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какое значение должна содержать экспортированная отметка в одну минуту: 60000 или 1000?

1. **Вариант 1.** Записывать числовые значения временных отметок в миллисекундах.

   **Основание.** [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds».

   **Ожидаемый результат.** Для отметки в одну минуту записано 60000.

   При выборе этого варианта привести в соответствие [R-M0008-02](#r-m0008-02).

2. **Вариант 2.** Использовать числовое представление, в котором 1000 означает одну минуту.

   **Основание.** [R-M0008-02](#r-m0008-02) «Each timestamp field declares milliseconds; the numeric value 1000 represents one minute.».

   **Ожидаемый результат.** Для отметки в одну минуту записано 1000.

   При выборе этого варианта привести в соответствие [R-M0008-01](#r-m0008-01).

**Черновик приёмочного теста.** Экспортировать отметку в одну минуту и сверить числовое значение и объявленную единицу с согласованной шкалой.

### Z-004 · Приёмка реплики из 81 кодовой точки

**Дефект · Противоречивость · Критичная.** T-7 требует отклонить текст длиннее 80 кодовых точек Unicode. T-8 требует принять реплику из 81 кодовой точки и не устанавливает исключения из предела. Обязательный сценарий проверки предела нельзя принять.

Затронутые утверждения — [R-M0014-01](#r-m0014-01), [R-M0015-01](#r-m0015-01).

[R-M0014-01](#r-m0014-01) · Subtitle track export / Export limits · [строка 14](../../../../../benchmark/subtitles/requirements.md#L14)

> T-7. Reject a cue when its text exceeds 80 Unicode code points.  

[R-M0015-01](#r-m0015-01) · Subtitle track export / Export limits · [строка 15](../../../../../benchmark/subtitles/requirements.md#L15)

> T-8. In the acceptance sample, a cue of 81 Unicode code points is accepted.  

**Сценарий.** Подать на экспорт реплику из приёмочного примера T-8 длиной 81 кодовая точка Unicode.

**Последствие.** Проверка предела по T-7 отклоняет реплику, поскольку 81 больше 80. Приёмка по T-8 требует принять эту же реплику.

**Общее условие.** На экспорт подана реплика из приёмочного примера T-8 с текстом длиной 81 кодовая точка Unicode. Основания — [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.», [R-M0015-01](#r-m0015-01) «In the acceptance sample, a cue of 81 Unicode code points is accepted.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Для реплики из T-8 выбрать отклонение по пределу T-7 или принятие по примеру T-8?

1. **Вариант 1.** Отклонять реплику, если её текст превышает 80 кодовых точек Unicode, включая реплику из приёмочного примера.

   **Основание.** [R-M0014-01](#r-m0014-01) «T-7. Reject a cue when its text exceeds 80 Unicode code points.».

   **Ожидаемый результат.** Реплика из примера отклонена.

   При выборе этого варианта привести в соответствие [R-M0015-01](#r-m0015-01).

2. **Вариант 2.** Принимать реплику из приёмочного примера длиной 81 кодовая точка Unicode.

   **Основание.** [R-M0015-01](#r-m0015-01) «T-8. In the acceptance sample, a cue of 81 Unicode code points is accepted.».

   **Ожидаемый результат.** Реплика из примера принята.

   При выборе этого варианта привести в соответствие [R-M0014-01](#r-m0014-01).

**Черновик приёмочного теста.** Запустить экспорт с репликой из T-8 длиной 81 кодовая точка Unicode и проверить выбранный исход для реплики.

### Z-003 · Критерий удобства экспорта

**Дефект · Проверяемость · Существенная.** T-4 требует, чтобы экспорт воспринимался как лёгкий каждым пользователем, но не задаёт наблюдаемого критерия успеха. Запись файла можно проверить отдельно от удобства.

Затронутые утверждения — [R-M0009-01](#r-m0009-01).

[R-M0009-01](#r-m0009-01) · Subtitle track export / Format · [строка 9](../../../../../benchmark/subtitles/requirements.md#L9)

> T-4. The export experience must feel effortless to every user.  

**Сценарий.** Пользователь завершает экспорт, а проверяющий оценивает, потребовал ли тот усилий.

**Последствие.** При одном и том же поведении интерфейса проверяющие могут вынести разные решения о соответствии T-4.

**Уже установлено.** Оценивается восприятие экспорта одной открытой дорожки в локальный файл каждым пользователем. Основания — [R-M0009-01](#r-m0009-01), [R-M0003-02](#r-m0003-02).

**Открытое решение.** Какой наблюдаемый результат испытания подтверждает выполнение T-4?

**Что различит проверка.** Если все участники оценили лёгкость экспорта на 4 из 5, требование проходит при пороге 4 для каждого участника. / При тех же оценках требование не проходит при пороге 5 для каждого участника.

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** По какому наблюдаемому критерию и в каком сценарии следует принимать требование T-4?

Внести ответ на этот вопрос в [R-M0009-01](#r-m0009-01) для сценария «Пользователь завершает экспорт, а проверяющий оценивает, потребовал ли тот усилий.».

**Черновик приёмочного теста.** Выполнить согласованный сценарий экспорта и сравнить наблюдаемый результат с утверждённым критерием.

## Готовность и порядок исправлений

ТЗ не готово к разработке и приёмке затронутых сценариев. Сначала нужно согласовать формат файла, шкалу отметок и правило проверки длины реплики.

1. Согласовать требования к BOM, единицу и числовое представление отметок, исход для реплики из 81 кодовой точки. Привести приёмочные примеры в соответствие с этими решениями. ([Z-001](#z-001), [Z-002](#z-002), [Z-004](#z-004))
2. Задать сценарий оценки удобства экспорта и измеримый критерий успеха для каждого участника. ([Z-003](#z-003))
3. Исправить внутреннюю ссылку T-40 редакторской правкой. ([Z-005](#z-005))
