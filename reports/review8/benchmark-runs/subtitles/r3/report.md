## Проверка набора в целом

Требования к BOM, шкале временных меток и приёмке реплики из 81 кодовой точки противоречат друг другу в соответствующих сценариях. Для лёгкости экспорта отсутствует измеримый критерий. Ссылка на T-40 требует редакторской правки, а текст сообщения для пустой дорожки уже задан в T-6.

Открытых предполагаемых пробелов — 0. Неоднозначностей — 0. Рекомендаций — 0.

Каждый ID утверждения учитывается один раз. В число нарушений входят подтверждённые дефекты и неоднозначности, для которых показаны две опирающиеся на текст трактовки с разными последствиями. Один и тот же конфликт имеет один ID при любом числе затронутых требований. Критичный дефект блокирует приёмку существенного обязательного сценария. Предполагаемый пробел оставляет открытым ожидаемое поведение или источник данных. Рекомендация предлагает улучшение. Вопросы и рекомендации имеют отдельные счётчики.

### Z-001 · BOM в файле экспорта

**Дефект · Противоречивость · Критичная.** T-1 запрещает BOM в экспортированном файле, а T-2 требует BOM в первых трёх байтах того же файла. Один файл не может пройти обе проверки.

Затронутые утверждения — [R-M0006-01](#r-m0006-01), [R-M0007-01](#r-m0007-01).

[R-M0006-01](#r-m0006-01) · Subtitle track export / Format · [строка 6](../../../../../benchmark/subtitles/requirements.md#L6)

> Write the exported track in UTF-8 without a byte-order mark.  

[R-M0007-01](#r-m0007-01) · Subtitle track export / Format · [строка 7](../../../../../benchmark/subtitles/requirements.md#L7)

> The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.  

**Сценарий.** Успешно экспортировать непустую дорожку с допустимой репликой в локальный файл.

**Последствие.** Один файл не может одновременно удовлетворить формату записи и критерию приёмки.

**Общее условие.** Проверяются первые три байта файла, полученного успешным экспортом дорожки. Основания — [R-M0006-01](#r-m0006-01) «Write the exported track in UTF-8 without a byte-order mark.», [R-M0007-01](#r-m0007-01) «The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Должен ли файл начинаться с UTF-8 BOM или экспортироваться без него?

1. **Вариант 1.** Записывать файл экспорта в UTF-8 без BOM.

   **Основание.** [R-M0006-01](#r-m0006-01) «Write the exported track in UTF-8 without a byte-order mark.».

   **Ожидаемый результат.** Файл начинается без UTF-8 BOM.

   При выборе этого варианта привести в соответствие [R-M0007-01](#r-m0007-01).

2. **Вариант 2.** Требовать UTF-8 BOM в первых трёх байтах файла экспорта.

   **Основание.** [R-M0007-01](#r-m0007-01) «The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

   **Ожидаемый результат.** Первые три байта файла образуют UTF-8 BOM.

   При выборе этого варианта привести в соответствие [R-M0006-01](#r-m0006-01).

**Черновик приёмочного теста.** После экспорта прочитать первые три байта и проверить выбранный исход.

### Z-002 · Масштаб временных меток

**Дефект · Противоречивость · Критичная.** T-3 задаёт для каждого поля миллисекунды и одновременно приравнивает 1000 к одной минуте. Для минутной метки требуются два разных числа, поэтому формат временных меток нельзя принять.

Затронутые утверждения — [R-M0008-01](#r-m0008-01), [R-M0008-02](#r-m0008-02).

[R-M0008-01](#r-m0008-01) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> Each timestamp field declares milliseconds  

[R-M0008-02](#r-m0008-02) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> the numeric value 1000 represents one minute.  

**Сценарий.** Экспортировать допустимую реплику с временной меткой ровно в одну минуту.

**Последствие.** Проверка одного и того же поля потребует разных значений.

**Общее условие.** Проверяется числовое значение экспортируемого поля для временной метки ровно в одну минуту, прямо указанную в T-3. Основания — [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds», [R-M0008-02](#r-m0008-02) «the numeric value 1000 represents one minute.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какое значение должно быть в поле для метки в одну минуту, 60000 или 1000?

1. **Вариант 1.** Числовое значение каждого поля временной метки выражать в миллисекундах.

   **Основание.** [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds».

   **Ожидаемый результат.** Для метки в одну минуту записано 60000.

   При выборе этого варианта привести в соответствие [R-M0008-02](#r-m0008-02).

2. **Вариант 2.** Использовать шкалу, в которой число 1000 в поле временной метки соответствует одной минуте.

   **Основание.** [R-M0008-02](#r-m0008-02) «the numeric value 1000 represents one minute.».

   **Ожидаемый результат.** Для метки в одну минуту записано 1000.

   При выборе этого варианта привести в соответствие [R-M0008-01](#r-m0008-01).

**Черновик приёмочного теста.** Экспортировать реплику с меткой в одну минуту и сравнить число в поле с выбранным значением.

### Z-003 · Критерий лёгкости экспорта

**Дефект · Проверяемость · Существенная.** T-4 обещает лёгкость экспорта для каждого пользователя, но не задаёт меру и порог, по которым можно воспроизводимо оценить это свойство.

Затронутые утверждения — [R-M0009-01](#r-m0009-01).

[R-M0009-01](#r-m0009-01) · Subtitle track export / Format · [строка 9](../../../../../benchmark/subtitles/requirements.md#L9)

> The export experience must feel effortless to every user.  

**Сценарий.** Два пользователя успешно экспортируют одну и ту же дорожку и по-разному оценивают затраченные усилия.

**Последствие.** По ТЗ невозможно воспроизводимо вынести вердикт о выполнении T-4.

**Уже установлено.** Лёгкость требуется для каждого пользователя в сценарии экспорта. Основания — [R-M0009-01](#r-m0009-01).

**Открытое решение.** Какой измеримый критерий определяет, что экспорт дался пользователю без усилий?

**Что различит проверка.** При оценках лёгкости 4 и 5 из 5 проверка проходит, если достаточно оценки 4 от каждого участника. / При тех же оценках проверка не проходит, если от каждого участника требуется оценка 5.

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой наблюдаемый результат пользовательского сценария будет означать выполнение T-4?

Внести ответ на этот вопрос в [R-M0009-01](#r-m0009-01) для сценария «Два пользователя успешно экспортируют одну и ту же дорожку и по-разному оценивают затраченные усилия.».

**Черновик приёмочного теста.** Провести согласованный пользовательский сценарий и оценить результат по утверждённому критерию.

### Z-004 · Приёмка реплики на 81 кодовую точку

**Дефект · Противоречивость · Существенная.** Текст реплики в примере T-8 превышает предел T-7 на одну кодовую точку Unicode. T-7 требует отклонить реплику, а T-8 фиксирует её принятие. Расхождение блокирует приёмку этого примера.

Затронутые утверждения — [R-M0014-01](#r-m0014-01), [R-M0015-01](#r-m0015-01).

[R-M0014-01](#r-m0014-01) · Subtitle track export / Export limits · [строка 14](../../../../../benchmark/subtitles/requirements.md#L14)

> Reject a cue when its text exceeds 80 Unicode code points.  

[R-M0015-01](#r-m0015-01) · Subtitle track export / Export limits · [строка 15](../../../../../benchmark/subtitles/requirements.md#L15)

> In the acceptance sample, a cue of 81 Unicode code points is accepted.  

**Сценарий.** Выполнить приёмочный пример T-8 с репликой, текст которой содержит 81 кодовую точку Unicode.

**Последствие.** Отклонение удовлетворяет T-7 и проваливает пример T-8, а принятие даёт обратный результат.

**Общее условие.** Проверяется реплика из приёмочного примера T-8 с текстом длиной 81 кодовая точка Unicode. Основания — [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.», [R-M0015-01](#r-m0015-01) «In the acceptance sample, a cue of 81 Unicode code points is accepted.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой исход требуется для реплики из T-8, принятие или отклонение?

1. **Вариант 1.** Отклонять реплику, текст которой превышает 80 кодовых точек Unicode.

   **Основание.** [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.».

   **Ожидаемый результат.** Реплика отклонена.

   При выборе этого варианта привести в соответствие [R-M0015-01](#r-m0015-01).

2. **Вариант 2.** В приёмочном примере принимать реплику на 81 кодовую точку Unicode.

   **Основание.** [R-M0015-01](#r-m0015-01) «In the acceptance sample, a cue of 81 Unicode code points is accepted.».

   **Ожидаемый результат.** Реплика принята.

   При выборе этого варианта привести в соответствие [R-M0014-01](#r-m0014-01).

**Черновик приёмочного теста.** Выполнить пример T-8 с текстом на 81 кодовую точку Unicode и проверить выбранный исход для реплики.

Связанные замечания — [Z-001](#z-001).

<a id="decision"></a>

## Готовность и порядок исправлений

ТЗ не готово к передаче в разработку с однозначными критериями приёмки.

1. Согласовать наличие BOM и числовое представление временных меток в требованиях и проверках. ([Z-001](#z-001), [Z-002](#z-002))
2. Согласовать предел длины текста с ожидаемым исходом примера на 81 кодовую точку Unicode. ([Z-004](#z-004))
3. Задать измеримый критерий лёгкости экспорта для каждого пользователя. ([Z-003](#z-003))
4. Исправить внутреннюю ссылку на T-40. ([Z-005](#z-005))
