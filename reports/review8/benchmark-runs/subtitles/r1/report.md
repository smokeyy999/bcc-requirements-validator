## Проверка набора в целом

Правила экспорта и приёмки расходятся по BOM, шкале временных меток и исходу для реплики из 81 кодовой точки. Для удобства экспорта отсутствует критерий оценки. В правиле обработки пустой дорожки ссылка T-40 не разрешается, а точный текст сообщения задан в T-6.

Открытых предполагаемых пробелов — 0. Неоднозначностей — 0. Рекомендаций — 0.

Каждый ID утверждения учитывается один раз. В число нарушений входят подтверждённые дефекты и неоднозначности, для которых показаны две опирающиеся на текст трактовки с разными последствиями. Один и тот же конфликт имеет один ID при любом числе затронутых требований. Критичный дефект блокирует приёмку существенного обязательного сценария. Предполагаемый пробел оставляет открытым ожидаемое поведение или источник данных. Рекомендация предлагает улучшение. Вопросы и рекомендации имеют отдельные счётчики.

### Z-001 · Наличие BOM в файле экспорта

**Дефект · Противоречивость · Критичная.** T-1 требует записать файл без BOM, а T-2 требует BOM в первых трёх байтах этого же файла. Успешный экспорт нельзя принять по обоим правилам.

Затронутые утверждения — [R-M0006-02](#r-m0006-02), [R-M0007-01](#r-m0007-01).

[R-M0006-02](#r-m0006-02) · Subtitle track export / Format · [строка 6](../../../../../benchmark/subtitles/requirements.md#L6)

> Write the exported track in UTF-8 without a byte-order mark.  

[R-M0007-01](#r-m0007-01) · Subtitle track export / Format · [строка 7](../../../../../benchmark/subtitles/requirements.md#L7)

> The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.  

**Сценарий.** Экспортировать в локальный файл открытую дорожку с одной короткой репликой, начинающейся с обычной буквы.

**Последствие.** Файл, соответствующий T-1, не пройдёт проверку T-2, а файл, проходящий T-2, нарушит T-1.

**Общее условие.** Первые три байта файла после успешного экспорта одной открытой дорожки. Основания — [R-M0006-02](#r-m0006-02) «Write the exported track in UTF-8 without a byte-order mark.», [R-M0007-01](#r-m0007-01) «The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой файл должен пройти приёмку, с начальной меткой BOM или без неё?

1. **Вариант 1.** Записывать файл в UTF-8 без BOM.

   **Основание.** [R-M0006-02](#r-m0006-02) «Write the exported track in UTF-8 without a byte-order mark.».

   **Ожидаемый результат.** Начальной метки BOM нет.

   При выборе этого варианта привести в соответствие [R-M0007-01](#r-m0007-01).

2. **Вариант 2.** Файл в UTF-8 должен начинаться с BOM.

   **Основание.** [R-M0007-01](#r-m0007-01) «The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

   **Ожидаемый результат.** Первые три байта образуют UTF-8 BOM.

   При выборе этого варианта привести в соответствие [R-M0006-02](#r-m0006-02).

**Черновик приёмочного теста.** После успешного экспорта проверить первые три байта по выбранному правилу.

### Z-002 · Шкала временных меток

**Дефект · Противоречивость · Критичная.** T-3 задаёт для одного поля миллисекунды и соответствие 1000 одной минуте. В объявленной единице одна минута равна 60000, поэтому корректность экспортированной отметки нельзя принять по обоим правилам.

Затронутые утверждения — [R-M0008-01](#r-m0008-01), [R-M0008-02](#r-m0008-02).

[R-M0008-01](#r-m0008-01) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> Each timestamp field declares milliseconds  

[R-M0008-02](#r-m0008-02) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> the numeric value 1000 represents one minute  

**Сценарий.** Экспортировать реплику с отметкой ровно в одну минуту от начала дорожки.

**Последствие.** Одна и та же отметка записывается как 60000 по объявленной единице и как 1000 по соответствию, заданному в T-3.

**Общее условие.** Числовое значение экспортируемой отметки в одну минуту в поле с объявленной единицей «миллисекунды». Основания — [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds», [R-M0008-02](#r-m0008-02) «the numeric value 1000 represents one minute».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какое значение должна содержать экспортированная отметка в одну минуту, 60000 или 1000?

1. **Вариант 1.** Выражать числовые значения временных меток в объявленных миллисекундах.

   **Основание.** [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds».

   **Ожидаемый результат.** Отметка в одну минуту записана числом 60000.

   При выборе этого варианта привести в соответствие [R-M0008-02](#r-m0008-02).

2. **Вариант 2.** Кодировать одну минуту числовым значением 1000 и согласовать с этим объявленную единицу.

   **Основание.** [R-M0008-02](#r-m0008-02) «the numeric value 1000 represents one minute».

   **Ожидаемый результат.** Отметка в одну минуту записана числом 1000.

   При выборе этого варианта привести в соответствие [R-M0008-01](#r-m0008-01).

**Черновик приёмочного теста.** Сравнить значение экспортированной отметки и объявленную единицу с выбранной шкалой.

### Z-003 · Критерий удобства экспорта

**Дефект · Проверяемость · Существенная.** T-4 заявляет удобство экспорта для каждого пользователя. ТЗ не задаёт наблюдаемой меры этого свойства и правила оценки результата.

Затронутые утверждения — [R-M0009-01](#r-m0009-01).

[R-M0009-01](#r-m0009-01) · Subtitle track export / Format · [строка 9](../../../../../benchmark/subtitles/requirements.md#L9)

> The export experience must feel effortless to every user.  

**Сценарий.** Пользователь успешно экспортирует открытую дорожку, но оценивает процедуру как требующую усилий.

**Последствие.** По ТЗ нельзя определить, какие наблюдения достаточны, чтобы принять или отклонить требование.

**Уже установлено.** Оценивается удобство локального экспорта одной открытой дорожки для каждого пользователя. Основания — [R-M0009-01](#r-m0009-01), [R-M0003-01](#r-m0003-01).

**Открытое решение.** По какому наблюдаемому критерию принимать оценку удобства экспорта для каждого участника испытания?

**Что различит проверка.** При пороге «усилий не потребовалось» оценка «небольшое усилие» у одного участника приводит к непринятию T-4. / При пороге «не более небольшого усилия» те же оценки проходят проверку T-4, если каждый участник укладывается в порог.

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какие наблюдаемые признаки и какой охват проверки достаточны, чтобы принять удобство экспорта по T-4?

Внести ответ на этот вопрос в [R-M0009-01](#r-m0009-01) для сценария «Пользователь успешно экспортирует открытую дорожку, но оценивает процедуру как требующую усилий.».

**Черновик приёмочного теста.** Выполнить пользовательский сценарий экспорта и оценить результат по согласованным критерию и охвату.

### Z-004 · Приёмка реплики из 81 кодовой точки

**Дефект · Противоречивость · Существенная.** T-7 требует отклонить реплику из-за длины текста, а T-8 принимает эту же реплику. Без согласования нельзя определить ожидаемый результат проверки предела в приёмочном примере.

Затронутые утверждения — [R-M0014-01](#r-m0014-01), [R-M0015-01](#r-m0015-01).

[R-M0014-01](#r-m0014-01) · Subtitle track export / Export limits · [строка 14](../../../../../benchmark/subtitles/requirements.md#L14)

> Reject a cue when its text exceeds 80 Unicode code points.  

[R-M0015-01](#r-m0015-01) · Subtitle track export / Export limits · [строка 15](../../../../../benchmark/subtitles/requirements.md#L15)

> In the acceptance sample, a cue of 81 Unicode code points is accepted.  

**Сценарий.** Проверить реплику приёмочного примера, текст которой содержит 81 кодовую точку Unicode.

**Последствие.** T-7 требует отклонить реплику, поскольку 81 больше 80. T-8 требует принять эту же реплику.

**Общее условие.** Текст реплики из приёмочного примера содержит 81 кодовую точку Unicode. К нему применяется предел в 80 кодовых точек. Основания — [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.», [R-M0015-01](#r-m0015-01) «In the acceptance sample, a cue of 81 Unicode code points is accepted.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Должна ли реплика из 81 кодовой точки в приёмочном примере быть отклонена или принята?

1. **Вариант 1.** Отклонять реплику, если её текст превышает 80 кодовых точек Unicode, в том числе в приёмочном примере.

   **Основание.** [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.».

   **Ожидаемый результат.** Реплика из примера отклонена.

   При выборе этого варианта привести в соответствие [R-M0015-01](#r-m0015-01).

2. **Вариант 2.** Принимать реплику из 81 кодовой точки Unicode в приёмочном примере.

   **Основание.** [R-M0015-01](#r-m0015-01) «In the acceptance sample, a cue of 81 Unicode code points is accepted.».

   **Ожидаемый результат.** Реплика из примера принята.

   При выборе этого варианта привести в соответствие [R-M0014-01](#r-m0014-01).

**Черновик приёмочного теста.** Подать реплику из примера на экспорт и проверить, принята ли она при проверке длины.

<a id="decision"></a>

## Готовность и порядок исправлений

ТЗ не готово к разработке и приёмке в текущей редакции.

1. Согласовать наличие BOM в файле, а также единицу и числовую шкалу временных меток. ([Z-001](#z-001), [Z-002](#z-002))
2. Согласовать предел длины текста и ожидаемый исход для реплики из 81 кодовой точки. ([Z-004](#z-004))
3. Задать наблюдаемый критерий удобства экспорта и охват проверки. ([Z-003](#z-003))
4. Исправить внутреннюю ссылку T-40 в правиле обработки пустой дорожки. ([Z-005](#z-005))
