Каждый ID утверждения учитывается один раз. В число нарушений входят подтверждённые дефекты и неоднозначности, для которых показаны две опирающиеся на текст трактовки с разными последствиями. Один и тот же конфликт имеет один ID при любом числе затронутых требований. Критичный дефект блокирует приёмку существенного обязательного сценария. Предполагаемый пробел оставляет открытым ожидаемое поведение или источник данных. Рекомендация предлагает улучшение. Вопросы и рекомендации имеют отдельные счётчики.

**При попытке отправить черновик перевозчик должен получить ведомость или передача запрещена?**

**Общее условие.** При исправной сети и авторизации оператор пытается отправить сохранённую ведомость допустимого размера в состоянии «Черновик». Основания — [R-M0006-01](#r-m0006-01) «Оператор может отправить ведомость только в состоянии «Готова».», [R-M0007-02](#r-m0007-02) «При попытке отправить ведомость в состоянии «Черновик» терминал сразу передаёт её перевозчику.».

[R-M0011-01](#r-m0011-01) · Отправка грузовых ведомостей / Параметры · [строка 11](../../../../../benchmark/dispatch/requirements.md#L11)

> При загрузке ведомости из 25 строк терминал принимает файл и разрешает отправку.  

[R-M0011-02](#r-m0011-02) · Отправка грузовых ведомостей / Параметры · [строка 11](../../../../../benchmark/dispatch/requirements.md#L11)

> При загрузке ведомости из 25 строк терминал принимает файл и разрешает отправку.  

**Сценарий.** Оператор загружает один файл с ведомостью из 25 строк груза и проверяет возможность отправки этой ведомости в состоянии «Готова».

**Последствие.** По S-3 ведомость превышает предел в 24 строки и не может быть отправлена как одна ведомость. По S-4 терминал принимает файл и разрешает отправку. Правило о сокращении состава или исключении для этого случая отсутствует.

**Общее условие.** Оператор загружает один файл с ведомостью из 25 строк груза и проверяет разрешение на отправку всей ведомости при выполнении условия «Готова». Основания — [R-M0010-01](#r-m0010-01) «Одна ведомость содержит от 1 до 24 строк груза включительно.», [R-M0010-02](#r-m0010-02) «Одна ведомость содержит от 1 до 24 строк груза включительно.», [R-M0011-01](#r-m0011-01) «При загрузке ведомости из 25 строк терминал принимает файл и разрешает отправку.», [R-M0011-02](#r-m0011-02) «При загрузке ведомости из 25 строк терминал принимает файл и разрешает отправку.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Отправка одной ведомости из 25 строк должна быть запрещена по пределу S-3 или разрешена по S-4?

1. **Вариант 1.** Отправляемая ведомость содержит от 1 до 24 строк груза включительно.

   **Основание.** [R-M0010-02](#r-m0010-02) «Одна ведомость содержит от 1 до 24 строк груза включительно.».

   **Ожидаемый результат.** Отправка одной ведомости из 25 строк не разрешена.

   При выборе этого варианта привести в соответствие [R-M0011-01](#r-m0011-01).

2. **Вариант 2.** При загрузке ведомости из 25 строк терминал принимает файл и разрешает её отправку.

   **Основание.** [R-M0011-01](#r-m0011-01) «При загрузке ведомости из 25 строк терминал принимает файл и разрешает отправку.».

   **Ожидаемый результат.** Терминал принимает файл и разрешает отправку одной ведомости из 25 строк.

   При выборе этого варианта привести в соответствие [R-M0010-02](#r-m0010-02).

**Черновик приёмочного теста.** Загрузить файл с 25 строками, зафиксировать результат загрузки и проверить, разрешена ли отправка всей ведомости при выполнении условия «Готова».

### Z-003 · Единица срока хранения

Затронутые утверждения — [R-M0015-01](#r-m0015-01), [R-M0015-02](#r-m0015-02).

[R-M0015-02](#r-m0015-02) · Отправка грузовых ведомостей / Параметры · [строка 15](../../../../../benchmark/dispatch/requirements.md#L15)

> Срок локального хранения подтверждения задаётся в сутках; значение 7 означает семь часов.  

**Сценарий.** Для локально сохранённого подтверждения установлено значение срока хранения 7.

**Последствие.** По объявленной единице срок равен 604800000 мс, по указанному толкованию значения — 25200000 мс. Исключение из общей шкалы явно не задано.

**Общее условие.** Для локально сохранённого подтверждения задан срок хранения со значением 7. Основания — [R-M0015-01](#r-m0015-01) «Срок локального хранения подтверждения задаётся в сутках», [R-M0015-02](#r-m0015-02) «значение 7 означает семь часов.».

1. **Вариант 1.** Значение срока локального хранения подтверждения задаётся в сутках.

   **Основание.** [R-M0015-01](#r-m0015-01) «Срок локального хранения подтверждения задаётся в сутках; значение 7 означает семь часов.».

2. **Вариант 2.** Значение 7 означает семь часов.

   **Основание.** [R-M0015-02](#r-m0015-02) «Срок локального хранения подтверждения задаётся в сутках; значение 7 означает семь часов.».

   **Ожидаемый результат.** Через сутки после начала хранения срок хранения подтверждения уже истёк.

   При выборе этого варианта привести в соответствие [R-M0015-01](#r-m0015-01).

## Готовность и порядок исправлений

ТЗ не готово к разработке. Сначала нужно определить ожидаемые результаты двух обязательных сценариев отправки. Для полной приёмки также нужно согласовать срок хранения и предел задержки показа.

1. Согласовать результат попытки отправить черновик и разрешение на отправку готовой ведомости из 25 строк. ([Z-001](#z-001), [Z-002](#z-002))
2. Согласовать единицу срока хранения и значение 7, затем задать максимальную задержку показа «Передано». ([Z-003](#z-003), [Z-005](#z-005))
3. Исправить ссылку S-97 в правиле об отказе перевозчика. ([Z-006](#z-006))
