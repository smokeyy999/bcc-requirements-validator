Каждый ID утверждения учитывается один раз. В число нарушений входят подтверждённые дефекты и неоднозначности, для которых показаны две опирающиеся на текст трактовки с разными последствиями. Один и тот же конфликт имеет один ID при любом числе затронутых требований. Критичный дефект блокирует приёмку существенного обязательного сценария. Предполагаемый пробел оставляет открытым ожидаемое поведение или источник данных. Рекомендация предлагает улучшение. Вопросы и рекомендации имеют отдельные счётчики.

### R-M0006-01 · Отправка разрешена только для ведомости в состоянии «Готова».

Отправка грузовых ведомостей / Отправка · [строка 6](../../../../../benchmark/dispatch/requirements.md#L6)

> Оператор может отправить ведомость только в состоянии «Готова».  

**Связано с нарушением в спецификации.** S-1 допускает отправку только готовой ведомости, а S-2 при той же попытке отправки черновика предписывает передачу перевозчику. Ожидаемый результат проверки допуска к отправке определить невозможно.

### R-M0011-01 · Терминал принимает загружаемый файл ведомости из 25 строк.

Отправка грузовых ведомостей / Параметры · [строка 11](../../../../../benchmark/dispatch/requirements.md#L11)

> При загрузке ведомости из 25 строк терминал принимает файл и разрешает отправку.  

**Связано с нарушением в спецификации.** S-3 ограничивает ведомость 24 строками груза, а S-4 разрешает отправку той же загруженной ведомости из 25 строк. Изменение состава при загрузке не задано. ## Готовность и порядок исправлений

ТЗ не готово к разработке и приёмке отправки. Сначала нужно согласовать правила допуска, затем определить срок хранения и предел задержки показа надписи и исправить ссылку S-97.

1. Согласовать исход попытки отправки черновика и допуск готовой ведомости из 25 строк. ([Z-001](#z-001), [Z-003](#z-003))
2. Согласовать единицу срока хранения и длительность для значения 7. ([Z-005](#z-005))
3. Задать предельную задержку показа «Передано» после получения подтверждения перевозчика. ([Z-004](#z-004))
