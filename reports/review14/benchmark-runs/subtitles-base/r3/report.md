**Открытое решение.** Какой результат проверять по новому пути при экспорте дорожки с одной допустимой репликой и одной репликой из 81 кодовой точки Unicode?

**Что различит проверка.** Создан файл, который содержит только допустимую реплику. / Экспорт прерван, файл по указанному пути отсутствует.

### Z-002 · Объявление единицы временной метки

**Предполагаемый пробел · Проверяемость · Существенная.** T-3 задаёт масштаб числа и требует объявления миллисекунд для каждого поля. Проверка значения 1000 подтверждает масштаб. Для проверки самого объявления нужен наблюдаемый критерий.

Затронутые утверждения — [R-M0008-01](#r-m0008-01), [R-M0008-02](#r-m0008-02).

[R-M0008-01](#r-m0008-01) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/baseline.md#L8)

> Each timestamp field declares milliseconds  

[R-M0008-02](#r-m0008-02) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/baseline.md#L8)

> Each timestamp field declares milliseconds; the numeric value 1000 represents one second.  

**Сценарий.** Экспортировать дорожку с временной меткой в одну секунду и проверить соответствующее поле со значением 1000.

**Последствие.** Значение 1000 подтверждает масштаб числа. Проверка объявления миллисекунд остаётся без критерия успеха.

**Уже установлено.** Каждое поле временной метки объявляет миллисекунды, а значение 1000 соответствует одной секунде. Основания — [R-M0008-01](#r-m0008-01), [R-M0008-02](#r-m0008-02), [R-M0006-01](#r-m0006-01).

**Открытое решение.** Где в формате экспорта проверять объявление миллисекунд для каждого поля временной метки?

**Что различит проверка.** Значение равно 1000, объявление миллисекунд указано непосредственно в каждом поле временной метки. / Значение равно 1000, объявление миллисекунд указано в отдельном описании полей, которое явно охватывает каждое поле временной метки.

1. Задать ожидаемое состояние места назначения и состав файла при отклонении длинной реплики в смешанной дорожке. ([Z-001](#z-001))
