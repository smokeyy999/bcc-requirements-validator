## Проверка набора в целом

ТЗ задаёт несовместимые требования к BOM, шкале временных меток и приёмке реплики из примера. Для лёгкости экспорта отсутствует измеримый критерий. В T-5 указана отсутствующая ссылка T-40, при этом сообщение для пустой дорожки уже задано в T-6.

Открытых предполагаемых пробелов — 0. Неоднозначностей — 0. Рекомендаций — 0.

Каждый ID утверждения учитывается один раз. В число нарушений входят подтверждённые дефекты и неоднозначности, для которых показаны две опирающиеся на текст трактовки с разными последствиями. Один и тот же конфликт имеет один ID при любом числе затронутых требований. Критичный дефект блокирует приёмку существенного обязательного сценария. Предполагаемый пробел оставляет открытым ожидаемое поведение или источник данных. Рекомендация предлагает улучшение. Вопросы и рекомендации имеют отдельные счётчики.

### Z-001 · BOM в файле экспорта

**Дефект · Противоречивость · Критичная.** T-1 требует сохранить файл без BOM, а T-2 принимает тот же файл только при наличии BOM. Приёмка результата экспорта заблокирована.

Затронутые утверждения — [R-M0006-02](#r-m0006-02), [R-M0007-01](#r-m0007-01).

[R-M0006-02](#r-m0006-02) · Subtitle track export / Format · [строка 6](../../../../../benchmark/subtitles/requirements.md#L6)

> Write the exported track in UTF-8 without a byte-order mark.  

[R-M0007-01](#r-m0007-01) · Subtitle track export / Format · [строка 7](../../../../../benchmark/subtitles/requirements.md#L7)

> The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.  

**Сценарий.** Экспортировать открытую дорожку с одной допустимой репликой в локальный файл.

**Последствие.** Один файл не может одновременно удовлетворить обоим требованиям к начальному байтовому префиксу.

**Общее условие.** Первые три байта файла, полученного при экспорте дорожки. Основания — [R-M0006-02](#r-m0006-02) «Write the exported track in UTF-8 without a byte-order mark.», [R-M0007-01](#r-m0007-01) «The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой файл должен пройти приёмку: с UTF-8 BOM или без него?

1. **Вариант 1.** Записывать экспорт в UTF-8 без BOM.

   **Основание.** [R-M0006-02](#r-m0006-02) «Write the exported track in UTF-8 without a byte-order mark.».

   **Ожидаемый результат.** Файл начинается без BOM.

   При выборе этого варианта привести в соответствие [R-M0007-01](#r-m0007-01).

2. **Вариант 2.** Требовать UTF-8 BOM в первых трёх байтах экспорта.

   **Основание.** [R-M0007-01](#r-m0007-01) «The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

   **Ожидаемый результат.** Первые три байта файла образуют UTF-8 BOM.

   При выборе этого варианта привести в соответствие [R-M0006-02](#r-m0006-02).

**Черновик приёмочного теста.** После экспорта проверить первые три байта на префикс EF BB BF. Ожидать его наличия или отсутствия по выбранному правилу.

### Z-002 · Шкала временных меток

**Дефект · Противоречивость · Критичная.** T-3 задаёт две несовместимые шкалы для одного поля. Объявленная единица даёт 60000 для одной минуты, а явное соответствие даёт 1000. Корректность экспорта временных меток по обоим условиям подтвердить невозможно.

Затронутые утверждения — [R-M0008-01](#r-m0008-01), [R-M0008-02](#r-m0008-02).

[R-M0008-01](#r-m0008-01) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> the numeric value 1000 represents one minute.  

[R-M0008-02](#r-m0008-02) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> Each timestamp field declares milliseconds  

**Сценарий.** Экспортировать допустимую реплику с временной меткой ровно в одну минуту.

**Последствие.** При чтении значения 1000 в объявленных миллисекундах метка окажется на одной секунде вместо одной минуты.

**Общее условие.** Поле экспортированной временной метки в одну минуту объявляет миллисекунды. Основания — [R-M0008-02](#r-m0008-02) «Each timestamp field declares milliseconds», [R-M0008-01](#r-m0008-01) «the numeric value 1000 represents one minute.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какое значение должно пройти приёмку для отметки в одну минуту, и какая единица должна быть объявлена для выбранной шкалы?

1. **Вариант 1.** Записывать числовые значения всех временных меток в объявленных миллисекундах.

   **Основание.** [R-M0008-02](#r-m0008-02) «Each timestamp field declares milliseconds».

   **Ожидаемый результат.** Для отметки в одну минуту в файле записано 60000.

   При выборе этого варианта привести в соответствие [R-M0008-01](#r-m0008-01).

2. **Вариант 2.** Использовать соответствие, по которому значение 1000 представляет одну минуту.

   **Основание.** [R-M0008-01](#r-m0008-01) «the numeric value 1000 represents one minute.».

   **Ожидаемый результат.** Для отметки в одну минуту в файле записано 1000.

   При выборе этого варианта привести в соответствие [R-M0008-02](#r-m0008-02).

**Черновик приёмочного теста.** Проверить число и объявленную единицу в экспортированном поле. Для метки в одну минуту сравнить исходы 60000 и 1000.

### Z-003 · Критерий лёгкости экспорта

**Дефект · Проверяемость · Существенная.** T-4 требует, чтобы экспорт воспринимался как лёгкий каждым пользователем. Наблюдаемый показатель и порог для оценки этого свойства отсутствуют.

Затронутые утверждения — [R-M0009-01](#r-m0009-01).

[R-M0009-01](#r-m0009-01) · Subtitle track export / Format · [строка 9](../../../../../benchmark/subtitles/requirements.md#L9)

> The export experience must feel effortless to every user.  

**Сценарий.** Пользователи выполняют экспорт одной и той же допустимой дорожки и по-разному оценивают лёгкость операции.

**Последствие.** Для одних и тех же наблюдений возможны разные вердикты по T-4.

**Уже установлено.** Пользователь экспортирует одну открытую дорожку в локальный файл. T-4 требует, чтобы экспорт воспринимался как лёгкий каждым пользователем. Основания — [R-M0009-01](#r-m0009-01), [R-M0003-01](#r-m0003-01).

**Открытое решение.** Установить измеримый критерий приёмки лёгкости экспорта для каждого пользователя.

**Что различит проверка.** Если допускать оценку трудности до 3 из 5 включительно, экспорт проходит проверку при максимальной оценке 3. / Если допускать оценку трудности до 2 из 5 включительно, экспорт с теми же оценками проверку не проходит.

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** По какому наблюдаемому показателю, порогу и охвату пользователей следует принимать лёгкость экспорта?

Внести ответ на этот вопрос в [R-M0009-01](#r-m0009-01) для сценария «Пользователи выполняют экспорт одной и той же допустимой дорожки и по-разному оценивают лёгкость операции.».

**Черновик приёмочного теста.** После согласования критерия выполнить заданный сценарий экспорта с согласованным охватом и сравнить измеренный результат с порогом.

### Z-004 · Длина реплики в приёмочном примере

**Дефект · Противоречивость · Существенная.** T-7 требует отклонить реплику с текстом длиннее 80 кодовых точек Unicode, а T-8 принимает реплику длиной 81 в тех же единицах. Противоречие блокирует приёмку указанного граничного примера.

Затронутые утверждения — [R-M0014-01](#r-m0014-01), [R-M0015-01](#r-m0015-01).

[R-M0014-01](#r-m0014-01) · Subtitle track export / Export limits · [строка 14](../../../../../benchmark/subtitles/requirements.md#L14)

> Reject a cue when its text exceeds 80 Unicode code points.  

[R-M0015-01](#r-m0015-01) · Subtitle track export / Export limits · [строка 15](../../../../../benchmark/subtitles/requirements.md#L15)

> In the acceptance sample, a cue of 81 Unicode code points is accepted.  

**Сценарий.** Предъявить к экспорту реплику из приёмочного примера с текстом длиной 81 кодовую точку Unicode.

**Последствие.** Отклонение выполняет T-7, а принятие выполняет T-8. Действующее исключение для примера отсутствует.

**Общее условие.** При экспорте проверяется реплика из приёмочного примера с текстом длиной 81 кодовую точку Unicode. Основания — [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.», [R-M0015-01](#r-m0015-01) «In the acceptance sample, a cue of 81 Unicode code points is accepted.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой исход должна считать успешным приёмка для реплики из примера длиной 81 кодовая точка Unicode?

1. **Вариант 1.** Отклонять реплику с текстом длиннее 80 кодовых точек Unicode, включая реплику из примера.

   **Основание.** [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.».

   **Ожидаемый результат.** Реплика из примера отклонена.

   При выборе этого варианта привести в соответствие [R-M0015-01](#r-m0015-01).

2. **Вариант 2.** Принимать реплику из приёмочного примера с текстом длиной 81 кодовую точку Unicode.

   **Основание.** [R-M0015-01](#r-m0015-01) «In the acceptance sample, a cue of 81 Unicode code points is accepted.».

   **Ожидаемый результат.** Реплика из примера принята.

   При выборе этого варианта привести в соответствие [R-M0014-01](#r-m0014-01).

**Черновик приёмочного теста.** Передать реплику из примера на экспорт и проверить её принятие или отклонение по выбранному правилу.

## Готовность и порядок исправлений

ТЗ не готово к разработке и приёмке экспорта. Сначала нужно согласовать формат файла и исход граничного примера.

1. Согласовать наличие BOM, объявленную единицу временных меток и числовое значение для одной минуты. Привести требования и приёмку к согласованным результатам. ([Z-001](#z-001), [Z-002](#z-002))
2. Согласовать предел длины текста с ожидаемым исходом для реплики из примера длиной 81 кодовую точку Unicode. ([Z-004](#z-004))
3. Определить измеримый критерий лёгкости экспорта, порог и охват проверки требования для каждого пользователя. ([Z-003](#z-003))
4. Исправить в T-5 ссылку на отсутствующий пункт T-40. ([Z-005](#z-005))
