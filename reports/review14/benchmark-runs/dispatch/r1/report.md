## Проверка набора в целом

Приёмку отправки блокируют два противоречия: передача черновика и допуск ведомости из 25 строк. Для хранения нужно согласовать длительность при значении 7, для показа «Передано» — определить измеримый предел задержки. Ссылка S-97 требует редакторского исправления. Текст и состояние при отказе заданы в S-7.

Открытых предполагаемых пробелов — 0. Неоднозначностей — 0. Рекомендаций — 0.

Каждый ID утверждения учитывается один раз. В число нарушений входят подтверждённые дефекты и неоднозначности, для которых показаны две опирающиеся на текст трактовки с разными последствиями. Один и тот же конфликт имеет один ID при любом числе затронутых требований. Критичный дефект блокирует приёмку существенного обязательного сценария. Предполагаемый пробел оставляет открытым ожидаемое поведение или источник данных. Рекомендация предлагает улучшение. Вопросы и рекомендации имеют отдельные счётчики.

## Критичные дефекты

- [Z-001](#z-001) · S-1 разрешает отправку только из состояния «Готова», а S-2 требует передать ту же ведомость перевозчику при попытке отправки из «Черновика». Приёмка отправки требует определить, получит ли перевозчик ведомость.
- [Z-002](#z-002) · S-3 ограничивает одну ведомость 24 строками груза, а S-4 требует принять ведомость из 25 строк и разрешить её отправку. Расхождение касается допуска одной и той же ведомости к отправке.

### Z-001 · Отправка черновика

**Дефект · Противоречивость · Критичная.** S-1 разрешает отправку только из состояния «Готова», а S-2 требует передать ту же ведомость перевозчику при попытке отправки из «Черновика». Приёмка отправки требует определить, получит ли перевозчик ведомость.

Затронутые утверждения — [R-M0006-01](#r-m0006-01), [R-M0007-01](#r-m0007-01), [R-M0007-02](#r-m0007-02).

[R-M0006-01](#r-m0006-01) · Отправка грузовых ведомостей / Отправка · [строка 6](../../../../../benchmark/dispatch/requirements.md#L6)

> Оператор может отправить ведомость только в состоянии «Готова».  

[R-M0007-01](#r-m0007-01) · Отправка грузовых ведомостей / Отправка · [строка 7](../../../../../benchmark/dispatch/requirements.md#L7)

> При попытке отправить ведомость в состоянии «Черновик» терминал сразу передаёт её перевозчику.  

[R-M0007-02](#r-m0007-02) · Отправка грузовых ведомостей / Отправка · [строка 7](../../../../../benchmark/dispatch/requirements.md#L7)

> При попытке отправить ведомость в состоянии «Черновик» терминал сразу передаёт её перевозчику.  

**Сценарий.** При исправных сети и авторизации оператор пытается отправить сохранённую ведомость из одной строки в состоянии «Черновик».

**Последствие.** Проверяющий не может определить, должна ли ведомость поступить перевозчику.

**Общее условие.** Оператор пытается отправить сохранённую ведомость в состоянии «Черновик». Сеть и авторизация исправны. Основания — [R-M0006-01](#r-m0006-01) «Оператор может отправить ведомость только в состоянии «Готова».», [R-M0007-02](#r-m0007-02) «При попытке отправить ведомость в состоянии «Черновик» терминал сразу передаёт её перевозчику.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** При попытке отправить «Черновик» терминал должен блокировать передачу или сразу передавать ведомость?

1. **Вариант 1.** Оператор может отправить ведомость только в состоянии «Готова».

   **Основание.** [R-M0006-01](#r-m0006-01) «Оператор может отправить ведомость только в состоянии «Готова».».

   **Ожидаемый результат.** Перевозчик не получает ведомость.

   При выборе этого варианта привести в соответствие [R-M0007-02](#r-m0007-02).

2. **Вариант 2.** При попытке отправить ведомость в состоянии «Черновик» терминал сразу передаёт её перевозчику.

   **Основание.** [R-M0007-02](#r-m0007-02) «При попытке отправить ведомость в состоянии «Черновик» терминал сразу передаёт её перевозчику.».

   **Ожидаемый результат.** Перевозчик получает ведомость.

   При выборе этого варианта привести в соответствие [R-M0006-01](#r-m0006-01).

**Черновик приёмочного теста.** Попытаться отправить «Черновик» и проверить факт получения ведомости перевозчиком.

Затронутые утверждения — [R-M0010-01](#r-m0010-01), [R-M0010-02](#r-m0010-02), [R-M0011-01](#r-m0011-01), [R-M0011-02](#r-m0011-02).

> Одна ведомость содержит от 1 до 24 строк груза включительно.  

[R-M0011-01](#r-m0011-01) · Отправка грузовых ведомостей / Параметры · [строка 11](../../../../../benchmark/dispatch/requirements.md#L11)

> При загрузке ведомости из 25 строк терминал принимает файл и разрешает отправку.  

[R-M0011-02](#r-m0011-02) · Отправка грузовых ведомостей / Параметры · [строка 11](../../../../../benchmark/dispatch/requirements.md#L11)

> При загрузке ведомости из 25 строк терминал принимает файл и разрешает отправку.  

**Сценарий.** Оператор загружает файл одной ведомости из 25 строк груза. Проверяется допуск этой ведомости к отправке при выполнении условия «Готова».

**Последствие.** Одна проверка требует запретить отправку по числу строк, другая требует разрешить её.

**Общее условие.** Загружается файл одной ведомости из 25 строк груза. Допуск к отправке проверяется при выполнении условия «Готова». Основания — [R-M0010-01](#r-m0010-01) «Одна ведомость содержит от 1 до 24 строк груза включительно.», [R-M0010-02](#r-m0010-02) «Одна ведомость содержит от 1 до 24 строк груза включительно.», [R-M0011-01](#r-m0011-01) «При загрузке ведомости из 25 строк терминал принимает файл и разрешает отправку.», [R-M0011-02](#r-m0011-02) «При загрузке ведомости из 25 строк терминал принимает файл и разрешает отправку.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Запретить отправку ведомости из 25 строк груза по пределу S-3 или принять файл и разрешить её отправку по S-4?

1. **Вариант 1.** Одна ведомость содержит от 1 до 24 строк груза включительно.

   **Основание.** [R-M0010-01](#r-m0010-01) «Одна ведомость содержит от 1 до 24 строк груза включительно.».

   **Ожидаемый результат.** Ведомость из 25 строк груза не допускается к отправке.

   При выборе этого варианта привести в соответствие [R-M0011-02](#r-m0011-02).

2. **Вариант 2.** При загрузке ведомости из 25 строк терминал принимает файл и разрешает отправку.

   **Основание.** [R-M0011-02](#r-m0011-02) «При загрузке ведомости из 25 строк терминал принимает файл и разрешает отправку.».

   **Ожидаемый результат.** Терминал принимает файл и разрешает отправку ведомости из 25 строк груза.

   При выборе этого варианта привести в соответствие [R-M0010-01](#r-m0010-01).

**Черновик приёмочного теста.** Загрузить ведомость из 25 строк груза и проверить допуск к отправке при соблюдении остальных условий. Отдельно зафиксировать результат загрузки.

## Готовность и порядок исправлений

ТЗ не готово к разработке и приёмке отправки до согласования допустимого состояния и числа строк ведомости.

1. Согласовать результат попытки отправки черновика и допуск к отправке ведомости из 25 строк. ([Z-001](#z-001), [Z-002](#z-002))
2. Привести объявленную единицу хранения и пример со значением 7 к одной длительности. ([Z-004](#z-004))
3. Задать измеримый предел задержки показа «Передано» после получения подтверждения. ([Z-003](#z-003))
4. Исправить внутреннюю ссылку S-97. ([Z-006](#z-006))
