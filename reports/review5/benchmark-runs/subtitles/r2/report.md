## Проверка набора в целом

Правила и приёмка расходятся по BOM, шкале временных меток и исходу для реплики из 81 кодовой точки. Лёгкость экспорта требует измеримого критерия. Ссылка T-40 требует редакторского исправления. Сообщение для пустой дорожки задано в T-6.

Открытых предполагаемых пробелов — 0. Неоднозначностей — 0. Рекомендаций — 0.

Каждый ID утверждения учитывается один раз. В число нарушений входят подтверждённые дефекты и неоднозначности, для которых показаны две опирающиеся на текст трактовки с разными последствиями. Один и тот же конфликт имеет один ID при любом числе затронутых требований. Критичный дефект блокирует приёмку существенного обязательного сценария. Предполагаемый пробел оставляет открытым ожидаемое поведение или источник данных. Рекомендация предлагает улучшение. Вопросы и рекомендации имеют отдельные счётчики.

### Z-001 · BOM в экспортируемом файле

**Дефект · Противоречивость · Критичная.** T-1 запрещает начальный BOM, а T-2 требует его в том же файле. Файл успешного экспорта не может одновременно выполнить правило записи и пройти приёмку.

Затронутые утверждения — [R-M0006-01](#r-m0006-01), [R-M0007-01](#r-m0007-01).

[R-M0006-01](#r-m0006-01) · Subtitle track export / Format · [строка 6](../../../../../benchmark/subtitles/requirements.md#L6)

> Write the exported track in UTF-8 without a byte-order mark.  

[R-M0007-01](#r-m0007-01) · Subtitle track export / Format · [строка 7](../../../../../benchmark/subtitles/requirements.md#L7)

> The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.  

**Сценарий.** Экспортировать непустую дорожку из приёмочного теста и прочитать первые три байта файла.

**Последствие.** Реализация экспорта без BOM провалит приёмочный тест.

**Общее условие.** Проверяются первые три байта файла, полученного при успешном экспорте непустой дорожки в приёмочном тесте. Основания — [R-M0006-01](#r-m0006-01) «Write the exported track in UTF-8 without a byte-order mark.», [R-M0007-01](#r-m0007-01) «The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой файл принимать: с начальным BOM UTF-8 или без него?

1. **Вариант 1.** Записывать дорожку в UTF-8 без BOM.

   **Основание.** [R-M0006-01](#r-m0006-01) «Write the exported track in UTF-8 without a byte-order mark.».

   **Ожидаемый результат.** Начального BOM в файле нет.

   При выборе этого варианта привести в соответствие [R-M0007-01](#r-m0007-01).

2. **Вариант 2.** Требовать BOM UTF-8 в первых трёх байтах экспортируемого файла.

   **Основание.** [R-M0007-01](#r-m0007-01) «The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

   **Ожидаемый результат.** Первые три байта файла — EF BB BF.

   При выборе этого варианта привести в соответствие [R-M0006-01](#r-m0006-01).

**Черновик приёмочного теста.** Выполнить экспорт и проверить наличие BOM в начале файла по выбранному правилу.

### Z-002 · Шкала временных меток

**Дефект · Противоречивость · Критичная.** T-3 задаёт миллисекунды для каждого поля и приравнивает число 1000 к минуте. Для того же поля минута составляет 60000 миллисекунд. Приёмка временных меток требует единой шкалы.

Затронутые утверждения — [R-M0008-01](#r-m0008-01), [R-M0008-02](#r-m0008-02).

[R-M0008-01](#r-m0008-01) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> Each timestamp field declares milliseconds; the numeric value 1000 represents one minute.  

[R-M0008-02](#r-m0008-02) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> Each timestamp field declares milliseconds; the numeric value 1000 represents one minute.  

**Сценарий.** Экспортировать допустимую реплику с временной меткой в одну минуту.

**Последствие.** Проверка и реализация могут использовать разные масштабы и расходиться в моменте показа реплики.

**Общее условие.** При экспорте значение одного поля временной метки соответствует одной минуте. Объявленная единица и числовое соответствие применяются к этому полю. Основания — [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds», [R-M0008-02](#r-m0008-02) «the numeric value 1000 represents one minute».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какое число для метки в одну минуту считать правильным при приёмке: 60000 или 1000?

1. **Вариант 1.** Записывать значения каждого поля временной метки в миллисекундах.

   **Основание.** [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds; the numeric value 1000 represents one minute.».

   **Ожидаемый результат.** Метка в одну минуту записана как 60000.

   При выборе этого варианта привести в соответствие [R-M0008-02](#r-m0008-02).

2. **Вариант 2.** В каждом поле временной метки представлять одну минуту числом 1000.

   **Основание.** [R-M0008-02](#r-m0008-02) «Each timestamp field declares milliseconds; the numeric value 1000 represents one minute.».

   **Ожидаемый результат.** Метка в одну минуту записана как 1000.

   При выборе этого варианта привести в соответствие [R-M0008-01](#r-m0008-01).

**Черновик приёмочного теста.** Экспортировать реплику с меткой в одну минуту и сравнить записанное число с выбранным результатом.

**Сценарий.** Выполнить экспорт, измерить его восприятие пользователями по согласованному критерию и оценить соответствие T-4 для каждого пользователя.

**Последствие.** Один и тот же успешный экспорт может получить разные оценки соответствия T-4.

**Уже установлено.** Требование относится к восприятию экспорта каждым пользователем. Основания — [R-M0009-01](#r-m0009-01).

### Z-004 · Реплика из 81 кодовой точки

**Дефект · Противоречивость · Существенная.** T-7 требует отклонить текст длиннее 80 кодовых точек Unicode, а T-8 принимает реплику из 81 кодовой точки. Расхождение блокирует приёмку проверки лимита на этом примере.

Затронутые утверждения — [R-M0014-01](#r-m0014-01), [R-M0015-01](#r-m0015-01).

[R-M0014-01](#r-m0014-01) · Subtitle track export / Export limits · [строка 14](../../../../../benchmark/subtitles/requirements.md#L14)

> Reject a cue when its text exceeds 80 Unicode code points.  

[R-M0015-01](#r-m0015-01) · Subtitle track export / Export limits · [строка 15](../../../../../benchmark/subtitles/requirements.md#L15)

> In the acceptance sample, a cue of 81 Unicode code points is accepted.  

**Сценарий.** Подать на экспорт реплику из приёмочного примера с текстом длиной 81 кодовая точка Unicode.

**Последствие.** Приёмочный пример требует исхода, несовместимого с соблюдением общего ограничения.

**Общее условие.** На экспорт подана реплика из приёмочного примера с текстом длиной 81 кодовая точка Unicode. Основания — [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.», [R-M0015-01](#r-m0015-01) «In the acceptance sample, a cue of 81 Unicode code points is accepted.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Реплика из примера должна быть принята или отклонена?

1. **Вариант 1.** Отклонять реплику, если её текст превышает 80 кодовых точек Unicode, включая реплику из примера.

   **Основание.** [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.».

   **Ожидаемый результат.** Реплика с 81 кодовой точкой отклонена.

   При выборе этого варианта привести в соответствие [R-M0015-01](#r-m0015-01).

2. **Вариант 2.** Принимать реплику из приёмочного примера с текстом длиной 81 кодовая точка Unicode.

   **Основание.** [R-M0015-01](#r-m0015-01) «In the acceptance sample, a cue of 81 Unicode code points is accepted.».

   **Ожидаемый результат.** Реплика с 81 кодовой точкой принята.

   При выборе этого варианта привести в соответствие [R-M0014-01](#r-m0014-01).

**Черновик приёмочного теста.** Подать реплику из примера и сверить факт её принятия либо отклонения с выбранным исходом.

Subtitle track export / Format · [строка 7](../../../../../benchmark/subtitles/requirements.md#L7)

> The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.  

**Связано с нарушением в спецификации.** T-1 запрещает начальный BOM, а T-2 требует его в том же файле. Файл успешного экспорта не может одновременно выполнить правило записи и пройти приёмку.

Связанные замечания — [Z-001](#z-001).

<a id="decision"></a>

## Готовность и порядок исправлений

ТЗ не готово к разработке и приёмке экспорта. Для формата файла, временных меток и проверки лимита нужно согласовать ожидаемые результаты.

1. Согласовать наличие BOM и шкалу временных меток в правилах формата и приёмке. ([Z-001](#z-001), [Z-002](#z-002))
2. Согласовать исход для реплики из 81 кодовой точки с правилом проверки длины. ([Z-004](#z-004))
3. Задать измеримый критерий лёгкости экспорта. ([Z-003](#z-003))
4. Исправить ссылку T-40. ([Z-005](#z-005))
