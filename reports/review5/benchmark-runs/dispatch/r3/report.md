## Проверка набора в целом

Правила отправки черновика и допуска ведомости из 25 строк задают несовместимые исходы. Для локального хранения расходятся два значения срока. Для индикации «Передано» отсутствует предел задержки. Ссылка S-97 не имеет адресата, а текст при отказе уже задан в S-7.

Открытых предполагаемых пробелов — 1. Неоднозначностей — 0. Рекомендаций — 0.

Каждый ID утверждения учитывается один раз. В число нарушений входят подтверждённые дефекты и неоднозначности, для которых показаны две опирающиеся на текст трактовки с разными последствиями. Один и тот же конфликт имеет один ID при любом числе затронутых требований. Критичный дефект блокирует приёмку существенного обязательного сценария. Предполагаемый пробел оставляет открытым ожидаемое поведение или источник данных. Рекомендация предлагает улучшение. Вопросы и рекомендации имеют отдельные счётчики.

## Критичные дефекты

- [Z-001](#z-001) · S-1 разрешает отправку только из состояния «Готова», а S-2 предписывает передачу при попытке отправить черновик. Исход обязательного испытания отправки определить невозможно.
- [Z-002](#z-002) · S-3 ограничивает ведомость 24 строками груза, а S-4 разрешает отправку загруженной ведомости из 25 строк. Правило изменения состава отсутствует. Приёмку отправки такой ведомости провести невозможно.

### Z-001 · Отправка черновика

**Дефект · Противоречивость · Критичная.** S-1 разрешает отправку только из состояния «Готова», а S-2 предписывает передачу при попытке отправить черновик. Исход обязательного испытания отправки определить невозможно.

Затронутые утверждения — [R-M0006-01](#r-m0006-01), [R-M0007-01](#r-m0007-01).

[R-M0007-01](#r-m0007-01) · Отправка грузовых ведомостей / Отправка · [строка 7](../../../../../benchmark/dispatch/requirements.md#L7)

> S-2. При попытке отправить ведомость в состоянии «Черновик» терминал сразу передаёт её перевозчику.  

**Сценарий.** При исправных сети и авторизации оператор пытается отправить сохранённую ведомость из одной строки в состоянии «Черновик».

**Последствие.** Перевозчик либо получает ведомость, либо передача не происходит.

**Общее условие.** Оператор пытается отправить сохранённую ведомость в состоянии «Черновик» при исправных сети и авторизации. Основания — [R-M0006-01](#r-m0006-01) «Оператор может отправить ведомость только в состоянии «Готова».», [R-M0007-01](#r-m0007-01) «При попытке отправить ведомость в состоянии «Черновик» терминал сразу передаёт её перевозчику.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой исход выбрать при попытке отправить черновик: передать ведомость перевозчику или не передавать?

1. **Вариант 1.** Оператор может отправить ведомость только в состоянии «Готова».

   **Основание.** [R-M0006-01](#r-m0006-01) «S-1. Оператор может отправить ведомость только в состоянии «Готова».».

   **Ожидаемый результат.** Терминал не передаёт черновик перевозчику.

   При выборе этого варианта привести в соответствие [R-M0007-01](#r-m0007-01).

2. **Вариант 2.** При попытке отправить ведомость в состоянии «Черновик» терминал сразу передаёт её перевозчику.

   **Основание.** [R-M0007-01](#r-m0007-01) «S-2. При попытке отправить ведомость в состоянии «Черновик» терминал сразу передаёт её перевозчику.».

   **Ожидаемый результат.** Терминал передаёт черновик перевозчику.

   При выборе этого варианта привести в соответствие [R-M0006-01](#r-m0006-01).

### Z-002 · Вместимость ведомости

**Дефект · Противоречивость · Критичная.** S-3 ограничивает ведомость 24 строками груза, а S-4 разрешает отправку загруженной ведомости из 25 строк. Правило изменения состава отсутствует. Приёмку отправки такой ведомости провести невозможно.

Затронутые утверждения — [R-M0010-01](#r-m0010-01), [R-M0010-02](#r-m0010-02), [R-M0011-01](#r-m0011-01), [R-M0011-02](#r-m0011-02).

[R-M0010-02](#r-m0010-02) · Отправка грузовых ведомостей / Параметры · [строка 10](../../../../../benchmark/dispatch/requirements.md#L10)

> S-3. Одна ведомость содержит от 1 до 24 строк груза включительно.  

[R-M0011-01](#r-m0011-01) · Отправка грузовых ведомостей / Параметры · [строка 11](../../../../../benchmark/dispatch/requirements.md#L11)

> S-4. При загрузке ведомости из 25 строк терминал принимает файл и разрешает отправку.  

[R-M0011-02](#r-m0011-02) · Отправка грузовых ведомостей / Параметры · [строка 11](../../../../../benchmark/dispatch/requirements.md#L11)

> S-4. При загрузке ведомости из 25 строк терминал принимает файл и разрешает отправку.  

**Сценарий.** Оператор загружает ведомость из 25 строк груза. Для сравнения разрешения отправки проверяется та же ведомость в состоянии «Готова».

**Последствие.** По S-3 ведомость такого состава недопустима к отправке. По S-4 терминал принимает файл и разрешает отправку именно этой ведомости.

**Общее условие.** Загружается одна ведомость из 25 строк груза. Сравнивается допуск к отправке той же ведомости со всеми строками при выполненном условии «Готова». Основания — [R-M0010-01](#r-m0010-01) «Одна ведомость содержит от 1 до 24 строк груза включительно.», [R-M0010-02](#r-m0010-02) «Одна ведомость содержит от 1 до 24 строк груза включительно.», [R-M0011-01](#r-m0011-01) «При загрузке ведомости из 25 строк терминал принимает файл и разрешает отправку.», [R-M0011-02](#r-m0011-02) «При загрузке ведомости из 25 строк терминал принимает файл и разрешает отправку.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой исход выбрать для ведомости из 25 строк в состоянии «Готова»: разрешить отправку или запретить её по пределу вместимости?

1. **Вариант 1.** Одна ведомость содержит от 1 до 24 строк груза включительно.

   **Основание.** [R-M0010-01](#r-m0010-01) «S-3. Одна ведомость содержит от 1 до 24 строк груза включительно.».

   **Ожидаемый результат.** Отправка ведомости из 25 строк недопустима.

   При выборе этого варианта привести в соответствие [R-M0011-01](#r-m0011-01).

2. **Вариант 2.** При загрузке ведомости из 25 строк терминал принимает файл и разрешает отправку.

   **Основание.** [R-M0011-01](#r-m0011-01) «S-4. При загрузке ведомости из 25 строк терминал принимает файл и разрешает отправку.».

   **Ожидаемый результат.** Терминал принимает файл и разрешает отправку ведомости из 25 строк.

   При выборе этого варианта привести в соответствие [R-M0010-01](#r-m0010-01).

**Черновик приёмочного теста.** Загрузить файл из 25 строк и проверить, разрешена ли отправка той же ведомости со всеми строками при выполненном условии готовности.

## Готовность и порядок исправлений

ТЗ не готово к разработке и приёмке отправки ведомостей до согласования правил для черновика и ведомости из 25 строк.

1. Согласовать исход попытки отправить ведомость в состоянии «Черновик». ([Z-001](#z-001))
2. Согласовать предел вместимости с правилом загрузки и допуска к отправке ведомости из 25 строк. ([Z-002](#z-002))
3. Согласовать единицу срока локального хранения и срок для значения 7. ([Z-003](#z-003))
4. Задать максимальную задержку появления слова «Передано» после подтверждения перевозчика. ([Z-005](#z-005))
5. Исправить ссылку S-97 редакторской правкой. ([Z-006](#z-006))
