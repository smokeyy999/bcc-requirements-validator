# Банковский отчёт и две контрольные проверки

Основной банковский прогон `1a9fc9b` выполнен на `gpt-6.2-sol`. В [полном отчёте для чтения](review14/review-linked.md) доступны проверка 138 утверждений, цитаты и вывод о готовности. Команда уточнила три карточки для согласования и добавила переходы к строкам ТЗ. [Оригинал, сформированный агентом](review14/review.md) · [Исходное ТЗ](../docs/requirements.md) · [Паспорт банковского прогона](review14/review/run-meta.json)

## Какие решения нужны до приёмки

**1. Владельцу продукта — согласовать месячный лимит push.** По Ф-3 на карту приходится максимум одно уведомление за календарный месяц. По Ф-4 после повышения порога следующее достижение может снова вызвать уведомление, даже если предыдущая настройка уже сработала. Для проверки берут ту же карту и тот же месяц. Первый push уже получен, новый порог установлен выше накопленных расходов, следующая покупка доводит их до этого порога. Одно решение даёт один полученный push за месяц, другое — два. Пока владелец не выбрал правило, команда не может однозначно принять или отклонить поведение приложения. [Ф-3 и Ф-4](../docs/requirements.md?plain=1#L39-L40) · [Две трактовки, основания и исходы](review14/review-linked.md#z-009)

**2. Владельцу API — определить операцию записи.** В контракте и примере вызова указан `GET`. В алгоритме тот же вызов должен заменить действующую настройку карты. Владелец выбирает метод для сохранения, приводит в соответствие описание и пример. QA вызывает согласованную операцию с новым значением, сверяет ответ с записанной настройкой и повторяет тот же запрос, чтобы проверить эффект повторного вызова. [Метод и пример](../docs/requirements.md?plain=1#L103-L109) · [Алгоритм и правило замены](../docs/requirements.md?plain=1#L120-L125) · [Основание и черновик теста](review14/review-linked.md#z-012)

**3. Аналитику — дополнить предусловия готового примера.** В строке приёмки при расходах 48 500 ₸ покупка на 1 500 ₸ доводит итог до порога 50 000 ₸. Ожидается один push. Эту же строку можно выполнить при выключенных уведомлениях или уже исчерпанном месячном лимите. Чтобы тест однозначно проверял первое достижение порога, в исходные условия достаточно записать, что уведомления включены и в этом месяце по карте ещё не было push. Агент восстановил оба условия из ТЗ. Вопрос владельцу здесь не потребовался. [Настройки и лимит](../docs/requirements.md?plain=1#L37-L39) · [Строка приёмки](../docs/requirements.md?plain=1#L63) · [Предложенная правка](review14/review-linked.md#z-018)

Параллельно QA может готовить проверки с уже заданным результатом. Например, переводы исключаются из расходов, полный возврат уменьшает итог исходного месяца, а для передачи уведомления сервисом установлен минутный срок. Отдельного решения требуют частичный возврат и возможный срок доставки до устройства клиента. [Частичный возврат](review14/review-linked.md#z-008) · [Передача и получение push](review14/review-linked.md#z-001) · [Порядок исправлений](review14/review-linked.md#decision)

## Что произошло, когда модель предложила число без основания

В серии этой версии было 24 задания — один банковский документ, два контрольных варианта стенда и семь документов в трёх проходах. В 23 случаях отчёт получен с первого полного запуска CLI. Один документ про полив потребовал второго запуска. Оба относятся к одной версии кода и одному входному файлу. [Таблица всех 25 попыток](../checks/review14/attempts.md)

| Этап | Что увидел пользователь | Что можно проверить |
|---|---|---|
| Первая попытка на документе про полив | После точечного исправления валидатор нашёл в предлагаемой правке число, для которого отсутствовала подтверждающая цитата. CLI завершился с кодом 1 через 174,2 с. | [Причина отказа и код завершения](../checks/review14/cli/codex-irrigation-base-r1-attempt-1.txt) |
| Повтор той же команды | Агент заново обработал документ. Через 252,7 с CLI завершился с кодом 0 и сохранил отчёт по 11 утверждениям. | [Журнал повторного запуска](../checks/review14/cli/codex-irrigation-base-r1-attempt-2.txt) · [Полученный отчёт](review14/benchmark-runs/irrigation-base/r1/report.md) |
| Сбой при записи на диск | Код публикует отчёт и его паспорт после завершения рецензии. Автотест имитирует отказ записи нового отчёта и проверяет сохранность прежней пары файлов. | [Публикация файлов](../requirements_validator/__main__.py) · [Тест сохранения предыдущего результата](../tests/test_metrics.py) |

Внутри работающего процесса агент может запросить точечное исправление. После завершения с кодом 1 нужен новый полный запуск. В банковском случае одно выполнение CLI включало 10 обращений к модели, в том числе три повтора, и успешно завершилось за 22 мин 52 с. ## Что изменилось между контрольными прогонами

Оба входа описывают один учебный стенд. Каждый содержит 18 проверяемых утверждений. В первом заложены три дефекта. Во втором изменены условия приёмки, и для каждого опыта заранее известен ожидаемый результат.

| Опыт | Почему в первом отчёте появился вопрос | Что задано в согласованном документе |
|---|---|---|
| Текстовая метка «АБА» | Три буквы занимают 6 байт. Правило длины требует отклонить метку, отдельный пример требует принять её. | Для «АБА» явно задано «Отклонено». [Карточка](../checks/finish/independent-runs/review14/case-p/report.md#z-001) |
| Повреждённый узор | У стенда две рамки. Для события повреждения не указано, какую вывести. | При повреждении требуются «точки». [Карточка](../checks/finish/independent-runs/review14/case-p/report.md#z-002) |
| Время полного цикла | Начало и конец измерения известны, допустимый предел в миллисекундах отсутствует. | Весь цикл должен занять до 500 мс включительно. 500 мс проходит приёмку, 501 мс превышает предел. [Карточка](../checks/finish/independent-runs/review14/case-p/report.md#z-003) |

На первом входе агент выдал **3 дефекта и 3 вопроса**, на согласованном — **0 замечаний и 0 вопросов**. Это результат именно этой пары. Для более широкой оценки опубликованы три прохода по семи другим документам. В каждом найдены 15 из 15 заложенных дефектов при 26 выданных карточках. [Первый вход](../checks/finish/independent/case-p/variant.md) · [Первый отчёт](../checks/finish/independent-runs/review14/case-p/report.md) · [Согласованный вход](../checks/finish/independent/case-p/control.md) · [Второй отчёт](../checks/finish/independent-runs/review14/case-p-base/report.md) · [Метрики семи документов](review14/evaluation.md)

**Как оценить нагрузку на аналитика.** В трёх проходах по корпусу осталось по 11 карточек сверх эталона. Отдельная модельная вычитка разделила их по действию для команды. Среди них есть самостоятельные приёмочные вопросы, повторяющиеся спорные трактовки, уточнения к формату и вопросы подготовки испытания. У каждой классификации есть ссылка на исходный пункт и карточку конкретного прогона. [Таблица всех 33 случаев](review14/additional-findings.md)
