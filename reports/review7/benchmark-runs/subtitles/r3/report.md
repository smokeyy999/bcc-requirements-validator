## Проверка набора в целом

Правила записи и приёмки расходятся по BOM, единице временной метки и исходу проверки реплики из 81 кодовой точки. Для лёгкости экспорта отсутствует критерий оценки. Ссылка T-40 требует редакторской правки, а точный текст сообщения для пустой дорожки задан в T-6.

Открытых предполагаемых пробелов — 0. Неоднозначностей — 0. Рекомендаций — 0.

Каждый ID утверждения учитывается один раз. В число нарушений входят подтверждённые дефекты и неоднозначности, для которых показаны две опирающиеся на текст трактовки с разными последствиями. Один и тот же конфликт имеет один ID при любом числе затронутых требований. Критичный дефект блокирует приёмку существенного обязательного сценария. Предполагаемый пробел оставляет открытым ожидаемое поведение или источник данных. Рекомендация предлагает улучшение. Вопросы и рекомендации имеют отдельные счётчики.

### Z-001 · BOM в экспортируемом файле

**Дефект · Противоречивость · Критичная.** T-1 запрещает BOM в записанном файле, а T-2 требует BOM в первых трёх байтах того же файла. Один файл не может одновременно выполнить правило записи и пройти этот тест.

Затронутые утверждения — [R-M0006-01](#r-m0006-01), [R-M0007-01](#r-m0007-01).

[R-M0006-01](#r-m0006-01) · Subtitle track export / Format · [строка 6](../../../../../benchmark/subtitles/requirements.md#L6)

> Write the exported track in UTF-8 without a byte-order mark.  

[R-M0007-01](#r-m0007-01) · Subtitle track export / Format · [строка 7](../../../../../benchmark/subtitles/requirements.md#L7)

> The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.  

**Сценарий.** Экспортировать непустую дорожку, для которой создаётся файл UTF-8.

**Последствие.** Реализация и приёмочный тест требуют несовместимых начальных байтов одного файла.

**Общее условие.** Проверяются первые три байта записанного файла экспорта UTF-8. Основания — [R-M0006-01](#r-m0006-01) «Write the exported track in UTF-8 without a byte-order mark.», [R-M0007-01](#r-m0007-01) «The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой файл должен пройти приёмку, с UTF-8 BOM или без него?

1. **Вариант 1.** Экспортируемый файл записывается в UTF-8 без BOM.

   **Основание.** [R-M0006-01](#r-m0006-01) «Write the exported track in UTF-8 without a byte-order mark.».

   **Ожидаемый результат.** В начале файла нет последовательности EF BB BF.

   При выборе этого варианта привести в соответствие [R-M0007-01](#r-m0007-01).

2. **Вариант 2.** Экспортируемый файл должен начинаться с UTF-8 BOM.

   **Основание.** [R-M0007-01](#r-m0007-01) «The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

   **Ожидаемый результат.** Первые три байта файла равны EF BB BF.

   При выборе этого варианта привести в соответствие [R-M0006-01](#r-m0006-01).

**Черновик приёмочного теста.** После экспорта проверить первые три байта файла по выбранному правилу.

### Z-002 · Единица временной метки

**Дефект · Противоречивость · Критичная.** T-3 объявляет миллисекунды единицей поля, но приписывает значению 1000 одну минуту. По объявленной единице это одна секунда, поэтому корректность времени в экспортированном файле нельзя принять однозначно.

Затронутые утверждения — [R-M0008-01](#r-m0008-01), [R-M0008-02](#r-m0008-02).

[R-M0008-01](#r-m0008-01) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> Each timestamp field declares milliseconds  

[R-M0008-02](#r-m0008-02) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> Each timestamp field declares milliseconds; the numeric value 1000 represents one minute.  

**Сценарий.** Прочитать экспортированную временную метку со значением 1000.

**Последствие.** Для одного значения приёмка ожидает одну секунду или одну минуту.

**Общее условие.** В поле временной метки с объявленной единицей «миллисекунды» записано значение 1000. Основания — [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds», [R-M0008-02](#r-m0008-02) «Each timestamp field declares milliseconds; the numeric value 1000 represents one minute.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какое время должно означать значение 1000 при приёмке, одну секунду или одну минуту?

1. **Вариант 1.** Числовое значение временной метки выражается в миллисекундах.

   **Основание.** [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds».

   **Ожидаемый результат.** Значение 1000 означает одну секунду.

   При выборе этого варианта привести в соответствие [R-M0008-02](#r-m0008-02).

2. **Вариант 2.** Числовое значение 1000 во временной метке означает одну минуту.

   **Основание.** [R-M0008-02](#r-m0008-02) «Each timestamp field declares milliseconds; the numeric value 1000 represents one minute.».

   **Ожидаемый результат.** Значение 1000 означает одну минуту.

   При выборе этого варианта привести в соответствие [R-M0008-01](#r-m0008-01).

**Черновик приёмочного теста.** Прочитать одно и то же поле со значением 1000 и сверить полученное время с выбранным соответствием.

<a id="z-003"></a>

### Z-003 · Критерий лёгкости экспорта

**Дефект · Проверяемость · Существенная.** T-4 требует, чтобы экспорт воспринимался как лёгкий каждым пользователем, и оставляет критерий успешной оценки неопределённым. По факту записи файла можно проверить экспорт, но нельзя оценить выполнение T-4.

Затронутые утверждения — [R-M0009-01](#r-m0009-01).

[R-M0009-01](#r-m0009-01) · Subtitle track export / Format · [строка 9](../../../../../benchmark/subtitles/requirements.md#L9)

> The export experience must feel effortless to every user.  

**Сценарий.** Пользователь успешно экспортирует дорожку. Проверяющий оценивает выполнение T-4.

**Последствие.** Успешная запись файла сама по себе не даёт результата проверки T-4.

**Уже установлено.** Оценивается опыт экспорта каждого пользователя. Основания — [R-M0009-01](#r-m0009-01).

**Открытое решение.** По какому наблюдаемому критерию опыт каждого пользователя засчитывается как лёгкий?

**Что различит проверка.** Экспорт, завершённый пользователем после обращения за помощью, проходит оценку T-4, если критерий допускает помощь. / Тот же экспорт проваливает оценку T-4, если критерий требует самостоятельного выполнения.

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой наблюдаемый критерий и какое правило оценки подтверждают выполнение T-4 для заявленной группы пользователей?

Внести ответ на этот вопрос в [R-M0009-01](#r-m0009-01) для сценария «Пользователь успешно экспортирует дорожку. Проверяющий оценивает выполнение T-4.».

**Черновик приёмочного теста.** Провести экспорт в согласованных условиях и оценить результат по заданному критерию.

### Z-004 · Реплика из 81 кодовой точки

**Дефект · Противоречивость · Существенная.** Текст реплики из T-8 превышает предел T-7 на одну кодовую точку Unicode. T-7 требует отклонения, а T-8 требует принятия в обязательном приёмочном примере. Конфликт блокирует проверку этого примера.

Затронутые утверждения — [R-M0014-01](#r-m0014-01), [R-M0015-01](#r-m0015-01).

[R-M0014-01](#r-m0014-01) · Subtitle track export / Export limits · [строка 14](../../../../../benchmark/subtitles/requirements.md#L14)

> Reject a cue when its text exceeds 80 Unicode code points.  

[R-M0015-01](#r-m0015-01) · Subtitle track export / Export limits · [строка 15](../../../../../benchmark/subtitles/requirements.md#L15)

> In the acceptance sample, a cue of 81 Unicode code points is accepted.  

**Сценарий.** Проверить реплику из T-8, текст которой содержит 81 кодовую точку Unicode.

**Последствие.** Одна и та же реплика должна быть отклонена по T-7 и принята по T-8.

**Общее условие.** Проверяется реплика из приёмочного примера T-8 с текстом длиной 81 кодовую точку Unicode. Основания — [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.», [R-M0015-01](#r-m0015-01) «In the acceptance sample, a cue of 81 Unicode code points is accepted.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой исход требуется для реплики из T-8, принятие или отклонение?

1. **Вариант 1.** Отклонять реплику, если её текст превышает 80 кодовых точек Unicode.

   **Основание.** [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.».

   **Ожидаемый результат.** Реплика из 81 кодовой точки отклонена.

   При выборе этого варианта привести в соответствие [R-M0015-01](#r-m0015-01).

2. **Вариант 2.** В приёмочном примере принять реплику из 81 кодовой точки Unicode.

   **Основание.** [R-M0015-01](#r-m0015-01) «In the acceptance sample, a cue of 81 Unicode code points is accepted.».

   **Ожидаемый результат.** Реплика из 81 кодовой точки принята.

   При выборе этого варианта привести в соответствие [R-M0014-01](#r-m0014-01).

**Черновик приёмочного теста.** Подать на экспорт реплику из приёмочного примера и сверить исход проверки с выбранным правилом.

## Готовность и порядок исправлений

ТЗ не готово к разработке и приёмке. Нужно согласовать формат файла, интерпретацию временных меток и исход приёмочного примера, затем определить критерий оценки лёгкости экспорта и исправить ссылку.

1. Согласовать наличие BOM и соответствие числового значения времени объявленной единице. ([Z-001](#z-001), [Z-002](#z-002))
2. Согласовать ожидаемый исход проверки реплики с текстом из 81 кодовой точки Unicode. ([Z-004](#z-004))
3. Задать наблюдаемый критерий и правило оценки лёгкости экспорта для каждого пользователя. ([Z-003](#z-003))
