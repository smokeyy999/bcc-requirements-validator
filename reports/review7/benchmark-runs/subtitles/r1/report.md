## Проверка набора в целом

Требования к формату файла, временным меткам и длине субтитра расходятся с заданными исходами. Лёгкость экспорта не имеет критерия приёмки. Ссылка T-40 требует редакторского исправления. Текст сообщения для пустой дорожки уже установлен в T-6.

Открытых предполагаемых пробелов — 0. Неоднозначностей — 0. Рекомендаций — 0.

Каждый ID утверждения учитывается один раз. В число нарушений входят подтверждённые дефекты и неоднозначности, для которых показаны две опирающиеся на текст трактовки с разными последствиями. Один и тот же конфликт имеет один ID при любом числе затронутых требований. Критичный дефект блокирует приёмку существенного обязательного сценария. Предполагаемый пробел оставляет открытым ожидаемое поведение или источник данных. Рекомендация предлагает улучшение. Вопросы и рекомендации имеют отдельные счётчики.

## Критичные дефекты

- [Z-001](#z-001) · T-1 запрещает BOM в начале файла экспорта, а T-2 требует его в том же файле при приёмке. Ни один вариант записи не удовлетворяет обоим пунктам.

### Z-001 · BOM в файле экспорта

**Дефект · Противоречивость · Критичная.** T-1 запрещает BOM в начале файла экспорта, а T-2 требует его в том же файле при приёмке. Ни один вариант записи не удовлетворяет обоим пунктам.

Затронутые утверждения — [R-M0006-02](#r-m0006-02), [R-M0007-01](#r-m0007-01).

[R-M0006-02](#r-m0006-02) · Subtitle track export / Format · [строка 6](../../../../../benchmark/subtitles/requirements.md#L6)

> Write the exported track in UTF-8 without a byte-order mark.  

[R-M0007-01](#r-m0007-01) · Subtitle track export / Format · [строка 7](../../../../../benchmark/subtitles/requirements.md#L7)

> The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.  

**Сценарий.** Экспортировать непустую допустимую дорожку и прочитать первые три байта файла.

**Последствие.** Экспорт без BOM провалит приёмку, а экспорт с BOM нарушит требование к формату.

**Общее условие.** Первые три байта файла, записанного при успешном приёмочном экспорте дорожки. Основания — [R-M0006-02](#r-m0006-02) «Write the exported track in UTF-8 without a byte-order mark.», [R-M0007-01](#r-m0007-01) «The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Должен ли файл в приёмочном экспорте начинаться с UTF-8 BOM?

1. **Вариант 1.** Записывать файл экспорта в UTF-8 без BOM.

   **Основание.** [R-M0006-02](#r-m0006-02) «Write the exported track in UTF-8 without a byte-order mark.».

   **Ожидаемый результат.** Первые три байта файла не образуют UTF-8 BOM.

   При выборе этого варианта привести в соответствие [R-M0007-01](#r-m0007-01).

2. **Вариант 2.** Первые три байта файла в приёмочном экспорте должны образовывать UTF-8 BOM.

   **Основание.** [R-M0007-01](#r-m0007-01) «The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

   **Ожидаемый результат.** Первые три байта файла образуют UTF-8 BOM.

   При выборе этого варианта привести в соответствие [R-M0006-02](#r-m0006-02).

**Черновик приёмочного теста.** Экспортировать ту же дорожку и проверить наличие либо отсутствие BOM в начале файла согласно выбранному правилу.

### Z-002 · Шкала временных меток

**Дефект · Противоречивость · Критичная.** Объявленная единица и пример относятся к одному полю. При значении 1000 они задают разные моменты, поэтому корректность экспортированной метки нельзя принять.

Затронутые утверждения — [R-M0008-01](#r-m0008-01), [R-M0008-02](#r-m0008-02).

[R-M0008-01](#r-m0008-01) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> Each timestamp field declares milliseconds  

[R-M0008-02](#r-m0008-02) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> Each timestamp field declares milliseconds; the numeric value 1000 represents one minute.  

**Сценарий.** В экспортированном поле временной метки указано значение 1000.

**Последствие.** Одна и та же метка обозначает одну секунду по заявленной единице или одну минуту по явной трактовке.

**Общее условие.** Поле экспортированной временной метки со значением 1000 и объявленной единицей «миллисекунды». Основания — [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds», [R-M0008-02](#r-m0008-02) «the numeric value 1000 represents one minute.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой момент должна обозначать экспортированная метка 1000: одну секунду или одну минуту?

1. **Вариант 1.** Интерпретировать числовое значение каждого поля временной метки в миллисекундах.

   **Основание.** [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds».

   **Ожидаемый результат.** Значение 1000 обозначает одну секунду.

   При выборе этого варианта привести в соответствие [R-M0008-02](#r-m0008-02).

2. **Вариант 2.** Сохранить соответствие значения 1000 одной минуте и согласовать с ним обозначение шкалы поля.

   **Основание.** [R-M0008-02](#r-m0008-02) «Each timestamp field declares milliseconds; the numeric value 1000 represents one minute.».

   **Ожидаемый результат.** Значение 1000 обозначает одну минуту.

   При выборе этого варианта привести в соответствие [R-M0008-01](#r-m0008-01).

**Черновик приёмочного теста.** Сопоставить метку 1000 с известным временем субтитра и проверить согласованность результата с единицей, указанной в поле.

### Z-003 · Критерий лёгкости экспорта

**Дефект · Проверяемость · Существенная.** T-4 обещает лёгкость экспорта для каждого пользователя, но не задаёт наблюдаемого критерия, по которому можно воспроизводимо оценить это свойство.

Затронутые утверждения — [R-M0009-01](#r-m0009-01).

[R-M0009-01](#r-m0009-01) · Subtitle track export / Format · [строка 9](../../../../../benchmark/subtitles/requirements.md#L9)

> The export experience must feel effortless to every user.  

**Сценарий.** Несколько пользователей выполняют один и тот же экспорт и по-разному оценивают его лёгкость.

**Последствие.** Приёмщик не может вынести воспроизводимое решение о выполнении T-4.

**Уже установлено.** Ощущение лёгкости заявлено для каждого пользователя при экспорте. Основания — [R-M0009-01](#r-m0009-01).

**Открытое решение.** Какой наблюдаемый результат у каждого участника считать признаком лёгкости экспорта?

**Что различит проверка.** Все участники завершили экспорт без помощи, поэтому по критерию самостоятельного выполнения проверка пройдена. / В том же испытании один участник счёл экспорт трудным, поэтому по критерию положительной оценки каждого участника проверка не пройдена.

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** По какому наблюдаемому критерию и на какой группе пользователей принимать заявленную лёгкость экспорта?

Внести ответ на этот вопрос в [R-M0009-01](#r-m0009-01) для сценария «Несколько пользователей выполняют один и тот же экспорт и по-разному оценивают его лёгкость.».

**Черновик приёмочного теста.** После согласования критерия провести сценарий экспорта на указанной группе и сопоставить наблюдения с условием успеха.

### Z-004 · Субтитр из 81 кодовой точки

**Дефект · Противоречивость · Существенная.** T-7 требует отклонить текст из 81 кодовой точки. T-8 задаёт приём того же субтитра в примере без правила об исключении или приоритете. Расхождение затрагивает приёмку проверки длины.

Затронутые утверждения — [R-M0014-01](#r-m0014-01), [R-M0015-01](#r-m0015-01).

[R-M0014-01](#r-m0014-01) · Subtitle track export / Export limits · [строка 14](../../../../../benchmark/subtitles/requirements.md#L14)

> Reject a cue when its text exceeds 80 Unicode code points.  

[R-M0015-01](#r-m0015-01) · Subtitle track export / Export limits · [строка 15](../../../../../benchmark/subtitles/requirements.md#L15)

> In the acceptance sample, a cue of 81 Unicode code points is accepted.  

**Сценарий.** Выполнить приёмочный пример с субтитром, текст которого содержит 81 кодовую точку Unicode. Оба пункта относятся к одному субтитру при проверке экспорта, исключение для примера отсутствует.

**Последствие.** T-7 требует отклонить субтитр, так как 81 больше 80. T-8 требует принять тот же субтитр.

**Общее условие.** Приёмочный пример экспорта с субтитром, текст которого содержит 81 кодовую точку Unicode. Основания — [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.», [R-M0015-01](#r-m0015-01) «In the acceptance sample, a cue of 81 Unicode code points is accepted.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** В указанном приёмочном примере субтитр из 81 кодовой точки нужно отклонить или принять как исключение?

1. **Вариант 1.** Отклонять субтитр, если его текст длиннее 80 кодовых точек Unicode, в том числе в приёмочном примере.

   **Основание.** [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.».

   **Ожидаемый результат.** Субтитр из 81 кодовой точки Unicode отклонён.

   При выборе этого варианта привести в соответствие [R-M0015-01](#r-m0015-01).

2. **Вариант 2.** Принимать субтитр из 81 кодовой точки Unicode в указанном приёмочном примере как явно установленное исключение из общего предела.

   **Основание.** [R-M0015-01](#r-m0015-01) «In the acceptance sample, a cue of 81 Unicode code points is accepted.».

   **Ожидаемый результат.** Субтитр из 81 кодовой точки Unicode принят.

   При выборе этого варианта привести в соответствие [R-M0014-01](#r-m0014-01).

**Черновик приёмочного теста.** Запустить экспорт на входе приёмочного примера с 81 кодовой точкой в тексте и проверить выбранный исход для этого субтитра.

<a id="decision"></a>

## Готовность и порядок исправлений

ТЗ не готово к разработке с однозначной приёмкой. Сначала нужно согласовать формат файла, шкалу времени и исход примера с 81 кодовой точкой.

1. Согласовать наличие BOM с проверкой первых трёх байтов, а объявленную единицу времени — со значением метки 1000. ([Z-001](#z-001), [Z-002](#z-002))
2. Согласовать предел длины текста с исходом приёмочного примера для 81 кодовой точки Unicode. ([Z-004](#z-004))
3. Задать критерий лёгкости экспорта и способ его проверки. ([Z-003](#z-003))
4. Исправить ссылку T-40 и проверить переход к правилу. ([Z-005](#z-005))
