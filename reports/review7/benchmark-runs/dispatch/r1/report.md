## Проверка набора в целом

ТЗ задаёт взаимоисключающие исходы отправки черновика и отправки ведомости из 25 строк. Для приёмки реакции на подтверждение нужен предел задержки, а для локального хранения — единый срок для значения 7. Ссылка S-97 требует редакторского исправления. Текст сообщения и состояние ведомости при отказе уже заданы в S-7.

Открытых предполагаемых пробелов — 0. Неоднозначностей — 0. Рекомендаций — 0.

Каждый ID утверждения учитывается один раз. В число нарушений входят подтверждённые дефекты и неоднозначности, для которых показаны две опирающиеся на текст трактовки с разными последствиями. Один и тот же конфликт имеет один ID при любом числе затронутых требований. Критичный дефект блокирует приёмку существенного обязательного сценария. Предполагаемый пробел оставляет открытым ожидаемое поведение или источник данных. Рекомендация предлагает улучшение. Вопросы и рекомендации имеют отдельные счётчики.

## Критичные дефекты

- [Z-001](#z-001) · S-1 разрешает отправку только из состояния «Готова», а S-2 требует передать ведомость при попытке отправить её из состояния «Черновик». По одной попытке нельзя определить, должен ли перевозчик получить ведомость.
- [Z-003](#z-003) · S-3 ограничивает одну ведомость 24 строками груза. S-4 разрешает отправку той же ведомости из 25 строк после загрузки. Для этого входа нельзя определить ожидаемую доступность отправки.

> При загрузке ведомости из 25 строк терминал принимает файл и разрешает отправку.  

**Сценарий.** Оператор загружает одну ведомость из 25 строк груза и проверяет доступность её отправки при выполненных прочих условиях.

**Последствие.** S-3 исключает такую ведомость из допустимых к отправке, а S-4 прямо разрешает её отправку. Приём файла сам по себе мог бы быть отдельным этапом, но S-4 задаёт и результат проверки доступности отправки.

**Общее условие.** Загружена одна ведомость из 25 строк груза. Проверяется разрешение её отправки при выполненных прочих условиях. Основания — [R-M0010-01](#r-m0010-01) «Одна ведомость содержит от 1 до 24 строк груза включительно.», [R-M0010-02](#r-m0010-02) «от 1 до 24 строк груза включительно», [R-M0011-01](#r-m0011-01) «При загрузке ведомости из 25 строк терминал принимает файл и разрешает отправку.», [R-M0011-02](#r-m0011-02) «терминал принимает файл и разрешает отправку».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Должна ли быть доступна отправка одной загруженной ведомости из 25 строк?

1. **Вариант 1.** Применять предел от 1 до 24 строк груза включительно к одной отправляемой ведомости.

   **Основание.** [R-M0010-01](#r-m0010-01) «Одна ведомость содержит от 1 до 24 строк груза включительно.».

   **Ожидаемый результат.** Отправка загруженной ведомости из 25 строк недоступна.

   При выборе этого варианта привести в соответствие [R-M0011-01](#r-m0011-01).

2. **Вариант 2.** При загрузке ведомости из 25 строк принимать файл и разрешать отправку.

   **Основание.** [R-M0011-01](#r-m0011-01) «При загрузке ведомости из 25 строк терминал принимает файл и разрешает отправку.».

   **Ожидаемый результат.** Терминал принимает файл и разрешает отправку.

   При выборе этого варианта привести в соответствие [R-M0010-01](#r-m0010-01).

## Готовность и порядок исправлений

ТЗ не готово к разработке отправки. Сначала согласовать исходы двух сценариев отправки, затем уточнить срок хранения и предел задержки. Ссылку S-97 исправить при редактуре перед утверждением ТЗ.

1. Установить ожидаемую передачу при попытке отправить черновик и доступность отправки одной ведомости из 25 строк. ([Z-001](#z-001), [Z-003](#z-003))
2. Согласовать единицу настройки со сроком локального хранения для значения 7. ([Z-005](#z-005))
3. Задать предельную задержку от подтверждения перевозчика до показа «Передано». ([Z-004](#z-004))
