## Проверка набора в целом

Правила отправки расходятся для черновика и ведомости из 25 строк. Для хранения подтверждения при значении 7 заданы разные сроки. Для показа «Передано» нужен измеримый предел задержки. Ссылка S-97 требует редакторского исправления. Поведение при отказе уже задано в S-7.

Открытых предполагаемых пробелов — 0. Неоднозначностей — 0. Рекомендаций — 0.

Каждый ID утверждения учитывается один раз. В число нарушений входят подтверждённые дефекты и неоднозначности, для которых показаны две опирающиеся на текст трактовки с разными последствиями. Один и тот же конфликт имеет один ID при любом числе затронутых требований. Критичный дефект блокирует приёмку существенного обязательного сценария. Предполагаемый пробел оставляет открытым ожидаемое поведение или источник данных. Рекомендация предлагает улучшение. Вопросы и рекомендации имеют отдельные счётчики.

## Критичные дефекты

- [Z-001](#z-001) · S-1 разрешает отправку только из состояния «Готова», а S-2 требует сразу передать перевозчику «Черновик» при попытке отправки. Для одной команды заданы взаимоисключающие исходы, поэтому сценарий отправки черновика нельзя принять.
- [Z-002](#z-002) · S-3 ограничивает одну ведомость 24 строками, а S-4 после загрузки разрешает отправить ведомость из 25 строк. Оба правила относятся к составу той же ведомости. Приёмку разрешения на отправку в исходном составе провести нельзя.

> При попытке отправить ведомость в состоянии «Черновик» терминал сразу передаёт её перевозчику.

**Последствие.** По одному правилу перевозчик не получает ведомость, по другому терминал сразу передаёт её.

**Общее условие.** Оператор пытается отправить сохранённую ведомость в состоянии «Черновик» при исправных сети и авторизации. Основания — [R-M0006-01](#r-m0006-01) «Оператор может отправить ведомость только в состоянии «Готова».», [R-M0007-01](#r-m0007-01) «При попытке отправить ведомость в состоянии «Черновик» терминал сразу передаёт её перевозчику.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

   **Ожидаемый результат.** Терминал не передаёт черновик перевозчику.

   При выборе этого варианта привести в соответствие [R-M0007-01](#r-m0007-01).

2. **Вариант 2.** При попытке отправить черновик терминал сразу передаёт его перевозчику.

   **Основание.** [R-M0007-01](#r-m0007-01) «При попытке отправить ведомость в состоянии «Черновик» терминал сразу передаёт её перевозчику.».

> При загрузке ведомости из 25 строк терминал принимает файл и разрешает отправку.  

**Сценарий.** Оператор загружает файл одной ведомости из 25 строк груза и проверяет разрешение на её отправку при выполненном условии о состоянии «Готова».

**Последствие.** Предел в 24 строки исключает отправку этой ведомости в исходном составе. Правило загрузки разрешает её отправку. Применимый фильтр, разделение или исключение не заданы.

**Общее условие.** Загружается файл одной ведомости из 25 строк груза. Проверяется разрешение на отправку этой ведомости в исходном составе. Основания — [R-M0010-01](#r-m0010-01) «Одна ведомость содержит от 1 до 24 строк груза включительно.», [R-M0010-02](#r-m0010-02) «Одна ведомость содержит от 1 до 24 строк груза включительно.», [R-M0011-01](#r-m0011-01) «При загрузке ведомости из 25 строк терминал принимает файл и разрешает отправку.», [R-M0011-02](#r-m0011-02) «При загрузке ведомости из 25 строк терминал принимает файл и разрешает отправку.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Для ведомости из 25 строк в состоянии «Готова» сохранить предел в 24 строки или разрешить отправку всех 25?

1. **Вариант 1.** Одна ведомость содержит от 1 до 24 строк груза включительно.

   **Основание.** [R-M0010-01](#r-m0010-01) «Одна ведомость содержит от 1 до 24 строк груза включительно.».

   **Ожидаемый результат.** Отправка ведомости со всеми 25 строками не разрешена.

   При выборе этого варианта привести в соответствие [R-M0011-01](#r-m0011-01).

2. **Вариант 2.** При загрузке ведомости из 25 строк терминал принимает файл и разрешает отправку.

   **Основание.** [R-M0011-01](#r-m0011-01) «При загрузке ведомости из 25 строк терминал принимает файл и разрешает отправку.».

   **Ожидаемый результат.** Терминал принимает файл и разрешает отправку ведомости из 25 строк.

   При выборе этого варианта привести в соответствие [R-M0010-01](#r-m0010-01).

**Черновик приёмочного теста.** Загрузить файл с 25 строками и проверить приём файла и разрешение отправки ведомости в исходном составе.

### Z-003 · Единица срока хранения подтверждения

**Дефект · Противоречивость · Существенная.** S-8 задаёт для одного срока общую шкалу в сутках и значение 7 в часах. Отдельного правила об исключении для 7 нет. Расхождение затрагивает проверку локального хранения.

Затронутые утверждения — [R-M0015-01](#r-m0015-01), [R-M0015-02](#r-m0015-02).

[R-M0015-01](#r-m0015-01) · Отправка грузовых ведомостей / Параметры · [строка 15](../../../../../benchmark/dispatch/requirements.md#L15)

> значение 7 означает семь часов  

[R-M0015-02](#r-m0015-02) · Отправка грузовых ведомостей / Параметры · [строка 15](../../../../../benchmark/dispatch/requirements.md#L15)

> Срок локального хранения подтверждения задаётся в сутках  

**Сценарий.** Терминал хранит подтверждение перевозчика при значении настройки 7.

**Последствие.** По объявленной единице срок составляет 604800000 мс, по трактовке значения 7 — 25200000 мс. Исключение из общей шкалы явно не установлено.

**Общее условие.** Терминал локально хранит подтверждение при значении срока 7. Основания — [R-M0015-02](#r-m0015-02) «Срок локального хранения подтверждения задаётся в сутках», [R-M0015-01](#r-m0015-01) «значение 7 означает семь часов».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой срок должен действовать при значении 7 — семь суток или семь часов?

1. **Вариант 1.** Срок локального хранения подтверждения задаётся в сутках.

   **Основание.** [R-M0015-02](#r-m0015-02) «Срок локального хранения подтверждения задаётся в сутках».

   **Ожидаемый результат.** При значении 7 срок составляет семь суток.

2. **Вариант 2.** Для значения 7 срок хранения составляет семь часов.

   **Основание.** [R-M0015-01](#r-m0015-01) «значение 7 означает семь часов».

   **Ожидаемый результат.** Срок хранения заканчивается через семь часов.

   При выборе этого варианта привести в соответствие [R-M0015-02](#r-m0015-02).

ТЗ не готово к разработке отправки и согласованию её приёмки, пока не определены исходы для черновика и ведомости из 25 строк.

2. Согласовать срок хранения при значении 7 и максимальную задержку показа «Передано». ([Z-003](#z-003), [Z-005](#z-005))
3. Исправить ссылку S-97 с учётом уже заданного поведения при отказе. ([Z-006](#z-006))
