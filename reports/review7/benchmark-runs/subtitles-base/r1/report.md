### Z-002 · Как в экспортируемом файле должно быть представлено объявление миллисекунд для каждого поля временной метки?

**Предполагаемый пробел · Полнота · Существенная.** T-3 задаёт значение 1000 для одной секунды и требует объявления миллисекунд для каждого поля. Форма этого объявления в файле остаётся открытой.

Затронутые утверждения — [R-M0008-01](#r-m0008-01), [R-M0008-02](#r-m0008-02).

[R-M0008-01](#r-m0008-01) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/baseline.md#L8)

> Each timestamp field declares milliseconds  

[R-M0008-02](#r-m0008-02) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/baseline.md#L8)

> Each timestamp field declares milliseconds; the numeric value 1000 represents one second.  

**Сценарий.** Экспортировать дорожку с временной меткой в одну секунду. Проверить число 1000 в соответствующем поле и объявление миллисекунд в согласованной форме для каждого поля временной метки.

**Последствие.** T-3 задаёт значение 1000 для одной секунды и требует объявления миллисекунд для каждого поля. Форма этого объявления в файле остаётся открытой.

**Уже установлено.** Каждое поле объявляет миллисекунды, а одной секунде соответствует число 1000. Основания — [R-M0008-01](#r-m0008-01), [R-M0008-02](#r-m0008-02).

**Открытое решение.** Нужно определить форму объявления миллисекунд в файле.

**Что различит проверка.** Миллисекунды указаны в имени каждого поля временной метки. Метка в одну секунду имеет числовое значение 1000. / Миллисекунды указаны в отдельном атрибуте каждого поля временной метки. Метка в одну секунду имеет числовое значение 1000.

### Z-003 · Каким должен быть итог экспорта в существующий файл после обязательного отклонения одной реплики из 81 кодовой точки Unicode, если остальные 99 реплик укладываются в лимит?

Затронутые утверждения — [R-M0014-01](#r-m0014-01), [R-M0015-01](#r-m0015-01).

[R-M0014-01](#r-m0014-01) · Subtitle track export / Export limits · [строка 14](../../../../../benchmark/subtitles/baseline.md#L14)

> Reject a cue when its text exceeds 80 Unicode code points.  

[R-M0015-01](#r-m0015-01) · Subtitle track export / Export limits · [строка 15](../../../../../benchmark/subtitles/baseline.md#L15)

> In the acceptance sample, a cue of 81 Unicode code points is rejected.  

**Сценарий.** На ST-1 экспортировать в существующий файл дорожку из 100 реплик, ровно одна из которых содержит 81 кодовую точку Unicode, а остальные содержат не более 80. Проверить итоговое состояние файла по согласованному результату, включая отсутствие отклонённой реплики среди экспортированных, и показ диалога завершения не позднее 2 секунд после команды.

**Последствие.** T-7 и T-8 задают отклонение реплики из 81 кодовой точки. T-4 задаёт срок показа диалога для дорожки из 100 реплик. Ожидаемое состояние файла после отклонения остаётся открытым.

**Уже установлено.** Реплика из 81 кодовой точки отклоняется. На ST-1 для 100 реплик действует срок в 2 секунды. Сохранение файла прямо оговорено для пустой дорожки. Основания — [R-M0014-01](#r-m0014-01), [R-M0003-01](#r-m0003-01), [R-M0015-01](#r-m0015-01), [R-M0009-01](#r-m0009-01), [R-M0010-02](#r-m0010-02).

**Открытое решение.** Нужно определить итоговое состояние существующего файла после отклонения реплики.

**Что различит проверка.** Реплика отклонена, файл содержит остальные 99 реплик, диалог показан в срок. / Реплика отклонена, существующий файл остался без изменений, диалог показан в срок.
