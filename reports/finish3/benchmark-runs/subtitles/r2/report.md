## Проверка набора в целом

Правила формата и приёмки расходятся по BOM, числовой шкале временных меток и обработке реплики из 81 кодовой точки. Для лёгкости экспорта нужна измеримая мера. Ссылка на T-40 требует редакторского исправления. T-6 уже задаёт текст сообщения для пустой дорожки.

Открытых предполагаемых пробелов — 0. Неоднозначностей — 0. Рекомендаций — 0.

Каждый ID утверждения учитывается один раз. В число нарушений входят подтверждённые дефекты и неоднозначности, для которых показаны две опирающиеся на текст трактовки с разными последствиями. Один и тот же конфликт имеет один ID при любом числе затронутых требований. Критичный дефект блокирует приёмку существенного обязательного сценария. Предполагаемый пробел оставляет открытым ожидаемое поведение или источник данных. Рекомендация предлагает улучшение. Вопросы и рекомендации имеют отдельные счётчики.

### Z-001 · BOM в экспортируемом файле

**Дефект · Противоречивость · Критичная.** T-1 запрещает BOM в экспортируемом файле, а T-2 требует BOM в первых трёх байтах того же файла. Обычный успешный экспорт нельзя принять по обоим пунктам.

Затронутые утверждения — [R-M0006-02](#r-m0006-02), [R-M0007-01](#r-m0007-01).

[R-M0006-02](#r-m0006-02) · Subtitle track export / Format · [строка 6](../../../../../benchmark/subtitles/requirements.md#L6)

> Write the exported track in UTF-8 without a byte-order mark.  

[R-M0007-01](#r-m0007-01) · Subtitle track export / Format · [строка 7](../../../../../benchmark/subtitles/requirements.md#L7)

> The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.  

**Сценарий.** Экспортировать непустую дорожку с допустимой репликой, текст которой начинается с обычной буквы.

**Последствие.** Файл, соответствующий T-1, провалит проверку T-2.

**Общее условие.** Один и тот же экспортируемый файл проверяется по правилу формата T-1 и приёмочному тесту T-2. Основания — [R-M0006-02](#r-m0006-02) «Write the exported track in UTF-8 without a byte-order mark.», [R-M0007-01](#r-m0007-01) «The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой исход должен проходить приёмку — файл с BOM или без BOM?

1. **Вариант 1.** Записывать дорожку в UTF-8 без начальной метки BOM.

   **Основание.** [R-M0006-02](#r-m0006-02) «Write the exported track in UTF-8 without a byte-order mark.».

   **Ожидаемый результат.** Файл начинается без BOM.

   При выборе этого варианта привести в соответствие [R-M0007-01](#r-m0007-01).

2. **Вариант 2.** Первые три байта экспортированного файла должны образовывать BOM UTF-8.

   **Основание.** [R-M0007-01](#r-m0007-01) «The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

   **Ожидаемый результат.** Файл начинается с EF BB BF.

   При выборе этого варианта привести в соответствие [R-M0006-02](#r-m0006-02).

**Черновик приёмочного теста.** После экспорта проверить, образуют ли первые три байта файла BOM UTF-8.

### Z-002 · Шкала временных меток

**Дефект · Противоречивость · Критичная.** Объявленная единица T-3 даёт 60000 для одной минуты, а заданное в том же пункте соответствие даёт 1000. Числовое значение обязательного поля нельзя принять по обеим частям правила.

Затронутые утверждения — [R-M0008-01](#r-m0008-01), [R-M0008-02](#r-m0008-02).

[R-M0008-01](#r-m0008-01) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> Each timestamp field declares milliseconds; the numeric value 1000 represents one minute.  

[R-M0008-02](#r-m0008-02) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> Each timestamp field declares milliseconds; the numeric value 1000 represents one minute.  

**Сценарий.** Экспортировать реплику с временной меткой в одну минуту от начала дорожки.

**Последствие.** Для этой метки нельзя одновременно выполнить оба условия T-3.

**Общее условие.** В поле временной метки нужно представить одну минуту. К этому же полю относится объявление миллисекунд. Основания — [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds», [R-M0008-02](#r-m0008-02) «the numeric value 1000 represents one minute.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какое число должно пройти приёмку для метки в одну минуту — 60000 или 1000?

1. **Вариант 1.** Числовые значения всех полей временных меток выражаются в миллисекундах.

   **Основание.** [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds; the numeric value 1000 represents one minute.».

   **Ожидаемый результат.** Метка в одну минуту записывается числом 60000.

   При выборе этого варианта привести в соответствие [R-M0008-02](#r-m0008-02).

2. **Вариант 2.** Числовое значение 1000 в поле временной метки обозначает одну минуту.

   **Основание.** [R-M0008-02](#r-m0008-02) «Each timestamp field declares milliseconds; the numeric value 1000 represents one minute.».

   **Ожидаемый результат.** Метка в одну минуту записывается числом 1000.

   При выборе этого варианта привести в соответствие [R-M0008-01](#r-m0008-01).

**Черновик приёмочного теста.** Экспортировать указанную реплику и сверить число в поле её временной метки с выбранным результатом.

### Z-003 · Реплика из 81 кодовой точки

**Дефект · Противоречивость · Существенная.** Реплика T-8 содержит 81 кодовую точку и подпадает под общий порог T-7. Ожидаемый результат для этого приёмочного образца противоречив.

Затронутые утверждения — [R-M0014-01](#r-m0014-01), [R-M0015-01](#r-m0015-01).

[R-M0014-01](#r-m0014-01) · Subtitle track export / Export limits · [строка 14](../../../../../benchmark/subtitles/requirements.md#L14)

> Reject a cue when its text exceeds 80 Unicode code points.  

[R-M0015-01](#r-m0015-01) · Subtitle track export / Export limits · [строка 15](../../../../../benchmark/subtitles/requirements.md#L15)

> In the acceptance sample, a cue of 81 Unicode code points is accepted.  

**Сценарий.** Запустить экспорт с репликой из приёмочного образца T-8, текст которой содержит 81 кодовую точку Unicode.

**Последствие.** Реализация порога T-7 провалит приёмочный пример T-8.

**Общее условие.** Проверяется реплика из образца T-8 с текстом длиной 81 кодовая точка Unicode. Это превышает порог T-7 в 80 кодовых точек. Основания — [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.», [R-M0015-01](#r-m0015-01) «In the acceptance sample, a cue of 81 Unicode code points is accepted.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой исход должен пройти приёмку для реплики из T-8 — принятие или отклонение?

1. **Вариант 1.** Отклонять реплику, если её текст превышает 80 кодовых точек Unicode.

   **Основание.** [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.».

   **Ожидаемый результат.** Реплика из приёмочного образца отклоняется.

   При выборе этого варианта привести в соответствие [R-M0015-01](#r-m0015-01).

2. **Вариант 2.** Реплика из приёмочного образца длиной 81 кодовая точка Unicode должна приниматься.

   **Основание.** [R-M0015-01](#r-m0015-01) «In the acceptance sample, a cue of 81 Unicode code points is accepted.».

   **Ожидаемый результат.** Реплика из приёмочного образца принимается.

   При выборе этого варианта привести в соответствие [R-M0014-01](#r-m0014-01).

**Черновик приёмочного теста.** Выполнить экспорт с указанным образцом и проверить исход обработки реплики.

### Z-004 · Критерий лёгкости экспорта

**Дефект · Проверяемость · Существенная.** T-4 требует лёгкости экспорта для каждого пользователя, но не задаёт измеримого критерия. Запись файла можно проверить отдельно.

Затронутые утверждения — [R-M0009-01](#r-m0009-01).

[R-M0009-01](#r-m0009-01) · Subtitle track export / Format · [строка 9](../../../../../benchmark/subtitles/requirements.md#L9)

> The export experience must feel effortless to every user.  

**Сценарий.** Попросить пользователей выполнить один и тот же экспорт в согласованных условиях и применить утверждённый критерий к результату каждого участника.

**Последствие.** По T-4 невозможно однозначно вынести вердикт об удобстве экспорта.

**Уже установлено.** Редактор экспортирует открытую дорожку в локальный файл. Экспорт должен восприниматься как лёгкий каждым пользователем. Основания — [R-M0009-01](#r-m0009-01), [R-M0003-01](#r-m0003-01).

**Открытое решение.** Выбрать измеримый критерий лёгкости экспорта для каждого пользователя.

**Что различит проверка.** Если минимум составляет 4 из 5 и все участники дали 4 из 5, испытание пройдено. / Если минимум составляет 5 из 5, при тех же оценках испытание не пройдено.

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** По какому измеримому критерию определять, что экспорт воспринимается как лёгкий каждым пользователем?

Внести ответ на этот вопрос в [R-M0009-01](#r-m0009-01) для сценария «Попросить пользователей выполнить один и тот же экспорт в согласованных условиях и применить утверждённый критерий к результату каждого участника.».

**Черновик приёмочного теста.** Попросить пользователей выполнить один и тот же экспорт в согласованных условиях и применить утверждённый критерий к результату каждого участника.

<a id="decision"></a>

## Готовность и порядок исправлений

ТЗ не готово к разработке и приёмке. Сначала нужно согласовать формат выходного файла и ожидаемый результат для приёмочного образца.

1. Согласовать правило BOM и шкалу временных меток, затем привести к ним приёмочные проверки. ([Z-001](#z-001), [Z-002](#z-002))
2. Согласовать порог длины реплики с ожидаемым результатом образца из 81 кодовой точки. ([Z-003](#z-003))
3. Задать измеримый критерий лёгкости экспорта для каждого пользователя. ([Z-004](#z-004))
4. Исправить ссылку на отсутствующий T-40. ([Z-005](#z-005))
