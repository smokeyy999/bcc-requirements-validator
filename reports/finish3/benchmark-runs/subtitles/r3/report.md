## Проверка набора в целом

Требования расходятся по BOM, шкале временных меток и исходу примера с 81 кодовой точкой. Для смешанной дорожки нужно определить состояние файла, а для удобства экспорта — критерий приёмки. Ссылка T-40 требует редакторской правки. Поведение для пустой дорожки уже задано в T-5 и T-6.

Открытых предполагаемых пробелов — 1. Неоднозначностей — 0. Рекомендаций — 0.

Каждый ID утверждения учитывается один раз. В число нарушений входят подтверждённые дефекты и неоднозначности, для которых показаны две опирающиеся на текст трактовки с разными последствиями. Один и тот же конфликт имеет один ID при любом числе затронутых требований. Критичный дефект блокирует приёмку существенного обязательного сценария. Предполагаемый пробел оставляет открытым ожидаемое поведение или источник данных. Рекомендация предлагает улучшение. Вопросы и рекомендации имеют отдельные счётчики.

### Z-001 · BOM в экспортированном файле

**Дефект · Противоречивость · Критичная.** T-1 требует записать файл без BOM, а T-2 требует BOM в первых трёх байтах того же файла. Экспорт допустимой дорожки нельзя принять по обоим правилам.

Затронутые утверждения — [R-M0006-01](#r-m0006-01), [R-M0007-01](#r-m0007-01).

[R-M0006-01](#r-m0006-01) · Subtitle track export / Format · [строка 6](../../../../../benchmark/subtitles/requirements.md#L6)

> Write the exported track in UTF-8 without a byte-order mark.  

[R-M0007-01](#r-m0007-01) · Subtitle track export / Format · [строка 7](../../../../../benchmark/subtitles/requirements.md#L7)

> The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.  

**Сценарий.** Экспортировать непустую дорожку с одной допустимой репликой и прочитать первые три байта файла.

**Последствие.** Файл, записанный по T-1, проваливает приёмочную проверку T-2.

**Общее условие.** Запись экспортированной дорожки и проверка начала полученного файла. Основания — [R-M0006-01](#r-m0006-01) «Write the exported track in UTF-8 without a byte-order mark.», [R-M0007-01](#r-m0007-01) «The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой файл должна принимать проверка — с UTF-8 BOM или без него?

1. **Вариант 1.** Записывать дорожку в UTF-8 без BOM.

   **Основание.** [R-M0006-01](#r-m0006-01) «Write the exported track in UTF-8 without a byte-order mark.».

   **Ожидаемый результат.** Файл начинается с данных, без BOM.

   При выборе этого варианта привести в соответствие [R-M0007-01](#r-m0007-01).

2. **Вариант 2.** Записывать UTF-8 BOM в первых трёх байтах файла.

   **Основание.** [R-M0007-01](#r-m0007-01) «The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

   **Ожидаемый результат.** Первые три байта файла — EF BB BF.

   При выборе этого варианта привести в соответствие [R-M0006-01](#r-m0006-01).

**Черновик приёмочного теста.** Экспортировать одну допустимую реплику и проверить первые три байта по выбранному правилу.

### Z-003 · Шкала временных меток

**Дефект · Противоречивость · Критичная.** В T-3 объявленная единица и числовое соответствие относятся к одному полю. Одна минута в миллисекундах равна 60000, а T-3 задаёт для неё 1000. Ожидаемое значение для приёмки временной метки противоречиво.

Затронутые утверждения — [R-M0008-01](#r-m0008-01), [R-M0008-02](#r-m0008-02).

[R-M0008-01](#r-m0008-01) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> Each timestamp field declares milliseconds; the numeric value 1000 represents one minute.  

[R-M0008-02](#r-m0008-02) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> Each timestamp field declares milliseconds; the numeric value 1000 represents one minute.  

**Сценарий.** Экспортировать дорожку с меткой ровно через одну минуту от начала.

**Последствие.** Приёмка одной и той же метки требует двух разных чисел в одном поле.

**Общее условие.** Поле экспортированной временной метки со значением в одну минуту. Основания — [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds», [R-M0008-02](#r-m0008-02) «the numeric value 1000 represents one minute.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какое число должно стоять в поле метки на одной минуте — 60000 или 1000?

1. **Вариант 1.** Записывать числовые значения всех полей временных меток в миллисекундах.

   **Основание.** [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds; the numeric value 1000 represents one minute.».

   **Ожидаемый результат.** В поле записано 60000.

   При выборе этого варианта привести в соответствие [R-M0008-02](#r-m0008-02).

2. **Вариант 2.** Записывать одну минуту числом 1000 и согласовать с этим объявленную единицу.

   **Основание.** [R-M0008-02](#r-m0008-02) «Each timestamp field declares milliseconds; the numeric value 1000 represents one minute.».

   **Ожидаемый результат.** В поле записано 1000.

   При выборе этого варианта привести в соответствие [R-M0008-01](#r-m0008-01).

**Черновик приёмочного теста.** Экспортировать метку на одной минуте, проверить её числовое значение и объявленную единицу.

### Z-004 · Критерий удобства экспорта

**Дефект · Проверяемость · Существенная.** T-4 требует, чтобы экспорт ощущался лёгким для каждого пользователя. При разных оценках одного экспорта ТЗ не даёт критерия, по которому можно вынести вердикт.

Затронутые утверждения — [R-M0009-01](#r-m0009-01).

[R-M0009-01](#r-m0009-01) · Subtitle track export / Format · [строка 9](../../../../../benchmark/subtitles/requirements.md#L9)

> The export experience must feel effortless to every user.  

**Сценарий.** Пользователи выполняют один и тот же экспорт и по-разному оценивают затраченные усилия.

**Последствие.** По результатам испытания нельзя вынести однозначный вердикт по T-4.

**Уже установлено.** Свойство относится к опыту экспорта каждого пользователя. Основания — [R-M0009-01](#r-m0009-01).

**Открытое решение.** Определить измеримый критерий лёгкости экспорта для каждого проверяемого пользователя.

**Что различит проверка.** Наблюдаемые результаты всех участников удовлетворяют выбранному критерию, T-4 пройдено. / Те же результаты при другом критерии выходят за его предел хотя бы для одного участника, T-4 не пройдено.

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какие наблюдаемые результаты и какой охват пользователей подтверждают выполнение T-4?

Внести ответ на этот вопрос в [R-M0009-01](#r-m0009-01) для сценария «Пользователи выполняют один и тот же экспорт и по-разному оценивают затраченные усилия.».

**Черновик приёмочного теста.** Проверить экспорт с согласованным охватом пользователей и оценить результаты по заданному критерию.

### Z-005 · Реплика из 81 кодовой точки

**Дефект · Противоречивость · Существенная.** Реплика из T-8 содержит 81 кодовую точку Unicode и подпадает под предел T-7. T-7 требует её отклонить, а T-8 ожидает её принятия в этом же испытании.

Затронутые утверждения — [R-M0014-01](#r-m0014-01), [R-M0015-01](#r-m0015-01).

[R-M0014-01](#r-m0014-01) · Subtitle track export / Export limits · [строка 14](../../../../../benchmark/subtitles/requirements.md#L14)

> Reject a cue when its text exceeds 80 Unicode code points.  

[R-M0015-01](#r-m0015-01) · Subtitle track export / Export limits · [строка 15](../../../../../benchmark/subtitles/requirements.md#L15)

> In the acceptance sample, a cue of 81 Unicode code points is accepted.  

**Сценарий.** Выполнить экспорт с репликой из 81 кодовой точки Unicode из приёмочного примера.

**Последствие.** Соблюдение T-7 приводит к провалу примера T-8. Исключение для примера не задано.

**Общее условие.** Экспорт реплики из 81 кодовой точки Unicode в приёмочном примере T-8. Основания — [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.», [R-M0015-01](#r-m0015-01) «In the acceptance sample, a cue of 81 Unicode code points is accepted.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** В приёмочном примере реплику из 81 кодовой точки следует принять или отклонить?

1. **Вариант 1.** Отклонять реплики длиннее 80 кодовых точек Unicode, включая реплику из приёмочного примера.

   **Основание.** [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.».

   **Ожидаемый результат.** Реплика из 81 кодовой точки отклонена.

   При выборе этого варианта привести в соответствие [R-M0015-01](#r-m0015-01).

2. **Вариант 2.** Принимать реплику из 81 кодовой точки Unicode в приёмочном примере.

   **Основание.** [R-M0015-01](#r-m0015-01) «In the acceptance sample, a cue of 81 Unicode code points is accepted.».

   **Ожидаемый результат.** Реплика из 81 кодовой точки принята.

   При выборе этого варианта привести в соответствие [R-M0014-01](#r-m0014-01).

**Черновик приёмочного теста.** Выполнить пример T-8 и сверить исход для реплики с выбранным правилом.

### Z-002 · Что должно остаться в существующем файле назначения после экспорта дорожки с допустимой репликой и репликой, отклонённой по T-7?

**Предполагаемый пробел · Полнота · Существенная.** T-7 задаёт отклонение реплики. Сохранение назначения в T-5 относится к пустой дорожке. Для экспорта дорожки с допустимой и отклоняемой репликами исход для файла не задан.

Затронутые утверждения — [R-M0003-02](#r-m0003-02), [R-M0014-01](#r-m0014-01).

[R-M0003-02](#r-m0003-02) · Subtitle track export · [строка 3](../../../../../benchmark/subtitles/requirements.md#L3)

[R-M0014-01](#r-m0014-01) · Subtitle track export / Export limits · [строка 14](../../../../../benchmark/subtitles/requirements.md#L14)

> Reject a cue when its text exceeds 80 Unicode code points.  

**Сценарий.** Попытаться экспортировать в существующий файл дорожку с одной допустимой репликой и одной репликой из 82 кодовых точек Unicode. Проверить отклонение второй реплики и согласованное содержимое файла.

**Последствие.** T-7 задаёт отклонение реплики. Сохранение назначения в T-5 относится к пустой дорожке. Для экспорта дорожки с допустимой и отклоняемой репликами исход для файла не задан.

**Уже установлено.** Редактор экспортирует открытую дорожку в локальный файл. Реплика длиннее 80 кодовых точек Unicode отклоняется. Для пустой дорожки назначение сохраняется. Основания — [R-M0014-01](#r-m0014-01), [R-M0003-02](#r-m0003-02), [R-M0010-02](#r-m0010-02).

**Открытое решение.** Определить содержимое существующего файла после попытки экспорта смешанной дорожки.

**Что различит проверка.** Реплика из 82 кодовых точек отклонена, прежнее содержимое файла сохранено. / Реплика из 82 кодовых точек отклонена, файл содержит экспорт допустимой реплики.

## Готовность и порядок исправлений

ТЗ не готово к разработке и приёмке полного экспорта. Сначала нужно согласовать формат файла и ожидаемый исход проверки предельной длины реплики.

1. Согласовать наличие BOM, объявленную единицу и числовое представление временных меток с приёмочными проверками. ([Z-001](#z-001), [Z-003](#z-003))
2. Согласовать предел длины реплики с исходом приёмочного примера. ([Z-005](#z-005))
3. Определить состояние файла назначения при обязательном отклонении реплики в смешанной дорожке. ([Z-002](#z-002))
4. Задать измеримый критерий удобства экспорта и охват проверки. ([Z-004](#z-004))
5. Исправить ссылку T-40 редакторской правкой с сохранением поведения, заданного T-5 и T-6. ([Z-006](#z-006))
