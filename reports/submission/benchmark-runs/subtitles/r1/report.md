## Проверка набора в целом

Требования к BOM и шкале времени задают несовместимые результаты для экспортируемого файла. Ограничение длины расходится с приёмочным примером. Исход смешанного экспорта требует уточнения. Для удобства нужен критерий проверки, для сообщения пустой дорожки — корректная ссылка.

Открытых предполагаемых пробелов — 1. Неоднозначностей — 0. Рекомендаций — 0.

Каждый ID утверждения учитывается один раз. В число нарушений входят подтверждённые дефекты и неоднозначности, для которых показаны две опирающиеся на текст трактовки с разными последствиями. Один и тот же конфликт имеет один ID при любом числе затронутых требований. Критичный дефект блокирует приёмку существенного обязательного сценария. Предполагаемый пробел оставляет открытым ожидаемое поведение или источник данных. Рекомендация предлагает улучшение. Вопросы и рекомендации имеют отдельные счётчики.

### Z-002 · BOM в начале файла

**Дефект · Противоречивость · Критичная.** T-1 требует записать файл без BOM, а T-2 требует BOM в начале того же файла. Приёмка формата экспорта по обоим правилам невозможна.

Затронутые утверждения — [R-M0006-01](#r-m0006-01), [R-M0007-01](#r-m0007-01).

[R-M0006-01](#r-m0006-01) · Subtitle track export / Format · [строка 6](../../../../../benchmark/subtitles/requirements.md#L6)

> Write the exported track in UTF-8 without a byte-order mark.  

[R-M0007-01](#r-m0007-01) · Subtitle track export / Format · [строка 7](../../../../../benchmark/subtitles/requirements.md#L7)

> The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.  

**Сценарий.** Экспортировать непустую дорожку с допустимыми субтитрами и проверить начало файла.

**Последствие.** Реализация формата по T-1 провалит тест T-2.

**Общее условие.** Начало записанного файла при проверке формата экспорта. Основания — [R-M0006-01](#r-m0006-01) «Write the exported track in UTF-8 without a byte-order mark.», [R-M0007-01](#r-m0007-01) «The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой файл должен пройти приёмку — с UTF-8 BOM или без него?

1. **Вариант 1.** Записывать экспорт в UTF-8 без BOM.

   **Основание.** [R-M0006-01](#r-m0006-01) «Write the exported track in UTF-8 without a byte-order mark.».

   **Ожидаемый результат.** В начале файла отсутствует BOM.

   При выборе этого варианта привести в соответствие [R-M0007-01](#r-m0007-01).

2. **Вариант 2.** Требовать в первых трёх байтах файла UTF-8 BOM.

   **Основание.** [R-M0007-01](#r-m0007-01) «The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

   **Ожидаемый результат.** Первые три байта файла образуют UTF-8 BOM.

   При выборе этого варианта привести в соответствие [R-M0006-01](#r-m0006-01).

**Черновик приёмочного теста.** Выгрузить одну и ту же дорожку и проверить наличие UTF-8 BOM в начале файла по выбранному правилу.

### Z-003 · Шкала временных меток

**Дефект · Противоречивость · Критичная.** Для одной минуты объявленная единица даёт 60000, а заданное соответствие даёт 1000. Приёмка временных меток требует согласованной пары числа и единицы.

Затронутые утверждения — [R-M0008-01](#r-m0008-01), [R-M0008-02](#r-m0008-02).

[R-M0008-01](#r-m0008-01) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> Each timestamp field declares milliseconds; the numeric value 1000 represents one minute.  

[R-M0008-02](#r-m0008-02) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> Each timestamp field declares milliseconds; the numeric value 1000 represents one minute.  

**Сценарий.** Экспортировать субтитр с временной меткой ровно в одну минуту от начала отсчёта.

**Последствие.** По T-3 нельзя выбрать ожидаемое число для сравнения при приёмке.

**Общее условие.** Представление одной минуты в поле временной метки, для которого T-3 объявляет миллисекунды. Основания — [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds», [R-M0008-02](#r-m0008-02) «the numeric value 1000 represents one minute.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какую единицу объявлять в поле временной метки и какое число записывать для одной минуты?

1. **Вариант 1.** Выражать значения всех полей временных меток в миллисекундах.

   **Основание.** [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds; the numeric value 1000 represents one minute.».

   **Ожидаемый результат.** В поле записано 60000.

   При выборе этого варианта привести в соответствие [R-M0008-02](#r-m0008-02).

2. **Вариант 2.** Использовать шкалу, в которой значение 1000 соответствует одной минуте, и согласовать с ней обозначение единицы.

   **Основание.** [R-M0008-02](#r-m0008-02) «Each timestamp field declares milliseconds; the numeric value 1000 represents one minute.».

   **Ожидаемый результат.** В поле записано 1000.

   При выборе этого варианта привести в соответствие [R-M0008-01](#r-m0008-01).

**Черновик приёмочного теста.** Экспортировать метку в одну минуту и сверить объявленную единицу и записанное число с согласованной парой.

### Z-005 · Приёмка субтитра из 81 кодовой точки

**Дефект · Противоречивость · Существенная.** Длина текста из T-8 превышает порог T-7. Общее правило требует отклонения, а приёмочный пример задаёт принятие. Расхождение блокирует проверку этого примера.

Затронутые утверждения — [R-M0014-01](#r-m0014-01), [R-M0015-01](#r-m0015-01).

[R-M0014-01](#r-m0014-01) · Subtitle track export / Export limits · [строка 14](../../../../../benchmark/subtitles/requirements.md#L14)

> Reject a cue when its text exceeds 80 Unicode code points.  

[R-M0015-01](#r-m0015-01) · Subtitle track export / Export limits · [строка 15](../../../../../benchmark/subtitles/requirements.md#L15)

> In the acceptance sample, a cue of 81 Unicode code points is accepted.  

**Сценарий.** Проверить субтитр из приёмочного примера с текстом длиной 81 кодовую точку Unicode.

**Последствие.** Реализация ограничения T-7 даст результат, противоположный ожидаемому в T-8.

**Общее условие.** Субтитр из приёмочного примера T-8 имеет длину 81 кодовую точку Unicode и подпадает под порог T-7. Основания — [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.», [R-M0015-01](#r-m0015-01) «In the acceptance sample, a cue of 81 Unicode code points is accepted.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой исход должен пройти приёмку для субтитра из T-8 с текстом длиной 81 кодовую точку Unicode: принятие или отклонение?

1. **Вариант 1.** Отклонять субтитры с текстом длиннее 80 кодовых точек Unicode, включая приёмочный пример.

   **Основание.** [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.».

   **Ожидаемый результат.** Субтитр из примера отклонён.

   При выборе этого варианта привести в соответствие [R-M0015-01](#r-m0015-01).

2. **Вариант 2.** Принять субтитр из приёмочного примера длиной 81 кодовую точку Unicode как исключение.

   **Основание.** [R-M0015-01](#r-m0015-01) «In the acceptance sample, a cue of 81 Unicode code points is accepted.».

   **Ожидаемый результат.** Субтитр из примера принят.

   При выборе этого варианта привести в соответствие [R-M0014-01](#r-m0014-01).

**Черновик приёмочного теста.** Подать на экспорт субтитр из T-8 и сверить результат его проверки с согласованным исходом.

## Готовность и порядок исправлений

ТЗ не готово к разработке формата и составлению полного набора приёмочных тестов. Сценарий пустой дорожки уже проверяем по заданным сообщению и состоянию файла.

1. Согласовать наличие BOM и пару из единицы и числового значения временной метки. Привести к ним правила формата и приёмки. (Z-002, Z-003)
2. Согласовать ограничение длины с приёмочным примером, затем определить результат смешанного экспорта и состояние файла. (Z-005, Z-001)
3. Определить наблюдаемый критерий удобства и способ проверить заявленный охват пользователей. (Z-004)
4. Исправить ссылку из T-5 на T-6. (Z-006)
