## Проверка набора в целом

ТЗ задаёт несовместимые исходы отправки черновика, допуска готовой ведомости из 25 строк и хранения подтверждения при настройке 7. Для своевременности показа «Передано» отсутствует измеримый критерий. Ссылка S-97 требует редакторского исправления. Текст при отказе и состояние ведомости уже заданы в S-7.

Открытых предполагаемых пробелов — 0. Неоднозначностей — 0. Рекомендаций — 0.

Каждый ID утверждения учитывается один раз. В число нарушений входят подтверждённые дефекты и неоднозначности, для которых показаны две опирающиеся на текст трактовки с разными последствиями. Один и тот же конфликт имеет один ID при любом числе затронутых требований. Критичный дефект блокирует приёмку существенного обязательного сценария. Предполагаемый пробел оставляет открытым ожидаемое поведение или источник данных. Рекомендация предлагает улучшение. Вопросы и рекомендации имеют отдельные счётчики.

[R-M0007-01](#r-m0007-01) · Отправка грузовых ведомостей / Отправка · [строка 7](../../../../../benchmark/dispatch/requirements.md#L7)

[R-M0007-02](#r-m0007-02) · Отправка грузовых ведомостей / Отправка · [строка 7](../../../../../benchmark/dispatch/requirements.md#L7)

> При попытке отправить ведомость в состоянии «Черновик» терминал сразу передаёт её перевозчику.  

**Сценарий.** Оператор пытается отправить сохранённую ведомость в состоянии «Черновик». Сеть и авторизация исправны.

**Последствие.** Один и тот же факт передачи будет успехом по S-2 и нарушением по S-1.

**Общее условие.** Оператор пытается отправить сохранённую ведомость в состоянии «Черновик» при исправных сети и авторизации. Основания — [R-M0006-01](#r-m0006-01) «Оператор может отправить ведомость только в состоянии «Готова».», [R-M0007-02](#r-m0007-02) «При попытке отправить ведомость в состоянии «Черновик» терминал сразу передаёт её перевозчику.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** При попытке отправить черновик терминал должен заблокировать передачу или передать ведомость перевозчику?

1. **Вариант 1.** Отправка разрешена только в состоянии «Готова».

   **Основание.** [R-M0006-01](#r-m0006-01) «Оператор может отправить ведомость только в состоянии «Готова».».

   **Ожидаемый результат.** Терминал не передаёт черновик перевозчику.

   При выборе этого варианта привести в соответствие [R-M0007-02](#r-m0007-02).

2. **Вариант 2.** При попытке отправки ведомости в состоянии «Черновик» терминал сразу передаёт её перевозчику.

   **Основание.** [R-M0007-02](#r-m0007-02) «При попытке отправить ведомость в состоянии «Черновик» терминал сразу передаёт её перевозчику.».

   **Ожидаемый результат.** Перевозчик получает черновик после попытки отправки.

   При выборе этого варианта привести в соответствие [R-M0006-01](#r-m0006-01).

   **Ожидаемый результат.** Ведомость из 25 строк недопустима к отправке. Момент отказа при обработке файла этим правилом не задан.

## Проверка каждого требования

<a id="r-m0006-01"></a>

### R-M0006-01 · Отправка разрешена только для ведомости в состоянии «Готова».

Отправка грузовых ведомостей / Отправка · [строка 6](../../../../../benchmark/dispatch/requirements.md#L6)

> Оператор может отправить ведомость только в состоянии «Готова».  

**Связано с нарушением в спецификации.** Для одной попытки отправки черновика S-1 запрещает передачу, а S-2 требует её. Ожидаемый результат проверки отправки определить невозможно. S-3 ограничивает одну ведомость 24 строками груза. S-4 требует принять файл с одной ведомостью из 25 строк и допустить её к отправке. Ожидаемый результат проверки допуска готовой ведомости определить невозможно.

Связанные замечания — [Z-001](#z-001), [Z-002](#z-002).

## Готовность и порядок исправлений

ТЗ не готово к передаче в разработку. Для приёмки отправки и хранения нужно согласовать ожидаемые исходы, для приёмки своевременности показа статуса нужно задать измеримый предел.

1. Согласовать исход попытки отправки черновика и допуск к отправке готовой ведомости из 25 строк. ([Z-001](#z-001), [Z-002](#z-002))
2. Согласовать срок локального хранения для значения 7 и привести к нему единицу и пояснение настройки. ([Z-004](#z-004))
3. Задать измеримый предел задержки показа «Передано» от наблюдаемого события подтверждения перевозчика. ([Z-003](#z-003))
4. Исправить внутреннюю ссылку S-97 редакторски с учётом результата отказа, уже заданного в S-7. ([Z-006](#z-006))
