## Проверка набора в целом

Формат экспорта противоречив по BOM и шкале временных меток. Правило длины реплики расходится с приёмочным примером. Для удобства экспорта отсутствует измеримый критерий, а ссылка T-40 требует редакторского исправления.

Открытых предполагаемых пробелов — 0. Неоднозначностей — 0. Рекомендаций — 0.

Каждый ID утверждения учитывается один раз. В число нарушений входят подтверждённые дефекты и неоднозначности, для которых показаны две опирающиеся на текст трактовки с разными последствиями. Один и тот же конфликт имеет один ID при любом числе затронутых требований. Критичный дефект блокирует приёмку существенного обязательного сценария. Предполагаемый пробел оставляет открытым ожидаемое поведение или источник данных. Рекомендация предлагает улучшение. Вопросы и рекомендации имеют отдельные счётчики.

### Z-001 · BOM в файле экспорта

**Дефект · Противоречивость · Критичная.** T-1 исключает BOM из экспортированного файла, а T-2 требует BOM в первых трёх байтах того же файла. Файл, записанный по T-1, не пройдёт обязательную проверку формата.

Затронутые утверждения — [R-M0006-02](#r-m0006-02), [R-M0007-01](#r-m0007-01).

[R-M0006-02](#r-m0006-02) · Subtitle track export / Format · [строка 6](../../../../../benchmark/subtitles/requirements.md#L6)

> Write the exported track in UTF-8 without a byte-order mark.  

[R-M0007-01](#r-m0007-01) · Subtitle track export / Format · [строка 7](../../../../../benchmark/subtitles/requirements.md#L7)

> The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.  

**Сценарий.** Экспортировать непустую дорожку с допустимой репликой и прочитать первые три байта файла.

**Последствие.** Приёмка отклонит файл, записанный в соответствии с T-1.

**Общее условие.** Приёмка проверяет первые три байта файла, записанного при экспорте дорожки. Основания — [R-M0006-02](#r-m0006-02) «Write the exported track in UTF-8 without a byte-order mark.», [R-M0007-01](#r-m0007-01) «The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой исход должен пройти приёмку для этого файла — наличие или отсутствие начального BOM?

1. **Вариант 1.** Записывать файл UTF-8 без BOM.

   **Основание.** [R-M0006-02](#r-m0006-02) «Write the exported track in UTF-8 without a byte-order mark.».

   **Ожидаемый результат.** В начале файла нет BOM.

   При выборе этого варианта привести в соответствие [R-M0007-01](#r-m0007-01).

2. **Вариант 2.** Записывать BOM UTF-8 в первые три байта файла.

   **Основание.** [R-M0007-01](#r-m0007-01) «The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

   **Ожидаемый результат.** Первые три байта файла содержат BOM UTF-8.

   При выборе этого варианта привести в соответствие [R-M0006-02](#r-m0006-02).

**Черновик приёмочного теста.** После экспорта проверить первые три байта на наличие BOM UTF-8.

### Z-002 · Шкала временной метки

**Дефект · Противоречивость · Критичная.** В T-3 объявленная единица каждого поля даёт 60000 для одной минуты, а правило для числа 1000 прямо приписывает ему ту же длительность. Приёмка шкалы временных меток заблокирована.

Затронутые утверждения — [R-M0008-01](#r-m0008-01), [R-M0008-02](#r-m0008-02).

[R-M0008-01](#r-m0008-01) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> Each timestamp field declares milliseconds; the numeric value 1000 represents one minute.  

[R-M0008-02](#r-m0008-02) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> Each timestamp field declares milliseconds; the numeric value 1000 represents one minute.  

**Сценарий.** Экспортировать допустимую реплику с временной меткой в одну минуту от начала дорожки.

**Последствие.** Читатель, использующий объявленные миллисекунды, интерпретирует записанное значение 1000 как одну секунду.

**Общее условие.** Оба правила T-3 применяются к числу в экспортируемом поле временной метки, соответствующей одной минуте. Основания — [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds», [R-M0008-02](#r-m0008-02) «the numeric value 1000 represents one minute.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какое число должно пройти приёмку для минутной метки — 60000 или 1000?

1. **Вариант 1.** Записывать временные метки в миллисекундах, как объявлено в каждом поле.

   **Основание.** [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds; the numeric value 1000 represents one minute.».

   **Ожидаемый результат.** Метка в одну минуту записана числом 60000.

   При выборе этого варианта привести в соответствие [R-M0008-02](#r-m0008-02).

2. **Вариант 2.** Записывать одну минуту числом 1000 и согласовать объявленную единицу с этой шкалой.

   **Основание.** [R-M0008-02](#r-m0008-02) «Each timestamp field declares milliseconds; the numeric value 1000 represents one minute.».

   **Ожидаемый результат.** Метка в одну минуту записана числом 1000.

   При выборе этого варианта привести в соответствие [R-M0008-01](#r-m0008-01).

**Черновик приёмочного теста.** Сверить числовое значение экспортированной минутной метки и объявленную для её поля единицу.

### Z-003 · Реплика из 81 кодовой точки

**Дефект · Противоречивость · Существенная.** T-7 требует отклонить реплику с текстом длиннее 80 кодовых точек Unicode, а T-8 требует принять реплику с 81 кодовой точкой. Расхождение блокирует обязательную проверку лимита.

Затронутые утверждения — [R-M0014-01](#r-m0014-01), [R-M0015-01](#r-m0015-01).

[R-M0014-01](#r-m0014-01) · Subtitle track export / Export limits · [строка 14](../../../../../benchmark/subtitles/requirements.md#L14)

> Reject a cue when its text exceeds 80 Unicode code points.  

[R-M0015-01](#r-m0015-01) · Subtitle track export / Export limits · [строка 15](../../../../../benchmark/subtitles/requirements.md#L15)

> In the acceptance sample, a cue of 81 Unicode code points is accepted.  

**Сценарий.** Подать реплику из приёмочного примера, текст которой содержит 81 кодовую точку Unicode.

**Последствие.** Отклонение по лимиту 80 кодовых точек приведёт к провалу приёмочного примера.

**Общее условие.** Проверяется реплика из приёмочного примера с текстом длиной 81 кодовую точку Unicode. Основания — [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.», [R-M0015-01](#r-m0015-01) «In the acceptance sample, a cue of 81 Unicode code points is accepted.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой исход должен пройти приёмку для реплики из примера — принятие или отклонение?

1. **Вариант 1.** Отклонять реплику, если в её тексте больше 80 кодовых точек Unicode.

   **Основание.** [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.».

   **Ожидаемый результат.** Реплика из 81 кодовой точки Unicode отклонена.

   При выборе этого варианта привести в соответствие [R-M0015-01](#r-m0015-01).

2. **Вариант 2.** Принимать реплику из 81 кодовой точки Unicode в приёмочном примере.

   **Основание.** [R-M0015-01](#r-m0015-01) «In the acceptance sample, a cue of 81 Unicode code points is accepted.».

   **Ожидаемый результат.** Реплика из 81 кодовой точки Unicode принята.

   При выборе этого варианта привести в соответствие [R-M0014-01](#r-m0014-01).

**Черновик приёмочного теста.** Подать реплику с текстом длиной ровно 81 кодовую точку Unicode и зафиксировать исход проверки.

### Z-004 · Критерий лёгкости экспорта

**Дефект · Проверяемость · Существенная.** T-4 требует лёгкости экспорта для каждого пользователя, но не задаёт измеримого критерия. Это мешает оценить удобство, сохраняя возможность проверить работу экспорта.

Затронутые утверждения — [R-M0009-01](#r-m0009-01).

[R-M0009-01](#r-m0009-01) · Subtitle track export / Format · [строка 9](../../../../../benchmark/subtitles/requirements.md#L9)

> The export experience must feel effortless to every user.  

**Сценарий.** Пользователь выполняет экспорт, после чего проверяющий оценивает выполнение T-4.

**Последствие.** По одному и тому же результату проверяющие могут вынести разные решения о выполнении T-4.

**Уже установлено.** Экспорт должен восприниматься как лёгкий каждым пользователем. Основания — [R-M0009-01](#r-m0009-01).

**Открытое решение.** Какой измеримый критерий подтверждает лёгкость экспорта для каждого пользователя?

**Что различит проверка.** Зафиксированный результат экспорта для каждого участника удовлетворяет выбранному критерию, и проверка проходит. / Тот же результат хотя бы одного участника не удовлетворяет выбранному критерию, и проверка не проходит.

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какое наблюдение и какой порог подтверждают лёгкость экспорта и на каких пользователях это проверять?

Внести ответ на этот вопрос в [R-M0009-01](#r-m0009-01) для сценария «Пользователь выполняет экспорт, после чего проверяющий оценивает выполнение T-4.».

**Черновик приёмочного теста.** Провести экспорт с согласованной группой пользователей и сопоставить измеренный результат с порогом.

Subtitle track export / Format · [строка 7](../../../../../benchmark/subtitles/requirements.md#L7)

> The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.  

**Связано с нарушением в спецификации.** T-1 исключает BOM из экспортированного файла, а T-2 требует BOM в первых трёх байтах того же файла. Файл, записанный по T-1, не пройдёт обязательную проверку формата.

Связанные замечания — [Z-001](#z-001).

## Готовность и порядок исправлений

ТЗ не готово к разработке по заданным критериям приёмки. Сначала нужно согласовать формат файла, шкалу временных меток и исход проверки реплики из 81 кодовой точки Unicode.

1. Согласовать наличие BOM, единицу временных меток и числовое значение для одной минуты. Привести требования и проверки формата к согласованным исходам. ([Z-001](#z-001), [Z-002](#z-002))
2. Согласовать предел длины текста с приёмочным исходом для реплики из 81 кодовой точки Unicode. ([Z-003](#z-003))
3. Задать измеримый критерий лёгкости экспорта и способ его проверки для пользователей. ([Z-004](#z-004))
