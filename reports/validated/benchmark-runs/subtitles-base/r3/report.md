## Вопросы к автору ТЗ

Вопросы приведены в порядке согласования. Автор ТЗ фиксирует решение, затем QA проверяет указанный сценарий.

### Согласовать до приёмки

**Какой исход команды и состояние назначения должны подтвердить обязательное отклонение реплики из 81 кодовой точки?**

Блокирует приёмку · [Z-004](#z-004). Зависимый сценарий — Выполнить экспорт для приёмочного образца и проверить согласованный исход. На границе убедиться, что длина 80 кодовых точек сама по себе не вызывает отклонения по этому правилу.

### Уточнить ожидаемое поведение

**Из какого источника приёмочный тест определяет локальный путь назначения конкретного вызова экспорта, включая вызов для пустой дорожки?**

Требует уточнения · [Z-002](#z-002). Зависимый сценарий — По согласованному источнику определить назначение каждого вызова. Для допустимой непустой дорожки проверить запись по этому пути. Для пустой дорожки проверить сообщение «Add at least one cue» и сохранность существующего файла либо отсутствие нового файла на свободном пути.

**Где приёмочный тест должен найти объявление миллисекунд, применимое к каждому полю временной метки?**

Требует уточнения · [Z-003](#z-003). Зависимый сценарий — Экспортировать дорожку с меткой в одну секунду. Проверить значение 1000 в соответствующем поле и по согласованному источнику подтвердить объявление миллисекунд для каждого поля временной метки.

### Z-004 · Наблюдаемый результат отклонения реплики

**Предполагаемый пробел · Полнота · Критичная.** T-7 требует отклонить реплику, а T-8 прямо включает 81 кодовую точку в приёмку. Без ожидаемого исхода команды и состояния назначения нельзя принять этот сценарий.

Затронутые утверждения — [R-M0014-01](#r-m0014-01), [R-M0015-01](#r-m0015-01).

[R-M0014-01](#r-m0014-01) · Subtitle track export / Export limits · [строка 14](../../../../../benchmark/subtitles/baseline.md#L14)

> Reject a cue when its text exceeds 80 Unicode code points.  

[R-M0015-01](#r-m0015-01) · Subtitle track export / Export limits · [строка 15](../../../../../benchmark/subtitles/baseline.md#L15)

> In the acceptance sample, a cue of 81 Unicode code points is rejected.  

**Сценарий.** Выполнить экспорт дорожки из приёмочного примера с репликой длиной 81 кодовая точка Unicode.

**Последствие.** По тексту нельзя определить ожидаемое состояние файла и способ подтвердить отклонение реплики.

**Уже установлено.** Реплику из 81 кодовой точки Unicode нужно отклонить. Сохранение назначения явно предписано для пустой дорожки. Основания — [R-M0015-01](#r-m0015-01), [R-M0014-01](#r-m0014-01), [R-M0010-02](#r-m0010-02).

**Открытое решение.** Какой наблюдаемый исход экспорта подтверждает отклонение реплики в приёмочном образце.

**Что различит проверка.** Команда отклоняет экспорт целиком, назначение сохраняется. / Команда записывает экспорт без отклонённой реплики, назначение содержит результат записи.

**Открытое решение.** Где проверять объявление единицы для каждого поля.

**Что различит проверка.** Тест находит объявление для каждого поля в выгруженном файле и видит 1000 в поле метки на одной секунде. / Тест находит объявление для каждого поля в отдельном описании формата и видит 1000 в поле метки на одной секунде.

## Готовность и порядок исправлений

К разработке однозначных правил можно приступать. Приёмка ограничения длины реплики заблокирована до определения ожидаемого исхода экспорта.

1. Задать исход команды и состояние назначения для приёмочного образца с репликой из 81 кодовой точки Unicode. ([Z-004](#z-004))
2. Указать источник фактического пути назначения для каждого тестового вызова. ([Z-002](#z-002))
3. Указать, где тест проверяет объявление миллисекунд для каждого поля временной метки. ([Z-003](#z-003))
