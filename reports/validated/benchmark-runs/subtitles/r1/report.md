## Проверка набора в целом

Требования к BOM, шкале временных меток и исходу приёмочного примера с 81 кодовой точкой противоречат друг другу. Для лёгкости экспорта отсутствует критерий проверки. Сообщение для пустой дорожки определено в T-6, ссылка в T-5 ошибочна.

Открытых предполагаемых пробелов — 0. Неоднозначностей — 0. Рекомендаций — 0.

Каждый ID утверждения учитывается один раз. В число нарушений входят подтверждённые дефекты и неоднозначности, для которых показаны две опирающиеся на текст трактовки с разными последствиями. Один и тот же конфликт имеет один ID при любом числе затронутых требований. Критичный дефект блокирует приёмку существенного обязательного сценария. Предполагаемый пробел оставляет открытым ожидаемое поведение или источник данных. Рекомендация предлагает улучшение. Вопросы и рекомендации имеют отдельные счётчики.

### Z-001 · BOM в файле экспорта

**Дефект · Противоречивость · Критичная.** T-1 запрещает BOM в экспортированном файле, а T-2 требует BOM в первых трёх байтах того же файла. Приёмка формата экспорта заблокирована.

Затронутые утверждения — [R-M0006-01](#r-m0006-01), [R-M0007-01](#r-m0007-01).

[R-M0006-01](#r-m0006-01) · Subtitle track export / Format · [строка 6](../../../../../benchmark/subtitles/requirements.md#L6)

> Write the exported track in UTF-8 without a byte-order mark.  

[R-M0007-01](#r-m0007-01) · Subtitle track export / Format · [строка 7](../../../../../benchmark/subtitles/requirements.md#L7)

> The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.  

**Сценарий.** Экспортировать непустую дорожку с короткой допустимой репликой и проверить начало полученного файла.

**Последствие.** Файл, записанный по T-1, не проходит проверку T-2. Файл, проходящий T-2, нарушает T-1.

**Общее условие.** Создан файл экспорта, к которому применяется проверка первых трёх байтов. Основания — [R-M0006-01](#r-m0006-01) «Write the exported track in UTF-8 without a byte-order mark.», [R-M0007-01](#r-m0007-01) «The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой файл должен пройти приёмку — с BOM или без BOM?

1. **Вариант 1.** Записывать файл в UTF-8 без BOM.

   **Основание.** [R-M0006-01](#r-m0006-01) «Write the exported track in UTF-8 without a byte-order mark.».

   **Ожидаемый результат.** В начале файла нет BOM.

   При выборе этого варианта привести в соответствие [R-M0007-01](#r-m0007-01).

2. **Вариант 2.** Первые три байта файла должны образовывать BOM UTF-8.

   **Основание.** [R-M0007-01](#r-m0007-01) «The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

   **Ожидаемый результат.** Файл начинается с EF BB BF.

   При выборе этого варианта привести в соответствие [R-M0006-01](#r-m0006-01).

**Черновик приёмочного теста.** Экспортировать одну и ту же дорожку и проверить наличие BOM в первых трёх байтах по выбранному правилу.

### Z-002 · Шкала временных меток

**Дефект · Противоречивость · Критичная.** Объявленная единица и явное соответствие относятся к одному полю. Значение 1000 в миллисекундах означает одну секунду, а T-3 приписывает ему одну минуту. Корректность экспортированных временных меток нельзя принять.

Затронутые утверждения — [R-M0008-01](#r-m0008-01), [R-M0008-02](#r-m0008-02).

[R-M0008-01](#r-m0008-01) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> Each timestamp field declares milliseconds  

[R-M0008-02](#r-m0008-02) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> Each timestamp field declares milliseconds; the numeric value 1000 represents one minute.  

**Сценарий.** При проверке экспортированного поля временной метки взять значение 1000 и определить соответствующее ему время от начала отсчёта этого поля.

**Последствие.** Одна и та же метка соответствует одной секунде по объявленной единице или одной минуте по явному соответствию.

**Общее условие.** Экспортированное поле временной метки объявляет миллисекунды и содержит число 1000. Основания — [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds», [R-M0008-02](#r-m0008-02) «the numeric value 1000 represents one minute.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой результат принять для значения 1000 — одну секунду или одну минуту?

1. **Вариант 1.** Числовое значение поля измеряется в объявленных миллисекундах.

   **Основание.** [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds».

   **Ожидаемый результат.** Значению 1000 соответствует одна секунда.

   При выборе этого варианта привести в соответствие [R-M0008-02](#r-m0008-02).

2. **Вариант 2.** Зафиксировать шкалу поля, в которой значение 1000 означает одну минуту, и согласовать с ней объявленную единицу.

   **Основание.** [R-M0008-02](#r-m0008-02) «Each timestamp field declares milliseconds; the numeric value 1000 represents one minute.».

   **Ожидаемый результат.** Значению 1000 соответствует одна минута.

   При выборе этого варианта привести в соответствие [R-M0008-01](#r-m0008-01).

**Черновик приёмочного теста.** Проверить поле со значением 1000 и сопоставить его с выбранным временем и объявленной единицей.

### Z-003 · Критерий лёгкости экспорта

**Дефект · Проверяемость · Существенная.** T-4 требует, чтобы экспорт воспринимался как лёгкий каждым пользователем. Наблюдаемый критерий успеха отсутствует, поэтому один и тот же результат может получить разные оценки.

Затронутые утверждения — [R-M0009-01](#r-m0009-01).

[R-M0009-01](#r-m0009-01) · Subtitle track export / Format · [строка 9](../../../../../benchmark/subtitles/requirements.md#L9)

> The export experience must feel effortless to every user.  

**Сценарий.** Оценить экспорт одной открытой дорожки по T-4.

**Последствие.** Проверяющие могут вынести разные вердикты по одному и тому же сценарию.

**Уже установлено.** Оценивается восприятие экспорта одной открытой дорожки. T-4 распространяется на каждого пользователя. Основания — [R-M0009-01](#r-m0009-01), [R-M0003-01](#r-m0003-01).

**Открытое решение.** Какой наблюдаемый критерий подтверждает лёгкость экспорта?

**Что различит проверка.** Пользователь завершил экспорт без помощи, но назвал его трудным. Проверка по самостоятельному завершению пройдена. / При том же результате проверка по оценке лёгкости самим пользователем не пройдена.

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** По какому наблюдаемому критерию и для каких пользователей проверять выполнение T-4?

Внести ответ на этот вопрос в [R-M0009-01](#r-m0009-01) для сценария «Оценить экспорт одной открытой дорожки по T-4.».

**Черновик приёмочного теста.** Выполнить сценарий экспорта с указанными пользователями и сравнить наблюдения с согласованным критерием.

### Z-004 · Приёмка реплики из 81 кодовой точки

**Дефект · Противоречивость · Существенная.** Порог T-7 распространяется на текст реплики из T-8. Конфликт блокирует проверку конкретного приёмочного примера.

Затронутые утверждения — [R-M0014-01](#r-m0014-01), [R-M0015-01](#r-m0015-01).

[R-M0014-01](#r-m0014-01) · Subtitle track export / Export limits · [строка 14](../../../../../benchmark/subtitles/requirements.md#L14)

> Reject a cue when its text exceeds 80 Unicode code points.  

[R-M0015-01](#r-m0015-01) · Subtitle track export / Export limits · [строка 15](../../../../../benchmark/subtitles/requirements.md#L15)

> In the acceptance sample, a cue of 81 Unicode code points is accepted.  

**Сценарий.** При экспорте проверить реплику из T-8 с текстом длиной 81 кодовая точка Unicode.

**Последствие.** Поскольку 81 больше 80, T-7 требует отклонить ту самую реплику, которую T-8 требует принять.

**Общее условие.** В приёмочном примере экспортируется реплика с текстом длиной 81 кодовая точка Unicode. Основания — [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.», [R-M0015-01](#r-m0015-01) «In the acceptance sample, a cue of 81 Unicode code points is accepted.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой исход должен пройти приёмку для реплики из T-8 — отклонение или принятие?

1. **Вариант 1.** Отклонять реплику, если её текст превышает 80 кодовых точек Unicode.

   **Основание.** [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.».

   **Ожидаемый результат.** Реплика из примера отклонена.

   При выборе этого варианта привести в соответствие [R-M0015-01](#r-m0015-01).

2. **Вариант 2.** В приёмочном примере принимать реплику из 81 кодовой точки Unicode.

   **Основание.** [R-M0015-01](#r-m0015-01) «In the acceptance sample, a cue of 81 Unicode code points is accepted.».

   **Ожидаемый результат.** Реплика из примера принята.

   При выборе этого варианта привести в соответствие [R-M0014-01](#r-m0014-01).

**Черновик приёмочного теста.** Выполнить экспорт с репликой из T-8 и проверить, принята ли она.

### R-M0010-01 · При экспорте пустой дорожки показывается точное сообщение из T-40.

Subtitle track export / Format · [строка 10](../../../../../benchmark/subtitles/requirements.md#L10)

> For an empty track, display the exact message listed in T-40  

**Связано с нарушением в спецификации.** T-5 ссылается на отсутствующее T-40. Для того же условия пустой дорожки T-6 прямо задаёт строку «Add at least one cue». Этого достаточно для проверки сообщения. Разрыв ссылки остаётся замечанием по трассируемости.

<a id="decision"></a>

## Готовность и порядок исправлений

ТЗ не готово к передаче в разработку и приёмку. Для формата файла, временных меток и приёмочного примера с 81 кодовой точкой нужно согласовать ожидаемые результаты.

1. Согласовать правило BOM и привести объявленную единицу временных меток в соответствие со шкалой. ([Z-001](#z-001), [Z-002](#z-002))
2. Согласовать порог длины текста с ожидаемым исходом приёмочного примера. ([Z-004](#z-004))
3. Задать наблюдаемый критерий лёгкости экспорта. ([Z-003](#z-003))
4. Заменить ссылку на T-40 точным сообщением из T-6. ([Z-005](#z-005))
