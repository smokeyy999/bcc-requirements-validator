## Проверка набора в целом

T-1 и T-2 задают несовместимые требования к экспортному файлу, а T-3 задаёт несовместимые значения минутной метки. Лимит T-7 расходится с приёмочным примером T-8. Для T-4 нужна наблюдаемая мера, а в T-5 нужно исправить ссылку на уже заданный текст.

Открытых предполагаемых пробелов — 0. Неоднозначностей — 0. Рекомендаций — 0.

Каждый ID утверждения учитывается один раз. В число нарушений входят подтверждённые дефекты и неоднозначности, для которых показаны две опирающиеся на текст трактовки с разными последствиями. Один и тот же конфликт имеет один ID при любом числе затронутых требований. Критичный дефект блокирует приёмку существенного обязательного сценария. Предполагаемый пробел оставляет открытым ожидаемое поведение или источник данных. Рекомендация предлагает улучшение. Вопросы и рекомендации имеют отдельные счётчики.

## Критичные дефекты

- [Z-001](#z-001) · T-1 требует записать экспортный файл без BOM, а T-2 требует BOM в первых трёх байтах того же файла. Успешный экспорт нельзя принять по обоим правилам.

### Z-001 · BOM в экспортном файле

**Дефект · Противоречивость · Критичная.** T-1 требует записать экспортный файл без BOM, а T-2 требует BOM в первых трёх байтах того же файла. Успешный экспорт нельзя принять по обоим правилам.

Затронутые утверждения — [R-M0006-02](#r-m0006-02), [R-M0007-01](#r-m0007-01).

[R-M0006-02](#r-m0006-02) · Subtitle track export / Format · [строка 6](../../../../../benchmark/subtitles/requirements.md#L6)

> Write the exported track in UTF-8 without a byte-order mark.  

[R-M0007-01](#r-m0007-01) · Subtitle track export / Format · [строка 7](../../../../../benchmark/subtitles/requirements.md#L7)

> The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.  

**Сценарий.** Успешно экспортировать открытый непустой трек с одной допустимой репликой в локальный файл.

**Последствие.** Реализация и приёмочный тест требуют взаимоисключающих вариантов начала одного файла.

**Общее условие.** Проверяются первые три байта файла, полученного при успешном экспорте трека. Основания — [R-M0006-02](#r-m0006-02) «Write the exported track in UTF-8 without a byte-order mark.», [R-M0007-01](#r-m0007-01) «The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой результат должен пройти приёмку: файл без BOM или файл с BOM в первых трёх байтах?

1. **Вариант 1.** Записывать трек в UTF-8 без BOM и принимать файл без BOM.

   **Основание.** [R-M0006-02](#r-m0006-02) «Write the exported track in UTF-8 without a byte-order mark.».

   **Ожидаемый результат.** В начале файла нет UTF-8 BOM.

   При выборе этого варианта привести в соответствие [R-M0007-01](#r-m0007-01).

2. **Вариант 2.** Записывать UTF-8 BOM в первые три байта файла и проверять его наличие при приёмке.

   **Основание.** [R-M0007-01](#r-m0007-01) «The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

   **Ожидаемый результат.** Первые три байта файла образуют UTF-8 BOM.

   При выборе этого варианта привести в соответствие [R-M0006-02](#r-m0006-02).

**Черновик приёмочного теста.** Экспортировать трек и сверить первые три байта файла с выбранным правилом.

### Z-002 · Шкала временной метки

**Дефект · Противоречивость · Критичная.** T-3 объявляет миллисекунды для каждого поля, поэтому одна минута соответствует 60000. Для той же минуты T-3 прямо задаёт 1000. Оба указания действуют в одном поле, поэтому корректность экспортированной метки нельзя принять.

Затронутые утверждения — [R-M0008-01](#r-m0008-01), [R-M0008-02](#r-m0008-02).

[R-M0008-01](#r-m0008-01) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> Each timestamp field declares milliseconds  

[R-M0008-02](#r-m0008-02) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> Each timestamp field declares milliseconds; the numeric value 1000 represents one minute.  

**Сценарий.** Экспортировать допустимую реплику с временной меткой в одну минуту.

**Последствие.** Один и тот же момент получает разные значения в одном поле.

**Общее условие.** В поле экспортируемой временной метки с объявленной единицей «миллисекунды» проверяется значение одной минуты. Основания — [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds», [R-M0008-02](#r-m0008-02) «the numeric value 1000 represents one minute.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какое число должно пройти приёмку для минутной метки: 60000 в миллисекундах или 1000 по заданному соответствию?

1. **Вариант 1.** Число в каждом поле временной метки выражает время в объявленных миллисекундах.

   **Основание.** [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds».

   **Ожидаемый результат.** В поле записано 60000.

   При выборе этого варианта привести в соответствие [R-M0008-02](#r-m0008-02).

2. **Вариант 2.** Записывать одну минуту числом 1000 и согласовать объявляемую единицу с этим соответствием.

   **Основание.** [R-M0008-02](#r-m0008-02) «Each timestamp field declares milliseconds; the numeric value 1000 represents one minute.».

   **Ожидаемый результат.** В поле записано 1000.

   При выборе этого варианта привести в соответствие [R-M0008-01](#r-m0008-01).

**Черновик приёмочного теста.** Экспортировать минутную метку и сверить число и объявленную единицу с выбранной шкалой.

### Z-003 · Критерий лёгкости экспорта

**Дефект · Проверяемость · Существенная.** T-4 требует, чтобы экспорт ощущался лёгким для каждого пользователя. Наблюдаемая мера и условие прохождения отсутствуют, поэтому оценка T-4 зависит от проверяющего.

Затронутые утверждения — [R-M0009-01](#r-m0009-01).

[R-M0009-01](#r-m0009-01) · Subtitle track export / Format · [строка 9](../../../../../benchmark/subtitles/requirements.md#L9)

> The export experience must feel effortless to every user.  

**Сценарий.** Пользователь экспортирует открытый трек, а проверяющий оценивает, насколько лёгким был экспорт.

**Последствие.** Проверяющие могут дать разные оценки одному выполнению и не смогут обосновать решение по T-4.

**Уже установлено.** Свойство относится к экспорту открытого трека и заявлено для каждого пользователя. Основания — [R-M0009-01](#r-m0009-01), [R-M0003-01](#r-m0003-01), [R-M0003-02](#r-m0003-02).

**Открытое решение.** Какой наблюдаемый критерий подтверждает лёгкость экспорта для каждого участника проверки?

**Что различит проверка.** При пороге самооценки 4 из 5 результаты проходят, если минимальная оценка участников равна 4. / При пороге 5 из 5 те же результаты не проходят.

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Для каких пользователей и по какому наблюдаемому критерию считать T-4 выполненным?

Внести ответ на этот вопрос в [R-M0009-01](#r-m0009-01) для сценария «Пользователь экспортирует открытый трек, а проверяющий оценивает, насколько лёгким был экспорт.».

**Черновик приёмочного теста.** Проверить экспорт для согласованной группы пользователей и сопоставить наблюдения с критерием прохождения.

### Z-004 · Реплика из 81 кодовой точки

**Дефект · Противоречивость · Существенная.** Реплика из T-8 содержит 81 кодовую точку Unicode и превышает порог T-7. T-7 требует её отклонить, а T-8 фиксирует принятие. Исключение для примера отсутствует, поэтому его приёмка заблокирована.

Затронутые утверждения — [R-M0014-01](#r-m0014-01), [R-M0015-01](#r-m0015-01).

[R-M0014-01](#r-m0014-01) · Subtitle track export / Export limits · [строка 14](../../../../../benchmark/subtitles/requirements.md#L14)

> Reject a cue when its text exceeds 80 Unicode code points.  

[R-M0015-01](#r-m0015-01) · Subtitle track export / Export limits · [строка 15](../../../../../benchmark/subtitles/requirements.md#L15)

> In the acceptance sample, a cue of 81 Unicode code points is accepted.  

**Сценарий.** Подать на экспорт реплику из приёмочного примера T-8 с текстом из 81 кодовой точки Unicode.

**Последствие.** Для одной реплики приёмка требует взаимоисключающих результатов.

**Общее условие.** Проверяется реплика из приёмочного примера T-8 с текстом из 81 кодовой точки Unicode. Основания — [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.», [R-M0015-01](#r-m0015-01) «In the acceptance sample, a cue of 81 Unicode code points is accepted.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой исход должен пройти приёмку для реплики T-8: отклонение или принятие?

1. **Вариант 1.** Отклонять реплики с текстом длиннее 80 кодовых точек Unicode, включая реплику приёмочного примера.

   **Основание.** [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.».

   **Ожидаемый результат.** Реплика из 81 кодовой точки отклонена.

   При выборе этого варианта привести в соответствие [R-M0015-01](#r-m0015-01).

2. **Вариант 2.** Принимать реплику из 81 кодовой точки Unicode в приёмочном примере и явно согласовать этот случай с общим лимитом.

   **Основание.** [R-M0015-01](#r-m0015-01) «In the acceptance sample, a cue of 81 Unicode code points is accepted.».

   **Ожидаемый результат.** Реплика из 81 кодовой точки принята.

   При выборе этого варианта привести в соответствие [R-M0014-01](#r-m0014-01).

**Черновик приёмочного теста.** Подать реплику T-8 и проверить выбранный исход на уровне реплики.

## Готовность и порядок исправлений

ТЗ не готово к разработке и приёмке экспорта. Сначала нужно согласовать формат файла и шкалу временных меток, затем определить исход приёмочного примера с 81 кодовой точкой.

1. Согласовать наличие BOM в файле, а также число и объявленную единицу для минутной метки. ([Z-001](#z-001), [Z-002](#z-002))
2. Согласовать лимит длины реплики с исходом приёмочного примера. ([Z-004](#z-004))
3. Задать наблюдаемый критерий прохождения T-4. ([Z-003](#z-003))
4. Заменить ссылку на T-40 в T-5 ссылкой на T-6. ([Z-005](#z-005))
