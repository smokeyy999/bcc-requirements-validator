## Проверка набора в целом

Правила формата и приёмки расходятся по BOM, значению временной метки 1000 и обработке реплики из 81 кодовой точки. Для лёгкости экспорта отсутствует критерий оценки. Точное сообщение для пустой дорожки задано в T-6, ссылка в T-5 ошибочна.

Открытых предполагаемых пробелов — 0. Неоднозначностей — 0. Рекомендаций — 0.

Каждый ID утверждения учитывается один раз. В число нарушений входят подтверждённые дефекты и неоднозначности, для которых показаны две опирающиеся на текст трактовки с разными последствиями. Один и тот же конфликт имеет один ID при любом числе затронутых требований. Критичный дефект блокирует приёмку существенного обязательного сценария. Предполагаемый пробел оставляет открытым ожидаемое поведение или источник данных. Рекомендация предлагает улучшение. Вопросы и рекомендации имеют отдельные счётчики.

### Z-001 · BOM в начале файла

**Дефект · Противоречивость · Критичная.** T-1 требует записать файл без BOM, а T-2 требует BOM в первых трёх байтах того же файла. Успешный экспорт нельзя принять по обоим правилам.

Затронутые утверждения — [R-M0006-02](#r-m0006-02), [R-M0007-01](#r-m0007-01).

[R-M0006-02](#r-m0006-02) · Subtitle track export / Format · [строка 6](../../../../../benchmark/subtitles/requirements.md#L6)

> UTF-8 without a byte-order mark  

[R-M0007-01](#r-m0007-01) · Subtitle track export / Format · [строка 7](../../../../../benchmark/subtitles/requirements.md#L7)

> The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.  

**Сценарий.** Экспортировать открытую непустую дорожку с допустимой репликой и проверить первые три байта файла.

**Последствие.** Один файл не может одновременно удовлетворить формату и приёмочному тесту.

**Общее условие.** Проверяются первые три байта файла, полученного при успешном экспорте дорожки. Основания — [R-M0006-02](#r-m0006-02) «UTF-8 without a byte-order mark», [R-M0007-01](#r-m0007-01) «The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой результат должна принять проверка начала файла: наличие или отсутствие UTF-8 BOM?

1. **Вариант 1.** Записывать файл в UTF-8 без BOM.

   **Основание.** [R-M0006-02](#r-m0006-02) «UTF-8 without a byte-order mark».

   **Ожидаемый результат.** Первые три байта файла не образуют UTF-8 BOM.

   При выборе этого варианта привести в соответствие [R-M0007-01](#r-m0007-01).

2. **Вариант 2.** Записывать UTF-8 BOM в первые три байта файла.

   **Основание.** [R-M0007-01](#r-m0007-01) «The acceptance test requires the first three bytes to be a UTF-8 byte-order mark.».

   **Ожидаемый результат.** Первые три байта файла образуют UTF-8 BOM.

   При выборе этого варианта привести в соответствие [R-M0006-02](#r-m0006-02).

**Черновик приёмочного теста.** Экспортировать допустимую дорожку и сравнить первые три байта с последовательностью UTF-8 BOM.

### Z-002 · Шкала временных меток

**Дефект · Противоречивость · Критичная.** T-3 объявляет миллисекунды единицей поля и приписывает числу 1000 одну минуту. Для одной метки получаются два разных времени, поэтому корректность экспортированных меток нельзя принять.

Затронутые утверждения — [R-M0008-01](#r-m0008-01), [R-M0008-02](#r-m0008-02).

[R-M0008-01](#r-m0008-01) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> Each timestamp field declares milliseconds  

[R-M0008-02](#r-m0008-02) · Subtitle track export / Format · [строка 8](../../../../../benchmark/subtitles/requirements.md#L8)

> the numeric value 1000 represents one minute.  

**Сценарий.** Прочитать значение 1000 в поле временной метки экспортированного файла.

**Последствие.** Одна и та же метка обозначает одну секунду или одну минуту на шкале поля.

**Общее условие.** В поле временной метки с объявленной единицей «миллисекунды» записано значение 1000. Основания — [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds», [R-M0008-02](#r-m0008-02) «the numeric value 1000 represents one minute.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какое время должна обозначать метка 1000: одну секунду или одну минуту?

1. **Вариант 1.** Число в каждом поле временной метки выражает количество миллисекунд.

   **Основание.** [R-M0008-01](#r-m0008-01) «Each timestamp field declares milliseconds».

   **Ожидаемый результат.** Значение 1000 обозначает одну секунду.

   При выборе этого варианта привести в соответствие [R-M0008-02](#r-m0008-02).

2. **Вариант 2.** Шкала поля задаётся соответствием значения 1000 одной минуте.

   **Основание.** [R-M0008-02](#r-m0008-02) «the numeric value 1000 represents one minute.».

   **Ожидаемый результат.** Значение 1000 обозначает одну минуту.

   При выборе этого варианта привести в соответствие [R-M0008-01](#r-m0008-01).

**Черновик приёмочного теста.** Прочитать метку 1000 в экспортированном файле и сверить её значение с выбранной шкалой.

### Z-004 · Приёмка реплики из 81 кодовой точки

**Дефект · Противоречивость · Критичная.** Порог T-7 распространяется на реплику из T-8. Слова «In the acceptance sample» задают случай, в котором ожидается принятие, и не устанавливают исключения из лимита. Приёмка ограничения даёт взаимоисключающие исходы.

Затронутые утверждения — [R-M0014-01](#r-m0014-01), [R-M0015-01](#r-m0015-01).

[R-M0014-01](#r-m0014-01) · Subtitle track export / Export limits · [строка 14](../../../../../benchmark/subtitles/requirements.md#L14)

> Reject a cue when its text exceeds 80 Unicode code points.  

[R-M0015-01](#r-m0015-01) · Subtitle track export / Export limits · [строка 15](../../../../../benchmark/subtitles/requirements.md#L15)

> In the acceptance sample, a cue of 81 Unicode code points is accepted.  

**Сценарий.** Выполнить пример T-8 с репликой, текст которой содержит 81 кодовую точку Unicode.

**Последствие.** Для одной реплики T-7 требует отклонения, а T-8 требует принятия.

**Общее условие.** Текст реплики в приёмочном примере содержит 81 кодовую точку Unicode и превышает порог 80. Основания — [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.», [R-M0015-01](#r-m0015-01) «In the acceptance sample, a cue of 81 Unicode code points is accepted.».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой исход закрепить для реплики из T-8: принятие или отклонение?

1. **Вариант 1.** Отклонять реплику, если её текст превышает 80 кодовых точек Unicode, в том числе в приёмочном примере.

   **Основание.** [R-M0014-01](#r-m0014-01) «Reject a cue when its text exceeds 80 Unicode code points.».

   **Ожидаемый результат.** Реплика из 81 кодовой точки Unicode отклонена.

   При выборе этого варианта привести в соответствие [R-M0015-01](#r-m0015-01).

2. **Вариант 2.** В приёмочном примере принять реплику из 81 кодовой точки Unicode.

   **Основание.** [R-M0015-01](#r-m0015-01) «In the acceptance sample, a cue of 81 Unicode code points is accepted.».

   **Ожидаемый результат.** Реплика из 81 кодовой точки Unicode принята.

   При выборе этого варианта привести в соответствие [R-M0014-01](#r-m0014-01).

**Черновик приёмочного теста.** Выполнить T-8, проверить длину текста в кодовых точках Unicode и зафиксировать исход для реплики.

**Дефект · Проверяемость · Существенная.** Фраза «feel effortless to every user» задаёт обязательное свойство, но не определяет меру его выполнения. Сам факт успешного экспорта проверяем.

Затронутые утверждения — [R-M0009-01](#r-m0009-01).

[R-M0009-01](#r-m0009-01) · Subtitle track export / Format · [строка 9](../../../../../benchmark/subtitles/requirements.md#L9)

**Сценарий.** Пользователь успешно экспортирует дорожку, после чего проверяющий оценивает выполнение T-4.

**Последствие.** По одному и тому же результату разные проверяющие могут принять разные решения.

**Уже установлено.** Экспорт должен восприниматься как лёгкий каждым пользователем. Основания — [R-M0009-01](#r-m0009-01).

**Открытое решение.** По какому критерию оценивать лёгкость экспорта для каждого пользователя?

**Что различит проверка.** Все участники сочли экспорт лёгким, один повторил попытку. По критерию самооценки испытание проходит. / При тех же результатах испытание не проходит, если критерий требует также завершить экспорт с первой попытки.

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой наблюдаемый результат и какое правило оценки для каждого пользователя подтверждают лёгкость экспорта?

Внести ответ на этот вопрос в [R-M0009-01](#r-m0009-01) для сценария «Пользователь успешно экспортирует дорожку, после чего проверяющий оценивает выполнение T-4.».

**Черновик приёмочного теста.** Провести экспорт по согласованному сценарию и оценить результаты пользователей по заданному автором критерию.

## Готовность и порядок исправлений

ТЗ не готово к разработке и приёмке экспорта. Сначала нужно согласовать ожидаемые результаты трёх обязательных проверок.

1. Согласовать наличие BOM и значение метки 1000 с правилами формата и приёмки. ([Z-001](#z-001), [Z-002](#z-002))
2. Согласовать исход для реплики из 81 кодовой точки в лимите и приёмочном примере. ([Z-004](#z-004))
3. Установить проверяемый критерий лёгкости экспорта для каждого пользователя. ([Z-003](#z-003))
4. Исправить ссылку в T-5 на T-6. ([Z-005](#z-005))
