# Повторная проверка после разбора пропусков

Используется ранее зафиксированный протокол. Каждый из трёх проходов охватывает одни и те же семь документов и 15 размеченных дефектов. Каждый отчёт создаёт отдельный запуск `gpt-6.2-sol` из чистого клона. В оценку входит первый полностью завершённый отчёт для каждой пары «документ, проход». Журналы включают технические отказы и повторы. [Исходные критерии](../finish/protocol.md)

Промежуточная версия `d16b732` получила 13/15, 14/15 и 15/15. Проверяются три обнаруженных причины потери зачёта. Для случая с ограничением вместимости проверяется, можно ли обосновать отбор части входных данных текстом ТЗ. Для условия аварийного перехода отдельно проверяются смысл термина во входном условии и требуемое конечное состояние. Для внутренней ссылки проверяется распознавание адреса в английской формулировке. Оценщик, разметка, документы и правила повторов сохраняются. [Карточки промежуточной версии](../finish/comparison.md)

Для банковских вопросов оцениваются формулировка, основание в ТЗ и ожидаемый исход теста. Проверяющий отдельно отмечает, исчезло ли неподкреплённое предположение об алфавите идентификатора, сохранились ли два решения о границе доставки и моменте записи признака и указан ли вход примера ответа API. [Критерии и исходный банковский отчёт](../finish/protocol.md)
