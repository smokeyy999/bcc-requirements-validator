# Независимая вычитка свободной банковской очереди

В первом полном прогоне версии `396c490` через `gpt-6.2-sol` можно передать владельцу **15 из 15 вопросов** с опубликованными тестами. В той же очереди полностью воспроизведены **11 из 17 прежних тем** версии `5669ac8`. Каждый зачёт требует открытого решения и сценария, который различает его исходы. [Протокол](protocol.md) · [Новый отчёт](../../reports/review6/review.md) · [Прежняя очередь](../finish4/queue-review.md)

Обе целевые темы прошли проверку. Полный возврат 4 000 ₸ остаётся контрольным случаем, а ответ с ERROR обязан вернуть прежние 50 000 ₸ и значение переключателя. Отдельного вопроса про байты или алфавит cardId нет.
У всех 15 выданных вопросов обнаружился самостоятельный предмет для согласования. Две новые темы касаются соответствия между кодами и положениями переключателя и наличия адреса метода в Prod. Из старых тем четыре отсутствуют, ещё две покрыты частично.

### Z-012

**Отправлять ли второй push в этом сценарии?**

Тест из отчёта — Получить первый push, поднять порог, проверить сохранность итога, затем достичь нового порога и сосчитать push за месяц.

Наблюдаемый результат из карточки — После нового достижения число push за месяц остаётся равным одному.

Наблюдаемый результат из карточки — После нового достижения за месяц получено два push.

**Готов.** Ответ меняет счётчик отправок в одном месяце. В тесте разрешается прямое расхождение двух функциональных правил. [Строка 39](../../docs/requirements.md#L39) · [Строка 40](../../docs/requirements.md#L40) · [Z-012](../../reports/review6/review.md#z-012)

**Готов.** Срок у получателя вводится в тест только с согласия автора. Факт получения и минутный предел передачи остаются. ### Z-008

**Каким состояниям уведомления соответствуют значения enabled 0 и 1?**

Тест из отчёта — Сохранить 0 и 1 на отдельных картах и сверить состояния переключателя. При первом достижении порога на каждой карте проверить push только для согласованного кода включения.

**Готов.** Новая тема. В API используется целое 0 или 1. Текст и пример не связывают конкретный код с отображаемым состоянием. Проверка на двух картах различает возможные соглашения. Привычное соответствие 1 → включено разумно, но в тексте оно не установлено. ### Z-018

**В каких полях и структуре ответа при отклонении суммы возвращаются прежние порог и состояние переключателя?**

Тест из отчёта — Сохранить порог 50 000 ₸ и enabled=1. С действующей сессией владельца отправить для той же карты amount=999 и enabled=0. Проверить 400 и ERROR, считать оба прежних значения из согласованной структуры и сверить их с исходными.

Наблюдаемый результат из карточки — Порог 50 000 ₸ и enabled=1 считываются из полей верхнего уровня ответа 400 с ERROR. / Те же значения считываются из вложенной структуры ответа 400 с ERROR.

**Готов.** Прежние 50 000 ₸ и включённый переключатель уже сохранены. Тест получает оба значения из ответа с ERROR и сравнивает с исходными. Обе ветви сохраняют требование вернуть данные. ### Z-020

**Какой адрес соответствует этому методу в Prod, если он предусмотрен в этом контуре?**

Тест из отчёта — Проверить сохранение в Dev по указанному пути. Если для метода подтверждён адрес в Prod, повторить тот же сценарий по этому адресу.

Наблюдаемый результат из карточки — Для метода указан адрес в Prod, по которому можно проверить сохранение. / Метод предусмотрен только в Dev, поэтому проверка сохранения выполняется только там.

**Готов.** Новая тема низкого приоритета. Документ прямо перечисляет Dev/Prod и оставляет в адресе Prod прочерк. Вопрос и тест условны и разрешают ответ, что этот метод предусмотрен только в Dev.
