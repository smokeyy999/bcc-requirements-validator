# Независимая вычитка свободной банковской очереди

В первом полном прогоне версии `ed55df7` через `gpt-6.2-sol` можно передать владельцу **19 из 20 вопросов** с опубликованными тестами. В той же очереди полностью воспроизведены **13 из 17 прежних тем** версии `5669ac8`. Каждый зачёт требует открытого решения и сценария, который различает его исходы. [Протокол](protocol.md) · [Новый отчёт](../../reports/review7/review.md) · [Прежняя очередь](../finish4/queue-review.md)

Обе целевые доработки прошли свободную проверку. В Z-012 сумма полного возврата определена заранее, а обе ветви отличаются только применимостью частичного. В Z-019 после отказа обе прежние величины считываются из ответа вместе с ERROR. Вопроса про алфавит cardId и отдельного вопроса о входе для точной строки «Некорректный запрос» нет.
Четыре новые темы касаются кодировки переключателя, данных события покупки, пропущенного обязательного amount и применимости 201. Из них вопрос о данных события требует сужения: единица хранения суммы ещё не определяет единицу входа. Среди 17 старых тем три покрыты частично, у одной отсутствует вопрос с зависимым тестом.

### Z-005

**При достижении нового порога в том же месяце сохранить один push на карту или отправить второй?**

Тест из отчёта — После первого push поднять порог, убедиться в сохранении итога и провести покупку до нового порога. Проверить число push по выбранному правилу.

Наблюдаемый результат из карточки — Нового push нет. За месяц один push.

Наблюдаемый результат из карточки — Приходит второй push за тот же месяц.

**Готов.** Ответ меняет счётчик отправок в одном месяце. В тесте разрешается прямое расхождение двух функциональных правил. [Строка 39](../../docs/requirements.md#L39) · [Строка 40](../../docs/requirements.md#L40) · [Z-005](../../reports/review7/review.md#z-005)
