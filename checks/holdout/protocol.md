# Отложенная проверка двух версий

До первого модельного запуска и фиксации исправленной реализации независимый проверяющий подготовил две версии одного нового документа. На согласованной копии правила однозначно задают выход для всех допустимых входов. Вторая копия отличается двумя фрагментами. Описание ожидаемых несовпадений, категории и необходимые цитаты сохранены в [разметке](inputs/case-k/manifest.json). Разработчики получают доступ к описанию случаев после фиксации версии.

Исходная версия `bf920eb` и исправленная версия из чистого локального коммита проверяют оба входа. Для каждого сочетания выбирается первый сохранённый отчёт CLI. На технический отказ отводится не более трёх полных попыток суммарно. Используется `gpt-6.2-sol` с одним потоком извлечения. Модель видит только документ текущего запуска. Эталон, согласованная пара и другие отчёты ей недоступны.

Основные показатели — число готовых отчётов из двух, число подтверждённых дефектов из двух и числа вопросов и карточек в согласованной копии, для которой ожидается ноль. Учитывается штатное `scripts.evaluate.match_seeds`. Для каждого эталона нужна отдельная карточка заявленной категории с доказательствами из обоих указанных диапазонов. Отдельно приводится полнота на общих завершённых входах. Если отчёт не сохранён, как результат для пользователя засчитывается ноль доставленных замечаний, а семантическое качество на этом документе остаётся неизмеренным. Фиксируются все попытки и хеши документов и программной версии. Этот корпус оценивается отдельно от предыдущих четырёх входов и от первоначального корпуса на 15 дефектов.
