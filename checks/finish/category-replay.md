# Почему аварийное положение относится к полноте

В требовании W-4 задано действие при некорректном показании. Автору осталось определить положение, которое должен занять клапан. Даже после уточнения места в документе QA потребуется конкретное ожидаемое состояние. Обе архивные карточки верно задали этот вопрос, но сохранили категорию «Трассируемость». [Исходное требование](../../benchmark/irrigation/requirements.md#L9) · [Второй проход](../../reports/release/benchmark-runs/irrigation/r2/report.md#z-007) · [Третий проход](../../reports/release/benchmark-runs/irrigation/r3/report.md#z-007)

### Повтор проверки без модели

Для каждого отчёта сверены SHA-256 исходного документа и Markdown с паспортом прогона `fa37472`. Из карточки прочитаны исходная категория, вопрос, блок «Уже установлено», открытое решение, оба исхода испытания и ссылки на утверждения. Полное исходное сообщение рецензента в отчёте не хранится. Для технического эксперимента вручную выбрано состояние `не задан результат действия`. Связи `obligation_id` и `checked_ids` восстановлены из опубликованного списка оснований, а список обоснований конкурирующих трактовок оставлен пустым. Каждая версия функции `_check_question` получила одни и те же данные. [Паспорт второго прохода](../../reports/release/benchmark-runs/irrigation/r2/report/run-meta.json) · [Паспорт третьего прохода](../../reports/release/benchmark-runs/irrigation/r3/report/run-meta.json) · [Реализация](../../requirements_validator/engine.py)

Штатный оценщик прочёл все сохранённые карточки каждого документа. Для повторного сопоставления в памяти заменена только категория Z-007 на фактический вывод функции. Правила оценки, остальные карточки, виды замечаний и диапазоны строк остались исходными. [Правило сопоставления](../../scripts/evaluate.py) · [Эталон W-4](../../benchmark/irrigation/manifest.json)

| Архивный отчёт | Проверка версии `fa37472` | Исправленная проверка | Совпадения по этому документу |
|---|---|---|---:|
| Второй проход | Трассируемость | Полнота, I-03 → Z-007 | 4/5 → 5/5 |
| Третий проход | Трассируемость | Полнота, I-03 → Z-007 | 4/5 → 5/5 |

Так воспроизведена причина потери балла при правильном замечании. Значение внутреннего состояния в исторических ответах модели неизвестно. Таблица показывает эффект обработки одного и того же решения двумя версиями кода. Стабильность самостоятельного выбора состояния проверяется отдельными живыми прогонами.

### Контроль настоящей ошибки ссылки

В другом исходном ТЗ индекс документа повторно подтвердил отсутствие адресата `S-97`. Правило проверки ссылок сформировало редакторскую карточку без вопроса автору. Попытка передать ей искусственный вопрос о выборе результата была отклонена обеими версиями. Категория сохранилась как «Трассируемость», а строгий оценщик снова сопоставил D-04 с Z-006.
