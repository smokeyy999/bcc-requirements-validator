# Что показала независимая проверка

Протокол, новые входы и разметка зафиксированы в `1d3edbf` до первого запуска. Разработчики узнали их содержание после фиксации проверяемого кода. На один чистый запуск `gpt-6.2-sol` передан один документ. Доказательства сверены с исходными строками, паспортами и хешами. [Условия зачёта](protocol.md)

| Новая пара | Прежняя версия `fa37472` | Проверяемая версия `d16b732` |
|---|---:|---:|
| Готовых отчётов | 2/2 | 2/2 |
| Строго зачтено из трёх заложенных замечаний | 3/3 | 3/3 |
| Строгие совпадения среди всех опубликованных карточек | 3/3 | 3/3 |
| Вопросы / карточки в согласованном документе | 0 / 0 | 0 / 0 |
| Всего попыток CLI | 3 | 2 |

| Наблюдение | Прежняя версия | Проверяемая версия |
|---|---|---|
| P-01. После получения события нужно выбрать одну из двух рамок. Ожидаемая рамка не установлена. | [Z-001](independent-runs/before/case-p/report.md#z-001) | [Z-002](independent-runs/after/case-p/report.md#z-002) |
| P-02. Разрешённые три буквы занимают шесть байт. Общее правило отклоняет метку длиной свыше четырёх байт, а пример принимает эту метку. | [Z-002](independent-runs/before/case-p/report.md#z-002) | [Z-001](independent-runs/after/case-p/report.md#z-001) |
| P-03. Обе границы приёмочного интервала и событие подтверждения заданы. Для «достаточно коротким» отсутствует численное условие зачёта. | [Z-003](independent-runs/before/case-p/report.md#z-003) | [Z-003](independent-runs/after/case-p/report.md#z-003) |
| Согласованный полный текст | [0 вопросов, 0 карточек](independent-runs/before/case-p-base/report.md) | [0 вопросов, 0 карточек](independent-runs/after/case-p-base/report.md) |

В изменённом ТЗ обе версии задали три вопроса об отдельных решениях, а в согласованном — ни одного. Проверяемая версия сохранила вопрос о многобайтовой метке именно там, где автор прямо допустил кириллические буквы, описал кодирование и привёл пример длиной шесть байт. Для одного входа общее правило и пример требуют разных сообщений. [Изменённый вход](independent/case-p/variant.md#L11-L12) · [Варианты и зависимый тест](independent-runs/after/case-p/report.md#z-001)

Обе версии отнесли отсутствующую рамку к полноте. Исходная версия оформила её как предполагаемый пробел, проверяемая — как доказанный дефект. Обязателен сам вывод рамки, а документ перечисляет две доступные рамки без назначения для события. Агент спросил, какую вывести, и предложил проверить её после однократной подачи события. [Исходная версия](independent-runs/before/case-p/report.md#z-001) · [Проверяемая версия](independent-runs/after/case-p/report.md#z-002)

В этом ТЗ измерение полного цикла и подтверждение от внешнего экрана явно входят в приёмку. Вопрос о максимальном показании таймера обоснован. Тест сохранил обе заданные границы интервала и не добавил ещё одну точку подтверждения. Все три целевых замечания засчитаны на обеих версиях, поэтому этот опыт показывает сохранение нужных вопросов. [Условия измерения](independent/case-p/variant.md#L16-L17) · [Проверяемая версия](independent-runs/after/case-p/report.md#z-003)

При исходном запуске на изменённом документе CLI остановился из-за исчерпания квоты перед записью отчёта. После восстановления доступа повторился тот же вход с той же конфигурацией. У проверяемой версии оба входа завершились с первой полной попытки. [Первый отказ](independent-cli/before/case-p-attempt-1.txt) · [Успешный повтор](independent-cli/before/case-p-attempt-2.txt)

Каждый дополнительный документ проверен одним независимым запуском на версию. Для воспроизводимости этих результатов по повторным запускам на тех же входах данных нет. Три независимых прохода выполнялись по отдельному корпусу организованной проверки.
