## Проверка набора в целом

У всех трёх обязательных опытов есть блокирующие замечания. Для повреждённого узора отсутствует назначение рамки, для «АБА» заданы несовместимые ответы, для полного цикла отсутствует численный критерий приёмки.

Открытых предполагаемых пробелов — 0. Неоднозначностей — 0. Рекомендаций — 0.

Каждый ID утверждения учитывается один раз. В число нарушений входят подтверждённые дефекты и неоднозначности, для которых показаны две опирающиеся на текст трактовки с разными последствиями. Один и тот же конфликт имеет один ID при любом числе затронутых требований. Критичный дефект блокирует приёмку существенного обязательного сценария. Предполагаемый пробел оставляет открытым ожидаемое поведение или источник данных. Рекомендация предлагает улучшение. Вопросы и рекомендации имеют отдельные счётчики.

## Критичные дефекты

- [Z-001](#z-001) · П-1 требует вывести назначенную рамку и перечисляет два варианта. Назначение отсутствует, поэтому обязательный опыт нельзя принять по наблюдаемой рамке.
- [Z-002](#z-002) · Метка «АБА» состоит из трёх допустимых букв и занимает шесть байт. Для одной подачи М-1 требует «Отклонено», а М-2 требует «Принято». Приоритет между ними отсутствует, поэтому обязательный опыт нельзя принять.

### Z-002 · Противоречивый ответ на «АБА»

**Дефект · Противоречивость · Критичная.** Метка «АБА» состоит из трёх допустимых букв и занимает шесть байт. Для одной подачи М-1 требует «Отклонено», а М-2 требует «Принято». Приоритет между ними отсутствует, поэтому обязательный опыт нельзя принять.

Затронутые утверждения — [R-M0003-04](#r-m0003-04), [R-M0011-02](#r-m0011-02), [R-M0011-04](#r-m0011-04), [R-M0012-01](#r-m0012-01).

> В каждом опыте после сброса подают указанный вход один раз и наблюдают указанный результат.  

[R-M0011-02](#r-m0011-02) · Учебный стенд для мозаики / Текстовая метка · [строка 11](../../../independent/case-p/variant.md#L11)

> Метка состоит из букв А и Б, каждая буква занимает два байта в UTF-8.  

[R-M0011-04](#r-m0011-04) · Учебный стенд для мозаики / Текстовая метка · [строка 11](../../../independent/case-p/variant.md#L11)

> При длине до четырёх байт включительно стенд показывает «Принято», при большей длине — «Отклонено».  

[R-M0012-01](#r-m0012-01) · Учебный стенд для мозаики / Текстовая метка · [строка 12](../../../independent/case-p/variant.md#L12)

> Для входа «АБА» стенд должен показать «Принято».  

**Сценарий.** После сброса один раз подать «АБА». Три буквы по два байта занимают шесть байт в UTF-8.

**Последствие.** М-1 требует «Отклонено», а М-2 требует «Принято». Явного исключения для этого входа нет.

**Общее условие.** После сброса один раз подают метку «АБА» длиной шесть байт в UTF-8. Основания — [R-M0003-04](#r-m0003-04) «В каждом опыте после сброса подают указанный вход один раз и наблюдают указанный результат.», [R-M0011-02](#r-m0011-02) «Метка состоит из букв А и Б, каждая буква занимает два байта в UTF-8.», [R-M0011-04](#r-m0011-04) «При длине до четырёх байт включительно стенд показывает «Принято», при большей длине — «Отклонено».», [R-M0012-01](#r-m0012-01) «Для входа «АБА» стенд должен показать «Принято».».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой результат принять для «АБА», «Отклонено» по общему порогу или «Принято» как явное исключение?

1. **Вариант 1.** Применять общий порог к «АБА». При длине до четырёх байт включительно показывать «Принято», при большей длине показывать «Отклонено».

   **Основание.** [R-M0011-04](#r-m0011-04) «При длине до четырёх байт включительно стенд показывает «Принято», при большей длине — «Отклонено».».

   **Ожидаемый результат.** Для шестибайтной метки «АБА» стенд показывает «Отклонено».

   При выборе этого варианта привести в соответствие [R-M0012-01](#r-m0012-01).

2. **Вариант 2.** Выделить «АБА» как явное исключение из общего правила длины и показывать для этого входа «Принято».

   **Основание.** [R-M0012-01](#r-m0012-01) «Для входа «АБА» стенд должен показать «Принято».».

   **Ожидаемый результат.** Для шестибайтной метки «АБА» стенд показывает «Принято».

   При выборе этого варианта привести в соответствие [R-M0011-04](#r-m0011-04).

**Черновик приёмочного теста.** После сброса один раз подать «АБА» и сравнить показанный ответ с выбранным результатом.

## Готовность и порядок исправлений

ТЗ не готово к передаче в разработку. Для каждого обязательного опыта нужно установить однозначный критерий приёмки.

1. Согласовать М-1 и М-2, чтобы для метки «АБА» действовал один ожидаемый ответ. ([Z-002](#z-002))
2. Указать, какую рамку контроллер выводит после события «Узор повреждён». ([Z-001](#z-001))
3. Задать предел в целых миллисекундах для показания общего таймера и определить исход при равенстве пределу. ([Z-003](#z-003))
