## Проверка набора в целом

Порядок трёх опытов задан. Для метки «АБА» требования задают разные сообщения, для повреждённого узора не выбрана рамка, для полного цикла не задан предел длительности.

Открытых предполагаемых пробелов — 0. Неоднозначностей — 0. Рекомендаций — 0.

Каждый ID утверждения учитывается один раз. В число нарушений входят подтверждённые дефекты и неоднозначности, для которых показаны две опирающиеся на текст трактовки с разными последствиями. Один и тот же конфликт имеет один ID при любом числе затронутых требований. Критичный дефект блокирует приёмку существенного обязательного сценария. Предполагаемый пробел оставляет открытым ожидаемое поведение или источник данных. Рекомендация предлагает улучшение. Вопросы и рекомендации имеют отдельные счётчики.

## Критичные дефекты

- [Z-001](#z-001) · Метка «АБА» занимает шесть байт. Для этого входа М-1 требует «Отклонено», а М-2 требует «Принято». В тексте отсутствует правило приоритета, поэтому принять опыт по обоим требованиям невозможно.
- [Z-002](#z-002) · П-1 требует вывести рамку, предусмотренную для события «Узор повреждён». Перечень рамок задаёт два варианта, но не закрепляет результат, по которому можно принять опыт.
- [Z-003](#z-003) · Э-1 определяет единицу измерения и обе границы интервала. Формулировка «достаточно коротким» в Э-2 не задаёт допустимого времени, поэтому обязательную проверку длительности нельзя завершить.

**Общее условие.** После сброса один раз подают метку «АБА». Все три буквы входят в алфавит метки, её длина в UTF-8 составляет шесть байт.    **Основание.** [R-M0011-04](#r-m0011-04) «При длине до четырёх байт включительно стенд показывает «Принято», при большей длине — «Отклонено».».

   При выборе этого варианта привести в соответствие [R-M0012-01](#r-m0012-01).

2. **Вариант 2.** Явно установить исключение для «АБА». Для этого входа показывать «Принято».

   **Основание.** [R-M0012-01](#r-m0012-01) «Для входа «АБА» стенд должен показать «Принято».».

   **Ожидаемый результат.** Стенд показывает «Принято».

## Готовность и порядок исправлений

ТЗ требует доработки до начала разработки. Для каждого из трёх обязательных опытов нужен однозначный критерий приёмки.

1. Согласовать М-1 и М-2, закрепив одно сообщение для метки «АБА». ([Z-001](#z-001))
2. Указать рамку для события «Узор повреждён». ([Z-002](#z-002))
3. Указать максимальное допустимое показание таймера полного цикла в целых миллисекундах. ([Z-003](#z-003))
