## Проверка набора в целом

Для метки «АБА» заданы два взаимоисключающих ответа. Для опыта с повреждённым узором отсутствует назначение рамки, а для полного цикла показа отсутствует измеримый критерий длительности.

Открытых предполагаемых пробелов — 1. Неоднозначностей — 0. Рекомендаций — 0.

Каждый ID утверждения учитывается один раз. В число нарушений входят подтверждённые дефекты и неоднозначности, для которых показаны две опирающиеся на текст трактовки с разными последствиями. Один и тот же конфликт имеет один ID при любом числе затронутых требований. Критичный дефект блокирует приёмку существенного обязательного сценария. Предполагаемый пробел оставляет открытым ожидаемое поведение или источник данных. Рекомендация предлагает улучшение. Вопросы и рекомендации имеют отдельные счётчики.

## Критичные дефекты

- [Z-002](#z-002) · В «АБА» три допустимые буквы по два байта, всего шесть байт. М-1 требует «Отклонено», М-2 для того же входа требует «Принято». В тексте отсутствует оговорка о приоритете, поэтому принять опыт по обоим требованиям невозможно.
- [Z-003](#z-003) · Общий таймер измеряет целые миллисекунды от нажатия до регистрации подтверждения. Экран отправляет подтверждение при появлении «Готово», стенд регистрирует его без задержки. Э-2 требует проверить полный интервал и задаёт только «достаточно коротким», поэтому по показанию таймера нельзя вынести вердикт. Отдельный критерий для промежуточных событий не задан.

## Готовность и порядок исправлений

ТЗ не готово к разработке и приёмке. Для каждого из трёх обязательных опытов требуется согласовать ожидаемый результат или критерий его оценки.

1. Согласовать единственный ожидаемый ответ для «АБА» и привести М-1 и М-2 в соответствие. ([Z-002](#z-002))
2. Назначить рамку для события «Узор повреждён». ([Z-001](#z-001))
3. Установить предел полного цикла в целых миллисекундах и исход проверки при равенстве пределу. ([Z-003](#z-003))
