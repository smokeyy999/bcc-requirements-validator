## Проверка набора в целом

У каждого из трёх обязательных опытов есть блокирующий дефект. Для метки «АБА» заданы несовместимые результаты, для повреждённого узора не назначена рамка, для полного цикла не задан критерий допустимой длительности.

Открытых предполагаемых пробелов — 0. Неоднозначностей — 0. Рекомендаций — 0.

Каждый ID утверждения учитывается один раз. В число нарушений входят подтверждённые дефекты и неоднозначности, для которых показаны две опирающиеся на текст трактовки с разными последствиями. Один и тот же конфликт имеет один ID при любом числе затронутых требований. Критичный дефект блокирует приёмку существенного обязательного сценария. Предполагаемый пробел оставляет открытым ожидаемое поведение или источник данных. Рекомендация предлагает улучшение. Вопросы и рекомендации имеют отдельные счётчики.

**Сценарий.** После сброса один раз подать событие «Узор повреждён».

**Последствие.** Нельзя определить, какой из двух наблюдаемых вариантов засчитать как успешный.

**Уже установлено.** После однократной подачи события контроллер обязан вывести одну из двух предусмотренных рамок. Основания — [R-M0007-01](#r-m0007-01), [R-M0007-02](#r-m0007-02), [R-M0003-03](#r-m0003-03).

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

### Z-002 · Результат для метки «АБА»

**Дефект · Противоречивость · Критичная.** Метка «АБА» занимает шесть байт в UTF-8. М-1 требует показать «Отклонено», а М-2 для той же метки требует «Принято». Исключение или приоритет не заданы, поэтому обязательный опыт нельзя принять по обеим нормам.

Затронутые утверждения — [R-M0011-02](#r-m0011-02), [R-M0011-04](#r-m0011-04), [R-M0012-01](#r-m0012-01).

[R-M0011-02](#r-m0011-02) · Учебный стенд для мозаики / Текстовая метка · [строка 11](../../../independent/case-p/variant.md#L11)

> Метка состоит из букв А и Б, каждая буква занимает два байта в UTF-8.  

[R-M0011-04](#r-m0011-04) · Учебный стенд для мозаики / Текстовая метка · [строка 11](../../../independent/case-p/variant.md#L11)

> При длине до четырёх байт включительно стенд показывает «Принято», при большей длине — «Отклонено».  

[R-M0012-01](#r-m0012-01) · Учебный стенд для мозаики / Текстовая метка · [строка 12](../../../independent/case-p/variant.md#L12)

> Для входа «АБА» стенд должен показать «Принято».  

**Сценарий.** После сброса один раз подать метку «АБА». Три буквы занимают шесть байт в UTF-8.

**Последствие.** По М-1 стенд должен показать «Отклонено», по М-2 — «Принято». Опыт нельзя принять по обеим нормам.

**Общее условие.** После сброса один раз подают метку «АБА». Каждая из трёх букв занимает два байта в UTF-8. Основания — [R-M0011-02](#r-m0011-02) «Метка состоит из букв А и Б, каждая буква занимает два байта в UTF-8.», [R-M0011-04](#r-m0011-04) «При длине до четырёх байт включительно стенд показывает «Принято», при большей длине — «Отклонено».», [R-M0012-01](#r-m0012-01) «Для входа «АБА» стенд должен показать «Принято».».

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Какой результат выбрать для «АБА» — «Отклонено» или «Принято»?

1. **Вариант 1.** Применять к «АБА» общий предел в четыре байта включительно.

   **Основание.** [R-M0011-04](#r-m0011-04) «При длине до четырёх байт включительно стенд показывает «Принято», при большей длине — «Отклонено».».

   **Ожидаемый результат.** Для шестибайтной метки «АБА» стенд показывает «Отклонено».

   При выборе этого варианта привести в соответствие [R-M0012-01](#r-m0012-01).

2. **Вариант 2.** Для входа «АБА» применять отдельное правило и показывать «Принято».

   **Основание.** [R-M0012-01](#r-m0012-01) «Для входа «АБА» стенд должен показать «Принято».».

   **Ожидаемый результат.** Для шестибайтной метки «АБА» стенд показывает «Принято».

   При выборе этого варианта привести в соответствие [R-M0011-04](#r-m0011-04).

**Черновик приёмочного теста.** После сброса один раз подать «АБА» и сверить показанное слово с выбранным результатом.

**Что различит проверка.** Показание, равное заданному пределу, проходит приёмку при включённой границе. / То же показание не проходит приёмку при строгой границе.

**Предложение для автора.** Предложение модели. Выбор формулировки и ожидаемого результата утверждает автор ТЗ.

**Вопрос для решения.** Каков предел длительности в целых миллисекундах и считается ли равенство пределу успешным?

## Готовность и порядок исправлений

ТЗ не готово к разработке по проверяемым требованиям. Для каждого опыта нужен однозначный критерий приёмки.

1. Устранить противоречие между М-1 и М-2 и установить один результат для «АБА». ([Z-002](#z-002))
2. Назначить рамку для события «Узор повреждён». ([Z-001](#z-001))
3. Задать предел длительности по Э-1 в целых миллисекундах и результат при равенстве пределу. ([Z-003](#z-003))
