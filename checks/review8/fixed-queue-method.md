# Как повторить рецензию фиксированной очереди

Эксперимент использует все 17 исходных вопросов по идентификаторам из [банковского отчёта версии 5669ac8](../../reports/finish4/review.md). В паспорте этого отчёта сумма SHA-256 связывает исходное ТЗ, отчёт и версию реализации. Перед обращением к модели программа проверяет оба хэша, 127 утверждений и точность цитат. Она восстанавливает каждый вопрос, его тест, сценарий, последствия и опубликованные варианты решения со ссылками на источник. [Паспорт исходного запуска](../../reports/finish4/review/run-meta.json)

Один запрос к `gpt-6.2-sol` объединяет всю очередь и 87 блоков исходного ТЗ. В нём используются производственные инструкции этапа рецензии, JSON-схема, диагностика черновика и проверки оснований текущей версии. Внутренняя трассировка предыдущего поиска кандидатов в Markdown не сохраняется. Все опубликованные сведения о карточках берутся из архива до редакторской вычитки. Восстановление не использует её замечания и рекомендуемые формулировки. [Программа повторной рецензии](fixed-queue-replay.py)

При ошибке допустим штатный запрос на исправление черновика. Вся попытка и полученные ответы сохраняются даже при техническом отказе. Если попытка окончательно отклонена, та же очередь отправляется повторно, максимум три раза. Первый принятый результат завершает эксперимент. Снятые либо объединённые вопросы исключаются из счётчика самостоятельных вопросов. Смысловая вычитка отдельно устанавливает, какие из оставленных вопросов и тестов пригодны для передачи владельцу ТЗ. [Критерии до запуска](protocol.md)

Автономная сверка с точкой вызова рецензии в `review()` подтвердила равенство полной инструкции и всех восстанавливаемых данных. Детектор данных для хранения выделил единицу суммы покупки и единицу порога. Четырнадцать готовых формулировок из редакторской вычитки и трёх предыдущих сборок проверены на отсутствие в запросе. [Проверка входа](fixed-queue-input.json)

Для нового измерения откройте корень проекта, установите зависимости и войдите в Codex CLI по [инструкции проекта](../../README.md). Команды создают рабочую копию зафиксированной версии и сохраняют новую рецензию в отдельный каталог текущего проекта.

```sh
git worktree add --detach ../bcc-validator-replay 48f37df5a9dbc5b52799d7bbd37870efe70c885e
python checks/review8/fixed-queue-replay.py --clone ../bcc-validator-replay --commit 48f37df5a9dbc5b52799d7bbd37870efe70c885e --output .tmp/fixed-queue
```

Та же команда без параметра `--output` проверяет входные данные автономно. При новой рецензии формулировки и количество оставленных вопросов могут измениться.
