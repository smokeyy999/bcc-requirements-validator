**Общее условие.** Для одной карты в том же календарном месяце после push на 50 000 ₸ повышают порог до 60 000 ₸. Сохранённые расходы ниже нового порога, а покупка на 10 000 ₸ доводит их до 60 000 ₸. **Вопрос для решения.** Должен ли в этом случае прийти второй push или действует месячный максимум? Для критерия 48 500 → 50 000 ₸ подтвердите, была ли прежняя отправка.

   **Основание.** [R-P001L0039-03](#r-p001l0039-03) «На карту приходится максимум один такой push за календарный месяц.».

   **Ожидаемый результат.** После покупки нового push нет. За месяц остаётся один push.

   При выборе этого варианта привести в соответствие [R-P001L0040-02](#r-p001l0040-02).

2. **Вариант 2.** Если накопленная сумма ниже нового порога, следующее достижение вызывает push независимо от истории предыдущей настройки.

   **Основание.** [R-P001L0040-02](#r-p001l0040-02) «Если она ниже нового порога, следующее достижение вызывает push независимо от истории предыдущей настройки.».

   **Ожидаемый результат.** После покупки приходит второй push за месяц.

   При выборе этого варианта привести в соответствие [R-P001L0039-03](#r-p001l0039-03).

**Черновик приёмочного теста.** Получить первый push, сменить порог и провести указанную покупку в том же месяце. Проверить итог и число push. Для критерия с одним push явно подготовить историю отправок.

> 2. Повторное сохранение заменяет действующую настройку.  

**Внешнее основание.** Безопасная операция не запрашивает изменение состояния ресурса. В HTTP к безопасным относятся GET, HEAD, OPTIONS и TRACE. Побочные действия сервера, которых клиент не запрашивал, сами по себе допустимы. [RFC 9110 § 9.2.1 · Safe Methods](https://www.rfc-editor.org/rfc/rfc9110.html#section-9.2.1)

**Уже установлено.** Уведомление по умолчанию выключено. API допускает 0 и 1. Приёмочная покупка доводит итог до порога и должна дать один push. Основания — [R-P002L0008-02](#r-p002l0008-02), [R-P001L0037-05](#r-p001l0037-05), [R-P001L0039-01](#r-p001l0039-01), [R-P001L0043-02](#r-p001l0043-02), [R-P003L0044-04](#r-p003l0044-04).

**Открытое решение.** Какой из двух сохранённых кодов обозначает состояние, при котором критерий даёт один push.

**Что различит проверка.** При enabled=1 приходит один push, при enabled=0 push отсутствует. / При enabled=0 приходит один push, при enabled=1 push отсутствует.

### R-P002L0008-02 · При расходах 48 500 ₸ и пороге 50 000 ₸ проведённая покупка на 1 500 ₸ приводит к одному push.

Уведомление о расходах по карте / Часть A. Новый функционал / Критерии приемки / Столбцы: Исходные условия · Действие · Ожидаемый результат · [PDF, стр. 2, строка 8 текстового слоя](../pdf/requirements-copy.pdf#page=2)

> \| Расходы 48 500 ₸, порог 50 000 ₸ \| Провести покупку на 1 500 ₸ \| Итог 50 000 ₸ и один push \|  

**Связано с нарушением в спецификации.** Ф-3 ограничивает число push за месяц, а Ф-4 требует push при следующем достижении независимо от истории прежней настройки. После первой отправки и повышения порога невозможно принять сценарий повторного достижения по обоим правилам. Ф-1 задаёт выключенное состояние по умолчанию, API допускает коды 0 и 1, а критерий с одним push не указывает сохранённый код включённого состояния. Позднее включение само по себе не образует перехода суммы по Ф-3.

## Готовность и порядок исправлений

ТЗ частично готово к разработке. Приёмка сохранения и уведомления после смены порога заблокирована до согласования исходов. Проверка пограничного примера месяца зависит от зоны совершения покупки, а проверка многобайтовой длины зависит от допустимых идентификаторов карт.

1. Определить число push после смены порога в том же месяце и закрепить HTTP-операцию, допускающую запрошенную замену настройки. ([Z-008](#z-008), [Z-010](#z-010))
2. Согласовать HTTP-код отклонённой суммы с примером, сохранив ERROR и прежнюю настройку. ([Z-005](#z-005))
3. Описать получение сохранённых порога и переключателя и указать источник месячной суммы для экрана. ([Z-003](#z-003), [Z-002](#z-002))
4. Указать код включённого состояния, определить сумму и её единицу, источник последних четырёх цифр и критерий своевременного получения push. ([Z-004](#z-004), [Z-006](#z-006), [Z-009](#z-009), [Z-001](#z-001))
5. Указать зону совершения покупки в примере и проверить его по Ф-2. Установить единицу длины, если допустимы идентификаторы с различным числом символов и байтов. ([Z-007](#z-007), [Z-012](#z-012))
6. Привести заголовки примеров в соответствие с описанными кодами 200 и 404. ([Z-015](#z-015))
