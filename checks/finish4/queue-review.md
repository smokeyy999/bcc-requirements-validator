**Полезен.** Последние четыре цифры прямо нужны в передаче. Хранимый идентификатор карты не объявлен номером карты. В тесте четыре цифры сверяются от указанного источника до исходящего сообщения. ### Z-014

**Какой исходный запрос или класс входов воспроизводит пример HTTP 200 с ERROR и сообщением «Проверьте сумму»?**

Тест из отчёта — Сначала проверить HTTP 400 для amount=999 при действительной сессии, своей карте и допустимом переключателе. Отдельно воспроизвести исходный запрос примера и сверить статус и тело. Сопоставить исходы при совпадении условий.

Исходы в Z-014 — Восстановленный вход подпадает под правило HTTP 400, и пример не согласуется с ним. / Восстановленный вход находится вне условий правила HTTP 400, и эта проверка не выявляет расхождения.

**Полезен.** Вход опубликованного примера отсутствует. Агент не приписал ему 999 ₸ и не переоткрыл 400 для нарушения нижней границы. Сначала выполняется определённый тест для 999, затем проверяется установленный автором запрос примера. Одни и те же входные условия нужны для вывода о конфликте. ### Z-015

**Какие из полей result и enabled обязательны для каждого описанного класса ошибок, кроме отклонения суммы?**

Тест из отчёта — Для отказа из-за неверного переключателя, запроса без авторизации, чужой или отсутствующей карты и внутренней ошибки проверить обязательность обоих полей по уточнённому контракту. При отклонении суммы отдельно проверить обязательный result=ERROR.

Исходы в Z-015 — Для проверяемого класса отказа тело с message проходит проверку, когда оба поля необязательны. / Для того же класса тело с message не проходит проверку, когда по контракту обязательно хотя бы одно из двух полей.

**Полезен.** В таблице приведены result и enabled, а примеры нескольких типов ошибок содержат message. Ответ определяет успешность проверки тела для уже перечисленных в документе классов. Отказ при отклонении суммы специально выведен в отдельную проверку с известным ERROR. ### Z-020

**Какое отдельное условие запрета доступа к этому методу, если оно предусмотрено, приводит к HTTP 403?**

Тест из отчёта — Проверить HTTP 404 для чужой и отсутствующей карты при действительной сессии и HTTP 401 без необходимой авторизации. При указании отдельного запрета воспроизвести его и проверить HTTP 403.

Исходы в Z-020 — Для указанного отдельного запрета воспроизводится 403. / Если отдельного запрета у метода нет, проверки 401 и 404 исчерпывают описанные сценарии отказа в доступе.

**Полезен.** Вопрос и тест предварительно устанавливают существование отдельного случая 403. Обязательные 401 без авторизации и 404 для чужой или отсутствующей карты сохранены. Автор может ответить, что отдельного входа для 403 на этом маршруте нет.
