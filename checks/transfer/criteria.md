# Проверка ревью до и после согласования

Два коротких документа подготовлены для этого испытания. В условном решении автора сохраняется один экземпляр квитанции, уточняется представление номера. Оба входа и следующие четыре критерия фиксируются в Git до обращения к модели. Каждый вход анализируется в отдельном процессе. Агенту передаётся только текст соответствующей версии.

| Критерий | Что засчитывается |
|---|---|
| Первоначальный конфликт | В одном сценарии первой успешной выдачи агент находит требование напечатать один экземпляр и пример с двумя. Для выбора автора предлагает обе проверяемые ветви. |
| Обязательный результат | В исходной версии агент сохраняет обязанность вернуть номер действующей записи. Открытым остаётся формат или способ его представления. Вопрос о том, возвращать ли номер вообще, считается ошибкой. |
| Согласованное число экземпляров | В исправленной версии агент не сообщает о расхождении между В-1 и Т-1 и не предлагает заново выбирать тираж. |
| Согласованное представление номера | В исправленной версии агент не просит выбрать уже определённые поле и формат. В-2 и Т-2 вместе позволяют проверить неизменность записи и отображение «804». |

Показатель относится только к этим четырём решениям. Дополнительные замечания рассматриваются отдельно. Время ревью человеком и экономию труда этот пример не измеряет.
