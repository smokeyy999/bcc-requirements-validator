# Передача коробок между читальным залом и хранением

## Назначение

Районный архив ведёт электронный журнал движения коробок с бумажными планами застройки. Сотрудник читального зала собирает список коробок для возвращения в хранилище. Дежурный хранитель принимает коробки по этому списку. Журнал нужен для ответа на два практических вопроса: кому сейчас передана конкретная коробка и на каком этапе остановилась передача. Публикация планов, выдача дел посетителям и учёт отдельных листов в коробке не входят в эту версию.

В системе два рабочих места. Первое находится за стойкой читального зала, второе у стола приёмки в хранилище. Оба работают с общим журналом. На бумажной наклейке каждой коробки напечатан инвентарный шифр и штрихкод с тем же шифром. Человек может ввести шифр с клавиатуры, если сканер не считывает штрихкод. Способ ввода не меняет проверок, порядка событий и текста сообщения об итогах действия.

## Исходная опись и участники

Перед началом проверки в системе есть опись коробок. Для каждой коробки опись содержит уникальный шифр, название фонда и текущее место ответственности. Место принимает одно из двух значений: читальный зал или хранилище. Начальная загрузка описи выполняется отдельно. В рамках передачи пользователь не может создавать и удалять коробки или менять название фонда. Шифры сравниваются с учётом регистра после удаления пробелов только в начале и в конце введённой строки.

Сотрудник зала имеет право составить список, передать его хранителю и посмотреть историю своего зала. Хранитель может принять коробки из переданного списка и зафиксировать расхождения. Обе роли могут просматривать одну и ту же карточку передачи. Проверка ролей происходит при каждом изменяющем действии. Если роль пользователя изменилась после открытия карточки, решение принимается по роли на момент отправки команды. При отказе показывается сообщение о недостаточных правах; данные карточки сохраняются.

## Создание передачи

При создании карточки журнал присваивает ей постоянный номер и состояние «Черновик». Время создания и идентификатор создавшего пользователя заполняет сервер журнала. Пустой черновик можно сохранить, закрыть и снова открыть по номеру. Номер не используется повторно после отмены или завершения. Одновременное создание двух разных черновиков на двух рабочих местах даёт два разных номера. Пользователь выбирает черновик для продолжения работы по номеру и времени создания.

Список внутри карточки хранит порядок первого добавления коробок. Название фонда для просмотра берётся из описи по шифру. Журнал показывает общее число строк и число разных фондов. Один фонд может присутствовать в нескольких несмежных строках, и при подсчёте он учитывается один раз. Эти два числа вычисляются заново после каждого принятого изменения списка. Для пустого черновика оба числа равны нулю. Сохранение списка без изменений оставляет порядок и оба числа прежними.

## Ввод и удаление коробки

Шифр можно добавить, когда найденная в описи коробка находится под ответственностью зала. При добавлении неизвестного шифра интерфейс оставляет введённое значение в поле и выводит «Нет в описи». Строка в список не добавляется. При добавлении известного шифра, который уже находится в хранилище, выводится «Коробка в хранилище». В обоих случаях оператор может исправить шифр и повторить действие без переоткрытия карточки.

Повтор того же шифра в одном черновике не создаёт вторую строку. Интерфейс выделяет уже существующую строку и сообщает «Уже в списке». При удалении строки из черновика другие строки сохраняют взаимный порядок. Если затем добавить удалённую коробку снова, она получает последнее место в текущем списке. Удаление последней строки возвращает карточку к пустому черновику с прежним номером. Операция удаления строки не меняет данные в описи.

## Подготовка к передаче

Сотрудник зала может составлять несколько черновиков для разных рейсов. Пока коробка находится только в черновиках, два разных черновика могут содержать её шифр. Окончательный контроль выполняется при переводе карточки из черновика в состояние «Передана». Для пустого списка этот переход отклоняется с сообщением «Добавьте хотя бы одну коробку». При отклонении карточка остаётся черновиком и доступна для обычного редактирования.

Журнал сверяет текущее место ответственности каждой строки с описью и проверяет, нет ли шифра в другой переданной, ещё не закрытой карточке. При наличии нескольких неподходящих коробок ответ содержит все соответствующие шифры в порядке списка. Получение такого ответа не должно приводить к частичной передаче подходящих строк. Сотрудник может открыть опись, уточнить фактическое положение коробок, отредактировать черновик и отправить обновлённый список повторно.

## Фиксация передачи

Успешная передача делает снимок состава списка, названий фондов и порядка строк. Дальнейшее изменение названия фонда в описи не меняет этот снимок. Система записывает время передачи и идентификатор сотрудника зала. В карточке становится видна подпись «Ожидает приёмки». Передача карточки сама по себе ещё не переводит коробки в хранилище: в описи место ответственности остаётся прежним до подтверждения конкретной коробки хранителем.

При одновременной передаче двух черновиков с общим шифром успешно фиксируется только одна передача. Вторая карточка остаётся черновиком, а сообщение по общему шифру содержит номер уже переданной карточки. Такой же порядок действует, если сотрудники используют разные способы ввода: один сканировал штрихкод, другой вводил те же символы вручную. Время появления текста на экране каждого рабочего места не определяет победившую карточку; решение принимает журнал при записи.

## Рабочее место приёмки

Хранитель открывает переданную карточку по её постоянному номеру. Для строк списка показываются шифр, название фонда на момент передачи и результат сверки. Начальный результат каждой строки — «Не сверена». При первом успешном подтверждении шифра результат становится «Принята», а место ответственности коробки в описи становится «Хранилище». Подтверждение строки и перенос ответственности записываются вместе. При сбое ни одно из этих двух изменений не должно быть видно отдельно от другого.

Повторное сканирование принятой коробки возвращает её существующий результат и время первого подтверждения. Общее число принятых строк при повторе не увеличивается. Сканирование неизвестного шифра показывает «Нет в описи». Сканирование известного шифра вне текущего списка показывает «Нет в этой передаче» и не добавляет строку. Тем самым внеплановая коробка не становится принятой автоматически, даже когда все остальные коробки его фонда уже находятся в хранилище.

## Расхождение при сверке

Если предусмотренная списком коробка физически отсутствует, хранитель может установить для несверенной строки результат «Не доставлена». В этом случае он вводит текстовое пояснение длиной от одного до двухсот символов после удаления пробелов по краям; длина считается в символах Unicode, включая внутренние пробелы. Пояснение больше максимальной длины отклоняется полностью. При отказе результат строки, место ответственности коробки и прежний текст пояснения не меняются.

Пока карточка открыта для приёмки, хранитель может вернуть строку «Не доставлена» в исходное состояние «Не сверена» и затем подтвердить найденную коробку обычным способом. Предыдущее пояснение остаётся в истории как часть события установки расхождения. В актуальной строке после возврата отображается пустое пояснение. Операция возврата разрешена только для текущего результата «Не доставлена». Снять отметку «Принята» таким действием нельзя.

## Закрытие и последующий просмотр

Хранитель закрывает переданную карточку после того, как у каждой строки есть окончательный результат «Принята» или «Не доставлена». Если остаётся хотя бы одна несверенная коробка, интерфейс перечисляет её шифр и остальные несверенные шифры в порядке исходного списка. При успешном закрытии система сохраняет идентификатор хранителя и серверное время закрытия. Карточка с одними расхождениями тоже может быть закрыта, если для каждого расхождения сохранено пояснение.

После закрытия пользователь может просматривать карточку и выгрузить её список, но не может исправлять результаты задним числом. Коробка с результатом «Не доставлена» остаётся под ответственностью зала. После закрытия карточки её можно включить в новую передачу. Поиск по этой коробке показывает обе карточки, если они имеются. История закрытой карточки сохраняет прежний результат даже после того, как коробка принята по новой передаче.

## Журнал событий

В журнале различаются создание черновика, изменение списка, передача, подтверждение приёмки, установка расхождения, снятие расхождения и закрытие. Запись содержит номер карточки, порядковый номер события внутри карточки, вид действия, идентификатор пользователя и время сервера. Для события, касающегося одной коробки, записывается её шифр. Изменение самого списка не перезаписывает предыдущие события. Результаты проверок, которые не поменяли карточку, не образуют новые записи её истории.

На экране истории записи упорядочены по возрастанию порядкового номера события внутри карточки. Этот номер задаёт порядок даже при совпадающем серверном времени с точностью до секунды. Фильтрация по шифру ограничивает видимый список событий конкретной коробкой и сохраняет исходные номера, поэтому они могут отображаться с пропусками. При снятии фильтра вновь видна полная хронология. Открытие и закрытие экрана истории не создают событий в журнале.

## Печать сверочного листа

Для переданной или закрытой карточки доступен сверочный лист. В заголовке печатаются номер карточки и дата передачи по серверному времени в UTC. Строки содержат шифр, сохранённое название фонда и текущий результат сверки. Порядок совпадает с порядком снимка при передаче. В конце листа указаны число строк, число принятых коробок и число коробок с расхождениями. Для ещё не закрытой карточки эти три числа разрешено читать как промежуточные данные на время построения листа.

Печать и просмотр документа не меняют карточку и не создают события приёмки. Если по одной карточке построить два листа без изменения состояния между построениями, набор и порядок строк, статусы и итоги совпадут. При сравнении не учитывается время самого построения листа. Данные разных карточек не объединяются в один лист. Правила печати отдельных наклеек, настройки физического принтера и учёт израсходованной бумаги в эту спецификацию не входят.

## Приёмочные ситуации

| Исходные данные | Действие | Наблюдаемый результат |
|---|---|---|
| Пустой черновик | Передать карточку | Черновик сохраняется; сообщение предлагает добавить коробку |
| Шифр ПЛ-07 уже третьим в списке | Ввести его снова | В списке прежнее число строк; выделена третья строка |
| Два черновика содержат ПЛ-11 | Отправить их при одновременной работе | Одна передана; вторая остаётся черновиком с номером первой в сообщении |
| Коробка ПЛ-12 принята по открытой передаче | Отсканировать её повторно | Время подтверждения и число принятых коробок сохраняются |
| Для ПЛ-13 указано расхождение | Снять отметку до закрытия | Текущая строка несверенная, прежнее пояснение доступно в истории |
| Из трёх строк две приняты, одна несверенная | Закрыть карточку | Показан шифр несверенной коробки; карточка остаётся открытой |
| Все три строки получили окончательный результат | Закрыть и построить сверочный лист | Состав листа совпадает со снимком, итоги соответствуют результатам строк |
