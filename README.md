# Агент статического ревью требований

Агент помогает аналитику решить, какие требования уже можно передать разработчику и что нужно уточнить у автора. Принимает Markdown, PDF с текстовым слоем и DOCX. Результат — отчёт на русском с дословными цитатами, вопросами и ожидаемыми результатами приёмочных тестов. Все отчёты агента в комплекте получены с помощью **`gpt-6.2-sol` через Codex CLI**.


## Результат на ТЗ организаторов

Агент проверил **143 утверждения** за 10 мин 46 с. Нарушений по оценке модели — 4, из них критичных — 1. Вопросов к автору — 16, из них блокирующих — 1. Версия агента `9869df2`. [Исходный Markdown](docs/requirements.md)

- После первого push Ф-3 запрещает вторую отправку за месяц, а Ф-4 требует её при достижении нового порога. Для обоих решений дан тест. [Z-011](reports/submission/review.md#z-011)
- Чтобы отнести покупку к январю или февралю, нужен часовой пояс её совершения. В примере указан только пояс проведения. [Z-009](reports/submission/review.md#z-009)

## Запуск на своём документе

Понадобятся Python 3.10+, Git и Codex CLI в `PATH`. В проверенном запуске использовался Codex CLI `0.171.0-alpha.13`. Из корня проекта выполните `codex login` под аккаунтом с доступом к `gpt-6.2-sol`, затем `codex login status`. CLI хранит данные авторизации отдельно от проекта. Для входа по ключу OpenAI принимает его через стандартный ввод команды `codex login --with-api-key`. [Установка Codex CLI](https://developers.openai.com/codex/cli/)

**Windows, PowerShell**

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m requirements_validator --input docs/requirements.md --output .tmp/review.md
```

**Linux и macOS**

```sh
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
python -m requirements_validator --input docs/requirements.md --output .tmp/review.md
```

Для другого документа замените путь после `--input`. Откройте `.tmp/review.md`. Паспорт этого запуска сохранится в `.tmp/review/run-meta.json`. Модель выбирается автоматически. Файл `.env` необязателен. Параметр `CODEX_EXTRACT_WORKERS` позволяет выбирать между одним и двумя потоками выделения требований. [Пример настроек](.env.example)

Если CLI пишет «Повторный ответ модели не прошёл проверку», автоматическая попытка исправления исчерпана. Повторите ту же команду. Ранее сохранённый отчёт останется доступен. [Журнал запусков](checks/submission/attempts.md)

## Как формируется вывод

1. Python сохраняет SHA-256 исходных байтов. Для каждого фрагмента он фиксирует строку Markdown, страницу и строки PDF, абзац или строку таблицы Word.
2. Модель выделяет проверяемые утверждения. Затем по полному документу сопоставляет правила, условия, примеры и описания интерфейсов. Валидатор проверяет каждую цитату.
3. Отдельный запрос к той же модели пересматривает замечания. Для внутреннего конфликта нужны две несовместимые обязанности в одном сценарии. Если общие условия ещё предстоит выяснить, автор получает вопрос и объяснение того, как ответ изменит тест.
4. Python проверяет ссылки и собирает сводку. Замечание учитывается один раз по ID. В перечне требований отдельно показано, какие фрагменты послужили основанием или контекстом. Для нарушений отчёт содержит предложение автору и приёмочный тест.

Строгая точность показывает, сколько карточек совпало с заранее заданной категорией дефекта и всеми требуемыми фрагментами ТЗ. В знаменатель входят и дополнительные вопросы. Например, в испытании версии `debbf85` агент спросил, как проверить кнопку «Возобновить», и сослался на нужные строки. Классификация «Проверяемость» разошлась с эталоном «Полнота», поэтому балл за этот дефект не начислен. [Пример из предыдущего испытания](reports/previous/benchmark-runs/irrigation/r1/report.md#z-005) · [Незачтённые карточки итоговой версии](reports/submission/evaluation-manual.md)

Автономные тесты и пересчёт по сохранённым отчётам выполняются из активного виртуального окружения. Для сверки версий через `scripts.verify_release` используйте комплект с каталогом `.git` или полный Git-клон. Библиотека `python-docx` в следующем блоке нужна для независимого чтения цитат из Word.

```sh
python -m unittest discover -v
python -m pip install python-docx==1.2.0
python -m scripts.verify_release
python -m scripts.evaluate --import-dir reports/submission/benchmark-runs --repeat 1 --output .tmp/evaluation.md
```

Последняя команда пересчитывает показатели по сохранённым отчётам без обращений к модели. Эталон и правила сопоставления зафиксированы отдельно от анализатора. [Состав корпуса и методика](benchmark/README.md)

Полные прогоны и установка проверены на Windows. Для сканов PDF требуется предварительное распознавание текста. Очень длинный документ может превысить доступный контекст модели. Время CLI измерено по паспорту. Независимого замера работы человека на том же объёме нет. Расход в деньгах зависит от аккаунта. Проверка цитат подтверждает их происхождение, а смысл замечания и выбор бизнес-правила можно проверить по связанным фрагментам.
