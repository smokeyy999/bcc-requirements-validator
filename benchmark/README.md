# Корпус для оценки статического ревью

В корпусе три исходных ТЗ. Для каждого сохранена исходная версия `baseline.md` и копия `requirements.md` с пятью заранее внесёнными дефектами. Отдельная короткая спецификация индикатора служит четвёртым документом без внесённых дефектов. Даже в контрольном тексте могут обнаружиться реальные недочёты.

| Каталог | Часть | Предмет | Файлы для модели |
|---|---|---|---|
| dispatch | dev | Отправка грузовой ведомости | Исходник и копия с дефектами |
| irrigation | test | Контроллер полива | Исходник и копия с дефектами |
| subtitles | test | Экспорт субтитров, английский язык | Исходник и копия с дефектами |
| indicator | test | Индикатор двухпозиционного выключателя | Контрольный документ |

Файлы `manifest.json` задают эталонные категории и диапазоны до запуска. CLI получает только байты одного документа. Разметка **dev** доступна для разработки. В каждом измерении код и подсказки зафиксированы до запуска. При подготовке этой версии команда изучала пропуски прошлых прогонов по обеим частям, включая **test**. Результат на этих семи документах показывает повторяемость на известном корпусе. Изменение критериев сопоставления образует другую версию измерения.

## Воспроизведение

Войдите в Codex CLI, как описано в [инструкции по запуску](../README.md), и выполняйте команды из корня проекта. Полный эксперимент по умолчанию делает три независимых прохода через семь входных файлов. Для приведённой ниже команды готовые результаты сохраняются в `.tmp/live/benchmark-runs/`. Повторите ту же команду для продолжения прерванного эксперимента.

```sh
python -m scripts.evaluate --repeat 3 --jobs 1 --resume --runs-dir .tmp/live/benchmark-runs --output reports/local/evaluation.md
```

При достаточной квоте Codex можно передать `--jobs 2`. Тогда в каждом дочернем процессе извлечение идёт в один поток. Для отдельной отладки доступна команда `python -m scripts.evaluate --split dev --repeat 1 --runs-dir .tmp/dev-stage/runs --output .tmp/dev/evaluation.md`.

По окончании в `reports/local/` появятся оценка, разбор незачтённых карточек и каталог `benchmark-runs/` с индивидуальными отчётами и паспортами. Чтобы перепроверить сравнение версий, пересчитайте три сохранённых прохода каждой. Верхняя команда читает результаты версии `1a9fc9b`, нижняя — версии `9ce4ce9`. Оба пересчёта выполняются автономно.

```sh
python -m scripts.evaluate --import-dir reports/review14/benchmark-runs --repeat 3 --output .tmp/review14/evaluation.md
python -m scripts.evaluate --import-dir reports/review13/benchmark-runs --repeat 3 --output .tmp/review13/evaluation.md
```

Для импорта нужен файл `<каталог>/<case>/r<N>/report.md` на каждую пару документа и повтора. ID документов: `dispatch`, `dispatch-base`, `irrigation`, `irrigation-base`, `subtitles`, `subtitles-base`, `indicator`. Для каждой исходной версии используется суффикс `-base`. Файл `report/run-meta.json` рядом с отчётом содержит метрики. Перед вызовами модели оценщик проверяет чистоту клона и возможность перенести отчёты из `.tmp/benchmark-runs/` в `reports/benchmark-runs/` с сохранением относительных ссылок на вход. После переноса он повторно проверяет паспорт, SHA-256 отчёта и вложенную ссылку на документ. При импорте исторических отчётов без полных метрик оценка явно помечается как диагностическая.

Для другого исходного Markdown можно сравнить три готовых отчёта без манифеста:

```sh
python -m scripts.evaluate --stability-only reports/s1/report.md reports/s2/report.md reports/s3/report.md --output reports/stability.md
```

Основные метрики считаются по первому прогону. Разбивка по повторам, типам и частям показывает возможные колебания. Зачитывается только один кандидат с точной эталонной категорией, чьи доказательства пересекают каждый заданный диапазон. При конфликте нескольких соответствий все спорные пары остаются для ручной проверки. В знаменателе точности учитываются все опубликованные карточки замечаний, в том числе вопросы и рекомендации. Проверка стабильности обходит весь реестр независимо от эталонов. Для зачёта общей группы нужны единая категория, общая строка цитаты и отсутствие двух конкурирующих карточек из одного запуска.
